# 第 07 章 · 生成器表达式

> 基准版本：CMake 4.3.4

生成器表达式（Generator Expressions，社区常简称 **genex**）是 CMake 中最强大、也最容易让初学者困惑的特性之一。它允许你把一个值的最终确定**推迟到生成期（generation phase）**，从而表达"随构建配置 / 平台 / 编译器 / 目标而变"的内容。本章是字典式参考章，逐一覆盖 CMake 4.3.4 支持的所有生成器表达式，并配以语法、示例与典型应用。

---

## 7.1 什么是生成器表达式

### 7.1.1 三个阶段：配置期、生成期、构建期

要理解 genex，首先要理解 CMake 的工作分为三个先后阶段：

| 阶段 | 英文 | 何时发生 | 在此阶段确定的东西 |
|------|------|----------|--------------------|
| 配置期 | configure phase | 执行 `cmake ..` 解释 `CMakeLists.txt` 时 | 普通变量 `${VAR}`、`if()`、`set()`、`message()` 全部在此求值 |
| 生成期 | generation phase | 配置期结束后，CMake 写出实际构建系统文件（Makefile / Ninja / `.vcxproj` 等）时 | **生成器表达式 `$<...>` 在此求值** |
| 构建期 | build phase | 执行 `cmake --build .` / `make` / `ninja` 时 | 编译、链接、自定义命令真正运行 |

普通变量引用 `${VAR}` 在 CMakeLists.txt 被读取的那一刻（配置期）就被替换成了字符串，之后再也不变。而 `$<...>` 在配置期会被原封不动地保留下来，直到生成期才被 CMake 求值并写入构建文件。

### 7.1.2 为什么需要它：配置期还"不知道"的信息

考虑 Visual Studio 和 Xcode 这类**多配置生成器（multi-config generator）**：同一次 `cmake ..` 会同时生成 `Debug`、`Release`、`RelWithDebInfo`、`MinSizeRel` 四套配置，用户在 IDE 里随时切换。在配置期，CMake 根本无法知道"用户最终会构建哪个配置"——因为答案是"全部，由构建期决定"。

这正是 `if()` 做不到的地方。下面这段代码在多配置生成器下是**错误**的：

```cmake
# ❌ 错误示范：在多配置生成器（VS/Xcode）下不成立
if(CMAKE_BUILD_TYPE STREQUAL "Debug")
  target_compile_definitions(app PRIVATE ENABLE_LOGGING)
endif()
```

原因：
- `CMAKE_BUILD_TYPE` 仅对**单配置生成器**（Makefiles / Ninja）有意义，对多配置生成器它通常为空。
- 即使非空，`if()` 在配置期只会被求值一次，无法表达"当且仅当构建 Debug 时才生效"。

正确的写法是用生成器表达式 `$<CONFIG:Debug>`，把判断推迟到生成期，对每个配置分别展开：

```cmake
# ✅ 正确：对任何生成器、任何配置都成立
target_compile_definitions(app PRIVATE
  $<$<CONFIG:Debug>:ENABLE_LOGGING>
)
```

CMake 在生成期会为 Debug 配置写出 `ENABLE_LOGGING`，为 Release 配置写出空字符串。

### 7.1.3 一句话总结

> **凡是"值取决于配置 / 平台 / 编译器 / 目标属性、而这些信息在配置期尚不确定"的场合，就该用生成器表达式而不是 `if()`。**

## 7.2 基本语法

### 7.2.1 三种基本形态

生成器表达式统一以 `$<` 开头、`>` 结尾，内部有三种基本形态：

| 形态 | 语法 | 含义 | 例子 |
|------|------|------|------|
| 变量查询 | `$<NAME>` | 求值为某个由生成器决定的值 | `$<CONFIG>`、`$<PLATFORM_ID>` |
| 布尔/操作 | `$<OP:arg>` | 对 `arg` 施加操作 `OP` | `$<BOOL:${X}>`、`$<UPPER_CASE:foo>` |
| 条件展开 | `$<condition:value>` | `condition` 为真则展开为 `value`，否则为空串 | `$<$<CONFIG:Debug>:--verbose>` |

其中第三种最常用：`condition` 必须求值为 `0` 或 `1`，`1` 时整体展开为 `value`，`0` 时展开为空字符串 `""`。

```cmake
# 当 condition=1 → 展开为 value；condition=0 → 展开为空
$<condition:value>
```

### 7.2.2 嵌套

生成器表达式可以任意嵌套，内层先求值、外层后求值：

```cmake
# 外层 $<...:...> 的条件是另一个 genex $<CONFIG:Debug>
$<$<CONFIG:Debug>:-g>

# 三层嵌套：仅 Debug 且编译 C++ 时加 -fno-inline
$<$<AND:$<CONFIG:Debug>,$<COMPILE_LANGUAGE:CXX>>:-fno-inline>
```

### 7.2.3 列表语义：按分号展开

生成器表达式的结果若含分号 `;`，在大多数命令里会被当作**列表**展开成多个参数。许多 genex（如 `$<TARGET_OBJECTS>`、`$<TARGET_RUNTIME_DLLS>`）本身就求值为分号分隔的列表。要让 `add_custom_command` / `add_custom_target` 把这种列表展开成多个命令行参数，需配合 `COMMAND_EXPAND_LISTS` 选项：

```cmake
add_custom_command(TARGET app POST_BUILD
  COMMAND ${CMAKE_COMMAND} -E copy
          $<TARGET_RUNTIME_DLLS:app> $<TARGET_FILE_DIR:app>
  COMMAND_EXPAND_LISTS            # 不加则整串被当作单个参数
)
```

### 7.2.4 可以用在哪里 / 不能用在哪里

生成器表达式**不是到处都能用**。它只在那些"由生成期处理"的命令/属性里被求值；放进配置期立即求值的命令里只会被当作普通字符串，导致 `$<...>` 原样泄漏。

**✅ 支持 genex 的常见场景：**

| 场景 | 典型命令 / 属性 |
|------|-----------------|
| 目标使用要求 | `target_compile_options`、`target_compile_definitions`、`target_include_directories`、`target_link_libraries`、`target_link_options`、`target_link_directories`、`target_sources`、`target_precompile_headers` |
| 目标属性 | `set_property` / `set_target_properties` 大多数属性的值 |
| 安装 | `install(TARGETS ...)`、`install(FILES ... DESTINATION $<...>)` 的部分参数 |
| 自定义命令 | `add_custom_command`、`add_custom_target`（`COMMAND`、`DEPENDS`、`OUTPUT` 等） |
| 文件生成 | `file(GENERATE OUTPUT ... CONTENT ...)`（这是**唯一**在配置脚本里能"看到" genex 求值结果的途径） |

**❌ 不支持 genex 的常见场景（会原样泄漏或报错）：**

- `message()`、`set()`、`if()`、`string()`、`list()` 等**配置期立即求值**的命令——它们看到的只是字面字符串 `$<...>`。
- `add_executable` / `add_library` 的**源文件列表**在历史上不支持，但通过 `target_sources` 添加源文件是支持的；许多源文件相关用法需要 CMake 3.x+ 才放开，使用前应核对。
- 大部分 `file()` 子命令（除 `file(GENERATE)`）。

> 经验法则：如果你想"立刻看到一个 genex 算成了什么"，唯一可靠的办法是 `file(GENERATE)` 落盘后再读文件（见 7.9 节）。

## 7.3 逻辑运算符

逻辑运算符的结果是 `0` 或 `1`，通常作为 `$<condition:value>` 的条件部分。

**`$<BOOL:string>`**：把任意字符串按 CMake 的布尔规则转成 `0`/`1`。
非空且不属于假值集合（`0`、`OFF`、`NO`、`FALSE`、`N`、`IGNORE`、`NOTFOUND`、空串、以 `-NOTFOUND` 结尾的串等）即为 `1`，否则为 `0`。常用于把普通变量"提升"为 genex 布尔。

```cmake
target_compile_definitions(app PRIVATE
  $<$<BOOL:${ENABLE_FEATURE_X}>:WITH_FEATURE_X>
)
```

**`$<AND:c1,c2,...>`**：所有参数都为 `1` 时结果为 `1`，否则 `0`。参数必须是 `0`/`1`。

```cmake
$<AND:$<CONFIG:Release>,$<PLATFORM_ID:Linux>>
```

**`$<OR:c1,c2,...>`**：任一参数为 `1` 时结果为 `1`，全为 `0` 才得 `0`。

```cmake
$<OR:$<CONFIG:Debug>,$<CONFIG:RelWithDebInfo>>
```

**`$<NOT:cond>`**：对单个 `0`/`1` 取反。

```cmake
$<$<NOT:$<CONFIG:Debug>>:-DNDEBUG>
```

**`$<IF:cond,true_value,false_value>`**：三元选择。`cond` 为 `1` 取 `true_value`，为 `0` 取 `false_value`。注意它和 `$<condition:value>` 的区别——后者假分支恒为空串，前者可指定假分支的值。

```cmake
target_compile_options(app PRIVATE
  $<IF:$<CONFIG:Debug>,-O0,-O2>
)
```

**`$<STREQUAL:a,b>`**：字符串**大小写敏感**比较，相等为 `1`。

```cmake
$<STREQUAL:${CMAKE_SYSTEM_NAME},Linux>
```

**`$<EQUAL:a,b>`**：把 `a`、`b` 当作**数值**比较，相等为 `1`。

```cmake
$<EQUAL:${SOME_COUNT},0>
```

**`$<VERSION_LESS:v1,v2>` / `$<VERSION_GREATER:v1,v2>` / `$<VERSION_EQUAL:v1,v2>`**：版本号比较。
还包括 `$<VERSION_LESS_EQUAL:v1,v2>` 与 `$<VERSION_GREATER_EQUAL:v1,v2>`。常配合编译器版本查询使用。

```cmake
# GCC 12 及以上才加 -std=c++23
$<$<AND:$<CXX_COMPILER_ID:GNU>,$<VERSION_GREATER_EQUAL:$<CXX_COMPILER_VERSION>,12>>:-std=c++23>
```

**`$<IN_LIST:item,list>`**：`item` 若出现在 `list`（分号分隔）中则为 `1`。

```cmake
$<IN_LIST:${CMAKE_SYSTEM_NAME},Linux;Darwin>
```

逻辑/比较运算符速查表：

| 表达式 | 结果 | 说明 |
|--------|------|------|
| `$<BOOL:string>` | 0/1 | 按 CMake 真值规则转布尔 |
| `$<AND:c1,c2,...>` | 0/1 | 逻辑与 |
| `$<OR:c1,c2,...>` | 0/1 | 逻辑或 |
| `$<NOT:cond>` | 0/1 | 逻辑非 |
| `$<IF:cond,t,f>` | t 或 f | 三元选择 |
| `$<STREQUAL:a,b>` | 0/1 | 字符串相等（大小写敏感） |
| `$<EQUAL:a,b>` | 0/1 | 数值相等 |
| `$<VERSION_LESS:v1,v2>` | 0/1 | 版本 v1 < v2 |
| `$<VERSION_GREATER:v1,v2>` | 0/1 | 版本 v1 > v2 |
| `$<VERSION_EQUAL:v1,v2>` | 0/1 | 版本 v1 == v2 |
| `$<VERSION_LESS_EQUAL:v1,v2>` | 0/1 | v1 <= v2 |
| `$<VERSION_GREATER_EQUAL:v1,v2>` | 0/1 | v1 >= v2 |
| `$<IN_LIST:item,list>` | 0/1 | 成员测试 |

## 7.4 查询表达式（variable queries）

这类表达式直接求值为生成期才确定的环境信息，是 genex 真正"威力"的来源。多数提供两种形态：**取值形态**（如 `$<CONFIG>` 求值为当前配置名）和**断言形态**（如 `$<CONFIG:cfgs>` 求值为 `0`/`1`）。

**`$<CONFIG>`**：求值为当前构建配置的名字，如 `Debug`、`Release`。

```cmake
file(GENERATE OUTPUT "info-$<CONFIG>.txt" CONTENT "config=$<CONFIG>\n")
```

**`$<CONFIG:cfgs>`**：当前配置匹配 `cfgs`（逗号分隔、大小写不敏感）中任一项时为 `1`。最常用的配置判断。

```cmake
target_compile_definitions(app PRIVATE
  $<$<CONFIG:Debug,RelWithDebInfo>:ENABLE_ASSERTS>
)
```

**`$<PLATFORM_ID>` / `$<PLATFORM_ID:ids>`**：取值/断言目标平台标识（即 `CMAKE_SYSTEM_NAME`，如 `Linux`、`Windows`、`Darwin`）。

```cmake
$<$<PLATFORM_ID:Windows>:/DWIN32_LEAN_AND_MEAN>
```

**`$<C_COMPILER_ID>` / `$<CXX_COMPILER_ID>`**（及断言形态 `$<C_COMPILER_ID:ids>`、`$<CXX_COMPILER_ID:ids>`）：取值/断言对应语言编译器的 CMake 编译器 ID，如 `GNU`、`Clang`、`AppleClang`、`MSVC`、`Intel`。通用形态为 `$<LANG_COMPILER_ID:ids>`（其中 `LANG` 替换为 `C`/`CXX`/`Fortran` 等）。

```cmake
target_compile_options(app PRIVATE
  $<$<CXX_COMPILER_ID:GNU,Clang>:-Wall -Wextra>
  $<$<CXX_COMPILER_ID:MSVC>:/W4>
)
```

**`$<COMPILE_LANGUAGE:langs>`**：当前正在**编译**的源文件语言匹配 `langs`（逗号分隔）时为 `1`。在混合 C/C++/CUDA 等多语言目标里按语言区分编译选项的关键。无参形态 `$<COMPILE_LANGUAGE>` 求值为当前编译语言。

```cmake
# 只给 C++ 文件加 -fno-exceptions，C 文件不受影响
target_compile_options(app PRIVATE
  $<$<COMPILE_LANGUAGE:CXX>:-fno-exceptions>
)
```

**`$<LINK_LANGUAGE:langs>`**：当前**链接**步骤使用的语言匹配 `langs` 时为 `1`；无参 `$<LINK_LANGUAGE>` 求值为链接语言。用于按链接语言区分链接选项/库。

```cmake
target_link_options(app PRIVATE
  $<$<LINK_LANGUAGE:CXX>:-stdlib=libc++>
)
```

**`$<COMPILE_LANG_AND_ID:lang,ids>`**：当前编译语言为 `lang` **且**该语言编译器 ID 属于 `ids` 时为 `1`。等价于 `$<AND:$<COMPILE_LANGUAGE:lang>,$<LANG_COMPILER_ID:ids>>` 的简写。对应链接侧有 `$<LINK_LANG_AND_ID:lang,ids>`。

```cmake
target_compile_definitions(app PRIVATE
  $<$<COMPILE_LANG_AND_ID:CXX,Clang,AppleClang>:USING_CLANG_CXX>
)
```

**`$<COMPILER_VERSION>`（通用 `$<LANG_COMPILER_VERSION>`）/ `$<C_COMPILER_VERSION>` / `$<CXX_COMPILER_VERSION>`**：求值为对应语言编译器的版本字符串。也有断言形态 `$<CXX_COMPILER_VERSION:version>`（精确等于才为 `1`），但更常见的是配合 `$<VERSION_GREATER_EQUAL:>` 做区间判断。

```cmake
# 仅当 MSVC 19.30+ 才启用某特性
$<$<AND:$<CXX_COMPILER_ID:MSVC>,$<VERSION_GREATER_EQUAL:$<CXX_COMPILER_VERSION>,19.30>>:/std:c++20>
```

查询表达式速查表：

| 表达式 | 取值形态 | 断言形态 |
|--------|----------|----------|
| 配置 | `$<CONFIG>` | `$<CONFIG:cfgs>` |
| 平台 | `$<PLATFORM_ID>` | `$<PLATFORM_ID:ids>` |
| 编译器 ID | `$<CXX_COMPILER_ID>` | `$<CXX_COMPILER_ID:ids>` |
| 编译器版本 | `$<CXX_COMPILER_VERSION>` | `$<CXX_COMPILER_VERSION:ver>` |
| 编译语言 | `$<COMPILE_LANGUAGE>` | `$<COMPILE_LANGUAGE:langs>` |
| 链接语言 | `$<LINK_LANGUAGE>` | `$<LINK_LANGUAGE:langs>` |
| 语言+编译器 ID | — | `$<COMPILE_LANG_AND_ID:lang,ids>` / `$<LINK_LANG_AND_ID:lang,ids>` |

## 7.5 目标相关表达式

这类表达式查询某个目标（target）的产物路径、对象文件或属性，是连接"目标"与"自定义命令/安装"的桥梁。被引用的目标无需是当前目录定义的，但必须在生成期已知。

**`$<TARGET_FILE:tgt>`**：求值为目标的**完整路径**（含目录、文件名、后缀），如 `/build/Debug/app.exe`。对可执行文件、共享库、静态库均可用。

```cmake
add_custom_command(TARGET app POST_BUILD
  COMMAND ${CMAKE_COMMAND} -E echo "Built: $<TARGET_FILE:app>"
)
```

**`$<TARGET_FILE_NAME:tgt>`**：仅文件名（含后缀），如 `app.exe`、`libfoo.so`。

**`$<TARGET_FILE_DIR:tgt>`**：仅所在目录，如 `/build/Debug`。常用作拷贝目标目录。

```cmake
add_custom_command(TARGET app POST_BUILD
  COMMAND ${CMAKE_COMMAND} -E copy
          ${CMAKE_SOURCE_DIR}/config.ini $<TARGET_FILE_DIR:app>
)
```

> 相关家族还有 `$<TARGET_FILE_BASE_NAME:tgt>`（去掉前缀和后缀的基名）、`$<TARGET_FILE_PREFIX:tgt>`、`$<TARGET_FILE_SUFFIX:tgt>`，以及面向链接/运行时库的 `$<TARGET_LINKER_FILE:tgt>`、`$<TARGET_SONAME_FILE:tgt>`、`$<TARGET_PDB_FILE:tgt>` 等，命名规律一致。

**`$<TARGET_OBJECTS:tgt>`**：求值为某个 `OBJECT` 库的所有目标对象文件（`.o`/`.obj`）列表。用于把对象库的产物直接喂给链接或其它目标。

```cmake
add_library(objs OBJECT a.cpp b.cpp)
add_executable(app main.cpp $<TARGET_OBJECTS:objs>)
# 或在链接处使用：
# target_link_libraries(app PRIVATE $<TARGET_OBJECTS:objs>)
```

**`$<TARGET_PROPERTY:tgt,prop>`**：求值为目标 `tgt` 的属性 `prop` 的值（会沿接口依赖做传递性求值）。
还有省略目标的形态 **`$<TARGET_PROPERTY:prop>`**，表示"正在被处理的当前目标"的属性，仅在目标属性上下文中有效。

```cmake
# 把依赖项的 INCLUDE_DIRECTORIES 取出来拼成 -I 串
target_compile_options(app PRIVATE
  "-I$<JOIN:$<TARGET_PROPERTY:dep,INTERFACE_INCLUDE_DIRECTORIES>, -I>"
)
```

**`$<TARGET_NAME:tgt>`**：把 `tgt` 标记为"这是一个目标名"，主要用于 `install(EXPORT)` 等需要原样保留目标名（而非求值为路径）的场合。

**`$<TARGET_EXISTS:tgt>`**：目标 `tgt` 存在时为 `1`，否则 `0`。

```cmake
$<$<TARGET_EXISTS:OpenSSL::SSL>:HAVE_OPENSSL>
```

**`$<TARGET_NAME_IF_EXISTS:tgt>`**：目标存在则求值为目标名本身，否则为空串。常用于"可选链接"。

```cmake
target_link_libraries(app PRIVATE
  $<TARGET_NAME_IF_EXISTS:fast_math>
)
```

**`$<TARGET_GENEX_EVAL:tgt,expr>`**：在目标 `tgt` 的上下文中，对 `expr` 做**二次求值**。当某个属性的值本身又包含 genex（即 genex 的结果是另一段 genex）时需要它。

```cmake
set_property(TARGET foo PROPERTY
  CUSTOM_KEYS $<$<CONFIG:Debug>:FOO_EXTRA_THINGS>
)
add_custom_target(printFooKeys
  COMMAND ${CMAKE_COMMAND} -E
    echo $<TARGET_GENEX_EVAL:foo,$<TARGET_PROPERTY:foo,CUSTOM_KEYS>>
)
```

**`$<GENEX_EVAL:expr>`**：与上者类似，但在**当前**上下文（而非指定目标）中对 `expr` 做二次求值。

| 表达式 | 求值结果 |
|--------|----------|
| `$<TARGET_FILE:t>` | 完整路径（目录+文件名+后缀） |
| `$<TARGET_FILE_NAME:t>` | 文件名（含后缀） |
| `$<TARGET_FILE_DIR:t>` | 所在目录 |
| `$<TARGET_OBJECTS:t>` | OBJECT 库的对象文件列表 |
| `$<TARGET_PROPERTY:t,prop>` | 目标 t 的属性 prop（传递性求值） |
| `$<TARGET_PROPERTY:prop>` | 当前目标的属性 prop |
| `$<TARGET_NAME:t>` | 原样目标名（用于 export） |
| `$<TARGET_EXISTS:t>` | 0/1，目标是否存在 |
| `$<TARGET_NAME_IF_EXISTS:t>` | 存在则目标名，否则空串 |
| `$<TARGET_GENEX_EVAL:t,expr>` | 在 t 上下文二次求值 expr |
| `$<GENEX_EVAL:expr>` | 在当前上下文二次求值 expr |
| `$<TARGET_RUNTIME_DLLS:t>` | 运行时依赖的 DLL 列表（见 7.8，3.21+） |

## 7.6 字符串与列表变换

这类表达式对字符串/列表做纯文本变换。

**`$<LOWER_CASE:string>` / `$<UPPER_CASE:string>`**：转小写 / 转大写。

```cmake
file(GENERATE OUTPUT out.txt CONTENT "$<UPPER_CASE:$<CONFIG>>\n")
```

**`$<JOIN:list,glue>`**：用 `glue` 连接 `list`（分号分隔）的各元素。注意 `glue` 本身若需含分号要用转义（见 7.7）。

```cmake
# 把 a;b;c 变成 a, b, c
$<JOIN:a;b;c,$<COMMA> >
```

**`$<REMOVE_DUPLICATES:list>`**：去重，保留首次出现的顺序。

```cmake
$<REMOVE_DUPLICATES:a;b;a;c;b>   # → a;b;c
```

**`$<FILTER:list,INCLUDE|EXCLUDE,regex>`**：按正则 `regex` 保留（`INCLUDE`）或剔除（`EXCLUDE`）匹配项。

```cmake
# 只保留以 .cpp 结尾的项
$<FILTER:a.cpp;b.h;c.cpp,INCLUDE,\\.cpp$>
```

**`$<PATH:operation,path...>`**（3.24+）：路径处理家族，能力对应 `cmake_path` 命令；自 3.27 起多数操作的 `path` 参数可为路径列表。常用子操作：

| 子操作 | 含义 |
|--------|------|
| `$<PATH:GET_FILENAME,path...>` | 取文件名部分 |
| `$<PATH:GET_EXTENSION[,LAST_ONLY],path...>` | 取扩展名 |
| `$<PATH:GET_STEM[,LAST_ONLY],path...>` | 取去扩展名的主名 |
| `$<PATH:GET_PARENT_PATH,path...>` | 取父目录 |
| `$<PATH:GET_ROOT_NAME,path...>` | 取根名（如 `C:`） |
| `$<PATH:GET_ROOT_PATH,path...>` | 取根路径 |
| `$<PATH:GET_RELATIVE_PART,path...>` | 取相对部分 |
| `$<PATH:IS_ABSOLUTE,path>` | 是否绝对路径（0/1） |
| `$<PATH:NORMAL_PATH,path...>` | 规范化路径 |
| `$<PATH:RELATIVE_PATH,path,base>` | 求相对路径 |
| `$<PATH:ABSOLUTE_PATH[,NORMALIZE],path,base>` | 求绝对路径 |
| `$<PATH:CMAKE_PATH[,NORMALIZE],path>` | 转为 CMake 风格（正斜杠）路径 |
| `$<PATH:NATIVE_PATH[,NORMALIZE],path>` | 转为平台原生路径（4.0+ 新增） |

```cmake
# 取得目标产物的扩展名
file(GENERATE OUTPUT ext.txt
     CONTENT "$<PATH:GET_EXTENSION,$<TARGET_FILE:app>>\n")
```

**`$<PATH_EQUAL:path1,path2>`**：按路径语义（而非纯字符串）比较两个路径是否相等，相等为 `1`。

**`$<LIST:operation,list[,...]>`**（3.27+）：列表处理家族，能力对应 `list()` 命令。常用子操作：

| 子操作 | 含义 |
|--------|------|
| `$<LIST:LENGTH,list>` | 元素个数 |
| `$<LIST:GET,list,index...>` | 按下标取元素 |
| `$<LIST:JOIN,list,glue>` | 连接（同 `$<JOIN>`） |
| `$<LIST:SUBLIST,list,begin,length>` | 取子列表 |
| `$<LIST:FIND,list,value>` | 查找下标，未找到为 -1 |
| `$<LIST:APPEND,list,item...>` | 追加 |
| `$<LIST:PREPEND,list,item...>` | 前插 |
| `$<LIST:INSERT,list,index,item...>` | 指定位置插入 |
| `$<LIST:POP_BACK,list>` / `$<LIST:POP_FRONT,list>` | 去尾 / 去头 |
| `$<LIST:REMOVE_ITEM,list,value...>` | 按值删除 |
| `$<LIST:REMOVE_AT,list,index...>` | 按下标删除 |
| `$<LIST:REMOVE_DUPLICATES,list>` | 去重 |
| `$<LIST:FILTER,list,INCLUDE\|EXCLUDE,regex>` | 过滤 |
| `$<LIST:TRANSFORM,list,ACTION[...]>` | 变换（如 `PREPEND`/`APPEND`/`REPLACE`） |
| `$<LIST:REVERSE,list>` | 反转 |
| `$<LIST:SORT,list[,(COMPARE:..\|CASE:..\|ORDER:..)...]>` | 排序 |

`$<LIST:SORT>` 的选项：`COMPARE:` 取 `STRING`（字典序，默认）/`FILE_BASENAME`/`NATURAL`（含数字的自然序）；`CASE:` 取 `SENSITIVE`（默认）/`INSENSITIVE`；`ORDER:` 取 `ASCENDING`（默认）/`DESCENDING`。

```cmake
$<LIST:SORT,banana;Apple;cherry,CASE:INSENSITIVE,ORDER:DESCENDING>
# → cherry;banana;Apple
```

> `$<PATH:...>` 与 `$<LIST:...>` 是较新的能力，使用前请确认项目要求的最低 CMake 版本（分别为 3.24 与 3.27）满足；CMake 4.3.4 全部支持。

## 7.7 接口 / 输出与转义

### 7.7.1 构建树 vs 安装树：接口表达式

库的"使用要求"在**构建时**（直接 `add_subdirectory` 使用）和**安装后**（`find_package` 导入使用）往往路径不同。下面三个表达式专门表达这种差异，且它们只能用于目标的 `INTERFACE_*` / `PUBLIC` 使用要求中：

**`$<BUILD_INTERFACE:content>`**：仅当该目标在**同一构建树内**被使用（导出到构建树）时，展开为 `content`；被 `install(EXPORT)` 安装导出时为空串。

**`$<INSTALL_INTERFACE:content>`**：与上者相反，仅在**安装导出**时展开为 `content`，构建树内使用时为空串。其中的相对路径相对于安装前缀。

```cmake
target_include_directories(mylib PUBLIC
  $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>   # 构建时用源码树头文件
  $<INSTALL_INTERFACE:include>                             # 安装后用 <prefix>/include
)
```

**`$<BUILD_LOCAL_INTERFACE:content>`**：更细一档——仅当目标在**同一构建系统内**（同一次 CMake 生成）被使用时展开；即便导出到构建树（`export()`）给外部项目也为空。适合只想给"本工程内部"看的使用要求。

**`$<INSTALL_PREFIX>`**：在安装导出上下文中求值为安装前缀（`CMAKE_INSTALL_PREFIX`）。仅在 `INSTALL_INTERFACE` 等安装相关上下文有意义。

```cmake
target_include_directories(mylib INTERFACE
  $<INSTALL_INTERFACE:$<INSTALL_PREFIX>/include/extra>
)
```

### 7.7.2 链接相关输出

**`$<LINK_ONLY:content>`**：标记 `content` 仅参与**链接**，不作为其它使用要求传播（例如不把它当作编译期的 include/define 传递）。`target_link_libraries(... PRIVATE ...)` 内部即用它实现"私有链接不传递"。

```cmake
target_link_libraries(mylib INTERFACE $<LINK_ONLY:onlylinkdep>)
```

### 7.7.3 多配置下的命令配置

**`$<COMMAND_CONFIG:content>`** 与 **`$<CONFIG>` 的配合**：在交叉/多配置场景里，`add_custom_command` 的"命令本身所属配置"可能与"被构建目标的配置"不同（典型：构建期工具在 `Release` 跑，产物服务于 `Debug` 目标）。`$<COMMAND_CONFIG:...>` 让其中的配置类 genex 按"命令的配置"而非"目标的配置"求值。需要它的场景较少，遇到"自定义命令里 `$<CONFIG>` 取到的配置不对"时再考虑。

### 7.7.4 转义：把特殊字符喂进 genex

由于 `<`、`>`、`,`、`;` 在 genex 语法里有特殊含义，要表达它们的**字面量**需用专门的转义 genex：

| 转义表达式 | 展开为 | 用途 |
|------------|--------|------|
| `$<ANGLE-R>` | `>` | 在 genex 内部表达字面右尖括号（如头文件 `<cstddef>`） |
| `$<COMMA>` | `,` | 在参数里表达字面逗号 |
| `$<SEMICOLON>` | `;` | 表达字面分号，避免被当作列表分隔 |

```cmake
# 给 C++ 预编译头加系统头文件 <cstddef>：> 必须写成 $<ANGLE-R>
target_precompile_headers(mylib PRIVATE
  "$<$<COMPILE_LANGUAGE:CXX>:<cstddef$<ANGLE-R>>"
)

# 用 $<SEMICOLON> 防止生成的串被命令拆成多参数
add_custom_command(TARGET app POST_BUILD
  COMMAND ${CMAKE_COMMAND} -E echo "a$<SEMICOLON>b$<SEMICOLON>c"
)
```

## 7.8 典型应用场景

下面给出可直接套用的完整片段。

### 7.8.1 按配置区分优化 / 调试选项

```cmake
add_executable(app main.cpp)

target_compile_options(app PRIVATE
  $<$<CONFIG:Debug>:-O0 -g>
  $<$<CONFIG:Release>:-O3 -DNDEBUG>
  $<$<CONFIG:RelWithDebInfo>:-O2 -g>
)

target_compile_definitions(app PRIVATE
  $<$<CONFIG:Debug>:ENABLE_LOGGING ENABLE_ASSERTS>
)
```

### 7.8.2 BUILD_INTERFACE / INSTALL_INTERFACE 双路径头文件

这是编写可安装库的标准范式：构建时头文件在源码树，安装后在 `<prefix>/include`。

```cmake
add_library(mylib src/mylib.cpp)

target_include_directories(mylib PUBLIC
  $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
  $<INSTALL_INTERFACE:include>
)

install(TARGETS mylib EXPORT mylibTargets
  ARCHIVE DESTINATION lib
  LIBRARY DESTINATION lib
  RUNTIME DESTINATION bin
  INCLUDES DESTINATION include
)
install(DIRECTORY include/ DESTINATION include)
install(EXPORT mylibTargets
  FILE mylibTargets.cmake
  NAMESPACE mylib::
  DESTINATION lib/cmake/mylib
)
```

### 7.8.3 按编译器添加专属 flag

```cmake
add_library(core core.cpp)

target_compile_options(core PRIVATE
  $<$<CXX_COMPILER_ID:GNU,Clang,AppleClang>:-Wall -Wextra -Wpedantic>
  $<$<CXX_COMPILER_ID:MSVC>:/W4 /permissive->
  # 仅 GCC 13+ 启用新告警
  $<$<AND:$<CXX_COMPILER_ID:GNU>,$<VERSION_GREATER_EQUAL:$<CXX_COMPILER_VERSION>,13>>:-Wnrvo>
)
```

### 7.8.4 用 `$<TARGET_FILE:>` 在构建后拷贝产物

```cmake
add_executable(app main.cpp)

# 把可执行文件拷到统一的 dist 目录
add_custom_command(TARGET app POST_BUILD
  COMMAND ${CMAKE_COMMAND} -E make_directory ${CMAKE_BINARY_DIR}/dist
  COMMAND ${CMAKE_COMMAND} -E copy
          $<TARGET_FILE:app> ${CMAKE_BINARY_DIR}/dist/$<TARGET_FILE_NAME:app>
  COMMENT "Copying $<TARGET_FILE_NAME:app> to dist/"
)
```

### 7.8.5 Windows：拷贝运行时依赖 DLL（`$<TARGET_RUNTIME_DLLS:>`，3.21+）

`$<TARGET_RUNTIME_DLLS:tgt>` 求值为目标在运行时依赖的所有 DLL（来自其传递依赖中 `SHARED`/`MODULE` 目标）。非 DLL 平台上为空串。这是把依赖 DLL 拷到可执行文件旁的标准做法：

```cmake
add_executable(app main.cpp)
target_link_libraries(app PRIVATE foo::foo foo::bar)

add_custom_command(TARGET app POST_BUILD
  COMMAND ${CMAKE_COMMAND} -E copy_if_different
          $<TARGET_RUNTIME_DLLS:app> $<TARGET_FILE_DIR:app>
  COMMAND_EXPAND_LISTS          # 列表展开成多个参数，缺它会失败
)
```

> 注意：导入目标（imported target）只有在其 `IMPORTED_LOCATION` 指向真实 `.dll` 时才会被纳入；许多 Find 模块产出的 `UNKNOWN` 类型导入目标会被忽略。

## 7.9 如何调试生成器表达式

genex 的最大调试难点：它在配置期**看不见**结果，`message()` 只会打印字面的 `$<...>`。

### 7.9.1 用 `file(GENERATE)` 落盘查看

这是查看 genex 真实求值结果的**唯一可靠手段**。它在生成期为每个配置写一个文件：

```cmake
file(GENERATE
  OUTPUT "${CMAKE_BINARY_DIR}/genex-debug-$<CONFIG>.txt"
  CONTENT
"config        = $<CONFIG>
platform      = $<PLATFORM_ID>
cxx_compiler  = $<CXX_COMPILER_ID> $<CXX_COMPILER_VERSION>
target_file   = $<TARGET_FILE:app>
is_debug      = $<CONFIG:Debug>
")
```

执行 `cmake ..` 后，到构建目录查看 `genex-debug-Debug.txt`、`genex-debug-Release.txt` 等，即可看到每个配置下各表达式的真实展开值。

> `message()` 对 genex 无效——它在配置期运行，看到的永远是未求值的字面串。务必改用 `file(GENERATE)`。

### 7.9.2 常见报错与排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 构建文件里出现原样的 `$<...>` | 把 genex 放进了不支持它的命令（`message`/`set`/`string` 等） | 改用支持 genex 的目标命令或 `file(GENERATE)` |
| `Error evaluating generator expression ... Expression did not evaluate to a known generator expression` | 表达式拼写错误，或用了当前版本不存在的运算符 | 核对 `cmake-generator-expressions.7` 拼写与版本 |
| 条件分支恒不生效 | 误把 `$<condition:value>` 的 `condition` 写成了非 `0/1` 的串（如直接写 `${VAR}`） | 用 `$<BOOL:${VAR}>` 把变量转成 `0/1` |
| `add_custom_command` 里 DLL/对象列表被当成一个参数 | 缺 `COMMAND_EXPAND_LISTS` | 加上 `COMMAND_EXPAND_LISTS` |
| 引用目标处报"目标不存在" | 目标在生成期才被 genex 引用但从未定义 | 先 `add_*`/`find_package` 定义目标，或用 `$<TARGET_NAME_IF_EXISTS:>` |
| `;` 把参数意外拆开 | 字面分号被当列表分隔 | 用 `$<SEMICOLON>` 转义，或对参数加引号 |
| `,` / `>` 进不去字符串 | 它们是 genex 语法字符 | 分别用 `$<COMMA>` / `$<ANGLE-R>` |

## 本章小结

- 生成器表达式 `$<...>` 在**生成期**求值，能表达 `if()` 无法表达的"随配置/平台/编译器/目标而变"的值——这是它存在的根本理由，对多配置生成器尤为关键。
- 三种基本形态：变量查询 `$<NAME>`、操作 `$<OP:arg>`、条件展开 `$<condition:value>`，可任意嵌套，结果含分号时按列表展开（自定义命令需 `COMMAND_EXPAND_LISTS`）。
- 逻辑运算（`BOOL`/`AND`/`OR`/`NOT`/`IF`/`STREQUAL`/`EQUAL`/`VERSION_*`/`IN_LIST`）产出 `0`/`1`，作条件；查询表达式（`CONFIG`/`PLATFORM_ID`/`*_COMPILER_ID`/`COMPILE_LANGUAGE` 等）提供生成期信息。
- 目标表达式（`TARGET_FILE*`/`TARGET_OBJECTS`/`TARGET_PROPERTY`/`TARGET_RUNTIME_DLLS`/`GENEX_EVAL` 等）连接目标产物与自定义命令、安装。
- 字符串/列表变换（`UPPER_CASE`/`JOIN`/`FILTER`/`PATH`/`LIST`）做纯文本处理；接口表达式（`BUILD_INTERFACE`/`INSTALL_INTERFACE`/`LINK_ONLY`）支撑可安装库的双路径使用要求；特殊字符靠 `$<ANGLE-R>`/`$<COMMA>`/`$<SEMICOLON>` 转义。
- 调试唯一可靠手段是 `file(GENERATE)` 落盘查看；`message()` 对 genex 无效。
