# 第 05 章 · 变量、缓存与作用域

> 基准版本：CMake 4.3.4

变量是 CMake 语言的血液。它看似简单——`set` 写、`${}` 读——但 CMake 的变量系统藏着三套独立的命名空间（普通 / 缓存 / 环境）、一套精巧的遮蔽（shadow）求值规则，以及一套与 C/C++ 语言截然不同的作用域模型。绝大多数 CMake 初学者踩的坑，根源都在这三件事没分清：

- 我 `set` 了为什么子目录读不到？（→ 作用域）
- 我 `set` 了为什么 `-D` 一改它又变了？（→ 缓存遮蔽）
- 我在函数里 `set` 了为什么外面读不到？（→ 函数作用域 / `PARENT_SCOPE`）

本章把这三件事彻底讲透，并附上一份分类齐全的「内置变量大全」表格，作为日常查阅手册。

---

## 5.1 三类变量：存储、生命周期与可见性

CMake 里有三种完全独立的变量，它们存放在不同的地方，活在不同的时间尺度上：

| 类别 | 语法（写 / 读） | 存储位置 | 生命周期 | 可见性 |
| :--- | :--- | :--- | :--- | :--- |
| **普通变量** Normal | `set(X v)` / `${X}` | 内存中的当前作用域栈 | 单次 cmake 运行内，离开作用域即失效 | 当前作用域及其子作用域（拷贝传递） |
| **缓存变量** Cache | `set(X v CACHE ...)` / `${X}` | 构建目录下 `CMakeCache.txt` | 跨多次 cmake 运行持久化 | 全局（整个工程任意位置可见） |
| **环境变量** Env | `set(ENV{X} v)` / `$ENV{X}` | 当前 cmake 进程的环境块 | 仅当前进程，不写盘 | 全进程，但不传给构建阶段的子进程持久化 |

理解这张表，等于理解了本章一半的内容。下面逐类拆解。

### 5.1.1 普通变量（Normal Variables）

普通变量是最常用的一种。它存放在内存里，作用域是「目录 / 函数」级别（详见 5.5 节）。

```cmake
set(MY_NAME "Alice")        # 定义
message(STATUS "${MY_NAME}") # 读取 -> Alice
```

关键性质：

- **运行时短命**：cmake 进程结束，普通变量就没了。下次重新配置时全部从头来过。
- **拷贝式向下传递**：当用 `add_subdirectory()` 进入子目录、或调用 `function()` 时，CMake 会把当前所有普通变量**拷贝**一份给新作用域。子作用域里改它，**不会**影响父作用域（除非显式 `PARENT_SCOPE`）。
- **大小写敏感**：`MyVar` 与 `myvar` 是两个不同的变量。

### 5.1.2 缓存变量（Cache Variables）

缓存变量是写进 `CMakeCache.txt` 文件、能跨多次运行保留的「持久变量」。它是用户配置工程的主要入口——所有你在命令行用 `-D` 传进去的，或者在 `cmake-gui` / `ccmake` 里看到的勾选框、下拉框，本质都是缓存变量。

```cmake
set(BUILD_TESTS ON CACHE BOOL "是否构建测试")
```

关键性质：

- **持久化**：第一次 `cmake` 时写入 `CMakeCache.txt`，之后每次配置都从该文件读回，**不会**被脚本里同名的 `set(... CACHE ...)` 默认覆盖（除非加 `FORCE`，见 5.4.4）。
- **全局可见**：缓存没有作用域概念，工程任何一个 `CMakeLists.txt` 都能读到同一个缓存条目。
- **带类型与文档**：每个缓存条目都有类型（`BOOL`/`STRING`/...）和一句帮助文本，供 GUI 渲染合适的控件。
- **删缓存 = 删文件**：想彻底重置，删掉 `CMakeCache.txt`（或整个 build 目录）即可。

### 5.1.3 环境变量（Environment Variables）

环境变量通过 `$ENV{}` 访问，对应操作系统进程的环境块。

```cmake
message(STATUS "PATH = $ENV{PATH}")
set(ENV{CC} "/usr/bin/clang")   # 仅影响当前 cmake 进程
```

关键性质：

- **只活在当前进程**：`set(ENV{X} ...)` 改的是 cmake 自己的环境块，**不写盘**、**不影响**你 shell 里后续的命令。
- **读优先于改**：实践中 90% 的用法是读（`$ENV{HOME}`、`$ENV{VCPKG_ROOT}`），很少在脚本里改。
- **配置期 vs 构建期**：在配置期（cmake 运行时）`set(ENV{})` 设的值，**不一定**能传到构建期（make/ninja 调编译器时）。要给编译命令传环境，应该用 target 属性 / 工具链文件，而非 `set(ENV{})`。

> ⚠️ 三类变量同名时互不干扰：`set(X a)`（普通）、`set(X b CACHE STRING "")`（缓存）、`set(ENV{X} c)`（环境）是三个独立的东西。`${X}` 读普通/缓存（见下节遮蔽规则），`$ENV{X}` 读环境。

### 5.1.4 遮蔽（Shadow）求值规则：`${X}` 到底读到谁？

这是 CMake 最容易让人困惑、也是面试高频考点的规则。当一个**普通变量**和一个**缓存变量**同名时，`${X}` 的求值遵循：

> **普通变量遮蔽缓存变量。** 若当前作用域存在名为 `X` 的普通变量，`${X}` 取普通变量的值；否则才回退去取缓存里的 `X`。

```cmake
set(FOO "cache-val" CACHE STRING "")   # 缓存 FOO = cache-val
message(STATUS "${FOO}")               # -> cache-val（无同名普通变量，读缓存）

set(FOO "normal-val")                  # 定义同名普通变量
message(STATUS "${FOO}")               # -> normal-val（普通遮蔽了缓存！）

unset(FOO)                             # 删掉普通变量（不动缓存）
message(STATUS "${FOO}")               # -> cache-val（遮蔽消失，重新看见缓存）
```

由此引出几条极其重要的实战推论：

1. **`set(X v CACHE ...)` 不会删除同名普通变量。** 如果之前作用域里已有普通 `X`，即便你设了缓存，`${X}` 仍读到老的普通值——这正是「我明明设了缓存却没生效」的头号原因。
2. **想强制让缓存值生效**，要么 `unset(X)` 清掉普通变量，要么用 `set(X v CACHE ... FORCE)` 并配合理解。
3. **显式读缓存**：CMake 4.x 提供 `$CACHE{X}` 语法，强制只读缓存条目、绕过遮蔽：
   ```cmake
   message(STATUS "always cache: $CACHE{FOO}")  # 永远是 cache-val
   ```

## 5.2 set() 完整形态

`set()` 是变量系统的总入口，按操作目标不同有四大形态。

### 5.2.1 普通变量：`set(<var> <value>...)`

```cmake
set(<variable> <value>... [PARENT_SCOPE])
```

- 设置当前作用域的普通变量。
- 多个值会用分号 `;` 连接成一个 **list**（CMake 的 list 本质就是分号分隔的字符串）：
  ```cmake
  set(SOURCES a.cpp b.cpp c.cpp)   # SOURCES = "a.cpp;b.cpp;c.cpp"
  set(GREETING "Hello World")       # 含空格要加引号，否则变成两个 list 元素
  ```
- **不给值即解除定义**（等价 `unset`）：
  ```cmake
  set(MY_VAR)        # MY_VAR 被 unset
  ```

### 5.2.2 缓存变量：`set(<var> <value> CACHE <type> <docstring> [FORCE])`

```cmake
set(<variable> <value>... CACHE <type> <docstring> [FORCE])
```

| 字段 | 说明 |
| :--- | :--- |
| `<value>` | 默认值（仅缓存中**不存在**该条目时写入；已存在则忽略，除非 `FORCE`） |
| `<type>` | 缓存类型，见 5.4 节：`BOOL`/`STRING`/`PATH`/`FILEPATH`/`INTERNAL` |
| `<docstring>` | 一句帮助文本，GUI 里鼠标悬停显示 |
| `FORCE` | 强制覆盖已存在的缓存条目（慎用，见 5.4.4） |

```cmake
set(INSTALL_PREFIX "/opt/myapp" CACHE PATH "安装根目录")
set(LOG_LEVEL "info" CACHE STRING "日志级别")
```

> **CMake 3.21+ 新形态** `set(CACHE{<var>} ...)`：4.x 文档中提供了更明确的 `set(CACHE{<variable>} [TYPE <type>] [HELP <helpstring>...] [FORCE] VALUE [<value>...])` 写法，可单独修改已有缓存条目的值/类型/文档而不必重复整套参数。日常仍以经典 `set(... CACHE ...)` 为主。

### 5.2.3 写父作用域：`set(<var> <value> PARENT_SCOPE)`

把普通变量的值写到**上一层**作用域（父目录或调用此函数的地方）。这是函数「返回值」的经典手段：

```cmake
function(get_full_name first last out_var)
  set(${out_var} "${first} ${last}" PARENT_SCOPE)   # 写回调用者作用域
endfunction()

get_full_name(Ada Lovelace full)
message(STATUS "${full}")   # -> Ada Lovelace
```

注意细节：

- `PARENT_SCOPE` 只影响**父**作用域，**不影响**当前作用域。下面这段里，`X` 在函数内部读仍是旧值：
  ```cmake
  function(demo)
    set(X new PARENT_SCOPE)
    message(STATUS "inside: ${X}")   # 注意：当前作用域并没被改！
  endfunction()
  ```
- 它只跨**一层**。要穿透多层 block，请用 `return(PROPAGATE)`（见 5.5.4）。

### 5.2.4 环境变量：`set(ENV{<var>} <value>)`

```cmake
set(ENV{<variable>} [<value>])
```

```cmake
set(ENV{LANG} "C")        # 设置（仅当前进程）
set(ENV{LANG})            # 不给值 = 从环境中删除该变量
```

### 5.2.5 unset() 各形态

`unset()` 是 `set()` 的反操作，同样区分三类目标：

| 形态 | 作用 |
| :--- | :--- |
| `unset(<var>)` | 解除当前作用域的**普通变量** |
| `unset(<var> PARENT_SCOPE)` | 解除**父作用域**的普通变量 |
| `unset(<var> CACHE)` | 从缓存中**删除**该条目 |
| `unset(ENV{<var>})` | 删除**环境变量**（等价 `set(ENV{<var>})`） |

```cmake
unset(TEMP_VAR)              # 删普通变量
unset(OLD_OPTION CACHE)     # 删缓存条目
unset(ENV{PROXY})           # 删环境变量
```

## 5.3 option()：布尔开关

当你只需要一个「开 / 关」的用户选项时，`option()` 比手写 `set(... CACHE BOOL ...)` 更简洁、语义更清晰。

```cmake
option(<variable> "<help_text>" [value])
```

- `value` 省略时默认为 `OFF`。
- 它本质上等价于创建一个 `BOOL` 类型的缓存变量：

```cmake
option(BUILD_TESTING "是否构建单元测试" ON)
# 大致等价于：
set(BUILD_TESTING ON CACHE BOOL "是否构建单元测试")
```

使用：

```cmake
option(USE_OPENMP "启用 OpenMP 并行" OFF)

if(USE_OPENMP)
  find_package(OpenMP REQUIRED)
  target_link_libraries(myapp PRIVATE OpenMP::OpenMP_CXX)
endif()
```

命令行覆盖：

```bash
cmake -S . -B build -DUSE_OPENMP=ON
```

### 5.3.1 option() vs set(... CACHE BOOL) 的取舍

| 维度 | `option()` | `set(... CACHE BOOL ...)` |
| :--- | :--- | :--- |
| 简洁度 | 高，专为布尔设计 | 啰嗦一点 |
| 默认值 | 仅 `ON`/`OFF` | 任意 truthy/falsy 值 |
| 可读性 | 一眼看出是「开关」 | 需读类型才知道是布尔 |
| 推荐场景 | 纯粹的功能开关 | 需要 `FORCE`、或非标准布尔字面量时 |

经验法则：**布尔开关一律用 `option()`**，其余类型才用 `set(... CACHE ...)`。

### 5.3.2 依赖型开关 CMakeDependentOption

有时某个选项只有在另一个选项打开时才有意义。例如「构建 GUI 测试」只在「构建 GUI」为真时才该出现。标准模块 `CMakeDependentOption` 提供了这个能力：

```cmake
include(CMakeDependentOption)

option(BUILD_GUI "构建图形界面" ON)
cmake_dependent_option(
  BUILD_GUI_TESTS "构建 GUI 测试"      # 变量名 + 帮助
  ON                                   # 满足依赖时的默认值
  "BUILD_GUI"                          # 依赖条件
  OFF                                  # 不满足依赖时的强制值
)
```

当 `BUILD_GUI` 为 `OFF` 时，`BUILD_GUI_TESTS` 被强制为 `OFF` 且在 GUI 中隐藏；只有 `BUILD_GUI` 为 `ON` 时它才作为可配置选项出现。

> 📎 `cmake_dependent_option` 的完整语法、多条件依赖与坑点，详见 **[[42.Cmake/17 - 模块与常用工具模块.md|第 17 章 · 模块与常用工具模块]]**。

## 5.4 CACHE 变量类型

缓存条目的值**本质都是字符串**，但每个条目带一个 `TYPE` 属性，作为 GUI 渲染控件的提示。CMake 4.x 中合法的类型如下：

| 类型 | 含义 | GUI 表现 |
| :--- | :--- | :--- |
| **BOOL** | 布尔 ON/OFF | 复选框 |
| **STRING** | 通用字符串 | 文本输入框（可配合 `STRINGS` 属性变下拉框） |
| **PATH** | 目录路径 | 目录选择对话框 |
| **FILEPATH** | 文件路径 | 文件选择对话框 |
| **INTERNAL** | 内部存储，**完全不在 GUI 显示** | 不显示（隐式带 `FORCE` 语义） |
| `STATIC` | 由 CMake 管理、用户勿改 | 不显示 |
| `UNINITIALIZED` | 类型尚未指定（如纯 `-DX=v` 不带类型时） | 一般显示为待定 |

> 类型只是「提示」——它不强制校验值的内容。`set(N "abc" CACHE BOOL "")` 不会报错，只是该值在布尔语境下会被当成假。

### 5.4.1 五种主类型逐一说明

**BOOL**：开关量。判定为真的字面量包括 `ON`/`TRUE`/`YES`/`1`/非零数；为假包括 `OFF`/`FALSE`/`NO`/`0`/空字符串/`NOTFOUND` 等。
```cmake
set(ENABLE_LTO OFF CACHE BOOL "链接期优化")
```

**STRING**：任意文本。最常用于枚举选择、版本号、自定义标识：
```cmake
set(CMAKE_BUILD_TYPE "Release" CACHE STRING "构建配置")
```

**PATH**：目录路径。GUI 弹出「选文件夹」对话框；CMake 会做路径规范化（统一斜杠等）：
```cmake
set(DATA_DIR "${CMAKE_SOURCE_DIR}/data" CACHE PATH "数据目录")
```

**FILEPATH**：单个文件路径。GUI 弹「选文件」对话框：
```cmake
set(CONFIG_FILE "" CACHE FILEPATH "配置文件路径")
```

**INTERNAL**：脚本内部使用的持久状态，**绝不**给用户看见。它**隐式带 FORCE**——每次都会覆盖。常用于缓存计算结果、记录上一次的检测值：
```cmake
set(_LAST_COMPILER "${CMAKE_CXX_COMPILER}" CACHE INTERNAL "上次使用的编译器")
```

### 5.4.2 STRINGS 属性：把字符串变成下拉枚举

`STRING` 类型默认是自由文本框。若想在 `cmake-gui` / `ccmake` 里给用户一个**下拉枚举**，用 `set_property` 给缓存条目加 `STRINGS` 属性：

```cmake
set(BUILD_VARIANT "Release" CACHE STRING "构建变体")
set_property(CACHE BUILD_VARIANT PROPERTY STRINGS
  "Debug" "Release" "RelWithDebInfo" "MinSizeRel")
```

这样 GUI 会渲染一个只含这四个选项的下拉框。注意：`STRINGS` 仅影响 GUI 显示，**不会**强制校验——命令行 `-DBUILD_VARIANT=Foobar` 仍可绕过它。要硬性约束，需自己写 `if(NOT ... IN_LIST ...)` 校验。

### 5.4.3 mark_as_advanced()：折叠高级选项

工程暴露的缓存变量一多，GUI 就会很乱。`mark_as_advanced()` 把不常改的条目标为「高级」，默认折叠，只有用户勾选「Advanced」才显示：

```cmake
mark_as_advanced(
  CMAKE_CXX_FLAGS_MINSIZEREL
  CMAKE_VERBOSE_MAKEFILE
  _LAST_COMPILER
)
```

可选 `FORCE` / `CLEAR` 关键字强制设置或清除高级标记。它纯粹影响显示，不改变变量的值或可用性。

### 5.4.4 -D 覆盖与 FORCE 语义

**命令行 `-D` 的优先级最高。** 在命令行用 `-DX=value` 设置的缓存条目，会先于 `CMakeLists.txt` 写入缓存。等脚本执行到 `set(X default CACHE ...)` 时，发现缓存已有 `X`，于是**跳过**默认值——这正是 `-D` 能覆盖脚本默认值的机制。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
```

| 场景 | 不带 FORCE | 带 FORCE |
| :--- | :--- | :--- |
| 缓存中条目**不存在** | 写入默认值 | 写入默认值 |
| 缓存中条目**已存在**（含 `-D` 设的） | **跳过**，保留旧值 | **覆盖**为新值 |

`FORCE` 的危险在于：它会**无视用户的 `-D` 选择**，每次配置都重置回脚本里的值。

```cmake
# ❌ 反模式：用户的 -DCMAKE_BUILD_TYPE 会被强行覆盖，永远改不动
set(CMAKE_BUILD_TYPE "Release" CACHE STRING "" FORCE)

# ✅ 推荐：仅在用户「未指定」时给默认值，尊重 -D
if(NOT CMAKE_BUILD_TYPE AND NOT CMAKE_CONFIGURATION_TYPES)
  set(CMAKE_BUILD_TYPE "Release" CACHE STRING "默认构建类型" FORCE)
endif()
```

> 经验：**除非你在写「初始化默认值」的兜底逻辑，否则不要随手加 FORCE。** 它是绝大多数「我命令行改了缓存却不生效」问题的元凶。

## 5.5 作用域规则

CMake 的作用域模型与 C/C++ 不同，必须单独理解。共有三类会创建新作用域的边界：**目录**、**函数**、**block**。（注意：`macro()` **不**创建新作用域，它在调用者作用域里展开。）

### 5.5.1 目录作用域（add_subdirectory）

当 `add_subdirectory(sub)` 进入子目录时：

- CMake 创建一个新的目录作用域，并把父作用域当前所有普通变量**拷贝**一份过去。
- 子目录里**新增 / 修改**普通变量，**不影响**父目录（除非 `PARENT_SCOPE`）。
- 反过来，父目录在 `add_subdirectory` **之后**才定义的变量，子目录看不到（因为拷贝发生在进入的那一刻）。

```cmake
# 顶层 CMakeLists.txt
set(SHARED_FLAG "from-parent")
add_subdirectory(child)        # child 拿到 SHARED_FLAG 的拷贝
message(STATUS "${CHILD_OUT}") # 需 child 用 PARENT_SCOPE 写回才读得到

# child/CMakeLists.txt
message(STATUS "${SHARED_FLAG}")        # -> from-parent（拷贝可见）
set(SHARED_FLAG "changed-in-child")     # 只改本地拷贝，不影响顶层
set(CHILD_OUT "hello" PARENT_SCOPE)     # 显式写回父作用域
```

### 5.5.2 函数作用域（function）

`function()` 调用时同样创建新作用域，行为类似目录：

- 进入函数时拷贝调用者的普通变量。
- 函数内 `set` 的变量是局部的，函数返回即消失。
- 要「返回」值，用 `set(... PARENT_SCOPE)` 或 `return(PROPAGATE)`。

函数还会自动提供一组特殊变量：`ARGC`（参数个数）、`ARGV`（全部参数）、`ARGN`（命名参数之外的多余参数）、`ARGV0`/`ARGV1`...（按位置）。

```cmake
function(sum out a b)
  math(EXPR result "${a} + ${b}")
  set(${out} "${result}" PARENT_SCOPE)
endfunction()

sum(total 3 4)
message(STATUS "${total}")   # -> 7
```

> 对比：`macro()` 不建作用域，宏体里的 `set` 直接作用在调用者身上，且参数是「文本替换」而非真正变量——`macro` 的坑较多，第 16 章详述。

### 5.5.3 PARENT_SCOPE 回顾

`PARENT_SCOPE` 是跨越**单层**作用域边界写值的工具。它适用于目录边界和函数边界，但**只跨一层**。如果当前在「函数内的 block 内」，`set(X v PARENT_SCOPE)` 只能跨出 block，到不了函数的调用者——这正是 `return(PROPAGATE)` 要解决的问题。

### 5.5.4 block() / endblock()（3.25+）与 return(PROPAGATE)

**block()**（CMake 3.25 引入）创建一段拥有独立变量和/或策略作用域的命令块。块内的变量改动默认在 `endblock()` 时丢弃，除非用 `PROPAGATE` 显式带出。

```cmake
block([SCOPE_FOR [POLICIES] [VARIABLES]] [PROPAGATE <var-name>...])
  <commands>
endblock()
```

- `SCOPE_FOR VARIABLES`：新建变量作用域；`SCOPE_FOR POLICIES`：新建策略作用域（等价 `cmake_policy(PUSH/POP)` 的自动配对）。
- 不写 `SCOPE_FOR` 时，等价于 `block(SCOPE_FOR VARIABLES POLICIES)`，两种作用域都建。
- `PROPAGATE <vars...>`：把列出的变量在退出块时同步回父作用域（等价对每个变量做 `set/unset(... PARENT_SCOPE)`）；**仅当创建了变量作用域时才允许**，否则报错。

```cmake
set(var1 "INIT1")
set(var2 "INIT2")
set(var3 "INIT3")

block(PROPAGATE var1 var2)
  set(var1 "VALUE1")
  unset(var2)
  set(var3 "VALUE3")     # var3 不在 PROPAGATE 列表里
endblock()
# 退出后：var1 = VALUE1，var2 已被 unset，var3 仍为 INIT3（块内改动被丢弃）
```

block 的另一价值是**临时隔离**：在循环或大段逻辑里建一个块，里面随便设临时变量，退出时自动清理，不污染外层。块在 `foreach()`/`while()` 内时，`break()`/`continue()` 仍可在块内使用。

**return(PROPAGATE)** 解决「穿透多层 block 一步到位返回」的难题：

```cmake
return([PROPAGATE <var-name>...])
```

`return` 会把指定变量**穿过所有包裹它的 block 作用域**带出去。在函数内，它确保变量传到**函数的调用者**，无论中间隔了多少层 block；不在函数内时，则传到父文件 / 父目录作用域。

```cmake
function(multi_scopes result_var1 result_var2)
  block(SCOPE_FOR VARIABLES)
    # 下面这样只能跨出当前 block，到不了函数调用者：
    #   set(${result_var1} "new-value" PARENT_SCOPE)
    # 用 return(PROPAGATE) 一步穿透 block 直达调用者：
    set(${result_var1} "new-value")
    unset(${result_var2})
    return(PROPAGATE ${result_var1} ${result_var2})
  endblock()
endfunction()

set(var1 "some-value")
set(var2 "another-value")
multi_scopes(var1 var2)
# 现在 var1 = "new-value"，var2 已 unset
```

> ⚠️ 跨目录传播的微妙边界：`block()` **本身**不把传播限制在当前文件，但**父目录作用域里的** `block()` 会阻止传播继续向上。换言之，传播会一直冒泡到「最近的、由父目录建立的 block 作用域」为止。

### 5.5.5 缓存与全局可见

与上述所有「有作用域」的普通变量相反，**缓存变量是全局的、无作用域的**。在任何目录、任何函数、任何 block 里 `set(X v CACHE ...)`，整个工程都能用 `${X}`（在无同名普通变量遮蔽的前提下）读到同一个值。这也是缓存常被用作「跨目录共享配置」的原因——但要警惕全局命名污染，给缓存变量加项目前缀（如 `MYPROJ_ENABLE_X`）是好习惯。

| 作用域类型 | 创建者 | 向下传递 | 向上写回手段 |
| :--- | :--- | :--- | :--- |
| 目录 | `add_subdirectory()` | 拷贝父变量 | `set(... PARENT_SCOPE)` / `return(PROPAGATE)` |
| 函数 | `function()` | 拷贝调用者变量 | `set(... PARENT_SCOPE)` / `return(PROPAGATE)` |
| 块 | `block()` | 继承外层（不拷贝，直接可见外层） | `block(PROPAGATE)` / `return(PROPAGATE)` |
| 宏 | `macro()` | **不建作用域**（就地展开） | 直接改调用者变量 |
| 缓存 | `set(CACHE)` / `option()` | 全局可见 | 全局，无需写回 |

## 5.6 常用内置变量大全

CMake 预定义了数百个变量。下面按用途分类，列出日常最常用的一批，每个一句话说明。完整清单见官方 `cmake-variables(7)`。

### 5.6.1 路径相关

| 变量 | 说明 |
| :--- | :--- |
| **CMAKE_SOURCE_DIR** | 顶层源码目录（最外层 `CMakeLists.txt` 所在），全工程唯一 |
| **CMAKE_BINARY_DIR** | 顶层构建目录（运行 cmake 时 `-B` 指定的根），全工程唯一 |
| **CMAKE_CURRENT_SOURCE_DIR** | 当前正在处理的 `CMakeLists.txt` 所在源码目录 |
| **CMAKE_CURRENT_BINARY_DIR** | 当前源码目录对应的构建输出目录 |
| **PROJECT_SOURCE_DIR** | 最近一次 `project()` 所在目录的源码路径 |
| **PROJECT_BINARY_DIR** | 最近一次 `project()` 对应的构建目录路径 |
| **CMAKE_CURRENT_LIST_DIR** | 当前正在解析的 `.cmake`/`CMakeLists.txt` 文件所在目录（在 include 的脚本里更准确） |
| **CMAKE_CURRENT_LIST_FILE** | 当前正在解析的文件的完整路径 |
| **CMAKE_CURRENT_FUNCTION_LIST_DIR** | 当前执行的 `function()` **定义所在**文件的目录（写可复用模块时定位资源极有用） |

> 易混点：`CMAKE_CURRENT_SOURCE_DIR` 指「当前目录」，`CMAKE_CURRENT_LIST_DIR` 指「当前文件」。在被 `include()` 进来的 `.cmake` 里，前者仍是调用方的目录，后者才是该脚本自身的目录。

### 5.6.2 项目相关

| 变量 | 说明 |
| :--- | :--- |
| **PROJECT_NAME** | 最近一次 `project()` 设定的项目名 |
| **PROJECT_VERSION** | 最近一次 `project(... VERSION x.y.z.t)` 的完整版本号 |
| **PROJECT_VERSION_MAJOR** | 主版本号 |
| **PROJECT_VERSION_MINOR** | 次版本号 |
| **PROJECT_VERSION_PATCH** | 补丁版本号 |
| **PROJECT_VERSION_TWEAK** | 微调版本号（第四段） |
| **CMAKE_PROJECT_NAME** | **顶层** `project()` 的名字（与 `PROJECT_NAME` 不同：后者随子项目变，前者恒为最外层） |
| **PROJECT_IS_TOP_LEVEL** | 布尔，当前 `project()` 是否为顶层（用于库「既可独立构建又可被 add_subdirectory 嵌入」的判断） |

```cmake
project(MyLib VERSION 2.4.1 LANGUAGES CXX)
message(STATUS "${PROJECT_NAME} v${PROJECT_VERSION}")  # MyLib v2.4.1
message(STATUS "major=${PROJECT_VERSION_MAJOR}")        # major=2

if(PROJECT_IS_TOP_LEVEL)
  # 仅当独立构建时才开测试、装东西
  enable_testing()
endif()
```

### 5.6.3 系统 / 平台判定

| 变量 | 说明 |
| :--- | :--- |
| **CMAKE_SYSTEM_NAME** | 目标系统名（`Linux`/`Windows`/`Darwin`/...），交叉编译时为目标平台 |
| **CMAKE_SYSTEM_PROCESSOR** | 目标 CPU 架构（`x86_64`/`aarch64`/...） |
| **WIN32** | 目标为 Windows（含 64 位！历史命名，非「仅 32 位」）时为真 |
| **UNIX** | 目标为类 Unix（Linux/macOS/BSD 等）时为真 |
| **APPLE** | 目标为 Apple 平台（macOS/iOS 等）时为真 |
| **LINUX** | 目标为 Linux 时为真（CMake 3.25+ 新增的便捷变量） |
| **MSVC** | 使用 MSVC 系列编译器（含 clang-cl）时为真 |
| **MINGW** | 使用 MinGW 工具链时为真 |
| **CMAKE_HOST_SYSTEM_NAME** | **宿主机**系统名（运行 cmake 的机器，交叉编译时与目标区分） |
| **CMAKE_SIZEOF_VOID_P** | 指针字节数：`8` 表示 64 位目标，`4` 表示 32 位 |

```cmake
if(WIN32)
  target_compile_definitions(app PRIVATE PLATFORM_WINDOWS)
elseif(APPLE)
  target_compile_definitions(app PRIVATE PLATFORM_MACOS)
elseif(LINUX)
  target_compile_definitions(app PRIVATE PLATFORM_LINUX)
endif()

if(CMAKE_SIZEOF_VOID_P EQUAL 8)
  message(STATUS "64-bit build")
endif()
```

> 注意 `WIN32`/`UNIX`/`APPLE` 描述的是**目标平台**，交叉编译时它们随 `CMAKE_SYSTEM_NAME` 走，不一定等于宿主机。判断宿主机用 `CMAKE_HOST_WIN32` / `CMAKE_HOST_UNIX` / `CMAKE_HOST_APPLE`。

### 5.6.4 编译 / 语言

| 变量 | 说明 |
| :--- | :--- |
| **CMAKE_CXX_COMPILER** | C++ 编译器可执行文件的完整路径 |
| **CMAKE_CXX_COMPILER_ID** | C++ 编译器标识（`GNU`/`Clang`/`MSVC`/`AppleClang`/`IntelLLVM`...） |
| **CMAKE_CXX_COMPILER_VERSION** | C++ 编译器版本号 |
| **CMAKE_C_COMPILER** | C 编译器可执行文件路径 |
| **CMAKE_CXX_STANDARD** | C++ 标准版本（`11`/`14`/`17`/`20`/`23`/`26`），作为新建 target 的默认值 |
| **CMAKE_BUILD_TYPE** | 单配置生成器（Make/Ninja）的构建类型（`Debug`/`Release`/`RelWithDebInfo`/`MinSizeRel`） |
| **CMAKE_CXX_FLAGS** | 所有配置通用的 C++ 编译选项 |
| **CMAKE_CXX_FLAGS_DEBUG** | Debug 配置追加的 C++ 选项（如 `-g`） |
| **CMAKE_CXX_FLAGS_RELEASE** | Release 配置追加的 C++ 选项（如 `-O3 -DNDEBUG`） |
| **CMAKE_<LANG>_FLAGS** | 任意语言的编译选项通式（`<LANG>` = `C`/`CXX`/`Fortran`/`CUDA`...） |

```cmake
message(STATUS "Compiler: ${CMAKE_CXX_COMPILER_ID} ${CMAKE_CXX_COMPILER_VERSION}")

if(CMAKE_CXX_COMPILER_ID STREQUAL "GNU"
   AND CMAKE_CXX_COMPILER_VERSION VERSION_GREATER_EQUAL 13)
  # GCC 13+ 才启用某特性
endif()
```

> ⚠️ `CMAKE_BUILD_TYPE` 对多配置生成器（Visual Studio、Xcode、Ninja Multi-Config）**无效**——它们在构建期用 `--config` 选配置，配置期该变量为空。判断时常配合 `CMAKE_CONFIGURATION_TYPES`。
> ⚠️ 现代 CMake 推荐**少直接动 `CMAKE_CXX_FLAGS` 这类全局变量**，优先用 target 级的 `target_compile_options()` / `target_compile_features()`（见第 04 章）。

### 5.6.5 构建控制

| 变量 | 说明 |
| :--- | :--- |
| **BUILD_SHARED_LIBS** | 全局开关：`add_library()` 不指定类型时，默认建动态库（`ON`）还是静态库（`OFF`） |
| **CMAKE_INSTALL_PREFIX** | `install()` 的安装根前缀（Unix 默认 `/usr/local`，Windows 默认 `C:/Program Files/...`） |
| **CMAKE_RUNTIME_OUTPUT_DIRECTORY** | 可执行文件（及 Windows 上 DLL）的输出目录 |
| **CMAKE_LIBRARY_OUTPUT_DIRECTORY** | 动态库 / 模块库的输出目录（Unix `.so`/`.dylib`） |
| **CMAKE_ARCHIVE_OUTPUT_DIRECTORY** | 静态库及 Windows 导入库（`.a`/`.lib`）的输出目录 |
| **CMAKE_GENERATOR** | 当前使用的生成器名（`Ninja`/`Unix Makefiles`/`Visual Studio 17 2022`...） |
| **CMAKE_EXPORT_COMPILE_COMMANDS** | 置 `ON` 时生成 `compile_commands.json`（供 clangd/clang-tidy 等工具用） |
| **CMAKE_PREFIX_PATH** | `find_package()`/`find_library()` 等的额外搜索根列表 |
| **CMAKE_MODULE_PATH** | `include()` 和 `find_package()`（Module 模式）查找 `.cmake` 模块的额外路径列表 |

```cmake
set(BUILD_SHARED_LIBS ON)                     # 默认建动态库
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)         # 给 LSP 用
list(APPEND CMAKE_MODULE_PATH "${CMAKE_SOURCE_DIR}/cmake")

set(CMAKE_RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/bin")
set(CMAKE_LIBRARY_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/lib")
set(CMAKE_ARCHIVE_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/lib")
```

### 5.6.6 版本信息

| 变量 | 说明 |
| :--- | :--- |
| **CMAKE_VERSION** | 当前运行的 CMake 完整版本号（如 `4.3.4`） |
| **CMAKE_MINIMUM_REQUIRED_VERSION** | `cmake_minimum_required()` 中声明的最低版本 |
| **CMAKE_COMMAND** | `cmake` 可执行文件自身的完整路径（在自定义命令里调用 `cmake -E` 时常用） |

```cmake
message(STATUS "Running CMake ${CMAKE_VERSION}")

if(CMAKE_VERSION VERSION_GREATER_EQUAL 3.25)
  # 可以放心用 block()/LINUX 等较新特性

# 跨平台复制文件：借 cmake -E，不依赖 shell
add_custom_command(TARGET app POST_BUILD
```

## 5.7 环境变量

环境变量用 `$ENV{<name>}` 读取，对应运行 cmake 时的进程环境。

```cmake
if(DEFINED ENV{VCPKG_ROOT})
  set(CMAKE_TOOLCHAIN_FILE "$ENV{VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake")
endif()
```

> 判断环境变量是否存在用 `if(DEFINED ENV{X})`；判断普通/缓存变量存在用 `if(DEFINED X)`。

### 5.7.1 常见环境变量

| 环境变量 | 作用 |
| :--- | :--- |
| **CC** | 指定默认 C 编译器（首次配置、未显式设 `CMAKE_C_COMPILER` 时被读取） |
| **CXX** | 指定默认 C++ 编译器 |
| **CMAKE_PREFIX_PATH** | 与同名缓存变量叠加，扩充 `find_package()` 的搜索根（分隔符：Unix `:`、Windows `;`） |
| **CMAKE_GENERATOR** | 指定默认生成器，省去每次敲 `-G` |
| **CMAKE_BUILD_PARALLEL_LEVEL** | `cmake --build` 的默认并行任务数（等价于不显式传 `-j N`） |

```bash
# 用环境变量影响配置（典型在 CI / Dockerfile 里）
export CC=clang
export CXX=clang++
export CMAKE_GENERATOR=Ninja
export CMAKE_BUILD_PARALLEL_LEVEL=8

cmake -S . -B build      # 自动用 clang++ + Ninja
cmake --build build      # 自动 8 路并行
```

> ⚠️ `CC`/`CXX` **只在第一次配置（缓存为空）时**被读取。一旦 `CMAKE_CXX_COMPILER` 写进缓存，之后改环境变量无效——必须删缓存重配，或显式 `-DCMAKE_CXX_COMPILER=...`。这是「换了 CXX 却没换成编译器」的常见坑。

## 本章小结

- **三类变量泾渭分明**：普通变量（有作用域、运行时短命）、缓存变量（全局、跨次持久、带类型）、环境变量（`$ENV{}`、仅当前进程）。三者同名互不干扰。
- **遮蔽规则是核心**：`${X}` 优先读同名普通变量，没有才回退缓存。「设了缓存却不生效」九成是被普通变量遮蔽，或缓存里已有旧值未加 `FORCE`。需要无视遮蔽时用 `$CACHE{X}`。
- **set() 四形态**：普通、`CACHE`、`PARENT_SCOPE`、`ENV{}`；`unset()` 对应四种解除。布尔开关首选 `option()`，依赖型开关用 `CMakeDependentOption`。
- **缓存类型** `BOOL/STRING/PATH/FILEPATH/INTERNAL`：配合 `STRINGS` 属性做下拉、`mark_as_advanced()` 折叠高级项；`-D` 优先级最高，**`FORCE` 会无视用户 `-D`，慎用**。
- **作用域三边界**：目录、函数（拷贝父变量，`PARENT_SCOPE` 写回一层）、`block()`（3.25+，隔离临时变量，`PROPAGATE` 带出）；`return(PROPAGATE)` 可穿透多层 block 一步返回；`macro()` 不建作用域；缓存全局可见。
- **内置变量大全**已按路径 / 项目 / 平台 / 编译 / 构建控制 / 版本六类列表，可作速查手册。环境变量中 `CC`/`CXX` 仅首次配置生效，务必记牢。
