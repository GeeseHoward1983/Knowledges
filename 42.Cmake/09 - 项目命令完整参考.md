# 第 09 章 · 项目命令完整参考

> 基准版本：CMake 4.3.4

本章是**字典式参考章**，逐条覆盖 CMake 的**项目命令（Project Commands）**。这类命令**只在拥有构建系统的项目中有效**——即 `CMakeLists.txt` 被 `cmake` 配置生成构建系统的场景；它们**不能用于 `cmake -P` 脚本模式**（脚本模式可用命令见 [[42.Cmake/08 - 脚本命令完整参考.md]]）。

阅读约定：

- 签名中 `<name>` 表示必填占位，`[OPTION]` 表示可选，`...` 表示可重复，`A | B` 表示二选一，`{A,B}` 表示枚举集合。
- 已在其他章详解的命令（`target_*` 全家、`install` / `export`、`add_test`），本章给**完整签名速查 + 链接**，不重复展开原理。

## 一、项目与子目录

### project

声明项目，设置项目名、版本、描述、主页与启用的语言。每个 `CMakeLists.txt` 顶层应在 `cmake_minimum_required()` 之后**尽早**调用一次；若顶层缺失，CMake 会隐式生成一个（默认启用 C、CXX）。

```cmake
project(<PROJECT-NAME>
        [VERSION <major>[.<minor>[.<patch>[.<tweak>]]]]
        [DESCRIPTION <project-description-string>]
        [HOMEPAGE_URL <url-string>]
        [LANGUAGES <language-name>...])

# 仅设置名字（向后兼容旧形式）
project(<PROJECT-NAME> [<language-name>...])
```

**参数**：详解

- `<PROJECT-NAME>`：项目名，写入 `PROJECT_NAME`、`<PROJECT-NAME>_*` 及（若为顶层）`CMAKE_PROJECT_NAME`。
- `VERSION`：版本号，分量填充 `PROJECT_VERSION`、`PROJECT_VERSION_MAJOR/MINOR/PATCH/TWEAK` 以及 `<PROJECT-NAME>_VERSION*`。未给的分量为空字符串。
- `DESCRIPTION` / `HOMEPAGE_URL`：填充 `PROJECT_DESCRIPTION` / `PROJECT_HOMEPAGE_URL`，被 CPack、`configure_package_config_file()` 等用作元数据默认值。
- `LANGUAGES`：要启用的语言（如 `C CXX CUDA CSharp OBJC OBJCXX Fortran HIP ASM ISPC Swift`）。**默认（完全不写该关键字）启用 `C` 和 `CXX`**；写 `LANGUAGES NONE` 或 `NONE` 则不启用任何语言（纯打包/脚本聚合工程常用）。启用某语言时 CMake 立即探测对应编译器。

```cmake
cmake_minimum_required(VERSION 3.21)
project(MyApp
        VERSION 1.4.2
        DESCRIPTION "示例应用"
        HOMEPAGE_URL "https://example.org/myapp"
        LANGUAGES CXX)
message(STATUS "版本: ${PROJECT_VERSION} (主版本 ${PROJECT_VERSION_MAJOR})")
```

### add_subdirectory

将一个子目录加入构建。CMake 会进入该目录处理其中的 `CMakeLists.txt`，子目录构成独立的变量作用域（继承父作用域变量的副本）。

```cmake
add_subdirectory(<source_dir> [<binary_dir>]
                 [EXCLUDE_FROM_ALL] [SYSTEM])
```

**参数**：详解

- `<source_dir>`：含 `CMakeLists.txt` 的源码目录，相对当前 `CMAKE_CURRENT_SOURCE_DIR`，也可为绝对路径。
- `<binary_dir>`：放置该子目录构建产物的目录；当 `<source_dir>` 在当前源码树**之外**时**必须**显式给出。
- `EXCLUDE_FROM_ALL`：子目录中的目标默认不纳入 `all` 目标，仅被显式依赖时才构建（常用于可选示例、第三方库）。
- `SYSTEM`（3.25+）：将该子目录目标的 `INTERFACE_INCLUDE_DIRECTORIES` 标记为系统头文件目录（抑制其告警）。

```cmake
add_subdirectory(libs/foo)
add_subdirectory(examples EXCLUDE_FROM_ALL)
```

> 相关：处理顺序内可用 `return(PROPAGATE ...)` 回传变量；子目录与函数作用域规则参见 [[42.Cmake/05 - 变量、缓存与作用域.md]]。

### include（项目内）

在**当前作用域**载入并执行另一个 `.cmake` 文件或 CMake 模块（不创建新作用域，与 `add_subdirectory` 的本质区别）。此处仅列项目内常见用法，完整语义见脚本命令章。

```cmake
include(<file|module>
        [OPTIONAL] [RESULT_VARIABLE <var>] [NO_POLICY_SCOPE])
```

**参数**：详解

- `<file|module>`：文件路径，或不带 `.cmake` 后缀的模块名（按 `CMAKE_MODULE_PATH` 再到 CMake 内置模块目录查找）。
- `OPTIONAL`：文件不存在时不报错。
- `RESULT_VARIABLE`：写入实际包含的完整路径，未找到时为 `NOTFOUND`。
- `NO_POLICY_SCOPE`：不为被包含文件开启独立的策略作用域。

```cmake
include(GNUInstallDirs)          # 内置模块
include(cmake/Helpers.cmake)     # 项目内文件
```

> 详解见 [[42.Cmake/08 - 脚本命令完整参考.md]]；查找包请用 `find_package()`，见 [[42.Cmake/10 - 查找与依赖管理.md]]。

### enable_language

在 `project()` 之后**追加**启用某编程语言（触发对应编译器探测）。通常优先在 `project(... LANGUAGES ...)` 里声明；本命令用于条件性启用（如仅在某平台启用 ASM）。

```cmake
enable_language(<lang>... [OPTIONAL])
```

**参数**：详解

- `<lang>`：语言名，同 `project()` 的 `LANGUAGES` 取值。
- `OPTIONAL`：探测失败也不报错（结果可由全局属性查询，但 CMake 不保证所有生成器都支持该标志）。

```cmake
if(APPLE)
  enable_language(OBJCXX)
endif()
```

## 二、定义目标

### add_executable

定义可执行目标。三种形态：普通、IMPORTED（引用外部已有可执行文件）、ALIAS（为现有目标起别名）。

```cmake
# 普通
add_executable(<name> [WIN32] [MACOSX_BUNDLE]
               [EXCLUDE_FROM_ALL]
               [source1] [source2 ...])

# 导入（引用外部可执行文件，不参与构建）
add_executable(<name> IMPORTED [GLOBAL])

# 别名
add_executable(<name> ALIAS <target>)
```

**参数**：详解

- `<name>`：目标逻辑名，**全局唯一**。
- `WIN32`：设置 `WIN32_EXECUTABLE`（Windows 上生成 GUI 子系统程序，入口为 `WinMain`）。
- `MACOSX_BUNDLE`：设置 `MACOSX_BUNDLE`（macOS 上生成 `.app` 包）。
- `EXCLUDE_FROM_ALL`：不纳入默认 `all` 目标。
- `IMPORTED [GLOBAL]`：声明一个外部可执行目标，需配合 `IMPORTED_LOCATION` 等属性；`GLOBAL` 使其在整个工程可见（否则仅当前目录及子目录）。
- `ALIAS <target>`：创建只读别名，可用于 `target_link_libraries` 等，但不能作为安装/属性设置的对象。

```cmake
add_executable(app main.cpp util.cpp)

add_executable(clang_tool IMPORTED)
set_target_properties(clang_tool PROPERTIES IMPORTED_LOCATION /usr/bin/clang)

add_executable(MyCo::app ALIAS app)   # 推荐带命名空间的别名
```

### add_library

定义库目标，覆盖普通库（STATIC/SHARED/MODULE）、OBJECT、INTERFACE，以及 IMPORTED 与 ALIAS。

```cmake
# 普通库（类型可省，由 BUILD_SHARED_LIBS 决定 STATIC/SHARED）
add_library(<name> [STATIC | SHARED | MODULE]
            [EXCLUDE_FROM_ALL]
            [<source>...])

# 对象库（只产出 .o，供其他目标复用）
add_library(<name> OBJECT [<source>...])

# 接口库（无产物，只承载使用需求 usage requirements）
add_library(<name> INTERFACE)

# 导入库（引用外部已构建的库）
add_library(<name> <type> IMPORTED [GLOBAL])

# 别名
add_library(<name> ALIAS <target>)
```

**参数 / 类型**：详解

- `STATIC`：静态库（`.a` / `.lib`）。
- `SHARED`：动态库（`.so` / `.dll` + 导入库 / `.dylib`）。
- `MODULE`：插件库，不参与链接、运行时 `dlopen`/`LoadLibrary` 加载。
- 省略类型：由 `BUILD_SHARED_LIBS` 决定（`ON` → SHARED，否则 STATIC）。
- `OBJECT`：对象库，编译为目标文件集合，供其他目标以 `$<TARGET_OBJECTS:name>` 或直接 `target_link_libraries` 复用，避免重复编译。
- `INTERFACE`：接口库，**无源文件、无产物**，仅通过 `INTERFACE` 属性向消费者传递头文件目录、宏、编译选项等（header-only 库、配置聚合的标准做法）。
- `<type> IMPORTED [GLOBAL]`：导入已存在的库，需设置 `IMPORTED_LOCATION`、`INTERFACE_INCLUDE_DIRECTORIES` 等。
- `ALIAS`：只读别名，常用 `命名空间::名字` 形式与 `find_package` 提供的目标统一风格。

```cmake
add_library(math STATIC add.cpp sub.cpp)
add_library(header_only INTERFACE)
target_include_directories(header_only INTERFACE ${CMAKE_CURRENT_SOURCE_DIR}/include)
add_library(MyCo::math ALIAS math)
```

> 各库类型的取舍、OBJECT/INTERFACE 用法、传播性（PUBLIC/PRIVATE/INTERFACE）详见 [[42.Cmake/04 - Target 与现代 CMake.md]]。

### add_custom_target

定义一个**无产物文件**的自定义目标，总被视为“过期”，每次构建都会执行其命令。适合“伪目标”（打包、清理、代码生成的总入口、跑脚本等）。

```cmake
add_custom_target(<Name> [ALL]
                  [COMMAND <command1> [<args1>...]]
                  [COMMAND <command2> [<args2>...] ...]
                  [DEPENDS <depend>...]
                  [BYPRODUCTS <file>...]
                  [WORKING_DIRECTORY <dir>]
                  [COMMENT <comment>]
                  [JOB_POOL <job_pool>]
                  [VERBATIM] [USES_TERMINAL] [COMMAND_EXPAND_LISTS]
                  [SOURCES <src>...])
```

**参数**：详解

- `<Name>`：目标名（同样占用全局目标名字空间）。
- `ALL`：纳入默认 `all` 目标，使其随默认构建自动执行。
- `COMMAND`：构建时执行的命令，可给多条；建议用 `${CMAKE_COMMAND} -E <mode>` 调用跨平台工具。
- `DEPENDS`：依赖的文件或 `add_custom_command(OUTPUT)` 产物（用于触发其生成）。
- `BYPRODUCTS`：命令会顺带产生、但不是主产物的文件（让 Ninja 等正确建模、并纳入 `clean`）。
- `WORKING_DIRECTORY`：命令的工作目录。
- `COMMENT`：执行前打印的提示。
- `VERBATIM`：**强烈推荐**，保证参数按原样转义传递，跨平台一致。
- `USES_TERMINAL`：让命令直接使用终端（如需要交互或实时进度）。
- `SOURCES`：仅为在 IDE 中显示而附带的源文件列表，不参与编译。

```cmake
add_custom_target(run_lint ALL
  COMMAND ${CMAKE_COMMAND} -E echo "running lint"
  COMMAND clang-format --dry-run ${CMAKE_SOURCE_DIR}/src/main.cpp
  COMMENT "代码检查"
  VERBATIM)
```

### add_custom_command

定义自定义命令。有**两种互斥形态**：

1. **生成文件形态（OUTPUT）**：声明“某些输出文件如何生成”，当有目标把这些输出当作源文件使用时，构建系统按需触发。
2. **目标事件形态（TARGET）**：把命令挂到某个已存在目标的构建生命周期事件上（编译前/链接前/链接后）。

```cmake
# 形态 1：生成输出文件
add_custom_command(
  OUTPUT <output1> [<output2> ...]
  COMMAND <command1> [ARGS] [<args1>...]
  [COMMAND <command2> [ARGS] [<args2>...] ...]
  [MAIN_DEPENDENCY <depend>]
  [DEPENDS <depend>...]
  [BYPRODUCTS <file>...]
  [IMPLICIT_DEPENDS <lang1> <depend1> [<lang2> <depend2>] ...]
  [WORKING_DIRECTORY <dir>]
  [COMMENT <comment>]
  [DEPFILE <depfile>]
  [JOB_POOL <job_pool>] [JOB_SERVER_AWARE <bool>]
  [VERBATIM] [APPEND] [USES_TERMINAL]
  [CODEGEN]
  [COMMAND_EXPAND_LISTS] [DEPENDS_EXPLICIT_ONLY])

# 形态 2：目标构建事件
add_custom_command(
  TARGET <target>
  PRE_BUILD | PRE_LINK | POST_BUILD
  COMMAND <command1> [ARGS] [<args1>...]
  [COMMAND <command2> [ARGS] [<args2>...] ...]
  [BYPRODUCTS <file>...]
  [WORKING_DIRECTORY <dir>]
  [COMMENT <comment>]
  [VERBATIM] [COMMAND_EXPAND_LISTS] [USES_TERMINAL])
```

**关键参数**：详解

| 参数 | 适用形态 | 含义 |
| --- | --- | --- |
| `OUTPUT` | 生成文件 | 命令产生的主输出文件（多个目标若都需要同一输出，应改挂到一个 `add_custom_target` 上避免竞态） |
| `TARGET` + 时机 | 目标事件 | 挂载目标及时机：`PRE_BUILD`（仅 VS 生成器真正“最先”，其他等同 PRE_LINK）/ `PRE_LINK`（编译后、链接前）/ `POST_BUILD`（目标全部规则之后）。**应总指定其一** |
| `COMMAND` | 两者 | 要执行的命令，可多条，至少一条 |
| `MAIN_DEPENDENCY` | 生成文件 | 主依赖（IDE 中把命令归到该源文件下） |
| `DEPENDS` | 生成文件 | 文件级 / 目标级依赖，变更则触发重新生成 |
| `BYPRODUCTS` | 两者 | 附带产物，纳入清理与依赖建模 |
| `DEPFILE` | 生成文件 | Make/Ninja 风格依赖文件，供精确增量（Ninja 全支持；Makefiles 3.20+，VS/Xcode 3.21+） |
| `IMPLICIT_DEPENDS` | 生成文件 | 让 CMake 扫描指定语言源文件的隐式头依赖（仅 Makefiles 生成器） |
| `WORKING_DIRECTORY` | 两者 | 工作目录 |
| `COMMENT` | 两者 | 执行前提示 |
| `VERBATIM` | 两者 | **推荐**：参数原样转义，跨平台一致 |
| `APPEND` | 生成文件 | 向同一 `OUTPUT` 已有命令追加 COMMAND/DEPENDS |
| `CODEGEN` | 生成文件 | 3.31+，使该输出可由 `codegen` 目标单独生成（用于只跑代码生成） |
| `COMMAND_EXPAND_LISTS` | 两者 | 展开命令中的 `;` 分隔列表（含生成器表达式产生的列表） |

```cmake
# 生成文件形态：用脚本从模板生成头文件
add_custom_command(
  OUTPUT ${CMAKE_CURRENT_BINARY_DIR}/version.h
  COMMAND ${CMAKE_COMMAND}
          -DOUT=${CMAKE_CURRENT_BINARY_DIR}/version.h
          -P ${CMAKE_CURRENT_SOURCE_DIR}/gen_version.cmake
  DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/gen_version.cmake
  COMMENT "生成 version.h"
  VERBATIM)
add_executable(app main.cpp ${CMAKE_CURRENT_BINARY_DIR}/version.h)

# 目标事件形态：构建后拷贝产物
add_custom_command(TARGET app POST_BUILD
  COMMAND ${CMAKE_COMMAND} -E copy
          $<TARGET_FILE:app> ${CMAKE_BINARY_DIR}/dist/
  COMMENT "拷贝可执行文件到 dist/"
  VERBATIM)
```

### add_dependencies

为顶层目标添加**目标级**显式依赖，强制构建顺序（A 在 B 之前构建）。注意：它**只排序，不传递使用需求**——链接关系请用 `target_link_libraries`。

```cmake
add_dependencies(<target> <dependency>... )
```

**参数**：详解

- `<target>`：被约束的目标（不可为 IMPORTED/ALIAS，须是本工程构建的顶层目标）。
- `<dependency>...`：它所依赖的一个或多个目标，会先于 `<target>` 构建。

```cmake
add_dependencies(app generate_resources)
```

## 三、target_* 全家（速查 + 详解链接）

> 以下命令均遵循 `PRIVATE` / `PUBLIC` / `INTERFACE` 传播模型，是现代 CMake 的核心。**原理、传播规则与最佳实践见 [[42.Cmake/04 - Target 与现代 CMake.md]]**，此处仅给签名速查。

### target_sources

为目标追加源文件；支持 `FILE_SET`（管理头文件等并参与安装，3.23+）。

```cmake
target_sources(<target>
  [<INTERFACE|PUBLIC|PRIVATE> <src>...]...)

# FILE_SET 形态（管理 HEADERS / CXX_MODULES 等）
target_sources(<target>
  [<INTERFACE|PUBLIC|PRIVATE>
   [FILE_SET <set> [TYPE <type>] [BASE_DIRS <dirs>...] [FILES <files>...]]...
  ]...)
```

`TYPE` 取值：`HEADERS`、`CXX_MODULES`、`CXX_MODULE_HEADER_UNITS`（默认集名 `HEADERS` 时可省 TYPE）。

```cmake
target_sources(mylib
  PUBLIC FILE_SET pub TYPE HEADERS BASE_DIRS include FILES include/mylib/api.h
  PRIVATE src/impl.cpp)
```

### target_include_directories

添加头文件搜索目录。

```cmake
target_include_directories(<target> [SYSTEM] [AFTER|BEFORE]
  <INTERFACE|PUBLIC|PRIVATE> <dir>... [<INTERFACE|PUBLIC|PRIVATE> <dir>...]...)
```

`SYSTEM` 标记为系统头（抑制告警）；`BEFORE` 提前到搜索列表前部。常配合 `$<BUILD_INTERFACE:..>` / `$<INSTALL_INTERFACE:..>`。

### target_compile_definitions

添加预处理宏定义（无需写 `-D`）。

```cmake
target_compile_definitions(<target>
  <INTERFACE|PUBLIC|PRIVATE> <def>... [...] )
```

```cmake
target_compile_definitions(app PRIVATE LOG_LEVEL=2 ENABLE_X)
```

### target_compile_options

添加编译器选项（直接传给编译器，按字面）。

```cmake
target_compile_options(<target> [BEFORE]
  <INTERFACE|PUBLIC|PRIVATE> <opt>... [...] )
```

### target_compile_features

声明目标所需的编译特性（如 `cxx_std_20`），由 CMake 推导所需标准与开关。

```cmake
target_compile_features(<target>
  <INTERFACE|PUBLIC|PRIVATE> <feature>... [...] )
```

```cmake
target_compile_features(app PUBLIC cxx_std_20)
```

### target_link_libraries

声明链接依赖与使用需求传播（最常用命令）。

```cmake
target_link_libraries(<target>
  <PRIVATE|PUBLIC|INTERFACE> <item>... [<PRIVATE|PUBLIC|INTERFACE> <item>...]...)
```

`<item>` 可为目标名、库文件路径、`-l`/`-framework` 标志或生成器表达式。

### target_link_options

添加链接器选项。

```cmake
target_link_options(<target> [BEFORE]
  <INTERFACE|PUBLIC|PRIVATE> <opt>... [...] )
```

### target_link_directories

添加链接库搜索目录（尽量优先用导入目标，少用本命令）。

```cmake
target_link_directories(<target> [BEFORE]
  <INTERFACE|PUBLIC|PRIVATE> <dir>... [...] )
```

### target_precompile_headers

为目标配置预编译头（PCH），加速编译。

```cmake
target_precompile_headers(<target>
  <INTERFACE|PUBLIC|PRIVATE> <header>... [...] )

# 复用另一个目标的 PCH
target_precompile_headers(<target> REUSE_FROM <other_target>)
```

```cmake
target_precompile_headers(app PRIVATE <vector> <string> "pch.h")
```

## 四、老式命令（⚠️ 不推荐，仅维护旧项目时了解）

> 以下为**目录级**命令：作用于“当前及之后定义的所有目标”，全局污染、来源难追踪。新代码请一律改用对应的 `target_*` 命令（见上一节）。

### include_directories ⚠️

为当前目录及子目录的所有目标添加头文件搜索路径。**改用 `target_include_directories`。**

```cmake
include_directories([AFTER|BEFORE] [SYSTEM] <dir>...)
```

### add_definitions ⚠️

添加编译器定义/标志（历史上可混入 `-D` 宏与其他标志）。**宏请改用 `target_compile_definitions`。**

```cmake
add_definitions(-DFOO -DBAR=1)
```

### add_compile_definitions ⚠️

目录级添加宏定义（比 `add_definitions` 干净，但仍是目录级）。**改用 `target_compile_definitions`。**

```cmake
add_compile_definitions(FOO BAR=1)
```

### add_compile_options ⚠️

目录级添加编译选项。**改用 `target_compile_options`。**

```cmake
add_compile_options(-Wall -Wextra)
```

### link_directories ⚠️

目录级添加链接库搜索路径。**改用 `target_link_directories` 或导入目标。**

```cmake
link_directories([AFTER|BEFORE] <dir>...)
```

### link_libraries ⚠️

为之后定义的所有目标添加链接库（极易误伤）。**改用 `target_link_libraries`。**

```cmake
link_libraries(<item>... [debug|optimized|general] <item>...)
```

### remove_definitions ⚠️

移除由 `add_definitions` 添加的定义（仅作用于目录级状态）。

```cmake
remove_definitions(-DFOO)
```

## 五、属性与分组

### set_target_properties

批量设置一个或多个目标的属性。

```cmake
set_target_properties(<target1> [<target2> ...]
                      PROPERTIES <prop1> <value1>
                                 [<prop2> <value2>] ...)
```

**参数**：详解

- 可一次对多个目标设置；`PROPERTIES` 后为“属性名 值”键值对序列。
- 常用属性：`CXX_STANDARD`、`OUTPUT_NAME`、`VERSION` / `SOVERSION`、`RUNTIME_OUTPUT_DIRECTORY`、`POSITION_INDEPENDENT_CODE`、`FOLDER`（IDE 分组）、`IMPORTED_LOCATION` 等。

```cmake
set_target_properties(mylib PROPERTIES
  OUTPUT_NAME "my"
  VERSION 1.2.0
  SOVERSION 1
  POSITION_INDEPENDENT_CODE ON)
```

### get_target_property

读取目标属性到变量；属性未设置时变量被置为 `<var>-NOTFOUND`。

```cmake
get_target_property(<var> <target> <property>)
```

```cmake
get_target_property(loc mylib OUTPUT_NAME)
message(STATUS "OUTPUT_NAME = ${loc}")
```

> 通用属性读写还有 `set_property` / `get_property`（可作用于 GLOBAL/DIRECTORY/TARGET/SOURCE/TEST 等多种作用域），详见 [[42.Cmake/08 - 脚本命令完整参考.md]]。

### source_group

在 IDE（VS / Xcode）中把源文件分组显示，不影响构建。

```cmake
# 显式列出文件归入某组（组名用 \\ 分隔层级）
source_group(<name> [FILES <src>...] [REGULAR_EXPRESSION <regex>])

# 按目录树自动分组（推荐）
source_group(TREE <root> [PREFIX <prefix>] [FILES <src>...])
```

**参数**：详解

- `<name>`：分组名，用 `\\`（或 `/`）表示子分组层级。
- `FILES`：归入该组的文件。
- `REGULAR_EXPRESSION`：按正则匹配文件名归组。
- `TREE <root>`：以 `<root>` 为根，按文件相对目录结构自动建立分组（最常用）；`PREFIX` 给所有组加前缀。

```cmake
source_group(TREE ${CMAKE_CURRENT_SOURCE_DIR}/src PREFIX "Source" FILES ${SOURCES})
```

### aux_source_directory

收集目录下所有源文件到变量。**不推荐**：无法感知新增文件触发重配（需手动重跑 cmake），现代实践偏向显式列出源文件。

```cmake
aux_source_directory(<dir> <variable>)
```

```cmake
aux_source_directory(src SRC_LIST)
add_executable(app ${SRC_LIST})   # 注意：新增源文件不会自动被发现
```

## 六、测试（速查，详解 → 第 12 章）

> 测试驱动、用例编写、CTest 运行与高级用法见 [[42.Cmake/12 - 测试 CTest.md]]。

### enable_testing

在当前目录及子目录启用测试，使 `add_test` 生效并生成 CTest 配置。通常在顶层调用一次（`include(CTest)` 也会隐式启用）。

```cmake
enable_testing()
```

### add_test

注册一个测试。详解（含 `COMMAND` 生成器表达式、`$<TARGET_FILE:..>` 用法）见第 12 章。

```cmake
add_test(NAME <name> COMMAND <command> [<arg>...]
         [CONFIGURATIONS <config>...]
         [WORKING_DIRECTORY <dir>]
         [COMMAND_EXPAND_LISTS])
```

```cmake
add_test(NAME unit COMMAND mytest --all)
```

### set_tests_properties

设置测试属性（超时、期望失败、环境变量、依赖等）。

```cmake
set_tests_properties(<test>... PROPERTIES <prop> <value> [<prop> <value>]...)
```

常用属性：`TIMEOUT`、`WILL_FAIL`、`ENVIRONMENT`、`LABELS`、`DEPENDS`、`PASS_REGULAR_EXPRESSION`、`FAIL_REGULAR_EXPRESSION`。

```cmake
set_tests_properties(unit PROPERTIES TIMEOUT 30 LABELS "fast")
```

## 七、安装与导出（速查，详解 → 第 11 章）

> 安装规则、导出包、`find_package` 配置文件、CPack 打包见 [[42.Cmake/11 - 安装、导出与打包.md]]。

### install

声明安装规则。多种形态，速查如下：

| 形态 | 一句话用途 |
| --- | --- |
| `install(TARGETS <tgt>... [EXPORT <name>] [ARCHIVE|LIBRARY|RUNTIME|OBJECTS|FRAMEWORK|BUNDLE|PUBLIC_HEADER|...] [DESTINATION <dir>] ...)` | 安装构建的目标（可执行/库），可按产物类型分别指定目的地，并用 `EXPORT` 收集到导出集 |
| `install(FILES <file>... DESTINATION <dir> [PERMISSIONS ...] [RENAME ...])` | 安装普通文件（如配置、license） |
| `install(DIRECTORY <dir>... DESTINATION <dir> [PATTERN/REGEX ... EXCLUDE] ...)` | 递归安装整个目录（可过滤） |
| `install(EXPORT <name> DESTINATION <dir> [NAMESPACE <ns>::] [FILE <f>.cmake])` | 生成并安装导出文件，供下游 `find_package` 导入目标 |
| `install(SCRIPT <file>)` / `install(CODE <code>)` | 安装期执行 CMake 脚本文件 / 内联代码 |
| `install(RUNTIME_DEPENDENCY_SET <set> [LIBRARY|RUNTIME|FRAMEWORK ...] [PRE_INCLUDE_REGEXES ...] ...)` | 安装运行时依赖集（自动随产物拷贝其依赖的共享库） |
| `install(IMPORTED_RUNTIME_ARTIFACTS <tgt>... ...)` | 安装导入目标的运行时产物 |

```cmake
install(TARGETS mylib app
        EXPORT MyProjTargets
        RUNTIME DESTINATION bin
        LIBRARY DESTINATION lib
        ARCHIVE DESTINATION lib)
install(DIRECTORY include/ DESTINATION include)
```

### export

把当前**构建树**中的目标导出，供其他项目从构建树直接使用（无需安装）。

```cmake
# 导出指定目标
export(TARGETS <tgt>... [NAMESPACE <ns>::] [APPEND] FILE <filename>
       [EXPORT_LINK_INTERFACE_LIBRARIES])

# 导出某个 install(EXPORT) 同名集合（构建树版本）
export(EXPORT <export-name> [NAMESPACE <ns>::] [FILE <filename>]
       [CXX_MODULES_DIRECTORY <dir>] [EXPORT_PACKAGE_DEPENDENCIES])

# 将本项目登记进用户包注册表
export(PACKAGE <PackageName>)
```

### install(EXPORT)

安装**安装树**版本的导出文件（与 `install(TARGETS ... EXPORT <name>)` 配对），是发布可被 `find_package` 发现之库的标准做法。

```cmake
install(EXPORT MyProjTargets
        FILE MyProjTargets.cmake
        NAMESPACE MyProj::
        DESTINATION lib/cmake/MyProj)
```

> 完整的“可重定位导出包 + Config.cmake + 版本文件”流程见 [[42.Cmake/11 - 安装、导出与打包.md]]。

## 八、其他历史命令（可略提）

- `fltk_wrap_ui`、`qt_wrap_cpp`、`qt_wrap_ui`：早期 FLTK/Qt 封装命令，现代 Qt 用 `qt_add_executable` / `qt_add_qml_module` 等官方宏，FLTK 直接用 `add_custom_command` 调 fluid。**新项目勿用。**

- `build_command`：为 CTest 生成构建命令行，一般由 CTest 脚本场景使用，普通工程不直接调用。

## 本章小结

- **项目命令仅在有构建系统的项目中有效**，与脚本命令（第 08 章）相对。
- 立项三件套：`project()` 声明项目与语言、`add_subdirectory()` 组织目录、`include()` 复用 `.cmake`；`enable_language()` 用于追加启用语言。
- 定义目标看四条：`add_executable` / `add_library`（含 IMPORTED/ALIAS/OBJECT/INTERFACE）、`add_custom_target`（伪目标）、`add_custom_command`（**OUTPUT 生成文件** 与 **TARGET 事件** 两形态）、`add_dependencies`（只排序不传需求）。
- **现代 CMake 用 `target_*` 全家**承载使用需求（PUBLIC/PRIVATE/INTERFACE）；对应的目录级老命令（`include_directories` / `add_definitions` / `link_libraries` 等）**仅维护旧项目时了解**。
- 属性用 `set_target_properties` / `get_target_property`，IDE 分组用 `source_group(TREE ...)`。
- 测试（`enable_testing` / `add_test` / `set_tests_properties`）、安装导出（`install` 各形态 / `export` / `install(EXPORT)`）本章给速查，详解分别见第 12、11 章。
