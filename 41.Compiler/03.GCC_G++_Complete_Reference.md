# GCC/G++ 编译器完整参数详解

> GCC（GNU Compiler Collection）是 GNU 项目的编译器套件，其中 `gcc`、`g++` 分别是它的 C 与 C++ 前端（驱动程序）。本文按**功能分类**梳理其最常用、最具代表性、以及面试与排错中最常被问到的命令行参数，并对易混淆项给出辨析。
>
> **版本基准**：以现代 GCC（**13 及以上**）为参考，涉及版本差异或新近选项处会显式标注。GCC 的开关数以百计，本文**不追求穷举每一个内部优化 pass**（那类开关绝大多数由 `-O` 级别自动启用），完整清单请查 `gcc --help=optimizers` 或 [官方手册](https://gcc.gnu.org/onlinedocs/gcc/Option-Index.html)。
>

## GCC/G++ 编译流程

`gcc`/`g++` 把源码变成可执行程序，概念上分 4 步：

1. **预处理（Preprocessing）**：展开宏、`#include` 头文件、处理条件编译，生成 `.i`（C）/`.ii`（C++）文件 —— 由预处理器 `cpp` 完成。
2. **编译（Compilation）**：将预处理结果翻译成汇编代码，生成 `.s` 文件 —— 由编译器 `cc1`/`cc1plus` 完成。
3. **汇编（Assembly）**：将汇编翻译成机器码目标文件 `.o` —— 由汇编器 `as` 完成。
4. **链接（Linking）**：合并目标文件与库，生成可执行程序 —— 由链接器 `ld` 完成。

> 💡 用 `-save-temps` 可一次性保留 `.i` / `.s` / `.o` 等全部中间产物，便于逐阶段排查；用 `-v` 可看到驱动程序实际调用了哪些子程序。

## 1. 总体选项（Overall Options）

- **-c**：只编译生成目标文件（`.o`），不进行链接
- **-S**：只编译到汇编代码（`.s`），不进行汇编和链接
- **-E**：只进行预处理，结果输出到标准输出
- **-o file**：指定输出文件名
- **-pipe**：用管道代替临时文件进行中间通信（略微加速）
- **-v**：显示编译器调用的各子程序及其版本
- **-###**：与 `-v` 类似，但只打印将要执行的命令而不真正执行
- **-x language**：显式指定源文件语言类型（`c`、`c++`、`objective-c`、`c-header` 等）
- **-x none**：停止 `-x` 的作用，恢复按文件扩展名判断语言

## 2. 语言选项（Language Options）

- **-ansi**：等价于 C 的 `-std=c90`、C++ 的 `-std=c++98`，关闭与 ISO 标准不兼容的 GNU 扩展
- **-std=standard**：指定要遵循的语言标准，常用值：
  - C：`c90`/`c89`、`c99`、`c11`、`c17`、`c23`，以及对应的 `gnu*` 变体
  - C++：`c++11`、`c++14`、`c++17`、`c++20`、`c++23`（早期临时名 `c++2b`）、`c++26`（实验，`c++2c`），以及对应的 `gnu++*` 变体
  - **`c++NN` vs `gnu++NN`**：`-std=c++17` 严格遵循 ISO C++17，不允许任何非标准扩展；`-std=gnu++17` 在 C++17 基础上额外允许 GNU 扩展（复合字面量、语句表达式、嵌套函数等）。**GCC 默认采用 `gnu++NN`**（即默认开启扩展）
- **-fno-asm**：禁止 `asm`、`inline`、`typeof` 作为关键字
- **-fno-builtin** / **-fno-builtin-function**：不使用（特定）内置函数
- **-ffreestanding**：按"独立环境"编译，不假定标准库存在（如内核/裸机）
- **-fhosted**：按"宿主环境"编译，假定标准库存在（默认）
- **-fno-common**：不把未初始化全局变量放入 common 块（GCC 10 起为默认，可及早暴露重复定义）
- **-fshort-enums**：枚举类型用容纳其值的最小尺寸
- **-fsigned-char** / **-funsigned-char**：将 `char` 视为有/无符号
- **-fsigned-bitfields** / **-funsigned-bitfields**：未显式声明时位域的符号性
- **-fexceptions** / **-fno-exceptions**：启用/禁用 C++ 异常机制
- **-frtti** / **-fno-rtti**：启用/禁用 C++ 运行时类型信息（RTTI）

## 3. 预处理器选项（Preprocessor Options）

- **-D macro** / **-D macro=value**：定义宏（等同 `#define`）
- **-U macro**：取消宏定义（等同 `#undef`）
- **-I dir**：添加头文件搜索目录
- **-iquote dir**：仅为 `#include "file"` 形式添加搜索目录
- **-isystem dir**：添加系统头文件搜索目录（其中的告警会被抑制）
- **-include file**：在所有源文件开头隐式包含指定头文件
- **-imacros file**：仅从指定文件读取宏定义（不引入其声明）
- **-idirafter dir**：添加次级（最后搜索）头文件目录
- **-undef**：取消所有非标准预定义宏
- **-nostdinc**：不搜索标准系统头文件目录
- **-MD** / **-MMD**：生成依赖关系 `.d` 文件（`-MMD` 忽略系统头文件）
- **-MF file**：指定依赖文件名
- **-MG**：把缺失头文件也当作目标
- **-MP**：为每个依赖生成空规则（避免删头文件后报错）
- **-MT target** / **-MQ target**：设置依赖规则的目标名（`-MQ` 会转义特殊字符）

## 4. 警告选项（Warning Options）

- **-w**：禁用所有警告
- **-Wall**：启用一组常用警告（**并非"所有"警告**）
- **-Wextra**：在 `-Wall` 之外再启用一批额外警告
- **-Werror**：将警告视为错误
- **-Werror=foo**：仅把某一类警告 `foo` 视为错误
- **-Wpedantic**（亦写作 `-pedantic`）：警告所有不符合 ISO C/C++ 标准之处
- **-pedantic-errors**：将上述不符合项视为错误
- **-Wconversion**：警告可能改变值的隐式类型转换
- **-Wsign-compare**：警告有/无符号混合比较
- **-Wuninitialized**：警告使用未初始化变量
- **-Wunused**（及 `-Wunused-variable`/`-Wunused-function`/`-Wunused-value` 等）：警告未使用的实体
- **-Wshadow**：警告变量遮蔽
- **-Wfloat-equal**：警告浮点数相等比较
- **-Wpointer-arith**：警告对 `void*`/函数指针的算术
- **-Wcast-qual**：警告类型转换丢弃 `const`/`volatile`
- **-Wcast-align**：警告类型转换提高了对齐要求
- **-Wwrite-strings**：把字符串字面量按 `const` 处理，对写入发出警告
- **-Wredundant-decls**：警告重复声明
- **-Winline**：警告声明为 `inline` 却无法内联的情况
- **-Winvalid-pch**：警告无法使用的预编译头文件
- **-Wmissing-braces**：警告聚合初始化缺少花括号
- **-Wmissing-prototypes**：警告全局函数缺少先前原型声明（C）
- **-Wreorder**：警告 C++ 成员初始化列表顺序与声明顺序不一致
- **-Wswitch** / **-Wswitch-default** / **-Wswitch-enum**：`switch` 相关告警
- **-Wshadow**、**-Wnon-virtual-dtor**、**-Woverloaded-virtual**：C++ 工程常配合启用的高价值告警

> 📌 实践建议：日常用 `-Wall -Wextra`，关键项目再叠加 `-Werror` 与 `-Wshadow -Wconversion`，把问题拦在编译期。

## 5. 调试选项（Debugging Options）

- **-g**：生成调试信息（默认 DWARF 格式，级别 2）
- **-g[0-3]**：调试信息级别（0 无、3 含宏信息）
- **-ggdb**：生成 GDB 能用的最丰富调试信息
- **-gdwarf** / **-gdwarf-5**：生成（指定版本的）DWARF 调试信息
- **-p** / **-pg**：生成 `prof`/`gprof` 性能分析信息（`-pg` 含调用图）
- **-save-temps**：保留 `.i`/`.s` 等中间临时文件

## 6. 优化选项（Optimization Options）

### 6.1 优化级别

- **-O0**：不优化（默认），编译最快、最易调试
- **-O1**：基础优化，在编译时间与执行效率间取平衡
- **-O2**：标准发布优化，开启 `-O1` 全部 + 大量不显著增大体积的优化
- **-O3**：在 `-O2` 之上开启更激进、可能增大体积的优化（如更强的内联、向量化）
- **-Os**：以**减小代码体积**为目标——开启 `-O2` 中**不会显著增大体积**的优化（例如不启用 `-ftree-ch`、循环展开等）
- **-Ofast**：在 `-O3` 基础上叠加 `-ffast-math` 等**可能违反 IEEE/语言标准**的激进优化（慎用）
- **-Og**：为调试体验优化——开启不妨碍调试的优化，是带 `-g` 调试时的推荐级别

### 6.2 常用单项优化开关

- **-finline-functions**：尝试内联小函数（`-O2`/`-O3` 已含）
- **-fno-inline**：禁用所有内联
- **-finline-functions-called-once**：内联仅被调用一次的函数
- **-fomit-frame-pointer**：省略帧指针，腾出一个寄存器（`-O` 级别在多数架构上已默认）
- **-funroll-loops**：循环展开（`-funroll-all-loops` 连不确定次数的循环也展开，更激进）
- **-fstrict-aliasing**：启用严格别名规则（`-O2` 起默认），违反它的代码可能被错误优化
- **-fno-strict-aliasing**：关闭严格别名假设（移植旧代码时常用）
- **-ffast-math**：放宽浮点语义换取速度（破坏 IEEE 严格性，`-Ofast` 隐含）
- **-fgcse**：全局公共子表达式消除
- **-fdce** / **-fdse**：死代码 / 死存储消除
- **-fdevirtualize**：尝试把虚函数调用去虚拟化为直接调用

> ⚙️ **关于成百上千个 `-ftree-*` / `-fipa-*` pass**：它们是 GCC 内部的树（GIMPLE/SSA）级与过程间优化 pass，**绝大多数由 `-O1`/`-O2`/`-O3` 自动启用，通常无需手动指定**。仅举两个常被误解的例子（也是旧资料常见错译处）：
> - **-ftree-ch**：**循环头复制**（loop header copying）——复制循环入口条件，使更多代码可安全外提、并省去一次跳转；`-O` 及以上默认启用，`-Os` 不启用（因其增大体积）。
> - **-ftree-loop-im**：**循环不变量外提**（loop invariant motion）——把循环内不随迭代变化的计算移到循环外。
>
> 完整 pass 列表见 `gcc --help=optimizers -Q`。

### 6.3 链接时优化（LTO）

- **-flto**：启用链接时优化，跨翻译单元做内联与全局分析（编译和链接都要加）
- **-flto=auto** / **-flto=N**：用自动检测/N 个并行任务做 LTO
- **-ffat-lto-objects**：在目标文件中同时保留普通代码与 LTO 字节码（兼容性更好）

## 7. 程序插桩与 Sanitizer（Instrumentation）

GCC 自 **4.8** 起内置 Google Sanitizer 系列，是排查内存与并发缺陷的利器。**编译与链接都需加同一选项**，并建议配合 `-g -fno-omit-frame-pointer` 以获得准确堆栈：

- **-fsanitize=address**（ASan）：检测越界、释放后使用（use-after-free）、栈/全局溢出等内存错误（约 2× 减速）
- **-fsanitize=undefined**（UBSan）：检测整数溢出、空指针解引用、非法移位等未定义行为
- **-fsanitize=thread**（TSan）：检测数据竞争（内存 5–10×、时间 2–20× 开销）
- **-fsanitize=leak**（LSan）：内存泄漏检测
- **-fsanitize=address,undefined**：ASan 与 UBSan **可组合**；但 **TSan 不能与 ASan 同时使用**
- **-fanalyzer**：GCC 10+ 的**静态**分析器，在编译期发现部分内存/资源缺陷（不同于上述运行期 Sanitizer）

> ⚠️ Sanitizer 是**测试/调试工具**，其运行时不应链接进生产可执行文件。

## 8. 链接器选项（Linker Options）

- **-L dir**：添加库搜索目录
- **-l library**：链接指定库（如 `-lm` 链接 math 库）
- **-static**：仅使用静态库
- **-shared**：生成共享库（`.so`）
- **-symbolic**：把对全局符号的引用尽量绑定到共享库内
- **-rdynamic**：把所有符号加入动态符号表（便于 `backtrace`/`dladdr`）
- **-Wl,option** / **-Xlinker option**：把选项透传给链接器
- **-nostartfiles** / **-nodefaultlibs** / **-nostdlib**：不使用标准启动文件 / 标准库 / 二者
- **-pie**：生成位置无关可执行文件（PIE）
- **-s**：从可执行文件中去除符号表与重定位信息
- **-u symbol**：将符号标记为未定义，促使链接器从库中拉取它

## 9. 代码生成选项（Code Generation Options）

- **-fPIC** / **-fpic**：生成位置无关代码（用于共享库，`-fpic` 受平台 GOT 大小限制）
- **-fPIE** / **-fpie**：生成位置无关可执行代码
- **-fverbose-asm**：在汇编输出中附带注释
- **-fpack-struct**：紧密打包结构体（去除填充，慎用）
- **-fstack-protector** / **-fstack-protector-strong** / **-fstack-protector-all**：栈溢出保护（强度递增）
- **-fvisibility=hidden|default**：设置符号默认可见性（库瘦身/加速加载常用 `hidden`）
- **-march=arch**：为指定架构生成代码（如 `x86-64-v3`、`native`、`armv8-a`）
- **-mtune=arch**：按指定架构调优但保持兼容性
- **-mcpu=cpu**：指定目标 CPU（部分架构，如 ARM）
- **-mfpmath=sse**：指定浮点运算单元
- **-m32 / -m64**：生成 32 位 / 64 位代码
- **-mcmodel=small|medium|large**：指定内存模型
- **-mfpu=neon|vfpv3|...**：指定 ARM 浮点/SIMD 单元类型

## 10. 目录与信息选项

- **-B prefix**：指定查找可执行文件/库/数据的前缀
- **-specs=file**：指定 spec 文件
- **-dumpmachine**：输出目标机器三元组
- **-dumpversion** / **-dumpfullversion**：输出（完整）版本号
- **--help** / **--help=optimizers** / **--target-help**：帮助信息（可叠加 `-Q` 查看各选项当前取值）
- **-print-search-dirs**：打印库/程序搜索路径
- **-print-prog-name=program**：打印某子程序的完整路径

---

这些参数提供了对 GCC/G++ 的精细控制。理解其分类与彼此关系，比死记每一个开关更重要：**`-O` 级别**决定整体优化策略，**`-W` 系列**把缺陷拦在编译期，**Sanitizer** 把缺陷暴露在运行期，三者配合即可覆盖绝大多数工程场景。
