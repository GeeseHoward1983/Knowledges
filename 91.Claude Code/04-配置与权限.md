# 04 · 配置与权限

> 本篇讲 Claude Code 的"治理面":**三层 settings.json**、**权限系统(allow/deny/ask)**、**CLAUDE.md 记忆**,以及它们与 hooks 的分工。
> hooks 的细节已有专篇 [[32.hooks/06-claude-code-hooks.md]],本篇只讲它在体系里的位置,不重复。

---

## 1. 三层 settings.json

Claude Code 按以下顺序合并配置(后者覆盖前者):

| 层级 | 路径(Windows) | 路径(Linux/macOS) | 用途 |
|---|---|---|---|
| 用户全局 | `%USERPROFILE%\.claude\settings.json` | `~/.claude/settings.json` | 所有项目共用 |
| 项目共享 | `<repo>\.claude\settings.json` | `<repo>/.claude/settings.json` | 团队共享(提交 git) |
| 项目本地 | `<repo>\.claude\settings.local.json` | `<repo>/.claude/settings.local.json` | 个人覆盖(gitignore) |
| 企业策略 | `managed-settings.json`(IT 部署) | 同 | **优先级最高**,锁定不可改 |

> 与 hooks 篇里的三层表一致——它们共用同一套 settings.json。

---

## 2. settings.json 结构

```json
{
  "permissions": {
    "allow": ["Bash(npm run *)", "Read(./src/**)"],
    "deny":  ["Bash(rm -rf *)", "Read(./.env)"],
    "ask":   ["Bash(git push *)"]
  },
  "env": { "API_TIMEOUT_MS": "1200000" },
  "model": "sonnet",
  "hooks": { "PostToolUse": [ /* ... */ ] }
}
```

| 键 | 作用 |
|---|---|
| `permissions` | 工具调用的允许/拒绝/询问规则(本篇 §3) |
| `env` | 注入环境变量(如超时、API Key、`ANTHROPIC_BASE_URL`) |
| `model` | 默认模型(别名或完整 id) |
| `hooks` | 工具前后必然执行的脚本 → [[32.hooks/06-claude-code-hooks.md]] |

## 3. 权限系统:allow / deny / ask

这是 Claude Code 最重要的安全机制。每当 Claude 想调用工具(跑命令、改文件、联网),都按规则判定:

```
工具调用请求
     │
     ├─ 命中 deny  → 直接拒绝
     ├─ 命中 ask   → 弹窗问你
     ├─ 命中 allow → 直接放行
     └─ 都没命中    → 按当前权限模式(default 则问你)
```

### 3.1 规则语法

格式是 `工具名(限定符)`,限定符支持通配:

| 规则 | 含义 |
|---|---|
| `Edit` | 允许所有文件编辑 |
| `Bash(npm run *)` | 允许 `npm run` 开头的命令 |
| `Bash(rm -rf *)` | (放 deny)禁止 `rm -rf` |
| `Read(./.env)` | (放 deny)禁止读 `.env` |
| `Read(./secrets/**)` | 禁止读整个 secrets 目录 |
| `WebFetch` | 允许联网抓取 |
| `mcp__github__*` | 允许某 MCP 服务器(github)的全部工具 |

### 3.2 三种典型配置

```json
{
  "permissions": {
    "allow": ["Bash(npm test *)", "Bash(npm run *)", "Read(./**)"],
    "deny":  ["Bash(rm -rf *)", "Bash(sudo *)", "Read(./.env)", "Read(./secrets/**)"],
    "ask":   ["Bash(git push *)", "Bash(git commit *)"]
  }
}
```

- **allow**:信任的高频命令,免打扰。
- **deny**:危险操作,一律拒绝(优先级最高)。
- **ask**:重要但需人确认的(如推送、提交)。

> 会话内用 `/permissions` 查看与临时调整;持久化就写进 settings.json。
> 启动加 `--dangerously-skip-permissions` 可跳过所有确认——**仅在容器/一次性隔离环境**用,别在日常机器上。

## 4. 权限模式 vs 权限规则

两者配合,别混淆:

| | 是什么 | 在哪设 |
|---|---|---|
| **权限模式** | 当前会话整体放手程度(default/acceptEdits/auto/plan) | `Shift+Tab` 切换,或 `--permission-mode` |
| **权限规则** | 具体哪条命令 allow/deny/ask | settings.json 的 `permissions` |

> 直觉:**模式是"油门档位",规则是"红绿灯"。** 见 [[91.Claude Code/03-基本使用与斜杠命令.md]] §6。

## 5. CLAUDE.md 记忆

`CLAUDE.md` 是给 **LLM 读的项目说明书/规则书**——每次会话自动加载进上下文,告诉 Claude 本项目的约定、技术栈、禁忌、命令。

### 5.1 层级

| 文件 | 作用范围 |
|---|---|
| `<repo>/CLAUDE.md` | 项目级,团队共享(提交 git) |
| `~/.claude/CLAUDE.md`(Win: `%USERPROFILE%\.claude\CLAUDE.md`) | 用户全局,跨所有项目 |
| `<repo>/子目录/CLAUDE.md` | 局部覆盖,只在该子树生效 |

### 5.2 怎么写与维护

- `/init`:扫描项目自动生成首版 `CLAUDE.md`。
- `/memory`:打开记忆文件编辑。
- `#` 前缀:会话里 `# 本项目用 pnpm` 一键追加一条记忆。
- `@path/to/file`:在 CLAUDE.md 里 `@docs/conventions.md` 导入其他文件内容。

### 5.3 写什么有效

✅ 技术栈与版本、构建/测试命令、代码风格、目录约定、"别碰 X"、领域术语。
❌ 别放密钥(它会进上下文);别写成长篇大论(占上下文且稀释重点)。

> 本质区别:**CLAUDE.md 影响"LLM 想怎么做"(概率性);权限/hooks 决定"环境必然做/不做什么"(确定性)。** 关键纪律(如"提交前必跑测试")要落到 hooks,不能只写进 CLAUDE.md。

## 6. 与 hooks 的分工

| 设施 | 性质 | 例子 |
|---|---|---|
| CLAUDE.md | 软约束(影响 LLM) | "优先用函数式风格" |
| permissions | 硬门禁(允许/拒绝调用) | 禁止 `rm -rf` |
| **hooks** | 硬自动化(必然执行) | 编辑后自动 `prettier`、提交前强制跑测试 |
