# 12 · 故障排查与技巧

> 本篇汇总 Claude Code 的常见故障与实战技巧,**重点照顾 Windows**(中文路径、编码、PowerShell 管道)。
> 很多条目来自在中文 Windows 环境里让 Claude Code 跑命令的真实踩坑。
> 排查总原则:**先 `claude doctor`,再看具体症状。**

---

## 1. 诊断第一步

```bash
claude doctor       # 安装类型/版本/登录/Git/PATH 一站式自检
claude --version    # 版本号
/status             # 会话内:当前身份与额度
/cost               # 会话内:本次 token 花费
```

> 任何"装好却不对劲",`claude doctor` 几乎都能定位到是安装、PATH、登录还是 Git 的问题。

---

## 2. 安装与 PATH

| 症状 | 原因 | 解法 |
|---|---|---|
| `claude` is not recognized | `~/.local/bin` 没进 PATH,或没开新终端 | 见 [[91.Claude Code/01-安装.md]] §2.6;开新终端 |
| 安装/运行直接崩 | 用了 **x86 版 PowerShell**(32 位) | 用普通 "Windows PowerShell" |
| `Raw mode is not supported` | 在 **Git Bash / MinTTY** 跑交互模式 | 改用 PowerShell / CMD / Windows Terminal,或 WSL |
| 没有 Bash 工具 | Windows 未装 Git for Windows | 装 Git for Windows,Claude 才有 Bash 工具(否则退化用 PowerShell) |

---

## 3. Windows 中文 / 特殊字符路径(高频坑)

项目路径含中文或括号(如 `边缘盒(柜)子`、`G:\知识库\...`)时,直接在命令里拼绝对中文路径极易乱码、找不到。**经验法则**:

> ✅ **让命令"cd 进目录 + 相对路径",命令里零中文字面量**——进程继承当前目录,后续全用相对路径:
> ```bash
> cd "05.code" && cmd /c '.\mvnw.cmd -q compile'
> cd "05.code/web" && cmd /c 'npm run build'
> ```
> 实测 Maven / npm 这样跑 `EXIT=0`。**别绕路去拼绝对中文路径。**

- 走 **cmd / PowerShell**(Windows `py` 启动器、正斜杠路径均可),**不要用 cygwin**。
- 万不得已要写脚本兜底:用 **Unicode 码点拼中文目录名**再 `Set-Location -LiteralPath`,脚本内其余全相对路径。**绝不在 `.ps1` 里写中文路径字面量**——Write 出的是 UTF-8 无 BOM,PowerShell 按 GBK 读会把中文乱码成 `杈圭紭鐩?` 之类,导致路径找不到。

---

## 4. 编码乱码(PowerShell / 控制台)

中文 Windows 控制台默认代码页是 **GBK/CP936**,而工具多输出 **UTF-8**,交叉就乱码。

- **命令输出含中文**:别依赖控制台直接看,**重定向写入 UTF-8 文件,再用 Read 工具读**,可靠得多。
- **判定成功与否以退出码为准**:`$LASTEXITCODE` / 重定向到文件的结果,比控制台花屏可信。
- **npm 的进度走 stderr**,会被 PowerShell 当 "error 流"标红显示,但**不影响** `EXIT`,别误判失败。
- **bash 工具尾部噪声** `.../claude-XXXX-cwd: No such file or directory` **可忽略**——它不代表命令失败,以退出码/文件结果为准。

---

## 5. bash 转发 PowerShell 管道:`$_` 被吞

当通过 bash 工具转发一段 PowerShell 管道时,命令里的 `$_` / `$Matches` 会被 **bash 先当成自己的变量展开**(变成空或 `extglob` 之类),把管道炸掉。

> ✅ 解法:凡用到 `$_` / `$Matches` 的 PowerShell 逻辑,**写进 `.ps1` 文件(纯 ASCII,中文路径用码点构造或 `-param` 传入)再 `powershell -File` 调**,不要内联 `-Command`。

---

## 6. 第三方 token 403 / 子代理静默失败

> 用第三方中转 token 时,若某动作(尤其**子代理**)默认派发到你**无权限的模型**(典型 `haiku`),会整批 **403** 且**静默**——表现为"任务返回空结果",像是"没发现问题",实则没跑成。

排查:

1. 看返回/通知里有没有 **403**。
2. 给子代理/工作流**显式指定有权限的模型**(`model: opus` 等),或去掉会解析到 haiku 的设置让其继承会话模型。
3. 结果异常为空时,**先确认不是 403 假阴性**,再判断是否真"零结果"。

详见 [[91.Claude Code/02-登录与API-Key.md]] §4、[[91.Claude Code/07-Subagents与工作流.md]] §10。

---

## 7. 代理 / 网络

- **公司网络/安全策略**可能拦截某些域名(连官方文档域名都可能被挡),表现为 WebFetch/更新失败。
- 配代理:
  ```bash
  export HTTPS_PROXY="http://proxy.company.com:8080"
  export HTTP_PROXY="http://proxy.company.com:8080"
  ```
  (Windows 用 `[Environment]::SetEnvironmentVariable(...,"User")` 持久化)
- 自动更新失败可临时 `DISABLE_AUTOUPDATER=1`,改用手动升级(见 [[91.Claude Code/01-安装.md]] §5)。

## 8. MCP 连接问题

| 症状 | 解法 |
|---|---|
| Windows `-- npx` 报 `Connection closed` | 改 `-- cmd /c npx -y <pkg>`(见 [[91.Claude Code/06-MCP.md]] §7) |
| server 显示 failed | `claude mcp get <name>` 看配置;`claude mcp list` 看状态 |
| 配置改了不生效 / 工具不出现 | stdio 工具会话开始才发现,**重开会话** |
| `.mcp.json` 无声失效 | JSON 非法(尾逗号/漏引号/反斜杠未转义),用校验器过一遍 |
| 远程 server 未授权 | 会话内 `/mcp` 做 OAuth 认证 |
| 项目 server 显示 Pending | 交互会话里确认批准 |

---

## 9. 上下文与性能

- 聊久了变慢/变笨,多半上下文快满:`/compact` 压缩历史保留要点,或 `/clear` 彻底重开。
- 超大仓库:用 `.claude/settings.json` 的权限收窄可读范围,或用**子代理**扫描(见 [[91.Claude Code/07-Subagents与工作流.md]]),避免主上下文爆掉。
- 长任务用 **plan 模式**先出方案,减少来回返工。

---

## 10. 实用技巧速查

| 技巧 | 怎么用 |
|---|---|
| 重活先规划 | `Shift+Tab` 切 **plan 模式**,确认方案再动手 |
| 改错了回滚 | `Esc Esc` 或 `/rewind` 回检查点(独立于 git) |
| 精准喂上下文 | `@文件`、`@目录` 引用;选区/报错直接粘 |
| 沉淀项目规则 | `#` 一键写入 CLAUDE.md;`/init` 生成首版 |
| 当 Unix 命令用 | `git diff \| claude -p "总结改动"` |
| 直接跑 shell | `!ls -la`(不经 LLM) |
| 强制纪律 | 用 **hooks** 而非提示词(见 [[32.hooks/06-claude-code-hooks.md]]) |
| 省钱省时 | 子代理/简单任务用 `haiku`/`sonnet`,难题才 `opus` |
