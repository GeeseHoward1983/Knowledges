# 07 · Subagents 与工作流

> 本篇讲**子代理(subagent)**:把任务委派给有独立上下文的"子 Claude",实现并行、隔离、专精;以及计划模式下的编排思路。
> 覆盖定义文件、`/agents`、CLI 临时定义、工具/模型限制、并行与后台、常见坑。

---

## 1. 为什么要子代理

核心价值是**上下文隔离**:与其把每一段调研都倒进主对话(很快撑满、稀释重点),不如把"支线任务"交给一个子实例——它有**自己的上下文窗口、工具集、模型**,干完只把**结论**带回来,主会话保持聚焦。

```
主会话(聚焦主线)
   │  委派"扫一遍这个模块,告诉我相关文件"
   ▼
子代理(独立上下文,自己读一堆文件)
   │  只返回一份提炼后的摘要
   ▼
主会话(拿到摘要,继续主线)
```

---

## 2. 定义子代理

子代理是 markdown 文件:**YAML frontmatter(配置)+ 正文(系统提示)**。

| 位置 | 范围 |
|---|---|
| `.claude/agents/*.md` | 项目级(随仓库) |
| `~/.claude/agents/*.md` | 用户级(跨项目) |

```markdown
---
name: code-reviewer
description: 审查代码质量与最佳实践。代码改动后主动使用。
tools: Read, Glob, Grep
model: sonnet
---
你是资深代码审查者。分析改动,就质量、安全、最佳实践给出具体、可操作的反馈。
```

同名时高优先级位置胜出。

---

## 3. `/agents` 管理界面

会话内 `/agents` 打开标签式界面:

- **Library**:列出内置 / 用户 / 项目 / 插件的全部子代理。
- **Running**:正在跑的子代理,可停止或打开查看。
- 可引导式新建、编辑、删除。**通过 `/agents` 建的子代理立即生效,无需重启**——官方推荐的管理方式。

---

## 4. CLI 临时定义(会话级)

不想存盘、只为本次测试/自动化,用 `--agents` 传 JSON:

```bash
claude --agents '{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",
    "prompt": "You are a senior code reviewer. Focus on quality, security.",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  }
}'
```

---

## 5. 工具限制(安全要点)

两个 frontmatter 字段控制工具访问:

| 字段 | 含义 |
|---|---|
| `tools` | **白名单**:写了就只能用这些;省略则继承全部工具 |
| `disallowedTools` | **黑名单**:从已有工具里减掉 |

> 🔒 **推荐实践:子代理用只读工具集**(在 `tools` 里省略 `Edit`/`Write`/`NotebookEdit`),把所有写操作/Bash 留给能处理审批弹窗的**父代理**。这样子代理既能调研,又不会绕过权限默默改文件。

---

## 6. 模型选择

`model` 字段接受:`sonnet` / `opus` / `haiku` / 完整 id(如 `claude-opus-4-7`)/ `inherit`,默认 `inherit`(继承主会话模型)。

> 经验法则:调研/扫描类子代理用 `haiku` 或 `sonnet`(快而省),需要深推理的用 `opus`。

---

## 7. 并行与后台

- **并行**:最多 **10 个**子代理同时跑。适合"把独立的子任务一次性铺开"(如分别审查多个模块)。
- **后台**:启动一个(子)任务后按 `Ctrl+B` 送后台,你继续在主会话输入;完成会通知你。

---

## 8. 计划模式里的子代理

在 **plan 模式**(见 [[91.Claude Code/03-基本使用与斜杠命令.md]] §6)下,Claude 常自动起一个 **Explore 风格子代理**去扫库,返回"相关文件/模式"的提炼地图,让主对话不被一堆文件内容撑爆。这是复杂任务规划的标准姿势。

---

## 9. 命令 vs 子代理(别混)

| | 是什么 | 怎么用 |
|---|---|---|
| **斜杠命令 / Skill** | 你手动触发的提示词/工作流 | "你随手拿起的工具" |
| **子代理** | 持久配置的执行者,主代理用 Task 工具按需 spawn | "随时待命的队友" |

---

## 10. 常见坑

> ⚠️ **子代理模型权限导致的"假成功"**:若用第三方中转 token,而某子代理默认派发到你**无权限的模型**(典型:`haiku`),会整批 **403 而静默失败**——主流程拿回**空结果**,看起来像"没发现问题",其实是没跑成。
> 排查:① 给子代理**显式指定有权限的模型**(如 `model: opus`),或去掉会解析到 haiku 的配置让它继承会话模型;② 结果异常空时,先看通知里的失败信息有无 403,再判断是不是真收敛。
> 详见 [[91.Claude Code/02-登录与API-Key.md]] §4 与 [[91.Claude Code/12-故障排查与技巧.md]]。
