# 详解PE文件(一)：PE文件基础概念

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154741703)　｜　发布：2025-11-12　｜　合集《PE文件详解》第 1/26 篇

> [!tip] 一句话核心
> **PE（Portable Executable）** 是 Windows 上一切可执行体（`.exe` / `.dll` / `.sys`）共用的"装箱格式"。一个 PE 文件 = **头部信息**（告诉加载器怎么装）+ **节数据**（真正的代码和数据）。读懂 PE，就读懂了 Windows 程序从"磁盘上的文件"到"内存中的进程"这一步是怎么发生的。

> [!info] 速查
> - **谁用 PE**：`.exe`（程序）、`.dll`（动态库）、`.sys`（驱动）、`.ocx`/`.cpl`/`.scr` 等
> - **整体结构**：DOS 头 → DOS Stub → PE 签名 → COFF 头 → 可选头 → 数据目录 → 节表 → 节数据（共 8 大部分）
> - **设计年代**：1990 年代初随 Windows NT 引入，沿用至今
> - **本篇定位**：全合集地图，后续每一篇深入一个部分

PE 格式是 Windows 平台软件执行的基础。无论是做系统编程、逆向工程、软件安全研究，还是想搞懂"双击 exe 之后发生了什么"，PE 都是绕不开的第一课。本篇先建立**全局地图**，后面 25 篇再逐个结构钻深。

## PE 文件用在哪些地方

PE 并不是 `.exe` 的专属——Windows 上几乎所有"可被加载执行的二进制"都是 PE：

| 扩展名 | 类型 | 说明 |
|---|---|---|
| `.exe` | 可执行程序 | 有入口点，可独立运行 |
| `.dll` | 动态链接库 | 被其它模块加载，导出函数供调用 |
| `.sys` | 内核驱动 | 运行在内核态的 PE |
| `.ocx` / `.cpl` / `.scr` | 控件 / 控制面板 / 屏保 | 本质都是 DLL |

它们结构相同，区别主要在 [[05-详解PE文件(五)：COFF文件头|COFF 头]] 的 `Characteristics` 标志与 [[06-详解PE文件(六)：可选头|可选头]] 的子系统/入口点设置。

## PE 文件的整体结构

把一个 PE 文件从头到尾摊开，是这样分层的——这张图建议记牢，后续每一篇都在讲其中一块：

```text
文件偏移低 ↓                         本合集对应篇目
┌───────────────────────────┐
│  DOS 头 IMAGE_DOS_HEADER   │  64B   →  [02] DOS头（含 e_lfanew 指针）
├───────────────────────────┤
│  DOS Stub 程序             │  可变  →  [03] "cannot be run in DOS mode"
├───────────────────────────┤
│  PE 签名 "PE\0\0"          │  4B    →  [04] PE 文件签名
├───────────────────────────┤
│  COFF 文件头               │  20B   →  [05] 机器类型/节数/属性
│  IMAGE_FILE_HEADER         │
├───────────────────────────┤
│  可选头 Optional Header    │  可变  →  [06] 入口点/ImageBase/子系统
│   └─ 数据目录(16 项) ──────┼──────►  [07] 指向下面各张表
├───────────────────────────┤
│  节表 Section Table        │        →  [24] 每个节的"目录"
├───────────────────────────┤
│  节数据 (.text/.data/...)  │        →  [25] 真正的代码与数据
└───────────────────────────┘
文件偏移高 ↑
```

> [!note] NT 头 = 签名 + COFF 头 + 可选头
> 习惯上把 **PE 签名 + COFF 文件头 + 可选头** 合称为 **NT 头（`IMAGE_NT_HEADERS`）**。[[02-详解PE文件(二)：DOS头|DOS 头]] 里的 `e_lfanew` 字段，指向的就是 NT 头的起点（即 PE 签名）。

| 4 | COFF 文件头 | 机器类型、节数量、文件属性 | [[05-详解PE文件(五)：COFF文件头]] |

常见的节（节数据部分）：

| 节名 | 内容 |
|---|---|
| `.text` | 可执行代码 |
| `.data` | 已初始化的可写数据 |
| `.rdata` | 只读数据（常量、导入/导出表等） |
| `.rsrc` | 资源（图标、对话框、版本信息） |
| `.reloc` | 基址重定位信息 |

## Windows 加载器如何加载 PE

理解结构后，再看"加载"就顺理成章了。加载器把磁盘上的 PE 变成内存中可运行进程，大致经历这 8 步：

```text
 ① 读 DOS 头 ── 取 e_lfanew ──► 找到 PE 头位置          [02]
        │
 ② 校验 PE 签名 "PE\0\0"                                 [04]
        │
 ③ 解析 COFF 头（机器类型/节数）                          [05]
        │
 ④ 解析可选头（入口点/ImageBase/子系统）                  [06]
        │
 ⑤ 按节表把各节映射到内存（文件偏移 → 虚拟地址）          [24][25]
        │
 ⑥ 若加载基址 ≠ ImageBase，按重定位表修正地址            [13]
        │
 ⑦ 解析导入表，加载依赖 DLL、填好导入地址表(IAT)          [08][20]
        │
 ⑧ 跳转到入口点 AddressOfEntryPoint，开始执行
```

> [!important] 文件视图 ≠ 内存视图
> PE 在**磁盘上**（文件视图）和**加载到内存后**（内存视图）的布局并不相同：节在文件里按 `FileAlignment` 对齐，在内存里按 `SectionAlignment` 对齐，位置和间隙都会变。后续多篇都会区分"文件偏移"与"RVA（相对虚拟地址）"，这是 PE 学习最容易绕晕的点，务必留意。

## 理解 PE 有什么用

> [!example] 典型应用场景
> - **逆向工程**：分析闭源或可疑程序的行为与结构
> - **调试**：看懂程序在内存中的布局、定位崩溃
> - **加壳 / 脱壳**：保护或还原程序真实代码
> - **代码注入 / Hook**：在目标进程中加载模块、拦截 API 调用
> - **安全研究**：识别异常 PE、做静态特征分析

> [!summary] 小结
> PE 是 Windows 可执行文件的统一格式，由 **DOS 头 → DOS Stub → PE 签名 → COFF 头 → 可选头 → 数据目录 → 节表 → 节数据** 八部分组成；加载器顺着 `e_lfanew` 找到 PE 头，逐层解析后把各节映射进内存并跳到入口点。建议按合集顺序往下读：先头部结构（[[02-详解PE文件(二)：DOS头|02 DOS头]] → [[06-详解PE文件(六)：可选头|06 可选头]]），再以 [[07-详解PE文件(七)：数据目录|07 数据目录]] 为枢纽展开各张功能表，最后看 [[24-详解PE文件(二十四)：节表|节]] 与 手写加载器 的实战。
