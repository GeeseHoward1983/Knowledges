# 详解PE文件(十五)：版权信息

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154744350)　｜　发布：2025-11-24　｜　合集《PE文件详解》第 15/26 篇

> [!tip] 一句话核心
> [[07-详解PE文件(七)：数据目录]] 第 7 项（索引 7，`IMAGE_DIRECTORY_ENTRY_ARCHITECTURE`）在现代 PE 中**保留为全零、基本不使用**；而我们通常说的"程序版权信息"，是以 **VERSIONINFO 资源**的形式存储在资源节 `.rsrc` 中，核心字段是 `StringFileInfo` 下的 `LegalCopyright`。

> [!info] 速查
> - **数据目录项**：索引 7，`IMAGE_DIRECTORY_ENTRY_ARCHITECTURE`，现代 PE 保留为 `0`
> - **版权实体**：资源节 `.rsrc` → `RT_VERSION` 资源类型 → `VS_VERSIONINFO` → `StringFileInfo` → `LegalCopyright`
> - **关键 API**：`GetFileVersionInfo` / `GetFileVersionInfoSize` / `VerQueryValue`
> - **常见工具**：Resource Hacker、PE Explorer、CFF Explorer
> - **所在节**：`.rsrc`（由 [[10-详解PE文件(十)：资源表]] 管辖）
> - **回链**：[[07-详解PE文件(七)：数据目录]]、[[06-详解PE文件(六)：可选头]]

## 数据目录第 7 项的实际情况

在 [[07-详解PE文件(七)：数据目录]] 列举的 16 个数据目录项中，索引 7 被称为 **Architecture Specific Data（体系结构特定数据）**，宏定义为：

```c
#define IMAGE_DIRECTORY_ENTRY_ARCHITECTURE   7   // Architecture Specific Data
```

> [!note] 现代 PE 中基本不使用
> 该目录项在 Windows PE 规范中被保留，但**现代 x86/x64 PE 文件均将其 VirtualAddress 和 Size 填为 0**，加载器不会对其进行处理。它是早期 PE 规范为多体系结构扩展预留的槽位，在实际软件开发中你几乎不会遇到非零值。分析真实 PE 文件时，看到索引 7 全为 0 是完全正常的。

数据目录项本身只有 8 字节的描述信息：

```text
数据目录第 7 项（偏移由可选头中 DataDirectory[7] 给出）
┌───────────────────────┬───────────────────────┐
│ VirtualAddress (4 字节)│    Size (4 字节)       │
│   现代 PE 通常 = 0    │   现代 PE 通常 = 0    │
└───────────────────────┴───────────────────────┘
```

数据目录在 [[06-详解PE文件(六)：可选头]] 的可选头末尾定义，共 16 项，每项 8 字节：

```text
数据目录整体位置（示意）

可选头（IMAGE_OPTIONAL_HEADER）
├── Magic / MajorLinkerVersion / ... （标准字段）
├── ImageBase / SectionAlignment / ... （Windows 专属字段）
└── DataDirectory[16]   ← 末尾 128 字节
     ├── [0]  导出表         → 09
     ├── [1]  导入表         → 08
     ├── [2]  资源表         → 10
     ├── [3]  异常表         → 11
     ├── [4]  证书表         → 12
     ├── [5]  基址重定位表   → 13
     ├── [6]  调试数据       → 14
     ├── [7]  体系结构数据   ← 本篇（现代均为 0）
     ├── [8]  全局指针       → 16
     ├── [9]  TLS 表         → 17
     ├── [10] 加载配置表     → 18
     ├── [11] 绑定导入表     → 19
     ├── [12] 导入地址表     → 20
     ├── [13] 延迟导入表     → 21
     ├── [14] CLR 运行时头   → 22
     └── [15] 保留           → 23
```

> [!warning] 逆向注意
> 恶意软件有时在数据目录的"保留/未使用"项里塞入自定义数据来绕过部分扫描器。分析时即使看到索引 7 的 Size 不为 0，也不要直接忽略——先确认是否被人为利用。

## 程序版权信息的真实存储位置

虽然数据目录第 7 项本身近乎空洞，但 Windows 程序的**版权声明**实实在在地存在于每个有版本资源的 PE 文件中。它的载体是**资源节（`.rsrc`）**，通过 `RT_VERSION` 资源类型承载，与 [[10-详解PE文件(十)：资源表]] 描述的资源目录体系配合使用。

```text
资源节 .rsrc
└── RT_VERSION（类型 ID = 16）
    └── 资源 ID（通常为 1）
        └── 语言 ID（如 0x0409 = 英语）
            └── VS_VERSIONINFO 数据块
                ├── VS_FIXEDFILEINFO    ← 二进制固定信息（版本号等）
                ├── StringFileInfo      ← 人类可读字符串，含版权
                └── VarFileInfo         ← 语言/代码页变量
```

> [!note] 和数据目录的关系
> 版权信息**不经过数据目录第 7 项**，而是通过[[07-详解PE文件(七)：数据目录]] 第 2 项（索引 2，资源表）找到 `.rsrc` 节，再按三层资源目录（类型→ID→语言）逐层定位到 `VS_VERSIONINFO` 数据块。

## VERSIONINFO 结构详解

### VS_VERSIONINFO 根结构

`VS_VERSIONINFO` 是版本资源的根节点，包含固定信息（二进制）与可变的字符串信息两部分：

| 部分 | 结构名 | 说明 |
|---|---|---|
| 根节点 | `VS_VERSIONINFO` | 整个版本资源的入口 |
| 固定信息 | `VS_FIXEDFILEINFO` | 文件版本号、产品版本号等二进制格式 |
| 字符串信息 | `StringFileInfo` | 包含版权、产品名等人类可读字段 |
| 变量信息 | `VarFileInfo` | 语言与代码页对照表 |

### VS_FIXEDFILEINFO — 二进制版本号

这部分以纯二进制存储文件和产品的版本号，固定大小 52 字节，关键字段包括：

- `dwFileVersionMS` / `dwFileVersionLS`：文件版本（如 `1.2.3.4`）
- `dwProductVersionMS` / `dwProductVersionLS`：产品版本
- `dwFileType`：文件类型（`VFT_APP`、`VFT_DLL` 等）

### StringFileInfo — 版权信息所在地

`StringFileInfo` 是版权信息真正的家，其内部按语言分为多个 `StringTable`，每个 `StringTable` 包含若干键值对字符串：

```text
StringFileInfo
└── StringTable（键：语言码 + 代码页，如 "040904B0" = 英语 + Unicode）
    ├── "CompanyName"      = "Microsoft Corporation"
    ├── "FileDescription"  = "Windows Explorer"
    ├── "FileVersion"      = "10.0.19041.1"
    ├── "InternalName"     = "explorer"
    ├── "LegalCopyright"   = "© Microsoft Corporation. All rights reserved."   ← 版权信息
    ├── "LegalTrademarks"  = ""
    ├── "OriginalFilename" = "EXPLORER.EXE"
    ├── "ProductName"      = "Microsoft® Windows® Operating System"
    └── "ProductVersion"   = "10.0.19041.1"
```

常见字符串键的含义一览：

| 键名 | 说明 |
|---|---|
| `CompanyName` | 公司名称 |
| `FileDescription` | 文件描述 |
| `FileVersion` | 文件版本（可读字符串形式） |
| `InternalName` | 内部名称 |
| `LegalCopyright` | **版权声明（核心字段）** |
| `LegalTrademarks` | 商标信息 |
| `OriginalFilename` | 原始文件名 |
| `ProductName` | 产品名称 |
| `ProductVersion` | 产品版本（可读字符串形式） |

> [!important] LegalCopyright 字段格式
> `LegalCopyright` 的值以 **UTF-16LE Unicode 字符串**存储，末尾 NULL 结尾，整体向 4 字节对齐。典型格式为：
> ```
> "LegalCopyright"="Copyright (C) 2023 Company Name. All rights reserved."
> ```
> 注意版权符号可以写作 `©`（Unicode U+00A9）或 ASCII 替代形式 `(C)`，两者均合法。

## 版权信息在二进制层面的存储

在 PE 文件的十六进制视图中，版权信息并非独立可见的连续字节块——它被嵌套在资源目录的三层树结构之后，格式如下：

```text
二进制存储示意（VS_VERSIONINFO 内 StringFileInfo 的一个 String 条目）

┌─────────────────────────────────────────────────────────┐
│  wLength       (2 字节)  : 本条目总长度（含子结构）      │
│  wValueLength  (2 字节)  : 值部分的字节数                │
│  wType         (2 字节)  : 0=二进制，1=文本              │
│  szKey         (可变)    : UTF-16LE 键名，如 "LegalCopyright\0"  │
│  Padding       (0~3 字节): 对齐到 4 字节                 │
│  Value         (可变)    : UTF-16LE 值字符串，如 "© Corp\0"       │
│  Padding       (0~3 字节): 对齐到 4 字节                 │
└─────────────────────────────────────────────────────────┘
```

> [!example] 资源节定位流程
> ```text
>    从可选头读取 DataDirectory[2]（资源表）
>           │
>           ▼
>    定位 .rsrc 节，找到 IMAGE_RESOURCE_DIRECTORY（根）
>           │
>           ▼
>    第一层：按类型过滤，找 RT_VERSION（ID = 16）
>           │
>           ▼
>    第二层：按资源 ID 过滤（通常 ID = 1）
>           │
>           ▼
>    第三层：按语言 ID 过滤（0x0409 英语 或其他）
>           │
>           ▼
>    IMAGE_RESOURCE_DATA_ENTRY → 指向实际数据偏移 + 大小
>           │
>           ▼
>    解析 VS_VERSIONINFO → StringFileInfo → LegalCopyright
> ```

## 访问版权信息的方法

### Windows API 读取

Windows 提供了一组专用 API 来读取版本资源，无需手动解析二进制：

| API | 说明 |
|---|---|
| `GetFileVersionInfoSize` | 获取版本信息块的字节数 |
| `GetFileVersionInfo` | 读取完整版本信息块到缓冲区 |
| `VerQueryValue` | 从缓冲区中按路径查询具体字段值 |

访问 `LegalCopyright` 的查询路径字符串固定格式为：

```
\\StringFileInfo\\<语言码+代码页>\\LegalCopyright
```

其中 `<语言码+代码页>` 通常先用 `\\VarFileInfo\\Translation` 查询再拼接，例如 `040904B0`（英语 + Unicode CP）。

### 常用工具查看

| 工具 | 特点 |
|---|---|
| Resource Hacker | 可视化资源树，支持编辑和导出 |
| CFF Explorer | 轻量，专注 PE 结构分析 |
| PE Explorer | 图形界面，版本信息显示友好 |
| Visual Studio | 内置资源编辑器，开发阶段最常用 |

## 版权信息的写入与修改

### 开发阶段：资源文件嵌入

开发者在 Visual Studio 项目中通过 `.rc` 资源文件或"项目属性 → 程序集信息"来填写版权信息，编译时由链接器将其写入资源节：

```
// .rc 文件片段（结构示意）
VS_VERSION_INFO VERSIONINFO
 FILEVERSION 1,0,0,1
 PRODUCTVERSION 1,0,0,1
BEGIN
    BLOCK "StringFileInfo"
    BEGIN
        BLOCK "040904b0"
        BEGIN
            VALUE "LegalCopyright", "Copyright (C) 2023 MyCompany"
            VALUE "ProductName",    "My Product"
            // ... 其他字段
        END
    END
    BLOCK "VarFileInfo"
    BEGIN
        VALUE "Translation", 0x409, 1200
    END
END
```

### 运行后修改：资源编辑工具

已编译的 PE 文件可通过 Resource Hacker 等工具直接编辑资源节，修改 `LegalCopyright` 字段后重新保存。

> [!warning] 法律合规提醒
> 修改他人软件的版权字段可能违反软件使用协议及著作权法。逆向分析时了解其格式完全正当，但在未获授权的情况下修改并再发布则属侵权行为，请务必注意法律边界。

## 版权信息的意义

| 维度 | 说明 |
|---|---|
| 法律保护 | 明确软件的版权归属，作为法律依据 |
| 来源识别 | 帮助用户/系统管理员确认软件开发者 |
| 品牌展示 | 在文件属性对话框中直接呈现公司品牌 |
| 安全分析 | 逆向工程中用于快速识别软件来源与伪造情况 |
| 版本管理 | 配合 `FileVersion` / `ProductVersion` 做软件生命周期追踪 |

> [!note] 在文件属性中查看
> Windows 资源管理器的"文件属性 → 详细信息"选项卡，展示的版权、公司、版本等信息均来自 `VS_VERSIONINFO` 的 `StringFileInfo`，底层就是本篇介绍的结构——每次右键点击一个 EXE 查看属性时，你看到的都是这套机制在工作。

> [!summary] 小结
> 数据目录第 7 项（索引 7，`IMAGE_DIRECTORY_ENTRY_ARCHITECTURE`）在现代 PE 中几乎无实际用途，VirtualAddress 和 Size 通常为 0。真正承载版权声明的是资源节中的 `VS_VERSIONINFO` 结构：`LegalCopyright` 字段位于 `StringFileInfo` 子树，以 UTF-16LE 字符串存储，可通过 Windows API（`GetFileVersionInfo` + `VerQueryValue`）或 Resource Hacker 等工具读取与修改。
>
