# 详解PE文件(二十四)：节表

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154745448)　｜　发布：2025-12-01　｜　合集《PE文件详解》第 24/26 篇

> [!tip] 一句话核心
> 节表是 PE 文件的"目录"——每个 `IMAGE_SECTION_HEADER`（40 字节）记录一个节在磁盘（`PointerToRawData`）与内存（`VirtualAddress` = RVA）中的双重坐标。**凡是需要把 RVA 换算为文件偏移的地方，都必须查节表**；几乎所有数据目录项的解析都依赖这一步。

> [!info] 速查
> - **结构体**：`IMAGE_SECTION_HEADER`
> - **单项大小**：固定 40 字节（`0x28`）
> - **节数量**：由 [[05-详解PE文件(五)：COFF文件头]] 中 `NumberOfSections` 字段决定
> - **位置**：紧跟 [[06-详解PE文件(六)：可选头]] 之后，配套 [[25-详解PE文件(二十五)：节数据]]
> - **换算核心字段**：`VirtualAddress`（RVA）+ `PointerToRawData`（文件偏移）+ `SizeOfRawData`
> - **对齐依据**：`SizeOfRawData` 与 `PointerToRawData` 均是 [[06-详解PE文件(六)：可选头]] `FileAlignment` 的整数倍

节表（Section Table）是 PE 文件中承上启下的关键数据结构：它在头部结构之后、节数据之前，以一个固定大小的数组形式，为每个节提供文件偏移与内存地址的"双坐标"映射。几乎所有对 PE 内部数据的定位——导入表、导出表、资源表……——最终都要经过节表完成从 RVA 到文件偏移的换算。理解节表，是理解整个 PE 加载与解析流程的核心一环。

## 节表在 PE 文件中的位置

节表紧跟在可选头之后，其起始偏移可以精确计算：

```text
文件偏移
0x00  ┌─────────────────────────────────────┐
      │  DOS 头 (IMAGE_DOS_HEADER)           │  64 字节
      │  e_lfanew ──────────────────────┐   │
0x40  ├─────────────────────────────────┼───┤
      │  DOS Stub 程序                   │   │
      ├─────────────────────────────────┼───┤
 e_lfanew ◄───────────────────────────┘   │
      ├─────────────────────────────────────┤
      │  PE 签名 "PE\0\0"                   │  4 字节
      ├─────────────────────────────────────┤
      │  COFF 文件头 (IMAGE_FILE_HEADER)    │  20 字节
      │    NumberOfSections ─── 节的总数    │
      │    SizeOfOptionalHeader ─────────┐  │
      ├──────────────────────────────────┼──┤
      │  可选头 (IMAGE_OPTIONAL_HEADER)   │  │  大小可变
      │    FileAlignment / SectionAlign  │  │
      ├──────────────────────────────────┘  │
 ◄────┤  节表 (Section Table)               │◄── 当前篇重点
      │    IMAGE_SECTION_HEADER[0]  40字节  │
      │    IMAGE_SECTION_HEADER[1]  40字节  │
      │    ...  × NumberOfSections          │
      ├─────────────────────────────────────┤
      │  节数据区 (.text / .data / ...)      │  见第25篇
      └─────────────────────────────────────┘
```

定位节表起始偏移的计算公式：

```text
节表起始偏移 = e_lfanew
             + 4（PE 签名）
             + 20（COFF 文件头）
             + SizeOfOptionalHeader（来自 COFF 文件头）
```

> [!note] 定位节表的标准宏
> WinNT.h 提供了宏 `IMAGE_FIRST_SECTION(pNtHeaders)`，它封装了上面的偏移计算，直接返回指向第一个 `IMAGE_SECTION_HEADER` 的指针，遍历时直接 `++` 即可。

## IMAGE_SECTION_HEADER 结构定义

每个节表项大小**固定为 40 字节（0x28）**，32 位与 64 位 PE 一致。结构定义如下：

```c
#define IMAGE_SIZEOF_SHORT_NAME 8

typedef struct _IMAGE_SECTION_HEADER {
    BYTE  Name[IMAGE_SIZEOF_SHORT_NAME]; // 节名称（8字节）
    union {
        DWORD PhysicalAddress;           // 物理地址（用于目标文件）
        DWORD VirtualSize;               // 虚拟大小（用于可执行文件）
    } Misc;
    DWORD VirtualAddress;                // 虚拟地址（RVA）
    DWORD SizeOfRawData;                 // 原始数据大小
    DWORD PointerToRawData;              // 指向原始数据的文件指针
    DWORD PointerToRelocations;          // 指向重定位表的指针
    DWORD PointerToLinenumbers;          // 指向行号表的指针
    WORD  NumberOfRelocations;           // 重定位项数
    WORD  NumberOfLinenumbers;           // 行号项数
    DWORD Characteristics;               // 节的属性
} IMAGE_SECTION_HEADER, *PIMAGE_SECTION_HEADER;
```

将 40 字节按偏移铺开对照：

| 偏移（相对节表项起始） | 字段 | 大小 | 说明 |
|---|---|---|---|
| `0x00` | `Name` | 8 字节 | 节名称，ASCII，不保证以 `\0` 结尾 |
| `0x08` | `Misc.VirtualSize` | 4 字节 | 内存中节的实际大小（可执行文件常用此字段） |
| `0x0C` ⭐ | `VirtualAddress` | 4 字节 | **节在内存中的起始 RVA**，换算的关键 |
| `0x10` | `SizeOfRawData` | 4 字节 | 节在磁盘文件中的大小（FileAlignment 对齐后） |
| `0x14` ⭐ | `PointerToRawData` | 4 字节 | **节在文件中的起始偏移**，换算的关键 |
| `0x18` | `PointerToRelocations` | 4 字节 | 重定位表指针（可执行文件通常为 0） |
| `0x1C` | `PointerToLinenumbers` | 4 字节 | 行号表指针（调试用，通常为 0） |
| `0x20` | `NumberOfRelocations` | 2 字节 | 重定位项数 |
| `0x22` | `NumberOfLinenumbers` | 2 字节 | 行号项数 |
| `0x24` ⭐ | `Characteristics` | 4 字节 | **节属性标志**（读/写/执行权限等） |

## 各字段详解

### Name — 节名称（偏移 0x00，8 字节）

- 以 ASCII 编码存储，**最多 8 字节**，可能不以 `\0` 结尾（满 8 字节时没有终止符）。
- 仅供人类阅读，Windows 加载器并不依赖节名称做任何决策——节名称可以随意修改，甚至置零，不影响加载。
- 常见节名称与其通常含义：

| 节名称 | 通常含义 |
|---|---|
| `.text` | 可执行代码段 |
| `.data` | 已初始化的全局/静态数据 |
| `.rdata` | 只读数据（字符串常量、导入表等） |
| `.bss` | 未初始化数据（BSS 段，文件中可能不占实际空间） |
| `.rsrc` | 资源数据（见数据目录中的资源表） |
| `.reloc` | 基址重定位表（见 [[13-详解PE文件(十三)：基址重定位表]]） |
| `.edata` | 导出表数据（见 [[09-详解PE文件(九)：导出表]]） |
| `.idata` | 导入表数据（见 [[08-详解PE文件(八)：导入表]]） |

> [!note] 节名称可以被混淆
> 恶意软件或加壳工具常将节名称改为无意义字符串（如 `UPX0`、随机字节）甚至置空，以混淆分析。识别节的真实用途应看 `Characteristics` 属性标志，而非节名称。

### Misc.VirtualSize — 内存中的实际大小（偏移 0x08，4 字节）

这是一个联合体字段，对可执行文件（而非 OBJ 目标文件）应读 `VirtualSize`：

- 表示节在内存中**实际使用的字节数**，是"真实大小"，未经对齐填充。
- 与 `SizeOfRawData` 的关系：`VirtualSize` 可以小于、等于或大于 `SizeOfRawData`：
  - **`VirtualSize` ≤ `SizeOfRawData`**：文件有填充字节（FileAlignment 对齐所致）。
  - **`VirtualSize` > `SizeOfRawData`**：内存中有更多空间（如 BSS 节，文件不存储未初始化数据，但内存展开时要补零到 `VirtualSize`）。

### VirtualAddress — 节的 RVA（偏移 0x0C，4 字节）

节加载到内存后，**相对于镜像基址（ImageBase）的偏移量**，即 RVA（Relative Virtual Address）。

- 绝对内存地址 = `ImageBase` + `VirtualAddress`
- 这是 **RVA → 文件偏移换算的核心输入**，见下节专门讲解。
- 必须是 [[06-详解PE文件(六)：可选头]] 中 `SectionAlignment` 的整数倍。

### SizeOfRawData — 磁盘文件中的大小（偏移 0x10，4 字节）

- 节在 PE 文件中占用的字节数，经 `FileAlignment` 向上对齐。
- 用于确定节数据在文件中的边界：`[PointerToRawData, PointerToRawData + SizeOfRawData)`。
- 若 `VirtualSize` 为零，则以此字段为准（某些链接器行为）。

### PointerToRawData — 节在文件中的偏移（偏移 0x14，4 字节）

- 节数据在 PE 文件中的**起始文件偏移**，从文件头算起。
- 必须是 `FileAlignment` 的整数倍（通常 `0x200` 的倍数）。
- 这是 **RVA → 文件偏移换算的另一个核心输入**。

### Characteristics — 节属性标志（偏移 0x24，4 字节）

描述节的属性，是一个按位组合的标志字段：

| 标志常量 | 值 | 含义 |
|---|---|---|
| `IMAGE_SCN_CNT_CODE` | `0x00000020` | 包含可执行代码 |
| `IMAGE_SCN_CNT_INITIALIZED_DATA` | `0x00000040` | 包含已初始化数据 |
| `IMAGE_SCN_CNT_UNINITIALIZED_DATA` | `0x00000080` | 包含未初始化数据（BSS） |
| `IMAGE_SCN_MEM_DISCARDABLE` | `0x02000000` | 加载完成后可丢弃 |
| `IMAGE_SCN_MEM_NOT_CACHED` | `0x04000000` | 不进行缓存 |
| `IMAGE_SCN_MEM_NOT_PAGED` | `0x08000000` | 不可换页 |
| `IMAGE_SCN_MEM_SHARED` | `0x10000000` | 节可被多进程共享 |
| `IMAGE_SCN_MEM_EXECUTE` | `0x20000000` | 内存中可执行 |
| `IMAGE_SCN_MEM_READ` | `0x40000000` | 内存中可读 |
| `IMAGE_SCN_MEM_WRITE` | `0x80000000` | 内存中可写 |

典型节的 `Characteristics` 组合：

| 节名 | 典型 Characteristics | 说明 |
|---|---|---|
| `.text` | `0x60000020` | 代码 + 可执行 + 可读 |
| `.data` | `0xC0000040` | 已初始化数据 + 可读 + 可写 |
| `.rdata` | `0x40000040` | 已初始化数据 + 只读 |
| `.reloc` | `0x42000040` | 已初始化数据 + 可丢弃 + 可读 |

> [!warning] 权限标志与安全分析
> `Characteristics` 决定节映射到内存后的页保护属性（通过 VirtualAlloc 的 `flProtect` 参数体现）。若 `.text` 节同时具有 `MEM_WRITE`，说明代码段可写——这是自修改代码或加壳程序的典型特征，也是漏洞利用（如 shellcode 注入）的常见目标，逆向时务必注意。

## RVA ↔ 文件偏移换算（核心重点）

这是节表最重要的用途，几乎所有 PE 解析工作都绕不开这一步。

### 为什么需要换算？

PE 文件存在两个视图：

```text
                  磁盘（文件视图）            内存（虚拟内存视图）
                  ┌────────────┐             ┌────────────────────────┐
  0x00 ─          │  PE 头部   │  加载器映射  │  PE 头部               │  ImageBase
                  ├────────────┤ ──────────► ├────────────────────────┤
PointerToRawData  │  .text     │   各节按    │  .text                 │  ImageBase + VA(.text)
  (文件对齐)       │  节数据    │  SectionAli │  (按 SectionAlignment  │
                  ├────────────┤  gnment     │   对齐展开，不足补零)    │
PointerToRawData  │  .data     │  重新布局   ├────────────────────────┤
                  │  节数据    │ ──────────► │  .data                 │  ImageBase + VA(.data)
                  ├────────────┤             ├────────────────────────┤
                  │  .reloc    │             │  .reloc                │
                  └────────────┘             └────────────────────────┘
  对齐：FileAlignment(0x200)                  对齐：SectionAlignment(0x1000)
```

- **文件视图**：各节紧凑排列，按 `FileAlignment`（通常 `0x200`）对齐，节间可能有填充。
- **内存视图**：加载器将各节映射到 `ImageBase + VirtualAddress`，按 `SectionAlignment`（通常 `0x1000`，即页大小）对齐，节间空白补零。

正因为两个视图的对齐单位不同，同一字节在文件中的偏移（FileOffset）和在内存中相对于 ImageBase 的偏移（RVA）并不相等，必须通过节表做换算。

### RVA → 文件偏移（最常用方向）

给定一个 RVA，找到包含它的节，然后：

```text
FileOffset = RVA - VirtualAddress + PointerToRawData
```

其中：
- `VirtualAddress`：该节的 RVA 起始（节表项中读取）
- `PointerToRawData`：该节在文件中的起始偏移（节表项中读取）

> [!example] RVA → 文件偏移换算示例
> 假设某 PE 文件有如下两个节：
>
> ```text
> 节名     VirtualAddress  SizeOfRawData  PointerToRawData
> .text    0x00001000      0x0000E200     0x00000400
> .rdata   0x00010000      0x00004A00     0x0000E600
> ```
>
> **问题**：RVA = `0x00012345` 对应的文件偏移是多少？
>
> **步骤**：
> 1. 判断 RVA 落在哪个节：
>    - `.text` 范围：`[0x1000, 0x1000 + 0xE200)` = `[0x1000, 0xF200)` → 不在
>    - `.rdata` 范围：`[0x10000, 0x10000 + 0x4A00)` = `[0x10000, 0x14A00)` → **在此节内**
> 2. 计算文件偏移：
>    ```text
>    FileOffset = 0x12345 - 0x10000 + 0x0000E600
>               = 0x02345 + 0xE600
>               = 0x10945
>    ```
> 3. 结论：文件偏移 `0x10945` 处即为 RVA `0x12345` 对应的数据。

### 文件偏移 → RVA（逆向方向）

给定文件偏移，找到包含它的节：

```text
RVA = FileOffset - PointerToRawData + VirtualAddress
```

### 换算失败的情况

> [!warning] 换算陷阱
> 以下情况会导致换算异常，需特别注意：
> - **RVA 落在 PE 头部范围内**（小于第一个节的 `VirtualAddress`）：头部在文件与内存中的相对布局一致，直接以文件偏移使用，不经节表换算。
> - **`PointerToRawData` 为 0**：节在文件中不存在对应数据（如纯 BSS 节），只在内存中占空间，无法换算为文件偏移。
> - **`SizeOfRawData` 为 0**：同上，该节在文件中无内容。
> - **RVA 落在两个节之间的空洞**：对齐填充区域，同样无法换算。

## 遍历节表示例代码

以下是一个遍历 PE 文件节表并打印信息的示例（原文）：

```c
#include <windows.h>
#include <stdio.h>

void PrintSectionHeaders(PVOID pFileBuffer) {
    PIMAGE_DOS_HEADER pDosHeader = (PIMAGE_DOS_HEADER)pFileBuffer;
    PIMAGE_NT_HEADERS pNtHeaders = (PIMAGE_NT_HEADERS)((BYTE*)pFileBuffer + pDosHeader->e_lfanew);
    PIMAGE_SECTION_HEADER pSectionHeader = IMAGE_FIRST_SECTION(pNtHeaders);

    printf("节表信息:\n");
    printf("名称\t\t虚拟地址\t虚拟大小\t原始数据大小\t原始数据指针\n");
    printf("----\t\t----\t\t----\t\t----\t\t----\n");

    for (int i = 0; i < pNtHeaders->FileHeader.NumberOfSections; i++) {
        printf("%.8s\t\t0x%08X\t0x%08X\t0x%08X\t\t0x%08X\n",
               pSectionHeader->Name,
               pSectionHeader->VirtualAddress,
               pSectionHeader->Misc.VirtualSize,
               pSectionHeader->SizeOfRawData,
               pSectionHeader->PointerToRawData);
        pSectionHeader++;
    }
}
```

关键路径分析：

```text
pFileBuffer（文件映射基址）
    │
    ├─ +0x00 → IMAGE_DOS_HEADER
    │          └─ e_lfanew ──────────────────────────┐
    │                                                │
    └─ +e_lfanew → IMAGE_NT_HEADERS ◄───────────────┘
                   ├─ FileHeader.NumberOfSections  （循环上限）
                   └─ IMAGE_FIRST_SECTION() ──────────┐
                                                      │
                       IMAGE_SECTION_HEADER[0] ◄──────┘
                       IMAGE_SECTION_HEADER[1]  （每次 ++ 移动 40 字节）
                       ...
                       IMAGE_SECTION_HEADER[N-1]
```

> [!important] `IMAGE_FIRST_SECTION` 的本质
> 该宏的展开等价于：
> ```c
> (IMAGE_SECTION_HEADER*)((BYTE*)&pNtHeaders->OptionalHeader
>                          + pNtHeaders->FileHeader.SizeOfOptionalHeader)
> ```
> 这正是"跳过可选头"找到节表起始的标准方式，与手工计算偏移完全等价。

## 文件视图与内存视图对比

下表以常见的三节 PE 文件为例，直观展示两种视图的差异：

```text
文件视图（FileAlignment = 0x200）
┌─────────────────────────────────┐
│ PE 头部（DOS头+NT头+节表）        │  0x000 ~ 0x3FF  (0x400 字节)
├─────────────────────────────────┤
│ .text 节数据                     │  0x400 ~ 0xE5FF (PointerToRawData=0x400)
├─────────────────────────────────┤
│ .rdata 节数据                    │  0xE600 ~ ...
├─────────────────────────────────┤
│ .data 节数据                     │
└─────────────────────────────────┘
节间距 = FileAlignment 的倍数

内存视图（SectionAlignment = 0x1000，ImageBase = 0x400000）
┌─────────────────────────────────┐
│ PE 头部                          │  0x400000 ~ 0x400FFF  (1 页)
├─────────────────────────────────┤
│ .text 节                         │  0x401000 ~ 0x40EFFF  (VirtualAddress=0x1000)
│ （不足整页的部分补零）             │
├─────────────────────────────────┤
│ .rdata 节                        │  0x410000 ~ ...       (VirtualAddress=0x10000)
├─────────────────────────────────┤
│ .data 节                         │
└─────────────────────────────────┘
节间距 = SectionAlignment (0x1000) 的倍数
```

> [!note] 对齐与空洞
> 文件视图中节之间的填充字节（`FileAlignment` 对齐所致）是无意义的零填充，不对应任何内存内容。内存视图中节之间的空洞（`SectionAlignment` 对齐所致）同样补零，但归属于各节的"尾部填充"。这些空白区域都不在合法的 RVA 换算范围内。

> [!summary] 小结
> 节表是连接 PE 文件"磁盘存储"与"内存映射"两个视图的桥梁。每个 `IMAGE_SECTION_HEADER`（40 字节）提供的 `VirtualAddress`（RVA）和 `PointerToRawData`（文件偏移）这对坐标，是解析任何 PE 内部数据结构时都绕不开的换算基础。节数量由 [[05-详解PE文件(五)：COFF文件头]] 的 `NumberOfSections` 决定，对齐参数来自 [[06-详解PE文件(六)：可选头]] 的 `FileAlignment` 与 `SectionAlignment`，具体节数据内容见 [[25-详解PE文件(二十五)：节数据]]。在逆向分析中，还需注意 `Characteristics` 权限标志异常（可写的代码段）和节名称混淆（不可信赖）等安全相关特征。
