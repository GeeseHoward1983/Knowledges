# 详解PE文件(九)：导出表

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154742838)　｜　发布：2025-11-19　｜　合集《PE文件详解》第 9/26 篇

> [!tip] 一句话核心
> 导出表是 DLL 的"**对外函数菜单**"——它告诉别人：我提供哪些函数、各自的序号和地址。它与上一篇 [[08-详解PE文件(八)：导入表|导入表]] 正好是一对：一方"导出"，一方"导入"。核心机制是**三张数组协作**：地址表（EAT）、名称表（ENT）、序号表（EOT）。`GetProcAddress` 的底层就是查这三张表。

> [!info] 速查
> - **数据目录索引**：0（`IMAGE_DIRECTORY_ENTRY_EXPORT`，见 [[07-详解PE文件(七)：数据目录|数据目录]]）
> - **核心结构**：`IMAGE_EXPORT_DIRECTORY`
> - **三张表**：EAT（地址）/ ENT（名称）/ EOT（序号）
> - **典型宿主**：DLL（EXE 也可有导出表，少见）
> - **对偶篇**：[[08-详解PE文件(八)：导入表|导入表]]

导出表主要用于描述 DLL 或其他可执行文件向外部提供的函数和变量信息。通过它，其他程序可以按名称或序号访问、调用这些导出的符号。

## 导出表概述

导出表记录模块（通常是 DLL）导出的函数、变量和其他符号，允许外部模块访问当前模块公开的接口。它记录了可供外部调用的函数名称、序号及其对应地址。

## 导出表结构

导出表的核心是 `IMAGE_EXPORT_DIRECTORY` 结构：

```c
typedef struct _IMAGE_EXPORT_DIRECTORY {
    DWORD   Characteristics;        // 未使用，恒为0
    DWORD   TimeDateStamp;          // 时间戳
    WORD    MajorVersion;           // 主版本号
    WORD    MinorVersion;           // 次版本号
    DWORD   Name;                   // 模块名称的RVA
    DWORD   Base;                   // 起始序号
    DWORD   NumberOfFunctions;      // 导出函数的总数
    DWORD   NumberOfNames;          // 按名称导出的函数数量
    DWORD   AddressOfFunctions;     // 导出函数地址表的RVA
    DWORD   AddressOfNames;         // 导出函数名称表的RVA
    DWORD   AddressOfNameOrdinals;  // 导出函数序号表的RVA
} IMAGE_EXPORT_DIRECTORY, *PIMAGE_EXPORT_DIRECTORY;
```

按偏移与作用归类：

| 偏移 | 字段 | 作用 |
|---|---|---|
| 0x00 | `Characteristics` | 保留，恒为 0 |
| 0x04 | `TimeDateStamp` | 时间戳（同文件头） |
| 0x08 | `MajorVersion`/`MinorVersion` | 版本号 |
| 0x0C | `Name` | 模块名字符串 RVA |
| 0x10 | `Base` ⭐ | 序号起始值 |
| 0x14 | `NumberOfFunctions` ⭐ | 导出函数总数（= EAT 项数） |
| 0x18 | `NumberOfNames` ⭐ | 按名导出的数量（= ENT/EOT 项数） |
| 0x1C | `AddressOfFunctions` | **EAT**：地址表 RVA |
| 0x20 | `AddressOfNames` | **ENT**：名称表 RVA |
| 0x24 | `AddressOfNameOrdinals` | **EOT**：序号表 RVA |

> [!important] NumberOfFunctions ≠ NumberOfNames
> 一个函数可以**只按序号导出而没有名字**，所以 `NumberOfFunctions`（地址表长度）通常 ≥ `NumberOfNames`（名称表长度）。这是导出表最易混淆处，下面三表协作图会讲清楚。

## 三表协作：从函数名到地址

这是导出表的精髓——`GetProcAddress(hDll, "Foo")` 内部就是这套查找：

```text
ENT 名称表(已排序)     EOT 序号表          EAT 地址表
AddressOfNames        AddressOfNameOrdinals  AddressOfFunctions
┌───────────┐ i      ┌──────────┐ i        ┌──────────────┐
│ "AbortDoc"│──────► │ ordinal=2│────────► │[0] 0x00011000│
│ "AddFontA"│        │ ordinal=5│          │[1] 0x00012000│
│ "BeginPath│        │ ordinal=0│          │[2] 0x00013000│◄─ 命中
└───────────┘        └──────────┘          │ ...          │
  ① 在 ENT 里        ② 取相同下标 i        │[ordinal]→地址│
   二分查找名字          得到 ordinal       └──────────────┘
                                          ③ EAT[ordinal] = 函数 RVA
对外序号 = ordinal + Base
```

三步走：① 在**有序**的 ENT 里二分查找函数名，得到下标 `i`；② 用 `i` 去 EOT 取出 `ordinal`；③ 用 `ordinal` 索引 EAT 得到函数地址 RVA。对外公布的序号 = `ordinal + Base`。

## 三张关键数组

1. **导出函数地址表（EAT — Export Address Table）**
   - 由 `AddressOfFunctions` 指向，是 `DWORD` 数组，存所有导出函数地址
   - 数组索引对应函数序号（从 `Base` 开始）
2. **导出函数名称表（ENT — Export Name Table）**
   - 由 `AddressOfNames` 指向，`DWORD` 数组，每个元素指向一个函数名字符串
   - 只包含**按名称导出**的函数，且**按字母排序**（支持二分查找）
3. **导出函数序号表（EOT — Export Ordinal Table）**
   - 由 `AddressOfNameOrdinals` 指向，`WORD` 数组，把"名字下标"映射到"地址表下标"

## 函数导出方式

### 1. 按名称导出

1. 在导出函数名称表中查找函数名称
2. 通过名称找到对应的序号（在序号表中）
3. 使用序号作为索引在地址表中找到函数地址

### 2. 按序号导出

1. 直接使用 `序号 - Base` 作为索引在地址表中查找函数地址
2. 这种方式更快速，但可读性较差（逆向时只见序号、不见名字）

## 导出表在 PE 文件中的位置

导出表的位置和大小存储在 [[07-详解PE文件(七)：数据目录|可选头的数据目录]]中，索引为 `IMAGE_DIRECTORY_ENTRY_EXPORT`（值为 0）：

```c
// 数据目录中的导出表项
DataDirectory[IMAGE_DIRECTORY_ENTRY_EXPORT]
```

## 实际示例

以下是一个遍历 PE 文件导出表的示例代码：

```c
#include <windows.h>
#include <stdio.h>

void PrintExportTable(const char* filename) {
    HANDLE hFile = CreateFile(filename, GENERIC_READ, FILE_SHARE_READ,
                              NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);

    if (hFile == INVALID_HANDLE_VALUE) {
        printf("无法打开文件: %s\n", filename);
        return;
    }

    HANDLE hMapping = CreateFileMapping(hFile, NULL, PAGE_READONLY, 0, 0, NULL);
    if (!hMapping) {
        printf("创建文件映射失败\n");
        CloseHandle(hFile);
        return;
    }

    LPVOID lpBase = MapViewOfFile(hMapping, FILE_MAP_READ, 0, 0, 0);
    if (!lpBase) {
        printf("映射文件失败\n");
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取DOS头
    IMAGE_DOS_HEADER* dosHeader = (IMAGE_DOS_HEADER*)lpBase;

    // 验证DOS签名
    if (dosHeader->e_magic != IMAGE_DOS_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取NT头
    IMAGE_NT_HEADERS* ntHeaders = (IMAGE_NT_HEADERS*)((BYTE*)lpBase + dosHeader->e_lfanew);

    // 验证PE签名
    if (ntHeaders->Signature != IMAGE_NT_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取导出表信息
    IMAGE_DATA_DIRECTORY* exportDir = &ntHeaders->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_EXPORT];
    if (exportDir->VirtualAddress == 0) {
        printf("该文件没有导出表\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取导出表目录
    IMAGE_EXPORT_DIRECTORY* exportDirStruct = (IMAGE_EXPORT_DIRECTORY*)((BYTE*)lpBase + exportDir->VirtualAddress);

    // 获取模块名称
    char* moduleName = (char*)((BYTE*)lpBase + exportDirStruct->Name);
    printf("=== 导出表信息 ===\n");
    printf("模块名称: %s\n", moduleName);
    printf("起始序号: %d\n", exportDirStruct->Base);
    printf("导出函数总数: %d\n", exportDirStruct->NumberOfFunctions);
    printf("按名称导出函数数: %d\n", exportDirStruct->NumberOfNames);

    // 获取三个关键数组
    DWORD* addressTable = (DWORD*)((BYTE*)lpBase + exportDirStruct->AddressOfFunctions);
    DWORD* nameTable = (DWORD*)((BYTE*)lpBase + exportDirStruct->AddressOfNames);
    WORD* ordinalTable = (WORD*)((BYTE*)lpBase + exportDirStruct->AddressOfNameOrdinals);

    printf("\n导出函数列表:\n");

    // 遍历按名称导出的函数
    for (DWORD i = 0; i < exportDirStruct->NumberOfNames; i++) {
        char* functionName = (char*)((BYTE*)lpBase + nameTable[i]);
        WORD ordinal = ordinalTable[i];
        DWORD functionAddress = addressTable[ordinal];

        printf("序号: %d, 名称: %s, 地址: 0x%08X\n",
               ordinal + exportDirStruct->Base, functionName, functionAddress);
    }

    UnmapViewOfFile(lpBase);
    CloseHandle(hMapping);
    CloseHandle(hFile);
}
```

代码正是三表协作的实现：`nameTable[i]`（ENT）取名字 → `ordinalTable[i]`（EOT）取 `ordinal` → `addressTable[ordinal]`（EAT）取地址。

## 导出表的重要性

| 价值 | 说明 |
|---|---|
| **模块化设计** | DLL 向外提供功能接口 |
| **代码重用** | 多个程序共享同一 DLL |
| **动态链接** | 支持运行时 `GetProcAddress` 解析 |
| **逆向工程** | 导出表就是一份现成的"API 清单" |

## 转发导出（Forwarder RVA）

### 什么是转发导出

在 EAT（导出地址表，`AddressOfFunctions`）中，每一项正常情况下存放的是**函数在本 DLL 内的 RVA**。但有一种特殊情况：如果该 RVA 落在**导出目录自身的 RVA 范围**（即 `DataDirectory[0].VirtualAddress` 到 `VirtualAddress + Size` 之间），则这个值不是函数地址，而是一个**指向 ASCII 字符串的 RVA**，格式为：

```
DllName.FunctionName
```

或按序号转发：

```
DllName.#Ordinal
```

这就是"**转发导出（Forwarder RVA）**"：本 DLL 没有自己实现这个函数，而是把调用者重定向到另一个 DLL 的另一个函数。

### 判断是否为转发的伪代码

```c
IMAGE_EXPORT_DIRECTORY *exp = ...;
IMAGE_DATA_DIRECTORY   *dir = &ntHeaders->OptionalHeader.DataDirectory[0];

DWORD expStart = dir->VirtualAddress;
DWORD expEnd   = expStart + dir->Size;

DWORD *eat = (DWORD*)(base + exp->AddressOfFunctions);
for (DWORD i = 0; i < exp->NumberOfFunctions; i++) {
    DWORD rva = eat[i];
    if (rva == 0) continue;  // 该序号未导出

    if (rva >= expStart && rva < expEnd) {
        // Forwarder RVA：指向字符串
        char *fwd = (char*)(base + rva);
        printf("Ordinal %lu -> FORWARD: %s\n", i + exp->Base, fwd);
        // fwd 形如 "KERNELBASE.CreateFileW" 或 "ntdll.#301"
    } else {
        printf("Ordinal %lu -> RVA 0x%08X\n", i + exp->Base, rva);
    }
}
```

### 典型转发链：ntdll / KernelBase / kernel32

Windows 系统 DLL 大量使用转发导出，构成层叠的"转发链"：

```text
kernel32.dll  ExportTable
  CreateFileW  →  Forwarder: "KERNELBASE.CreateFileW"
       │
       ▼
kernelbase.dll  ExportTable
  CreateFileW  →  RVA 0x12345  (真正实现)

ntdll.dll  ExportTable
  RtlAllocateHeap  →  真正实现（在 ntdll 内部）
  HeapAlloc        →  Forwarder: "ntdll.RtlAllocateHeap"
                       ↑ 这里 ntdll 自己转发给自己的另一个名字
```

常见转发关系速查：

| 调用者所见的 DLL | 导出名 | 实际实现 |
|---|---|---|
| `kernel32.dll` | `CreateFileW` | `KernelBase.dll!CreateFileW` |
| `kernel32.dll` | `HeapAlloc` | `ntdll.dll!RtlAllocateHeap` |
| `kernel32.dll` | `GetProcAddress` | `KernelBase.dll!GetProcAddress` |
| `advapi32.dll` | `RegOpenKeyExW` | `KernelBase.dll!RegOpenKeyExW` |
| `ntdll.dll` | `HeapAlloc` | `ntdll.dll!RtlAllocateHeap`（自转发） |

这种设计的目的是：
1. **向后兼容**：旧程序导入 `kernel32.CreateFileW`，API 重构后实现移到 `KernelBase` 不影响旧代码。
2. **最小化内存占用**：`KernelBase.dll` 在 Win7+ 才独立出来，之前代码全在 `kernel32` 里；分拆后转发让两者无需重复实现。
3. **分层架构**：ntdll 是用户态最底层（直接 syscall），kernel32/KernelBase 在其上封装，转发是这一层次结构的实现手段。

### dumpbin 查看转发导出

```cmd
:: 查看 kernel32 的转发项（输出中 [转发]) 标注了转发目标)
dumpbin /exports C:\Windows\System32\kernel32.dll | findstr -i "forward"

:: 完整导出列表（转发项格式：函数名 -> 目标字符串）
dumpbin /exports C:\Windows\System32\kernel32.dll
```

`dumpbin` 输出中转发项格式示例：

```text
   1    0 00000000 CreateFileA (forwarded to KERNELBASE.CreateFileA)
   2    1 00000000 CreateFileW (forwarded to KERNELBASE.CreateFileW)
```

CFF Explorer 在 Export Directory 视图中会在 "Function RVA" 列直接显示 `[FORWARD] KernelBase.CreateFileW` 而非数字 RVA。

### 逆向时的迷惑点与注意事项

1. **地址显示为 0**：`dumpbin`/CFF Explorer 对转发项显示的函数 RVA 为 0（因为不是函数地址），初学者常误以为该导出无效——实际上是转发，运行时 `GetProcAddress` 会**自动跟随转发**，返回最终函数地址。

2. **`GetProcAddress` 自动追踪**：`GetProcAddress(hKernel32, "CreateFileW")` 会自动跟随转发链，最终返回 `KernelBase!CreateFileW` 的地址，开发者无需手动处理。但**手写加载器**（如 Shellcode 中的 `GetProcAddress` 实现）若不处理 Forwarder RVA，会把字符串地址当函数指针调用，直接崩溃。

3. **反调试 / 壳的利用**：某些壳会在内存中动态修改 EAT，将合法函数替换为转发字符串指向自定义 Hook DLL，绕过静态分析（静态分析看到的 EAT 与运行时不同）。

4. **二进制扫描工具的盲区**：某些 YARA 规则扫描导入/导出函数名，但不检查转发链。恶意程序可通过"把危险 API 藏在转发链末端的非标准 DLL"欺骗规则引擎。

5. **按序号转发（`DllName.#N`）**：转发目标也可以是序号形式（`ntdll.#301`），此时加载器用序号在目标 DLL 的 EAT 中查找，同样自动完成。

> [!summary] 小结
> 导出表（`IMAGE_EXPORT_DIRECTORY`）是 DLL 对外的函数菜单，靠 **EAT（地址）+ ENT（名称）+ EOT（序号）** 三张表协作完成"按名→序号→地址"的查找——这正是 `GetProcAddress` 与 [[08-详解PE文件(八)：导入表|导入表]] 解析、以及 [[26-详解PE文件(二十六)手写Loadlibrary|手写加载器]] 取函数地址的共同基础。记住 `NumberOfFunctions ≥ NumberOfNames`（存在只按序号导出的函数）。当 EAT 中的 RVA 落在导出目录自身范围内时，它是**转发 RVA**（Forwarder RVA），指向 `DLL.Function` 字符串而非函数地址——`GetProcAddress` 自动追踪，但手写加载器必须显式处理，这是复现系统加载行为最容易漏掉的细节。
