# 详解PE文件(六)：可选头

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154742634)　｜　发布：2025-11-18　｜　合集《PE文件详解》第 6/26 篇

> [!tip] 一句话核心
> 可选头是 NT 头里**最大、信息最密**的一块。名字叫"可选"，对 EXE/DLL 却是**必需**。它回答四个加载关键问题：**从哪开始执行**（`AddressOfEntryPoint`）、**想加载到哪**（`ImageBase`）、**给哪种界面跑**（`Subsystem`），以及末尾那 16 项 [[07-详解PE文件(七)：数据目录|数据目录]] **各张表在哪**。

> [!info] 速查
> - **结构体**：`IMAGE_OPTIONAL_HEADER32`（32 位）/ `IMAGE_OPTIONAL_HEADER64`（PE32+）
> - **大小**：32 位约 224 字节（`0xE0`）/ 64 位约 240 字节（`0xF0`），由 [[05-详解PE文件(五)：COFF文件头|SizeOfOptionalHeader]] 给出
> - **类型判别**：`Magic` = `0x10B`（32 位）/ `0x20B`（PE32+）
> - **重点字段**：`AddressOfEntryPoint`、`ImageBase`、`SectionAlignment`/`FileAlignment`、`Subsystem`、`DataDirectory`

可选头紧跟在 [[05-详解PE文件(五)：COFF文件头|文件头（IMAGE_FILE_HEADER）]] 之后，包含 Windows 加载器加载和执行程序所需的关键信息，其大小由文件头中的 `SizeOfOptionalHeader` 字段指定。

## 可选头的两种结构

可选头分为两种类型，靠 `Magic` 区分：

1. `IMAGE_OPTIONAL_HEADER32` —— 用于 32 位 PE 文件
2. `IMAGE_OPTIONAL_HEADER64` —— 用于 64 位 PE32+ 文件

### IMAGE_OPTIONAL_HEADER32 结构

```c
typedef struct _IMAGE_OPTIONAL_HEADER {
    // 标准域
    WORD    Magic;                      // 魔数，标识PE文件类型
    BYTE    MajorLinkerVersion;         // 链接器主版本号
    BYTE    MinorLinkerVersion;         // 链接器次版本号
    DWORD   SizeOfCode;                 // 代码节大小
    DWORD   SizeOfInitializedData;      // 已初始化数据大小
    DWORD   SizeOfUninitializedData;    // 未初始化数据大小
    DWORD   AddressOfEntryPoint;        // 程序入口点RVA
    DWORD   BaseOfCode;                 // 代码节起始RVA
    DWORD   BaseOfData;                 // 数据节起始RVA

    // NT额外域
    DWORD   ImageBase;                  // 镜像加载基地址
    DWORD   SectionAlignment;           // 内存中节对齐值
    DWORD   FileAlignment;              // 文件中节对齐值
    WORD    MajorOperatingSystemVersion; // 所需操作系统主版本号
    WORD    MinorOperatingSystemVersion; // 所需操作系统次版本号
    WORD    MajorImageVersion;          // 镜像主版本号
    WORD    MinorImageVersion;          // 镜像次版本号
    WORD    MajorSubsystemVersion;      // 子系统主版本号
    WORD    MinorSubsystemVersion;      // 子系统次版本号
    DWORD   Win32VersionValue;          // 保留，必须为0
    DWORD   SizeOfImage;                // 内存中镜像大小
    DWORD   SizeOfHeaders;              // 所有头大小总和
    DWORD   CheckSum;                   // 校验和
    WORD    Subsystem;                  // 子系统类型
    WORD    DllCharacteristics;         // DLL特性
    DWORD   SizeOfStackReserve;         // 保留栈大小
    DWORD   SizeOfStackCommit;          // 初始提交栈大小
    DWORD   SizeOfHeapReserve;          // 保留堆大小
    DWORD   SizeOfHeapCommit;           // 初始提交堆大小
    DWORD   LoaderFlags;                // 加载器标志
    DWORD   NumberOfRvaAndSizes;        // 数据目录项数
    IMAGE_DATA_DIRECTORY DataDirectory[IMAGE_NUMBEROF_DIRECTORY_ENTRIES]; // 数据目录
} IMAGE_OPTIONAL_HEADER32, *PIMAGE_OPTIONAL_HEADER32;
```

### IMAGE_OPTIONAL_HEADER64 结构

```c
typedef struct _IMAGE_OPTIONAL_HEADER64 {
    // 标准域
    WORD    Magic;                      // 魔数，标识PE文件类型
    BYTE    MajorLinkerVersion;         // 链接器主版本号
    BYTE    MinorLinkerVersion;         // 链接器次版本号
    DWORD   SizeOfCode;                 // 代码节大小
    DWORD   SizeOfInitializedData;      // 已初始化数据大小
    DWORD   SizeOfUninitializedData;    // 未初始化数据大小
    DWORD   AddressOfEntryPoint;        // 程序入口点RVA
    DWORD   BaseOfCode;                 // 代码节起始RVA

    // NT额外域
    ULONGLONG ImageBase;                // 镜像加载基地址
    DWORD   SectionAlignment;           // 内存中节对齐值
    DWORD   FileAlignment;              // 文件中节对齐值
    WORD    MajorOperatingSystemVersion; // 所需操作系统主版本号
    WORD    MinorOperatingSystemVersion; // 所需操作系统次版本号
    WORD    MajorImageVersion;          // 镜像主版本号
    WORD    MinorImageVersion;          // 镜像次版本号
    WORD    MajorSubsystemVersion;      // 子系统主版本号
    WORD    MinorSubsystemVersion;      // 子系统次版本号
    DWORD   Win32VersionValue;          // 保留，必须为0
    DWORD   SizeOfImage;                // 内存中镜像大小
    DWORD   SizeOfHeaders;              // 所有头大小总和
    DWORD   CheckSum;                   // 校验和
    WORD    Subsystem;                  // 子系统类型
    WORD    DllCharacteristics;         // DLL特性
    ULONGLONG SizeOfStackReserve;       // 保留栈大小
    ULONGLONG SizeOfStackCommit;        // 初始提交栈大小
    ULONGLONG SizeOfHeapReserve;        // 保留堆大小
    ULONGLONG SizeOfHeapCommit;         // 初始提交堆大小
    DWORD   LoaderFlags;                // 加载器标志
    DWORD   NumberOfRvaAndSizes;        // 数据目录项数
    IMAGE_DATA_DIRECTORY DataDirectory[IMAGE_NUMBEROF_DIRECTORY_ENTRIES]; // 数据目录
} IMAGE_OPTIONAL_HEADER64, *PIMAGE_OPTIONAL_HEADER64;
```

> [!note] PE32 与 PE32+ 的差异
> 对照两个结构体，差异集中在"指针类宽度"上：
>
> | 维度 | PE32（32 位） | PE32+（64 位） |
> |---|---|---|
> | `Magic` | `0x10B` | `0x20B` |
> | `ImageBase` | `DWORD`（4 字节） | `ULONGLONG`（8 字节） |
> | `BaseOfData` | **有** | **无**（被宽 ImageBase 顶掉） |
> | 栈/堆 4 个字段 | `DWORD`（4 字节） | `ULONGLONG`（8 字节） |
> | 典型大小 | 224 字节（`0xE0`） | 240 字节（`0xF0`） |
>
> 因此解析可选头**必须先看 `Magic`**，再决定按 32 位还是 64 位布局去读后续字段——这是手写解析器最容易踩的坑。

## 关键字段详解

### Magic（偏移 0x00，2 字节）

标识 PE 文件类型：`0x10B` = 32 位 PE，`0x20B` = 64 位 PE32+，`0x107` = ROM 镜像。

### AddressOfEntryPoint（入口点 RVA）

程序入口点的相对虚拟地址（RVA）。文件加载到内存后，加载器把控制权交给 `ImageBase + AddressOfEntryPoint`。对 DLL 是可选的，可以为 0。

### ImageBase（首选加载基址）

| 文件类型 | 典型 ImageBase |
|---|---|
| EXE | `0x00400000` |
| DLL | `0x10000000` |
| 64 位 PE32+ | `0x0000000140000000` |

> [!warning] ImageBase 与重定位
> 如果加载时该基址被占用（如 ASLR 或多个 DLL 冲突），加载器会把映像放到别处，并依据 [[13-详解PE文件(十三)：基址重定位表|基址重定位表]] 修正所有硬编码地址。`ImageBase` 只是"首选"，不是"保证"。

### SectionAlignment / FileAlignment（两套对齐）

这是 PE"文件视图 ≠ 内存视图"的根源：

- `SectionAlignment`：节在**内存**中的对齐，通常 `0x1000`（4KB，一个内存页）。
- `FileAlignment`：节在**文件**中的对齐，通常 `0x200`（512 字节）。

```text
文件视图 (FileAlignment=0x200)         内存视图 (SectionAlignment=0x1000)
┌──────────────┐ 0x000                ┌──────────────┐ ImageBase+0x0000
│ 头部          │                      │ 头部(映射)    │
├──────────────┤ 0x400                ├──────────────┤ +0x1000
│ .text        │  紧凑(512 对齐)       │ .text        │  页对齐(4KB)
├──────────────┤ 0x600                ├──────────────┤ +0x2000
│ .data        │                      │ .data        │
└──────────────┘                      └──────────────┘
   小、连续                              大、按页、节间有空隙
```

同一个节，在文件里的偏移和在内存里的 RVA 通常不同——这正是后续"RVA ↔ 文件偏移"换算的由来（详见 [[24-详解PE文件(二十四)：节表|节表]]）。

### SizeOfImage / SizeOfHeaders

- `SizeOfImage`：加载到内存后整个镜像大小，必须是 `SectionAlignment` 的倍数。
- `SizeOfHeaders`：所有头（含节表）的总大小，必须是 `FileAlignment` 的倍数。

### Subsystem（子系统）

指定运行此映像所需的子系统，最常见的是 GUI 与 CUI：

| 值 | 子系统 |
|---|---|
| 1 | 本机（Native，多为驱动） |
| 2 | Windows GUI（图形界面） |
| 3 | Windows CUI（控制台） |
| 5 | OS/2 CUI |
| 7 | POSIX CUI |
| 9 | Windows CE GUI |
| 10~13 | EFI 应用 / 驱动 / ROM |
| 14 | XBOX |

### DllCharacteristics（DLL 特性）

| 标志 | 含义 |
|---|---|
| 0x0040 | DLL 可以被隔离运行（可重定位，ASLR 相关） |
| 0x0080 | 不使用结构化异常处理 |
| 0x0100 | 不绑定镜像 |
| 0x8000 | 强制完整性检查 |

### DllCharacteristics 安全标志与 CheckSum

#### IMAGE_DLLCHARACTERISTICS_* 逐位详解

`DllCharacteristics` 是一个 16 位位掩码，每一位启用或关闭一项安全/行为特性。Windows 加载器与安全机制会在映像加载时检查这些位。

| 宏名 | 值 | 含义与原理 |
|---|---|---|
| `IMAGE_DLLCHARACTERISTICS_HIGH_ENTROPY_VA` | `0x0020` | **高熵 64 位 ASLR（HIGH_ENTROPY_VA）**：仅对 PE32+（64 位）有效，允许加载器在整个 64 位虚拟地址空间中随机化基址，熵远高于 32 位 ASLR 的约 8 位随机量（64 位可达约 19 位），大幅增加暴力猜测基址的难度 |
| `IMAGE_DLLCHARACTERISTICS_DYNAMIC_BASE` | `0x0040` | **ASLR（地址空间布局随机化）**：标记映像可被重定位到随机基址。加载器在加载时若此位置位，会随机选择内存基址并用 [[13-详解PE文件(十三)：基址重定位表|重定位表]] 修正所有绝对地址。若未置位则优先按 `ImageBase` 加载，ASLR 不生效 |
| `IMAGE_DLLCHARACTERISTICS_FORCE_INTEGRITY` | `0x0080` | **强制代码完整性检查**：加载器必须验证 [[12-详解PE文件(十二)：证书表|Authenticode 签名]] 有效，否则拒绝加载。常见于内核驱动。注意此位与 `CheckSum` 校验是独立机制 |
| `IMAGE_DLLCHARACTERISTICS_NX_COMPAT` | `0x0100` | **DEP 兼容（数据执行保护，NX_COMPAT）**：告知加载器此映像兼容 DEP（硬件 NX/XD 位），加载器会启用 DEP 保护进程，使数据页（栈/堆）不可执行，阻止经典栈缓冲区溢出 shellcode 执行 |
| `IMAGE_DLLCHARACTERISTICS_NO_ISOLATION` | `0x0200` | **禁用 SxS 清单隔离**：不为此映像查找/使用 SxS（Side-by-Side）清单资源，少见 |
| `IMAGE_DLLCHARACTERISTICS_NO_SEH` | `0x0400` | **禁用结构化异常处理（NO_SEH）**：声明映像中没有 SEH 处理程序，也不能通过 SEH 链调用任何处理例程。结合 SafeSEH（在加载配置表中注册合法处理程序列表）可阻止经典 SEH 覆写攻击 |
| `IMAGE_DLLCHARACTERISTICS_NO_BIND` | `0x0800` | **禁止绑定**：禁止对此映像执行 [[19-详解PE文件(十九)：绑定配置表|绑定导入]]，确保每次加载都走正常 IAT 解析路径 |
| `IMAGE_DLLCHARACTERISTICS_APPCONTAINER` | `0x1000` | **AppContainer 执行**：映像必须在 AppContainer 沙箱进程中运行（UWP/Metro 应用专用） |
| `IMAGE_DLLCHARACTERISTICS_WDM_DRIVER` | `0x2000` | **WDM 驱动程序**：标记为 Windows 驱动模型驱动 |
| `IMAGE_DLLCHARACTERISTICS_GUARD_CF` | `0x4000` | **控制流保护（CFG，GUARD_CF）**：与 [[18-详解PE文件(十八)：加载配置表|加载配置表]] 中的 `GuardCFFunctionTable` 配合，由 Windows 内核在每次间接调用/跳转前检查目标地址是否在合法函数表内，阻止 ROP（面向返回的编程）和 JOP 链 |
| `IMAGE_DLLCHARACTERISTICS_TERMINAL_SERVER_AWARE` | `0x8000` | **终端服务器感知**：旧版标志，标明应用程序已适配多会话终端服务环境 |

> [!tip] 快速查看安全标志的命令
> ```cmd
> :: dumpbin（MSVC 工具链）
> dumpbin /headers notepad.exe | findstr /i "dll char"
>
> :: CFF Explorer：Optional Header → DllCharacteristics，勾选位一目了然
>
> :: PowerShell（读原始字段值）
> $bytes = [System.IO.File]::ReadAllBytes("C:\Windows\System32\notepad.exe")
> $e_lfanew = [BitConverter]::ToInt32($bytes, 0x3C)
> $dllchar_off = $e_lfanew + 4 + 20 + 70   # PE sig(4) + FileHeader(20) + offset to DllChar in OptHdr
> "DllCharacteristics: 0x{0:X4}" -f [BitConverter]::ToUInt16($bytes, $dllchar_off)
> ```
>
> 典型安全二进制（如 `ntdll.dll`）通常同时置位 `0x0020`（HIGH_ENTROPY_VA）+ `0x0040`（DYNAMIC_BASE）+ `0x0100`（NX_COMPAT）+ `0x4000`（GUARD_CF），合计值 `0x4160`。

#### CheckSum 字段与 CheckSumMappedFile

`CheckSum` 是可选头中的 32 位校验和，**不是**密码哈希，而是一种轻量级数值校验，防止文件损坏（不防止恶意篡改，那是 [[12-详解PE文件(十二)：证书表|Authenticode 签名]] 的职责）。

**哪些文件必须有有效 CheckSum？**
- 内核态驱动（`.sys`）——加载器严格校验
- 引导时加载的 EFI 模块
- 少数系统 DLL（`ntdll.dll`、`kernel32.dll` 等）

普通用户态 EXE/DLL 的 `CheckSum` 通常为 0，加载器不校验。

**算法原理（`CheckSumMappedFile` 内部实现）：**

```c
// imagehlp.h / dbghelp：API 原型
PIMAGE_NT_HEADERS IMAGEAPI CheckSumMappedFile(
    PVOID  BaseAddress,   // 已映射文件的起始指针
    DWORD  FileLength,    // 文件字节数
    PDWORD HeaderSum,     // 输出：头部 CheckSum 字段原始值
    PDWORD CheckSum       // 输出：重新计算的校验和
);
```

算法步骤（Microsoft 公开规范）：

1. 把 `OptionalHeader.CheckSum` 字段**清零**（计算期间排除自身）。
2. 将文件视为 16 位 WORD 数组（若文件长度为奇数，末尾补 0 组成完整 WORD）。
3. 对所有 WORD 做**无进位循环加法（32 位累加器，每步做 fold 处理溢出）**：
   ```text
   partialSum = 0
   for each WORD w in file:
       partialSum += w
       if partialSum > 0xFFFF:
           partialSum = (partialSum & 0xFFFF) + (partialSum >> 16)
   ```
4. 对最终 `partialSum` 做最后一次 fold（确保结果在 16 位范围内）。
5. `CheckSum = (DWORD)(partialSum & 0xFFFF) + FileLength`

结果写回 `OptionalHeader.CheckSum`。

> [!example] 用 signtool / dumpbin 查验 CheckSum
> ```cmd
> :: 查看头部记录值
> dumpbin /headers target.exe | findstr /i "checksum"
>
> :: 用 Windows SDK 的 mapval 或自写工具调用 CheckSumMappedFile
> :: 也可在 CFF Explorer：Optional Header → CheckSum → 右键 "Recalculate"
>
> :: signtool（主要用于签名校验，顺带输出完整性信息）
> signtool verify /v /pa target.exe
> ```
>
> 若 `dumpbin` 输出的 `checksum` 与文件实际内容不符，说明文件被修改过但链接器/签名工具未更新校验和——这在 packers 修改入口点后很常见，也是某些安全扫描器的判定依据之一。

## 编程访问可选头

以下是一个简单的 C 语言示例，演示如何读取可选头：

```c
#include <windows.h>
#include <stdio.h>
#include <winnt.h>

void PrintOptionalHeaderInfo(const char* filename) {
    HANDLE hFile = CreateFile(filename, GENERIC_READ, FILE_SHARE_READ,
                              NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);

    if (hFile == INVALID_HANDLE_VALUE) {
        printf("无法打开文件: %s\n", filename);
        return;
    }

    HANDLE hMapping = CreateFileMapping(hFile, NULL, PAGE_READONLY, 0, 0, NULL);
    if (!hMapping) {
        printf("创建文件映射失败\n");
        CloseHandle(hFile);
        return;
    }

    LPVOID lpBase = MapViewOfFile(hMapping, FILE_MAP_READ, 0, 0, 0);
    if (!lpBase) {
        printf("映射文件失败\n");
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取DOS头
    IMAGE_DOS_HEADER* dosHeader = (IMAGE_DOS_HEADER*)lpBase;

    // 验证DOS签名
    if (dosHeader->e_magic != IMAGE_DOS_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取NT头
    IMAGE_NT_HEADERS* ntHeaders = (IMAGE_NT_HEADERS*)((BYTE*)lpBase + dosHeader->e_lfanew);

    // 验证PE签名
    if (ntHeaders->Signature != IMAGE_NT_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取可选头
    IMAGE_OPTIONAL_HEADER32* optHeader = &ntHeaders->OptionalHeader;

    // 打印可选头信息
    printf("=== 可选头信息 ===\n");
    printf("Magic: 0x%04X\n", optHeader->Magic);
    printf("AddressOfEntryPoint: 0x%08X\n", optHeader->AddressOfEntryPoint);
    printf("ImageBase: 0x%08X\n", optHeader->ImageBase);
    printf("SectionAlignment: 0x%08X\n", optHeader->SectionAlignment);
    printf("FileAlignment: 0x%08X\n", optHeader->FileAlignment);
    printf("SizeOfImage: 0x%08X\n", optHeader->SizeOfImage);
    printf("SizeOfHeaders: 0x%08X\n", optHeader->SizeOfHeaders);
    printf("Subsystem: 0x%04X\n", optHeader->Subsystem);
    printf("NumberOfRvaAndSizes: 0x%08X\n", optHeader->NumberOfRvaAndSizes);

    UnmapViewOfFile(lpBase);
    CloseHandle(hMapping);
    CloseHandle(hFile);
}
```

> [!summary] 小结
> 可选头是加载器的"操作手册"：`Magic` 区分 PE32/PE32+，`AddressOfEntryPoint` 给出执行起点，`ImageBase` 给出首选基址（不满足则触发 [[13-详解PE文件(十三)：基址重定位表|重定位]]），`SectionAlignment`/`FileAlignment` 解释了文件视图与内存视图的差异，`Subsystem` 决定 GUI/CUI，末尾的 16 项 `DataDirectory` 则是通往 [[07-详解PE文件(七)：数据目录|各张功能表]] 的总索引。
