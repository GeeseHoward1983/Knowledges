# 详解PE文件(二十)：导入地址表

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154744889)　｜　发布：2025-12-02　｜　合集《PE文件详解》第 20/26 篇

> [!tip] 一句话核心
> IAT（Import Address Table，导入地址表）是 PE 动态链接的"最后一公里"：磁盘上它和 INT 内容相同、存着函数名或序号；Windows 加载器把 DLL 映射进内存后，逐槽把 IAT 覆写为真实函数地址，之后 `call [IAT槽]` 便直接命中目标函数。理解它的"加载前/加载后"两副面孔，是读懂导入机制、做 IAT Hook 的关键。

> [!info] 速查
> - **数据目录索引**：12（`IMAGE_DIRECTORY_ENTRY_IAT`），来源于 [[07-详解PE文件(七)：数据目录]] / [[06-详解PE文件(六)：可选头]]
> - **核心结构体**：`IMAGE_THUNK_DATA32`（4 字节）/ `IMAGE_THUNK_DATA64`（8 字节）
> - **在导入表中的位置**：`IMAGE_IMPORT_DESCRIPTOR.FirstThunk` 所指向的数组，详见 [[08-详解PE文件(八)：导入表]]
> - **相关结构**：`IMAGE_IMPORT_BY_NAME`（按名称导入时指向的名称记录）
> - **两种导入方式**：按名称（`AddressOfData` → `IMAGE_IMPORT_BY_NAME`）、按序号（最高位为 1）
> - **所属家族**：导入相关篇目 → [[08-详解PE文件(八)：导入表]] · [[19-详解PE文件(十九)：绑定配置表]] · [[21-详解PE文件(二十一)：延迟导入表]]

导入地址表（IAT）与导入表（[[08-详解PE文件(八)：导入表|Import Table]]）紧密交织，却在 [[07-详解PE文件(七)：数据目录|数据目录]] 中单独占据一个条目——这既说明它在动态链接中举足轻重，也暗示它有独立的生命周期：加载器操作它的时机、方式都与操作 INT 截然不同。本篇将从 IAT 在文件中的定位，到加载前后的形态演变，再到 IAT Hook，逐层拆解。

## IAT 在 PE 文件中的位置

IAT 在 [[06-详解PE文件(六)：可选头|可选头]] 末尾的 [[07-详解PE文件(七)：数据目录|数据目录]] 数组中，是**第 13 个条目（索引 12）**：

```text
数据目录数组（共16个条目）：
0.  导出表 (Export Table)              → [[09-详解PE文件(九)：导出表]]
1.  导入表 (Import Table)              → [[08-详解PE文件(八)：导入表]]
2.  资源表 (Resource Table)
3.  异常表 (Exception Table)
4.  证书表 (Certificate Table)
5.  基址重定位表 (Base Relocation Table)
6.  调试数据 (Debug Data)
7.  版权信息 (Architecture Specific Data)
8.  全局指针 (Global Pointer)
9.  TLS表 (Thread Local Storage Table)
10. 加载配置表 (Load Configuration Table)
11. 绑定导入表 (Bound Import Table)    → [[19-详解PE文件(十九)：绑定配置表]]
12. 导入地址表 (Import Address Table)  ← 本篇
13. 延迟导入表 (Delay Import Descriptor)→ [[21-详解PE文件(二十一)：延迟导入表]]
14. CLR运行时头 (CLR Runtime Header)
15. 保留 (Reserved)
```

> [!note] 为何 IAT 要单独列在数据目录？
> 导入表（索引 1）描述"要从哪个 DLL 导入哪些函数"，而 IAT（索引 12）是实际被加载器**写入真实地址**的区域。两者物理上虽相邻（IAT 就是导入表里的 `FirstThunk` 数组），但加载器需要精确知道 IAT 的起止范围，以便批量修改内存权限并完成填写，因此单独标出。

在 PE 文件的整体布局中，IAT 通常位于 `.rdata` 节或 `.idata` 节内，与导入表描述符数组相邻：

```text
文件/节布局（示意）
┌─────────────────────────────────────────────┐
│ 可选头 → 数据目录[1] = 导入表 RVA/Size       │
│         数据目录[12] = IAT RVA/Size    ◀ 本篇 │
├─────────────────────────────────────────────┤
│ .idata / .rdata 节                           │
│  ┌──────────────────────────────────────┐   │
│  │ IMAGE_IMPORT_DESCRIPTOR 数组          │   │
│  │   .OriginalFirstThunk ──→ INT 数组    │   │
│  │   .FirstThunk ──────────→ IAT 数组   │◀ IAT│
│  │   .Name ────────────────→ "kernel32.dll"│  │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

## IAT 与导入表的关系：INT vs IAT

要真正读懂 IAT，必须先厘清它与 [[08-详解PE文件(八)：导入表|导入表]] 中 INT（Import Name Table）的关系。两者共用同一个结构体 `IMAGE_THUNK_DATA`，却扮演截然不同的角色。

### IMAGE_IMPORT_DESCRIPTOR 把两张表串联起来

在 [[08-详解PE文件(八)：导入表|导入表]] 中，每个被导入的 DLL 对应一条 `IMAGE_IMPORT_DESCRIPTOR`，其中有两个指针：

| 字段 | 指向 | 作用 |
|---|---|---|
| `OriginalFirstThunk` | INT 数组（`IMAGE_THUNK_DATA[]`） | **只读**，始终保存函数名/序号，加载器不改它 |
| `FirstThunk` | IAT 数组（`IMAGE_THUNK_DATA[]`） | **加载后被覆写**为真实函数地址 |

两个指针在磁盘上指向**内容完全相同**的两份 `IMAGE_THUNK_DATA` 数组；加载完成后，INT 不动，IAT 变成了地址表。

> [!important] INT 与 IAT 的本质区别
> - **INT**（`OriginalFirstThunk`）：加载器的"参考书"——查名字、查序号用，加载前后**内容不变**。
> - **IAT**（`FirstThunk`）：加载器的"工作簿"——加载前存名字/序号（与 INT 相同），加载后被**逐槽覆写**为真实函数地址，成为程序运行时实际调用的跳板。

### 加载前 / 加载后对比图

```text
─── 加载前（磁盘/映射初始状态）───────────────────────────────────────

INT 数组 (OriginalFirstThunk)     IAT 数组 (FirstThunk)
┌─────────────────────────┐       ┌──────────────────────────────┐
│ RVA → IMAGE_IMPORT_     │       │ RVA → IMAGE_IMPORT_BY_NAME   │
│   BY_NAME("MessageBoxA")│       │   BY_NAME("MessageBoxA")     │
├─────────────────────────┤       ├──────────────────────────────┤
│ RVA → IMAGE_IMPORT_     │       │ RVA → IMAGE_IMPORT_BY_NAME   │
│   BY_NAME("ExitProcess")│       │   BY_NAME("ExitProcess")     │
├─────────────────────────┤       ├──────────────────────────────┤
│ 0x00000000 (终止符)      │       │ 0x00000000 (终止符)           │
└─────────────────────────┘       └──────────────────────────────┘

─── 加载后（加载器完成填写）──────────────────────────────────────────

INT 数组（不变）                   IAT 数组（已覆写）
┌─────────────────────────┐       ┌──────────────────────────────┐
│ RVA → "MessageBoxA"     │       │ 0x7FFE_1234  ← user32.dll   │
│                         │       │   MessageBoxA 真实地址        │
├─────────────────────────┤       ├──────────────────────────────┤
│ RVA → "ExitProcess"     │       │ 0x7FFE_5678  ← kernel32.dll │
│                         │       │   ExitProcess 真实地址        │
├─────────────────────────┤       ├──────────────────────────────┤
│ 0x00000000              │       │ 0x00000000 (终止符)           │
└─────────────────────────┘       └──────────────────────────────┘
```

### call [IAT] 调用示意

编译器生成对外部函数的调用时，不直接写死地址，而是通过 IAT 槽间接跳转：

```text
程序代码段（.text）                IAT 槽（.rdata / .idata）
┌───────────────────────┐         ┌──────────────────┐
│ ...                   │         │                  │
│ call [MessageBoxA_IAT]│────────▶│ 0x7FFE_1234      │──▶ MessageBoxA
│ ...                   │         │                  │    （user32.dll）
└───────────────────────┘         └──────────────────┘
     ↑ 编译器写的是这里的地址       ↑ 加载器把真实地址写在这里
```

这种间接调用（`call [mem]` 而非 `call addr`）正是 IAT Hook 可行的根本原因：只需替换 IAT 槽里的地址，即可劫持所有经过该槽的调用。

## IAT 的核心结构：IMAGE_THUNK_DATA

IAT 数组的每个元素都是 `IMAGE_THUNK_DATA`，在 32 位和 64 位架构下宽度不同，但逻辑完全相同。

### 32 位版本（IMAGE_THUNK_DATA32）

```c
typedef struct _IMAGE_THUNK_DATA32 {
    union {
        DWORD ForwarderString;      // 指向转发字符串的RVA
        DWORD Function;             // 指向导入函数的地址(导入时填写)
        DWORD Ordinal;              // 序号导入
        DWORD AddressOfData;        // 指向IMAGE_IMPORT_BY_NAME的RVA
    } u1;
} IMAGE_THUNK_DATA32;
```

### 64 位版本（IMAGE_THUNK_DATA64）

```c
typedef struct _IMAGE_THUNK_DATA64 {
    union {
        ULONGLONG ForwarderString;  // 指向转发字符串的RVA
        ULONGLONG Function;         // 指向导入函数的地址(导入时填写)
        ULONGLONG Ordinal;          // 序号导入
        ULONGLONG AddressOfData;    // 指向IMAGE_IMPORT_BY_NAME的RVA
    } u1;
} IMAGE_THUNK_DATA64;
```

联合体（union）意味着同一 4/8 字节在不同场景下含义不同，下表列出四个成员的使用时机：

| 联合体成员 | 使用场景 | 说明 |
|---|---|---|
| `AddressOfData` | 加载前，按名称导入 | 指向 `IMAGE_IMPORT_BY_NAME` 结构的 RVA |
| `Ordinal` | 加载前，按序号导入 | 最高位（`IMAGE_ORDINAL_FLAG`）为 1，低 16 位为序号 |
| `Function` | 加载后 | 加载器覆写的真实函数地址（VA，非 RVA） |
| `ForwarderString` | 特殊：DLL 转发 | 指向转发字符串 RVA，如 `"NTDLL.RtlAllocateHeap"` |

> [!note] 如何区分"按名称"与"按序号"？
> 只看最高位：若 `u1.Ordinal` 最高位为 1（32 位下 `& 0x80000000`，64 位下 `& 0x8000000000000000`），则为**序号导入**，低 16 位即序号值；否则视为**按名称导入**，整个值是指向 `IMAGE_IMPORT_BY_NAME` 的 RVA。

### 字段偏移布局

`IMAGE_THUNK_DATA` 本身只有一个联合体字段，没有复杂的偏移，但理解它所属的 IAT 数组在内存中的排布很重要：

```text
IAT 数组（每项 4 字节 / 8 字节，以全 0 终止）
┌──────────────────┬──────────────────────────────────────────┐
│  偏移（数组内）   │  含义（以 32 位为例）                     │
├──────────────────┼──────────────────────────────────────────┤
│  +0x00           │  IMAGE_THUNK_DATA[0].u1（第 1 个导入函数）│
│  +0x04           │  IMAGE_THUNK_DATA[1].u1（第 2 个导入函数）│
│  +0x08           │  IMAGE_THUNK_DATA[2].u1（第 3 个导入函数）│
│  ...             │  ...                                      │
│  +N*4            │  0x00000000（数组终止符）                  │
└──────────────────┴──────────────────────────────────────────┘
```

## 按名称导入：IMAGE_IMPORT_BY_NAME

按名称导入时，`IMAGE_THUNK_DATA.u1.AddressOfData` 是一个 RVA，指向：

```c
typedef struct _IMAGE_IMPORT_BY_NAME {
    WORD    Hint;           // 提示值，函数在导出表中的索引
    CHAR   Name[1];         // 函数名称，以NULL结尾
} IMAGE_IMPORT_BY_NAME, *PIMAGE_IMPORT_BY_NAME;
```

| 字段 | 大小 | 说明 |
|---|---|---|
| `Hint` | 2 字节 | 加速查找的提示索引——加载器先用它在导出表里直接定位，命中则省去字符串比较；不命中再回退到全名搜索 |
| `Name[1]` | 变长 | 以 `\0` 结尾的函数名，紧跟在 `Hint` 之后（变长数组惯用法） |

> [!note] Hint 的实用意义
> `Hint` 并非强制命中，只是"建议"；加载器以它为初始猜测，若导出表对应槽的函数名匹配则命中（O(1) 查找），否则退化到二分搜索。对于频繁调用同一批函数的 DLL，Hint 能显著加速加载。

按名称导入的完整数据流如下：

```text
IAT[i].AddressOfData（RVA）
        │
        ▼
┌───────────────────────────────┐
│ IMAGE_IMPORT_BY_NAME          │
│  Hint: 0x0183                 │  （提示：尝试导出表第 0x183 项）
│  Name: "MessageBoxA\0"        │
└───────────────────────────────┘
        │
        ▼ 加载器用 Hint + Name 在 user32.dll 导出表中找到真实地址
        │
        ▼
IAT[i].Function ← 0x7FFE_xxxx  （覆写完成）
```

## 按序号导入

按序号导入无需 `IMAGE_IMPORT_BY_NAME`，`IMAGE_THUNK_DATA.u1.Ordinal` 最高位为 1，低 16 位直接是序号：

```c
// IMAGE_THUNK_DATA中的值是函数序号
// 最高位设置为1，其余位是序号值
#define IMAGE_ORDINAL_FLAG32 0x80000000
#define IMAGE_ORDINAL_FLAG64 0x8000000000000000
```

| 情形 | 判断条件 | 取序号方式 |
|---|---|---|
| 32 位按序号 | `u1.Ordinal & 0x80000000 != 0` | `u1.Ordinal & 0xFFFF` |
| 64 位按序号 | `u1.Ordinal & 0x8000000000000000 != 0` | `u1.Ordinal & 0xFFFF` |
| 按名称 | 最高位为 0 | `u1.AddressOfData` 是 RVA |

> [!warning] 按序号导入的隐患
> 序号是导出 DLL 内部的编号，**不同版本的 DLL 同一序号可能对应不同函数**。现代开发中几乎不用（系统 API 均有名称），但恶意软件常用它来规避基于函数名的检测。逆向时遇到序号导入，需结合目标 DLL 的导出表（[[09-详解PE文件(九)：导出表]]）才能还原函数名。

## 导入地址表的加载过程

加载器处理 IAT 的步骤，与 [[08-详解PE文件(八)：导入表|导入表]] 的解析过程紧密配合：

```text
① 读取 IMAGE_IMPORT_DESCRIPTOR 数组（导入表）
        │
        ▼
② 对每个描述符，按 .Name 字段加载对应 DLL
        │
        ▼
③ 遍历 OriginalFirstThunk（INT），解析每个 IMAGE_THUNK_DATA：
   ├─ 最高位=1 → 按序号在 DLL 导出表定位函数
   └─ 最高位=0 → 按 IMAGE_IMPORT_BY_NAME.Name 在 DLL 导出表定位函数
        │
        ▼
④ 把找到的函数真实 VA，写入 FirstThunk（IAT）对应槽
        │
        ▼
⑤ IAT 填写完毕，程序 call [IAT槽] 即可正确跳转
```

> [!important] 加载器为何要修改 IAT 的内存权限？
> IAT 所在页通常在加载期间被临时改为可写（`VirtualProtect` → `PAGE_READWRITE`），填写完成后恢复为只读（`PAGE_READONLY`）或读写（因 DLL 需要时可再改）。这一机制也正是 IAT Hook 需要先调用 `VirtualProtect` 才能修改槽地址的原因。

## 实战：手动解析 IAT

### 遍历 IAT 示例

```c
// 遍历IAT的示例代码
void WalkIAT(PVOID pImageBase) {
    PIMAGE_DOS_HEADER pDosHeader = (PIMAGE_DOS_HEADER)pImageBase;
    PIMAGE_NT_HEADERS pNtHeaders = (PIMAGE_NT_HEADERS)((BYTE*)pImageBase + pDosHeader->e_lfanew);

    // 获取IAT的RVA和大小
    DWORD iatRVA = pNtHeaders->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_IAT].VirtualAddress;
    DWORD iatSize = pNtHeaders->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_IAT].Size;

    if (iatRVA && iatSize) {
        PIMAGE_THUNK_DATA pIAT = (PIMAGE_THUNK_DATA)((BYTE*)pImageBase + iatRVA);

        // 遍历IAT中的每个条目
        while (pIAT->u1.AddressOfData) {
            if (pIAT->u1.Ordinal & IMAGE_ORDINAL_FLAG32) {
                // 按序号导入
                DWORD ordinal = pIAT->u1.Ordinal & 0xFFFF;
                printf("按序号导入: %d\n", ordinal);
            } else {
                // 按名称导入
                PIMAGE_IMPORT_BY_NAME pImportByName = (PIMAGE_IMPORT_BY_NAME)((BYTE*)pImageBase + pIAT->u1.AddressOfData);
                printf("按名称导入: %s (提示值: %d)\n", pImportByName->Name, pImportByName->Hint);
            }
            pIAT++;
        }
    }
}
```

> [!warning] 遍历时机决定读到什么
> 上面代码用 `IMAGE_DIRECTORY_ENTRY_IAT`（索引 12）定位 IAT 起始地址，然后直接遍历。**若在加载后调用**，`pIAT->u1.AddressOfData` 已是真实函数 VA，不再是 RVA；此时判断序号导入的逻辑（高位为 1）可能误判——应改为从 INT（`OriginalFirstThunk`）读取类型，再从 IAT 读地址，二表并行遍历更为准确。

## 安全与逆向：IAT Hook

IAT Hook 是 Windows 注入与挂钩最经典的技术之一：通过把 IAT 槽里的函数地址替换为自定义函数地址，让所有经过该槽的调用先流经 Hook 函数。

> [!example] IAT Hook 实现示例
>
> ```c
> // 修改IAT实现Hook的示例
> FARPROC HookFunction(HMODULE hModule, LPCSTR lpModuleName, LPCSTR lpFunctionName, FARPROC lpNewFunction) {
>     PIMAGE_DOS_HEADER pDosHeader = (PIMAGE_DOS_HEADER)hModule;
>     PIMAGE_NT_HEADERS pNtHeaders = (PIMAGE_NT_HEADERS)((BYTE*)hModule + pDosHeader->e_lfanew);
>
>     // 获取导入表
>     PIMAGE_IMPORT_DESCRIPTOR pImportDesc = (PIMAGE_IMPORT_DESCRIPTOR)((BYTE*)hModule +
>         pNtHeaders->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_IMPORT].VirtualAddress);
>
>     // 查找目标模块
>     while (pImportDesc->Name) {
>         LPCSTR lpName = (LPCSTR)((BYTE*)hModule + pImportDesc->Name);
>         if (_stricmp(lpName, lpModuleName) == 0) {
>             // 找到目标模块，查找IAT
>             PIMAGE_THUNK_DATA pIAT = (PIMAGE_THUNK_DATA)((BYTE*)hModule + pImportDesc->FirstThunk);
>             PIMAGE_THUNK_DATA pINT = (PIMAGE_THUNK_DATA)((BYTE*)hModule + pImportDesc->OriginalFirstThunk);
>
>             // 遍历导入函数
>             while (pINT->u1.AddressOfData) {
>                 if (!(pINT->u1.Ordinal & IMAGE_ORDINAL_FLAG32)) {
>                     PIMAGE_IMPORT_BY_NAME pImportByName = (PIMAGE_IMPORT_BY_NAME)((BYTE*)hModule + pINT->u1.AddressOfData);
>                     if (strcmp(pImportByName->Name, lpFunctionName) == 0) {
>                         // 找到目标函数，修改IAT
>                         DWORD dwOldProtect;
>                         VirtualProtect(&pIAT->u1.Function, sizeof(DWORD), PAGE_READWRITE, &dwOldProtect);
>                         FARPROC lpOriginalFunction = (FARPROC)pIAT->u1.Function;
>                         pIAT->u1.Function = (DWORD)lpNewFunction;
>                         VirtualProtect(&pIAT->u1.Function, sizeof(DWORD), dwOldProtect, &dwOldProtect);
>                         return lpOriginalFunction;
>                     }
>                 }
>                 pIAT++;
>                 pINT++;
>             }
>         }
>         pImportDesc++;
>     }
>     return NULL;
> }
> ```

IAT Hook 流程示意：

```text
原始调用链
  call [IAT槽] → 0x7FFE_1234（MessageBoxA）

Hook 后
  call [IAT槽] → 0xDEAD_BEEF（MyMessageBoxA）
                      │
                      ▼
               （记录/篡改参数）
                      │
                      ▼
               call 0x7FFE_1234  ← 可选：转发给原函数
```

> [!warning] IAT Hook 的检测与反制
> - **检测方法**：将内存中 IAT 槽的地址与磁盘上（或干净副本）的期望地址对比，不一致则疑为 Hook。
> - **绕过 IAT Hook**：直接调用系统调用（syscall）或获取函数地址后不经 IAT 直接 `jmp`，可绕过纯 IAT Hook。
> - **安全场景**：杀毒软件、游戏反作弊（AC）常用 IAT Hook 监控敏感 API 调用；恶意软件也常以此拦截安全工具。
> - 关联技术：[[19-详解PE文件(十九)：绑定配置表|绑定导入]] 会预先固化 IAT 地址，可与 IAT Hook 相互影响。

## 数据流全景图

将本篇核心关系汇总为一张全景图：

```text
IMAGE_IMPORT_DESCRIPTOR（[[08-详解PE文件(八)：导入表]]）
    │
    ├── OriginalFirstThunk ──▶ INT 数组（IMAGE_THUNK_DATA[]）── 只读，不被加载器改动
    │                               │
    │                               ▼
    │                         AddressOfData ──▶ IMAGE_IMPORT_BY_NAME
    │                               或
    │                         Ordinal（最高位=1）
    │
    └── FirstThunk ──────────▶ IAT 数组（IMAGE_THUNK_DATA[]）── 加载后覆写为真实 VA
                                    │
                        ┌───────────┴────────────┐
                   加载前                    加载后
             RVA → IMPORT_BY_NAME      真实函数 VA
                                            │
                                            ▼
                                    call [IAT槽] ──▶ 目标函数
```

> [!summary] 小结
> IAT 是 PE 动态链接机制中"最终落地"的那张表：磁盘上它是函数名/序号的副本，内存中它被加载器改写为真实地址，之后成为程序调用外部函数的唯一中间层。理解 IAT 需要同时掌握：① 它在 [[07-详解PE文件(七)：数据目录|数据目录]] 中的索引（12）；② 它与 [[08-详解PE文件(八)：导入表|导入表]] INT 的"一读一写"分工；③ `IMAGE_THUNK_DATA` 联合体的"加载前为 RVA、加载后为 VA"两副面孔；④ `IMAGE_IMPORT_BY_NAME` 的 Hint 加速机制；⑤ IAT Hook 的原理与防御。
>
