# 详解PE文件(二十五)：节数据

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154745508)　｜　发布：2025-12-01　｜　合集《PE文件详解》第 25/26 篇

> [!tip] 一句话核心
> 节表（[[24-详解PE文件(二十四)：节表|IMAGE_SECTION_HEADER]]）是"目录"，**节数据**才是真正存放代码与数据的"货架"。两者一一对应：节表项告诉你"去文件偏移 X 处找，大小 Y 字节"，那块原始二进制就是节数据。

> [!info] 速查
> - **定位字段**：`PointerToRawData`（文件偏移）、`SizeOfRawData`（文件中的大小）
> - **内存字段**：`VirtualAddress`（RVA）、`Misc.VirtualSize`（内存中实际大小）
> - **文件对齐**：`FileAlignment`，典型值 `0x200`（512 B）——来自 [[06-详解PE文件(六)：可选头]]
> - **内存对齐**：`SectionAlignment`，典型值 `0x1000`（4096 B）——来自 [[06-详解PE文件(六)：可选头]]
> - **上游结构**：[[24-详解PE文件(二十四)：节表]] 中的 `IMAGE_SECTION_HEADER` 数组

节数据是 PE（Portable Executable）文件中**真正存储内容**的部分——代码、初始化数据、资源、重定位信息等，全部分散在各个节数据块里。[[24-详解PE文件(二十四)：节表|节表]] 里的每个 `IMAGE_SECTION_HEADER` 都对应一块节数据，它给出的偏移与大小字段是定位节数据的唯一凭据。

## 节数据在 PE 文件中的位置

节数据紧跟在节表之后，是 PE 文件最大的一块区域。整体布局如下：

```text
文件偏移
0x00  ┌────────────────────────────────┐
      │  DOS 头 (64 字节)               │
      ├────────────────────────────────┤
      │  DOS Stub                       │
      ├────────────────────────────────┤
e_lfanew → PE 签名 "PE\0\0" (4 字节)
      ├────────────────────────────────┤
      │  COFF 文件头 (20 字节)          │
      ├────────────────────────────────┤
      │  可选头 (Optional Header)       │  含 FileAlignment / SectionAlignment
      ├────────────────────────────────┤
      │  节表 (IMAGE_SECTION_HEADER ×N) │  每项 40 字节，记录各节的位置与属性
      ├────────────────────────────────┤
      │  节数据 1  (.text)              │  ← PointerToRawData[0]
      ├────────────────────────────────┤
      │  节数据 2  (.rdata)             │  ← PointerToRawData[1]
      ├────────────────────────────────┤
      │  节数据 3  (.data)              │  ← PointerToRawData[2]
      ├────────────────────────────────┤
      │  ...                            │
      └────────────────────────────────┘
```

> [!note] 节的顺序
> 节数据在文件中的顺序**通常**与节表中的顺序一致，但 PE 规范并不强制要求。工具（如 link.exe）惯例上会按 `PointerToRawData` 升序排列，但解析时应始终以节表字段为准，不要假设顺序固定。

## 节数据的组织原则

节数据的组织遵循以下三条核心原则：

1. **按属性分组**：具有相同访问属性（可读、可写、可执行）的内容合并进同一个节，减少页保护切换开销。
2. **两级对齐**：在文件中按 `FileAlignment` 对齐，在内存中按 `SectionAlignment` 对齐。两者可以不同，这是文件尺寸与内存效率之间的折中。
3. **一一对应**：每个节数据块对应节表中的一个 `IMAGE_SECTION_HEADER`，通过 `PointerToRawData` 和 `SizeOfRawData` 精确定位。

## 常见节一览

下表列出最常见的节及其用途，可配合相关章节深入阅读：

| 节名 | 权限 | 典型内容 | 相关章节 |
|------|------|----------|----------|
| `.text` | `R-X` | 程序机器码（主执行逻辑） | — |
| `.data` | `RW-` | 已初始化的全局/静态变量 | — |
| `.rdata` | `R--` | 常量、字符串字面量、导入导出表 | [[08-详解PE文件(八)：导入表]] / [[09-详解PE文件(九)：导出表]] |
| `.rsrc` | `R--` | 图标、菜单、对话框、字符串表等 | [[10-详解PE文件(十)：资源表]] |
| `.reloc` | `R--` | 基址重定位信息（DLL 必备） | [[13-详解PE文件(十三)：基址重定位表]] |
| `.bss` | `RW-` | 未初始化的数据（文件中不占空间） | — |
| `.idata` | `RW-` | 导入表（有时合并入 `.rdata`） | [[08-详解PE文件(八)：导入表]] |
| `.edata` | `R--` | 导出表（有时合并入 `.rdata`） | [[09-详解PE文件(九)：导出表]] |
| `.tls` | `RW-` | 线程局部存储数据 | [[17-详解PE文件(十七)：TLS表]] |

> [!note] 节名只是约定俗成
> 节名（Name 字段，8 字节 ASCII）对 Windows 加载器来说完全透明——加载器不靠名字判断节的用途，**只看 `Characteristics`（属性标志）**。恶意软件常用随机名或空名混淆分析，逆向时务必以属性位为准。

### .text 节（代码节）

`.text` 节存放编译器生成的**机器码**，是 PE 文件最核心的节。

```text
属性位：IMAGE_SCN_MEM_EXECUTE | IMAGE_SCN_MEM_READ
权限：  可读 + 可执行，不可写
典型内容：函数体、跳转表、内联代码
```

- 通常是 PE 文件中**最大**的节（对代码密集型程序而言）。
- 加壳/混淆工具会把加密的代码放在此节，动态解密后再执行。

### .data 节（初始化数据节）

`.data` 存放**有初始值的全局/静态变量**，程序运行时可以修改。

```text
属性位：IMAGE_SCN_MEM_READ | IMAGE_SCN_MEM_WRITE
权限：  可读 + 可写，不可执行
典型内容：int g_count = 0; 之类的初始化全局变量
```

### .rdata 节（只读数据节）

`.rdata` 是只读数据的容器，内容丰富：

```text
属性位：IMAGE_SCN_MEM_READ
权限：  只读，不可写不可执行
典型内容：
  - 字符串字面量（"Hello, World!\0"）
  - 浮点常量、只读数组
  - 导入表（Import Directory，有时在此节）
  - 导出表（Export Directory，有时在此节）
  - 调试信息引用
```

相关结构详见 [[08-详解PE文件(八)：导入表]] 与 [[09-详解PE文件(九)：导出表]]。

### .rsrc 节（资源节）

`.rsrc` 采用**三级树状结构**组织资源，详细解析见 [[10-详解PE文件(十)：资源表]]。

```text
属性位：IMAGE_SCN_MEM_READ
权限：  只读
典型内容：图标 (.ico)、菜单、对话框、版本信息、字符串表
```

### .reloc 节（重定位节）

`.reloc` 对 **DLL** 尤为关键——当 DLL 无法加载到首选基址时，加载器靠它修正所有绝对地址引用。详见 [[13-详解PE文件(十三)：基址重定位表]]。

```text
属性位：IMAGE_SCN_MEM_READ  （某些情况下加 IMAGE_SCN_MEM_DISCARDABLE）
权限：  可读，加载完成后可被丢弃
典型内容：基址重定位块（IMAGE_BASE_RELOCATION 数组）
```

> [!warning] 关于 ASLR 与 .reloc
> 开启 ASLR（地址空间布局随机化）的 EXE 同样需要 `.reloc`——操作系统每次加载都会随机选取基址，没有重定位表就无法完成修正。去掉 `.reloc` 会导致程序无法加载或在 ASLR 环境下崩溃。

## 对齐：文件 vs 内存

这是理解节数据最关键的概念，两个对齐参数均来自 [[06-详解PE文件(六)：可选头]] 的可选头字段：

| 参数 | 字段名 | 典型值 | 生效场景 |
|------|--------|--------|----------|
| 文件对齐 | `FileAlignment` | `0x200`（512 B） | 节在磁盘文件中的存储 |
| 内存对齐 | `SectionAlignment` | `0x1000`（4096 B） | 节映射到内存后的布局 |

> [!important] 两种对齐的意义
> - **`FileAlignment`** 对齐到磁盘扇区边界，让文件读取更高效，也便于直接内存映射。
> - **`SectionAlignment`** 对齐到内存页边界（x86 页 = 4096 B），使操作系统可以为每页独立设置读/写/执行权限，这是现代内存保护的基础。

两个对齐值不同，节在文件里和内存里的**起始偏移**就会不同，因此有两套关键字段：

```text
节表项字段与含义：

  PointerToRawData  ──▶  节数据在文件中的起始偏移（FileAlignment 的倍数）
  SizeOfRawData     ──▶  节数据在文件中的字节数（FileAlignment 的倍数）
  VirtualAddress    ──▶  节加载到内存后的 RVA（SectionAlignment 的倍数）
  Misc.VirtualSize  ──▶  节在内存中的实际使用字节数（可不对齐）
```

### 文件与内存布局对比图

```text
─────────── 文件中 ───────────────        ──────────── 内存中 ───────────────
偏移 0x0000                                RVA 0x0000
   [DOS头/PE头/节表]                          [DOS头/PE头/节表]

偏移 0x0400  ◀── PointerToRawData          RVA 0x1000  ◀── VirtualAddress
   ┌────────────────┐                         ┌────────────────────────────┐
   │  .text 节数据  │  SizeOfRawData           │  .text 节数据              │  VirtualSize
   │  (0x1200 字节) │  = 0x1400（对齐后）       │  (0x11E0 字节)              │
   └────────────────┘                         │  + 0x20 字节 0 填充         │
                                              └────────────────────────────┘

偏移 0x1800  ◀── PointerToRawData          RVA 0x2000  ◀── VirtualAddress
   ┌────────────────┐                         ┌────────────────────────────┐
   │  .rdata 节数据 │                          │  .rdata 节数据              │
   └────────────────┘                         └────────────────────────────┘

偏移间距 = FileAlignment 的倍数             RVA 间距 = SectionAlignment 的倍数
(0x200 = 512 B)                            (0x1000 = 4096 B)
```

### VirtualSize 与 SizeOfRawData 的差异

```text
情况一：VirtualSize > SizeOfRawData
─────────────────────────────────────
文件里：  [  实际数据  ]
内存里：  [  实际数据  ][ 0x00 填充  ]
          ←SizeOfRawData→←  补零   →
          ←────── VirtualSize ──────→
用途：.bss 段（未初始化数据）常见此情况，
      文件中不占空间，内存中按 VirtualSize 清零。

情况二：SizeOfRawData > VirtualSize
─────────────────────────────────────
文件里：  [  实际数据 + 对齐填充  ]
内存里：  [  实际数据  ]（截断到 VirtualSize）
          ←VirtualSize→
          ←─── SizeOfRawData ───→
用途：文件对齐填充字节在内存中被直接丢弃。
```

> [!note] 安全含义
> VirtualSize 与 SizeOfRawData 之差是逆向/安全分析的敏感区域：攻击者有时将 Shellcode 藏在文件的对齐填充字节中（`SizeOfRawData` 内但超出 `VirtualSize` 的部分），静态分析工具会忽略这些字节，但手工解析节数据时需要特别留意。

## RVA 与文件偏移的互转

在分析 PE 文件时，经常需要在"RVA（内存地址）"与"文件偏移（磁盘地址）"之间互转。节数据是完成转换的关键。

### RVA → 文件偏移

```text
算法：
1. 遍历所有节表项
2. 找到满足条件的节：
     VirtualAddress ≤ RVA < VirtualAddress + VirtualSize
3. 计算文件偏移：
     FileOffset = PointerToRawData + (RVA - VirtualAddress)
```

### 文件偏移 → RVA

```text
算法：
1. 遍历所有节表项
2. 找到满足条件的节：
     PointerToRawData ≤ FileOffset < PointerToRawData + SizeOfRawData
3. 计算 RVA：
     RVA = VirtualAddress + (FileOffset - PointerToRawData)
```

### 转换示意图

```text
文件偏移空间                         RVA 空间（内存）
─────────────────                   ─────────────────
PointerToRawData ─────────────────▶ VirtualAddress
       │         偏移量相等（delta）        │
FileOffset       ─────────────────▶ RVA
       │                                  │
delta = FileOffset - PointerToRawData = RVA - VirtualAddress
```

> [!example] 实战转换：文件偏移 0x1A30 → RVA
> 假设节表中有如下信息：
> ```text
> 节名       VirtualAddress  PointerToRawData  SizeOfRawData  VirtualSize
> .text      0x1000          0x0400            0x1400         0x11E0
> .rdata     0x3000          0x1800            0x0C00         0x0B50
> ```
> 查找 FileOffset = `0x1A30` 落在哪个节：
> - `.rdata`：`PointerToRawData=0x1800`，`0x1800 + 0x0C00 = 0x2400`
> - `0x1800 ≤ 0x1A30 < 0x2400` ✓ 落在 `.rdata`
>
> 计算 RVA：
> ```
> RVA = 0x3000 + (0x1A30 - 0x1800) = 0x3000 + 0x230 = 0x3230
> ```

## 访问节数据的代码示例

以下示例遍历所有节并打印基本信息，代码逐字保留原文：

```c
#include <windows.h>
#include <stdio.h>

void ReadSectionData(PVOID pFileBuffer) {
    PIMAGE_DOS_HEADER pDosHeader = (PIMAGE_DOS_HEADER)pFileBuffer;
    PIMAGE_NT_HEADERS pNtHeaders = (PIMAGE_NT_HEADERS)((BYTE*)pFileBuffer + pDosHeader->e_lfanew);
    PIMAGE_SECTION_HEADER pSectionHeader = IMAGE_FIRST_SECTION(pNtHeaders);

    printf("节数据信息:\n");
    for (int i = 0; i < pNtHeaders->FileHeader.NumberOfSections; i++) {
        printf("节名称: %.8s\n", pSectionHeader->Name);
        printf("  文件偏移: 0x%08X\n", pSectionHeader->PointerToRawData);
        printf("  文件大小: 0x%08X\n", pSectionHeader->SizeOfRawData);
        printf("  内存地址: 0x%08X\n", pSectionHeader->VirtualAddress);
        printf("  内存大小: 0x%08X\n", pSectionHeader->Misc.VirtualSize);

        // 显示节的属性
        printf("  属性: ");
        if (pSectionHeader->Characteristics & IMAGE_SCN_MEM_EXECUTE)
            printf("可执行 ");
        if (pSectionHeader->Characteristics & IMAGE_SCN_MEM_READ)
            printf("可读 ");
        if (pSectionHeader->Characteristics & IMAGE_SCN_MEM_WRITE)
            printf("可写 ");
        printf("\n");

        // 如果节数据存在，则显示前几个字节
        if (pSectionHeader->PointerToRawData != 0 && pSectionHeader->SizeOfRawData > 0) {
            BYTE* pData = (BYTE*)pFileBuffer + pSectionHeader->PointerToRawData;
            printf("  数据预览: ");
            for (int j = 0; j < min(16, pSectionHeader->SizeOfRawData); j++) {
                printf("%02X ", pData[j]);
            }
            printf("\n");
        }
        printf("\n");

        pSectionHeader++;
    }
}
```

> [!note] `IMAGE_FIRST_SECTION` 宏
> `IMAGE_FIRST_SECTION(pNtHeaders)` 是 WinNT.h 提供的宏，等价于：
> ```c
> (PIMAGE_SECTION_HEADER)((BYTE*)&pNtHeaders->OptionalHeader
>                          + pNtHeaders->FileHeader.SizeOfOptionalHeader)
> ```
> 它通过 `SizeOfOptionalHeader` 跳过可选头（32/64 位大小不同），精确定位到节表起始处。这是跨 PE32/PE32+ 的正确写法。

## 节数据的属性（Characteristics）

节表项的 `Characteristics` 字段是一个 32 位标志位集合，决定节在内存中的访问权限和链接器行为：

| 标志位常量 | 值 | 含义 |
|-----------|-----|------|
| `IMAGE_SCN_CNT_CODE` | `0x00000020` | 含机器码 |
| `IMAGE_SCN_CNT_INITIALIZED_DATA` | `0x00000040` | 含已初始化数据 |
| `IMAGE_SCN_CNT_UNINITIALIZED_DATA` | `0x00000080` | 含未初始化数据（.bss） |
| `IMAGE_SCN_MEM_DISCARDABLE` | `0x02000000` | 加载后可丢弃（如 .reloc） |
| `IMAGE_SCN_MEM_NOT_CACHED` | `0x04000000` | 不可缓存 |
| `IMAGE_SCN_MEM_NOT_PAGED` | `0x08000000` | 不可换出（驱动常用） |
| `IMAGE_SCN_MEM_SHARED` | `0x10000000` | 可在进程间共享 |
| `IMAGE_SCN_MEM_EXECUTE` | `0x20000000` | 可执行 |
| `IMAGE_SCN_MEM_READ` | `0x40000000` | 可读 |
| `IMAGE_SCN_MEM_WRITE` | `0x80000000` | 可写 |

```text
典型节的 Characteristics 组合：
.text  = 0x60000020  = IMAGE_SCN_CNT_CODE | IMAGE_SCN_MEM_EXECUTE | IMAGE_SCN_MEM_READ
.data  = 0xC0000040  = IMAGE_SCN_CNT_INITIALIZED_DATA | IMAGE_SCN_MEM_READ | IMAGE_SCN_MEM_WRITE
.rdata = 0x40000040  = IMAGE_SCN_CNT_INITIALIZED_DATA | IMAGE_SCN_MEM_READ
.reloc = 0x42000040  = IMAGE_SCN_CNT_INITIALIZED_DATA | IMAGE_SCN_MEM_DISCARDABLE | IMAGE_SCN_MEM_READ
```

> [!warning] 可写代码节：恶意代码特征
> 如果 `.text` 节同时带有 `IMAGE_SCN_MEM_WRITE`（即 `Characteristics & 0x80000000` 为真），通常意味着该 PE 已被注入或修改——正常编译器不会生成可写的代码节。这是静态检测恶意代码的常见启发特征之一。

## 节数据与内存映射

Windows 加载器（`ntdll!LdrLoadDll`）将 PE 映射进内存时，对节数据的处理步骤如下：

```text
PE 文件加载流程（节数据相关部分）：

1. 读取可选头，确定 ImageBase、SectionAlignment、FileAlignment
           │
           ▼
2. 按 NumberOfSections 遍历节表
           │
           ▼
3. 对每个节：
   ┌─────────────────────────────────────────────┐
   │ a. 按 VirtualAddress 在目标内存处申请页面    │
   │ b. 从 PointerToRawData 读取 SizeOfRawData   │
   │    字节，复制到内存中的对应位置              │
   │ c. 若 VirtualSize > SizeOfRawData，          │
   │    剩余内存清零（ZeroMemory）                │
   │ d. 按 Characteristics 设置页面访问权限       │
   │    (VirtualProtect)                          │
   └─────────────────────────────────────────────┘
           │
           ▼
4. 处理重定位（.reloc → [[13-详解PE文件(十三)：基址重定位表]]）
           │
           ▼
5. 处理导入（.idata/.rdata → [[08-详解PE文件(八)：导入表]]）
           │
           ▼
6. 跳转入口点执行
```

> [!summary] 小结
> 节数据是 PE 文件的"血肉"，节表是"骨架"。二者共同工作：[[24-详解PE文件(二十四)：节表|节表]] 中的 `IMAGE_SECTION_HEADER` 提供定位信息，节数据则存放实际的代码与数据。
>
> 理解节数据，核心是掌握三点：
> 1. **两套坐标**：`PointerToRawData`（文件偏移）↔ `VirtualAddress`（内存 RVA），通过节表做桥梁互转。
> 2. **两种对齐**：`FileAlignment`（磁盘效率）与 `SectionAlignment`（内存保护），均取自 [[06-详解PE文件(六)：可选头]]。
> 3. **大小可以不同**：`VirtualSize` 与 `SizeOfRawData` 之差对应内存 0 填充或文件对齐填充。
>
> 常见节的具体内容，可进一步阅读 [[08-详解PE文件(八)：导入表]]、[[09-详解PE文件(九)：导出表]]、[[10-详解PE文件(十)：资源表]]、[[13-详解PE文件(十三)：基址重定位表]]。下一篇 [[26-详解PE文件(二十六)手写Loadlibrary]] 将手工模拟加载器，把上述流程真正跑起来。
