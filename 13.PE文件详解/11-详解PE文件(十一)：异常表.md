# 详解PE文件(十一)：异常表

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154743100)　｜　发布：2025-11-20　｜　合集《PE文件详解》第 11/26 篇

> [!tip] 一句话核心
> 异常表是 **64 位（x64/IA-64）PE 文件专属**的静态异常处理表：它把每个函数的起止 RVA 与"如何还原调用栈"的展开信息（Unwind Info）绑在一起，让操作系统在异常发生时无需动态记录就能逐帧回溯。x86 用的是基于堆栈的动态 SEH（不依赖此表），而 x64 彻底切到表基机制——**没有这张表，64 位程序的异常与 C++ 析构就无法正确工作**。

> [!info] 速查
> - **数据目录索引**：`IMAGE_DIRECTORY_ENTRY_EXCEPTION = 3`（[[07-详解PE文件(七)：数据目录|数据目录]]第 4 项，0-based）
> - **适用架构**：x64（PE32+）、IA-64；x86（PE32）通常不含此表
> - **核心结构**：`IMAGE_RUNTIME_FUNCTION_ENTRY`（12 字节/项）→ `UNWIND_INFO`（变长）→ `UNWIND_CODE[]`
> - **所在节**：通常位于 `.pdata` 节（只读数据）
> - **定位方式**：[[06-详解PE文件(六)：可选头|可选头]] `DataDirectory[3].VirtualAddress`（RVA）+ `Size`

## 异常表在 PE 文件中的位置

异常表由[[06-详解PE文件(六)：可选头|可选头]]末尾的[[07-详解PE文件(七)：数据目录|数据目录]]数组第 3 项（索引 3，即 `IMAGE_DIRECTORY_ENTRY_EXCEPTION`）指向，内容通常存在 `.pdata` 节中：

```text
PE 文件结构（64 位）
┌─────────────────────────────────────────────┐
│  DOS 头 / DOS Stub / PE 签名                 │
├─────────────────────────────────────────────┤
│  COFF 文件头（IMAGE_FILE_HEADER）            │
├─────────────────────────────────────────────┤
│  可选头（IMAGE_OPTIONAL_HEADER64）           │
│  ┌─────────────────────────────────────┐    │
│  │  DataDirectory[3]                   │    │
│  │    VirtualAddress ──────────────┐   │    │
│  │    Size                         │   │    │
│  └─────────────────────────────────┼───┘    │
├──────────────────────────────────────┼──────┤
│  节表 / .text / .rdata / ...         │      │
├──────────────────────────────────────┼──────┤
│  .pdata 节  ◄────────────────────────┘      │
│  ┌──────────────────────────────────────┐   │
│  │  IMAGE_RUNTIME_FUNCTION_ENTRY[0]     │   │
│  │  IMAGE_RUNTIME_FUNCTION_ENTRY[1]     │   │
│  │  ...                                 │   │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

> [!note] x86 与 x64 的根本差异
> x86（PE32）使用**基于堆栈的动态 SEH**：编译器在函数序言里把异常处理链表节点压栈，通过 `FS:[0]` 穿成链表，异常时沿链遍历。这种方式运行时开销大、也是缓冲区溢出的常见攻击面。x64 改用**表基静态 SEH**：所有处理信息编译时写入 `.pdata` / `.xdata`，运行时只需二分查找——既快又安全，但**必须有完整的异常表**，否则跨帧异常无法展开。

## 异常表结构总览

异常表由三层嵌套结构组成，关系如下：

```text
.pdata 节（函数表）
┌────────────────────────────────────────────────────┐
│  IMAGE_RUNTIME_FUNCTION_ENTRY[0]  (12 bytes)        │
│    BeginAddress  ──── 函数起始 RVA                  │
│    EndAddress    ──── 函数结束 RVA                  │
│    UnwindInfoAddress ─────────────────────────────┐ │
├────────────────────────────────────────────────────┤ │
│  IMAGE_RUNTIME_FUNCTION_ENTRY[1]  ...              │ │
│  ...                                               │ │
└────────────────────────────────────────────────────┘ │
                                                       │
.xdata 节（展开信息）  ◄──────────────────────────────┘
┌─────────────────────────────────────────────────────┐
│  UNWIND_INFO                                         │
│    Version / Flags / SizeOfProlog / CountOfCodes     │
│    FrameRegister / FrameOffset                       │
│    UNWIND_CODE[CountOfCodes]  ─── 逆序还原序言操作  │
│    [可选] ExceptionHandler RVA                       │
│    [可选] ExceptionData[]                            │
└─────────────────────────────────────────────────────┘
```

| 层级 | 结构 | 大小 | 职责 |
|---|---|---|---|
| 函数表项 | `IMAGE_RUNTIME_FUNCTION_ENTRY` | 12 字节（固定） | 记录函数 RVA 范围 + 指向展开信息 |
| 展开信息 | `UNWIND_INFO` | 变长（4 字节头 + codes） | 描述序言操作、帧寄存器、异常处理程序 |
| 展开代码 | `UNWIND_CODE` | 每项 2 字节 | 逐步描述序言中每条保存操作的逆操作 |

## IMAGE_RUNTIME_FUNCTION_ENTRY — 函数表项

这是异常表的核心条目，每个需要异常处理的函数对应一项，按 `BeginAddress` 升序排列（便于二分查找）：

```c
typedef struct _IMAGE_RUNTIME_FUNCTION_ENTRY {
    DWORD BeginAddress;        // 函数起始地址的RVA
    DWORD EndAddress;          // 函数结束地址的RVA
    DWORD UnwindInfoAddress;   // 指向展开信息的RVA
} IMAGE_RUNTIME_FUNCTION_ENTRY, *PIMAGE_RUNTIME_FUNCTION_ENTRY;
```

对于64位PE32+文件，还有一个扩展版本：

```c
typedef struct _IMAGE_RUNTIME_FUNCTION_ENTRY {
    DWORD BeginAddress;
    DWORD EndAddress;
    union {
        DWORD UnwindInfoAddress;  // 指向展开信息的RVA
        DWORD UnwindData;         // 展开数据的RVA
    } DUMMYUNIONNAME;
} _IMAGE_RUNTIME_FUNCTION_ENTRY, *_PIMAGE_RUNTIME_FUNCTION_ENTRY;
```

### 字段偏移布局

| 偏移 | 字段 | 大小 | 说明 |
|---|---|---|---|
| `+0x00` ⭐ | `BeginAddress` | 4 | 函数起始 RVA（相对镜像基址） |
| `+0x04` ⭐ | `EndAddress` | 4 | 函数结束 RVA（指向函数体末尾之后一字节） |
| `+0x08` ⭐ | `UnwindInfoAddress` | 4 | `UNWIND_INFO` 的 RVA，低 1 位为 0；若低 1 位为 1 则为链式项 |

> [!note] 二分查找定位
> 异常发生时，Windows 内核用异常 PC（指令指针）在 `.pdata` 里做**二分查找**：找到满足 `BeginAddress ≤ PC < EndAddress` 的项，即可确认异常属于哪个函数，然后跳转到对应的展开信息。这就是为什么表项必须按 `BeginAddress` 升序且不重叠。

## UNWIND_INFO — 展开信息

展开信息结构描述了如何展开（unwind）一个函数的调用栈：

```c
typedef struct _UNWIND_INFO {
    BYTE Version       : 3;    // 版本号
    BYTE Flags         : 5;    // 标志位
    BYTE SizeOfProlog;         // 函数序言大小
    BYTE CountOfCodes;         // 展开代码数量
    BYTE FrameRegister : 4;    // 帧寄存器
    BYTE FrameOffset   : 4;    // 帧偏移
    // UNWIND_CODE UnwindCode[1]; // 展开代码数组
    // 可选字段:
    // union {
    //     OPTIONAL ULONG ExceptionHandler; // 异常处理程序
    //     OPTIONAL ULONG FunctionEntry;    // 函数入口
    // };
    // OPTIONAL ULONG ExceptionData[];     // 异常数据
} UNWIND_INFO, *PUNWIND_INFO;
```

### UNWIND_INFO 字段说明

| 字段 | 位宽 | 说明 |
|---|---|---|
| `Version` | 3 位 | 结构版本，目前固定为 1 |
| `Flags` | 5 位 | 标志位（见下方 Flags 速查） |
| `SizeOfProlog` | 1 字节 | 函数序言的字节长度 |
| `CountOfCodes` | 1 字节 | `UNWIND_CODE` 数组中的元素个数 |
| `FrameRegister` | 4 位 | 帧指针寄存器编号（0 = 不使用帧指针） |
| `FrameOffset` | 4 位 | 帧指针的初始偏移（乘以 16 为实际偏移量） |

### Flags 标志位速查

| 值 | 宏名 | 含义 |
|---|---|---|
| `0x01` | `UNW_FLAG_EHANDLER` | 函数有**异常处理程序**（`__except`/`catch`） |
| `0x02` | `UNW_FLAG_UHANDLER` | 函数有**终止处理程序**（`__finally`/析构） |
| `0x04` | `UNW_FLAG_CHAININFO` | 本结构**链接到另一个函数**的展开信息（尾部含 `RUNTIME_FUNCTION_ENTRY` 而非 Handler） |

> [!warning] 安全 / 逆向提醒
> `UNW_FLAG_CHAININFO` 链式展开是编译器切分超长函数或内联展开时产生的，逆向时容易把链式项误判为独立函数。当 `UnwindInfoAddress` 的低 1 位为 1（已减 1 做对齐标记）或 Flags 含 `CHAININFO` 时，要继续跟随链末的 `RUNTIME_FUNCTION_ENTRY` 递归处理。

## UNWIND_CODE — 展开代码

展开代码结构描述了函数序言中每一步操作的逆操作：

```c
typedef union _UNWIND_CODE {
    struct {
        BYTE CodeOffset;       // 操作在序言中的偏移
        BYTE UnwindOp : 4;     // 展开操作码
        BYTE OpInfo   : 4;     // 操作信息
    } DUMMYSTRUCTNAME;
    USHORT FrameOffset;        // 帧偏移
} UNWIND_CODE, *PUNWIND_CODE;
```

### 常用展开操作码

| 操作码值 | 宏名 | 含义 |
|---|---|---|
| `0` | `UWOP_PUSH_NONVOL` | 保存非易失性寄存器到栈（`push rXX`） |
| `1` | `UWOP_ALLOC_LARGE` | 大栈分配（超过 512KB） |
| `2` | `UWOP_ALLOC_SMALL` | 小栈分配（`sub rsp, N`，N ≤ 128 字节） |
| `3` | `UWOP_SET_FPREG` | 设置帧指针寄存器 |
| `4` | `UWOP_SAVE_NONVOL` | 将非易失性寄存器保存到栈（不用 push） |
| `5` | `UWOP_SAVE_NONVOL_FAR` | 同上，偏移较大时用 |
| `6` | `UWOP_SAVE_XMM128` | 保存 XMM 寄存器 |
| `7` | `UWOP_SAVE_XMM128_FAR` | 同上，偏移较大时用 |
| `8` | `UWOP_PUSH_MACHFRAME` | 保存机器帧（中断/异常入口使用） |

> [!note] 序言与展开代码的对应关系
> 编译器在生成函数序言（prologue）时记录每一步操作（push、sub rsp 等），并在 `UNWIND_CODE` 数组里以逆序写入对应的"撤销操作描述"。展开时按数组顺序执行，即可还原寄存器与栈指针到函数入口时的状态。

## 异常处理工作流程

```text
程序运行中，某函数抛出异常
         │
         ▼
操作系统取当前 RIP（指令指针）
         │
         ▼
在 .pdata 中二分查找
  满足 BeginAddress ≤ RIP < EndAddress 的项
         │
    找到? ─否─▶ 向上层（父帧）继续查找
         │是
         ▼
取 UnwindInfoAddress ──▶ 定位 UNWIND_INFO
         │
         ▼
检查 UNWIND_INFO.Flags
  ├── UNW_FLAG_EHANDLER？──▶ 调用异常处理程序（__except/__catch）
  ├── UNW_FLAG_UHANDLER？──▶ 调用终止处理程序（__finally/析构）
  └── UNW_FLAG_CHAININFO？──▶ 跟随链式 RUNTIME_FUNCTION_ENTRY 继续
         │
         ▼
按 UNWIND_CODE[] 逐步还原寄存器 / 栈指针
（逆序执行序言操作）
         │
         ▼
移至调用者栈帧，重复上述过程（向上展开）
         │
         ▼
找到合适的处理程序 → 执行异常处理逻辑
```

> [!important] 为什么 64 位必须有完整异常表
> x64 ABI 规定：**任何可能被展开（被异常穿越）的函数，都必须在 `.pdata` 有对应条目**，否则展开时内核找不到该帧的还原方法，只能抛出 `STATUS_UNWIND_CONSOLIDATE` 或直接终止进程。叶函数（leaf function，不分配栈、不保存非易失性寄存器、不调用其它函数）是唯一豁免——它们可以不在表中。

## 实际示例：遍历 PE 文件异常表

以下是一个遍历PE文件异常表的示例代码：

```c
#include <windows.h>
#include <stdio.h>

// RVA转文件偏移
DWORD RvaToFileOffset(PIMAGE_NT_HEADERS ntHeaders, DWORD rva) {
    PIMAGE_SECTION_HEADER section = IMAGE_FIRST_SECTION(ntHeaders);
    for (int i = 0; i < ntHeaders->FileHeader.NumberOfSections; i++) {
        if (rva >= section[i].VirtualAddress &&
            rva < section[i].VirtualAddress + section[i].Misc.VirtualSize) {
            return rva - section[i].VirtualAddress + section[i].PointerToRawData;
        }
    }
    return 0;
}

// 获取展开操作码的字符串描述
const char* GetUnwindOpName(BYTE unwindOp) {
    switch (unwindOp) {
        case 0: return "UWOP_PUSH_NONVOL";
        case 1: return "UWOP_ALLOC_LARGE";
        case 2: return "UWOP_ALLOC_SMALL";
        case 3: return "UWOP_SET_FPREG";
        case 4: return "UWOP_SAVE_NONVOL";
        case 5: return "UWOP_SAVE_NONVOL_FAR";
        case 6: return "UWOP_SAVE_XMM128";
        case 7: return "UWOP_SAVE_XMM128_FAR";
        case 8: return "UWOP_PUSH_MACHFRAME";
        default: return "UNKNOWN";
    }
}

// 打印展开代码信息
void PrintUnwindCodes(PUNWIND_INFO unwindInfo, LPBYTE baseAddress) {
    printf("  展开代码数量: %d\n", unwindInfo->CountOfCodes);

    // 展开代码数组紧随UNWIND_INFO结构
    PUNWIND_CODE unwindCodes = (PUNWIND_CODE)(unwindInfo + 1);

    for (int i = 0; i < unwindInfo->CountOfCodes; i++) {
        printf("    代码 %d: 偏移=0x%02X, 操作=%s, 信息=0x%X\n",
               i,
               unwindCodes[i].CodeOffset,
               GetUnwindOpName(unwindCodes[i].UnwindOp),
               unwindCodes[i].OpInfo);
    }
}

void PrintExceptionTable(const char* filename) {
    HANDLE hFile = CreateFile(filename, GENERIC_READ, FILE_SHARE_READ,
                              NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);

    if (hFile == INVALID_HANDLE_VALUE) {
        printf("无法打开文件: %s\n", filename);
        return;
    }

    HANDLE hMapping = CreateFileMapping(hFile, NULL, PAGE_READONLY, 0, 0, NULL);
    if (!hMapping) {
        printf("创建文件映射失败\n");
        CloseHandle(hFile);
        return;
    }

    LPVOID lpBase = MapViewOfFile(hMapping, FILE_MAP_READ, 0, 0, 0);
    if (!lpBase) {
        printf("映射文件失败\n");
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取DOS头
    PIMAGE_DOS_HEADER dosHeader = (PIMAGE_DOS_HEADER)lpBase;

    // 验证DOS签名
    if (dosHeader->e_magic != IMAGE_DOS_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取NT头
    PIMAGE_NT_HEADERS ntHeaders = (PIMAGE_NT_HEADERS)((LPBYTE)lpBase + dosHeader->e_lfanew);

    // 验证PE签名
    if (ntHeaders->Signature != IMAGE_NT_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 检查是否为64位PE文件
    if (ntHeaders->OptionalHeader.Magic != IMAGE_NT_OPTIONAL_HDR64_MAGIC) {
        printf("异常表仅存在于64位PE文件中\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取异常表信息
    PIMAGE_DATA_DIRECTORY exceptionDir =
        &ntHeaders->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_EXCEPTION];

    if (exceptionDir->VirtualAddress == 0) {
        printf("该文件没有异常表\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取异常表起始位置
    DWORD exceptionTableOffset = RvaToFileOffset(ntHeaders, exceptionDir->VirtualAddress);
    if (exceptionTableOffset == 0) {
        printf("无法定位异常表\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    PIMAGE_RUNTIME_FUNCTION_ENTRY runtimeFunctions =
        (PIMAGE_RUNTIME_FUNCTION_ENTRY)((LPBYTE)lpBase + exceptionTableOffset);

    // 计算异常表项数量
    DWORD entryCount = exceptionDir->Size / sizeof(IMAGE_RUNTIME_FUNCTION_ENTRY);

    printf("=== 异常表信息 ===\n");
    printf("异常表RVA: 0x%08X\n", exceptionDir->VirtualAddress);
    printf("异常表大小: %d bytes\n", exceptionDir->Size);
    printf("异常表项数: %d\n", entryCount);
    printf("\n");

    // 遍历异常表项
    for (DWORD i = 0; i < entryCount; i++) {
        printf("函数 %d:\n", i);
        printf("  起始地址 RVA: 0x%08X\n", runtimeFunctions[i].BeginAddress);
        printf("  结束地址 RVA: 0x%08X\n", runtimeFunctions[i].EndAddress);
        printf("  展开信息 RVA: 0x%08X\n", runtimeFunctions[i].UnwindInfoAddress);

        // 获取展开信息
        DWORD unwindInfoOffset = RvaToFileOffset(ntHeaders, runtimeFunctions[i].UnwindInfoAddress);
        if (unwindInfoOffset != 0) {
            PUNWIND_INFO unwindInfo = (PUNWIND_INFO)((LPBYTE)lpBase + unwindInfoOffset);
            printf("  版本: %d\n", unwindInfo->Version);
            printf("  标志: 0x%02X\n", unwindInfo->Flags);
            printf("  序言大小: %d bytes\n", unwindInfo->SizeOfProlog);
            printf("  帧寄存器: %d\n", unwindInfo->FrameRegister);
            printf("  帧偏移: %d\n", unwindInfo->FrameOffset);

            // 打印展开代码
            PrintUnwindCodes(unwindInfo, (LPBYTE)lpBase);
        }

        printf("\n");
    }

    UnmapViewOfFile(lpBase);
    CloseHandle(hMapping);
    CloseHandle(hFile);
}
```

## 异常表的重要性

异常表在64位Windows程序中具有重要意义：

1. **异常处理**：提供结构化的异常处理机制
2. **调用栈展开**：支持正确的调用栈展开和清理
3. **调试支持**：为调试器提供函数边界信息
4. **逆向工程**：通过分析异常表可以了解程序的函数结构
5. **性能优化**：相比于动态异常处理，静态异常表提供更好的性能

> [!warning] 逆向与安全分析要点
> - **函数识别**：`.pdata` 里的每条 `RUNTIME_FUNCTION_ENTRY` 精确标记一个函数的起止边界，是自动化函数识别的可靠依据（IDA/Ghidra 均优先解析此表）。
> - **混淆手段**：部分壳或手写汇编代码会故意填写错误的 `BeginAddress/EndAddress` 或指向非法 `UNWIND_INFO`，导致异常时崩溃或分析工具误判函数范围。
> - **叶函数豁免**：叶函数可以不出现在表中，但如果手写代码或 JIT 产生的非叶函数缺少条目，异常穿越时进程必然崩溃（`C0000602` 等）。
> - **加载时校验**：Windows 加载器对 `.pdata` 内容并不做严格校验，条目错误只在异常真正发生时才暴露。

> [!summary] 小结
> 异常表是 **64 位 PE 文件结构化异常处理的基石**，由[[07-详解PE文件(七)：数据目录|数据目录]]索引 3 指向，存于 `.pdata` 节。三层结构：函数表项（`IMAGE_RUNTIME_FUNCTION_ENTRY`，固定 12 字节/项）→ 展开信息（`UNWIND_INFO`，含 Flags、序言大小、帧寄存器）→ 展开代码数组（`UNWIND_CODE`，逐步描述如何逆向还原序言）。异常发生时内核二分查找函数表、读取展开信息、逐帧回溯，从而实现可靠的 SEH 与 C++ 析构。理解此表对 64 位程序的调试、逆向与安全分析至关重要。相关结构入口见[[06-详解PE文件(六)：可选头|可选头]]与[[07-详解PE文件(七)：数据目录|数据目录]]。
