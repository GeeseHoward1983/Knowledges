# 详解PE文件(十)：资源表

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154742956)　｜　发布：2025-11-20　｜　合集《PE文件详解》第 10/26 篇

> [!tip] 一句话核心
> 资源表是 PE 文件的"资产库"：图标、位图、对话框、字符串、版本信息全都收在这里，以**三层树形结构**（类型层 → ID层 → 语言层）组织，入口通过 [[07-详解PE文件(七)：数据目录]] 的第 3 项（索引 2）定位。

> [!info] 速查
> - **核心结构体**：`IMAGE_RESOURCE_DIRECTORY`（16 字节）、`IMAGE_RESOURCE_DIRECTORY_ENTRY`（8 字节）、`IMAGE_RESOURCE_DATA_ENTRY`（16 字节）
> - **数据目录索引**：`IMAGE_DIRECTORY_ENTRY_RESOURCE = 2`（见 [[07-详解PE文件(七)：数据目录]]）
> - **节名**：通常位于 `.rsrc` 节
> - **树深**：固定三层（类型 / 名称或 ID / 语言）
> - **地址类型**：`IMAGE_RESOURCE_DATA_ENTRY.OffsetToData` 是 **RVA**（相对虚拟地址）
> - **所属位置**：由 [[06-详解PE文件(六)：可选头]] 中 `DataDirectory[2]` 给出 RVA 和大小

PE 文件的资源表（Resource Table）是 Windows 可执行文件中用于存储和管理各种资源的结构，如图标、位图、对话框、字符串、菜单、版本信息等。资源表采用层次化的树形结构组织，使得程序能够在运行时方便地查找和使用这些资源。

## 资源表在 PE 文件中的位置

资源表的起始 RVA 和大小由 [[06-详解PE文件(六)：可选头]] 的 `OptionalHeader.DataDirectory[2]` 记录，通过 [[07-详解PE文件(七)：数据目录]] 可以直接定位到 `.rsrc` 节的根目录。

```text
PE 文件整体布局（简化）
────────────────────────────────────────────
  DOS 头 (IMAGE_DOS_HEADER)
  DOS Stub
  PE 签名 "PE\0\0"
  COFF 文件头 (IMAGE_FILE_HEADER)
  可选头 (IMAGE_OPTIONAL_HEADER)
    └─ DataDirectory[2]  ← VirtualAddress + Size
  节表 (Section Headers)
────────────────────────────────────────────
  .text  节（代码）
  .data  节（数据）
  .rsrc  节  ◄──── 资源表根目录从这里开始
    ├─ IMAGE_RESOURCE_DIRECTORY        (根/类型层)
    ├─ IMAGE_RESOURCE_DIRECTORY_ENTRY  (各条目)
    ├─ ...（子目录，ID 层 / 语言层）
    └─ IMAGE_RESOURCE_DATA_ENTRY       (叶节点，指向真实数据)
  ...
────────────────────────────────────────────
```

## 资源树三层结构总览

资源表采用**固定三层树形结构**，每层都是一个 `IMAGE_RESOURCE_DIRECTORY` + 若干 `IMAGE_RESOURCE_DIRECTORY_ENTRY`，最终叶节点由 `IMAGE_RESOURCE_DATA_ENTRY` 描述真实数据。

```text
根 IMAGE_RESOURCE_DIRECTORY
├─ 第一层：资源类型（RT_ICON / RT_BITMAP / RT_DIALOG ...）
│   ├─ 第二层：资源 ID 或名称
│   │   ├─ 第三层：语言 ID（LANGID，如 0x0409 = en-US）
│   │   │   └─ IMAGE_RESOURCE_DATA_ENTRY ──► 真实资源数据（RVA + 大小）
│   │   └─ ...
│   └─ ...
└─ ...
```

> [!note] 三层含义速记
> - **第一层（类型）**：这是什么资源？图标 / 位图 / 菜单 / 字符串……
> - **第二层（ID/名称）**：同类型下的第几个？可以是整数 ID，也可以是 Unicode 字符串名称。
> - **第三层（语言）**：同一资源的哪个语言版本？支持多语言本地化。

## 关键数据结构

### IMAGE_RESOURCE_DIRECTORY（目录头）

每一层的起点都是这个 16 字节的目录头，记录该层目录的元信息：

```c
typedef struct _IMAGE_RESOURCE_DIRECTORY {
    DWORD   Characteristics;        // 未使用，恒为0
    DWORD   TimeDateStamp;          // 时间戳
    WORD    MajorVersion;           // 主版本号
    WORD    MinorVersion;           // 次版本号
    WORD    NumberOfNamedEntries;   // 命名条目数
    WORD    NumberOfIdEntries;      // ID条目数
} IMAGE_RESOURCE_DIRECTORY, *PIMAGE_RESOURCE_DIRECTORY;
```

各字段偏移一览：

| 偏移 | 字段 | 大小 | 说明 |
|---|---|---|---|
| `0x00` | `Characteristics` | 4 | 恒为 0，未使用 |
| `0x04` | `TimeDateStamp` | 4 | 资源编译时间戳（通常可忽略） |
| `0x08` | `MajorVersion` | 2 | 主版本号 |
| `0x0A` | `MinorVersion` | 2 | 次版本号 |
| `0x0C` ⭐ | `NumberOfNamedEntries` | 2 | **字符串命名条目数** |
| `0x0E` ⭐ | `NumberOfIdEntries` | 2 | **整数 ID 条目数** |

紧随目录头之后是 `NumberOfNamedEntries + NumberOfIdEntries` 个 `IMAGE_RESOURCE_DIRECTORY_ENTRY`，命名条目在前，ID 条目在后。

### IMAGE_RESOURCE_DIRECTORY_ENTRY（目录条目）

描述资源目录中的每个条目，8 字节，包含两个 union：

```c
typedef struct _IMAGE_RESOURCE_DIRECTORY_ENTRY {
    union {
        struct {
            DWORD NameOffset:31;    // 名称偏移（如果是命名资源）
            DWORD NameIsString:1;   // 是否为字符串名称
        } DUMMYSTRUCTNAME;
        DWORD   Name;               // 资源ID或名称偏移
        WORD    Id;                 // 资源ID
    } DUMMYUNIONNAME;

    union {
        DWORD   OffsetToData;       // 指向数据或子目录的偏移
        struct {
            DWORD   OffsetToDirectory:31; // 指向子目录的偏移
            DWORD   DataIsDirectory:1;    // 是否为目录
        } DUMMYSTRUCTNAME2;
    } DUMMYUNIONNAME2;
} IMAGE_RESOURCE_DIRECTORY_ENTRY, *PIMAGE_RESOURCE_DIRECTORY_ENTRY;
```

两个 union 的语义如下：

| union 字段 | 最高位 | 说明 |
|---|---|---|
| `DUMMYUNIONNAME` | `NameIsString = 1` | 低 31 位是名称字符串的**相对资源节起点的偏移** |
| `DUMMYUNIONNAME` | `NameIsString = 0` | 低 16 位 `Id` 直接是整数资源类型 / 名称 ID |
| `DUMMYUNIONNAME2` | `DataIsDirectory = 1` | 低 31 位是子 `IMAGE_RESOURCE_DIRECTORY` 的偏移（还没到叶节点） |
| `DUMMYUNIONNAME2` | `DataIsDirectory = 0` | 低 31 位是 `IMAGE_RESOURCE_DATA_ENTRY` 的偏移（叶节点） |

> [!important] 偏移的基址是资源节起点
> `OffsetToDirectory` 和 `OffsetToData` **都是相对于资源节（`.rsrc`）起始地址的偏移**，而非文件头、也非 RVA——解析时要先把资源表 RVA 换算为文件偏移，再加上这里的偏移才能定位到正确位置。

### IMAGE_RESOURCE_DATA_ENTRY（叶节点）

到达树的最底层（第三层语言层）后，才会指向这个 16 字节的叶节点，描述真实资源数据的位置和大小：

```c
typedef struct _IMAGE_RESOURCE_DATA_ENTRY {
    DWORD   OffsetToData;           // 资源数据的RVA
    DWORD   Size;                   // 资源数据大小
    DWORD   CodePage;               // 代码页
    DWORD   Reserved;               // 保留
} IMAGE_RESOURCE_DATA_ENTRY, *PIMAGE_RESOURCE_DATA_ENTRY;
```

| 偏移 | 字段 | 大小 | 说明 |
|---|---|---|---|
| `0x00` ⭐ | `OffsetToData` | 4 | **资源数据的 RVA**，需转换为文件偏移才能读取 |
| `0x04` ⭐ | `Size` | 4 | **资源数据字节数** |
| `0x08` | `CodePage` | 4 | 代码页（通常为 0，Unicode 资源为 1200） |
| `0x0C` | `Reserved` | 4 | 保留，恒为 0 |

### IMAGE_RESOURCE_DIR_STRING_U（名称字符串）

当 `NameIsString = 1` 时，条目的名称不是整数 ID，而是一个 Unicode 字符串，结构如下：

```c
typedef struct _IMAGE_RESOURCE_DIR_STRING_U {
    WORD    Length;                 // 字符串长度
    WCHAR   NameString[1];          // Unicode字符串
} IMAGE_RESOURCE_DIR_STRING_U, *PIMAGE_RESOURCE_DIR_STRING_U;
```

## 资源类型速查表

Windows 内核头文件定义了多种标准资源类型，常用的如下：

| 资源类型宏 | ID 值 | 描述 |
|---|---|---|
| `RT_CURSOR` | 1 | 光标资源 |
| `RT_BITMAP` | 2 | 位图资源 |
| `RT_ICON` | 3 | 图标资源（单个） |
| `RT_MENU` | 4 | 菜单资源 |
| `RT_DIALOG` | 5 | 对话框资源 |
| `RT_STRING` | 6 | 字符串表资源 |
| `RT_FONTDIR` | 7 | 字体目录资源 |
| `RT_FONT` | 8 | 字体资源 |
| `RT_ACCELERATOR` | 9 | 快捷键表资源 |
| `RT_RCDATA` | 10 | 用户自定义原始数据 |
| `RT_MESSAGETABLE` | 11 | 消息表资源 |
| `RT_GROUP_CURSOR` | 12 | 光标组（整合多分辨率） |
| `RT_GROUP_ICON` | 14 | 图标组（整合多分辨率） |
| `RT_VERSION` | 16 | 版本信息资源 |
| `RT_MANIFEST` | 24 | 应用程序清单（XML） |

> [!note] RT_ICON 与 RT_GROUP_ICON 的区别
> 一个 `.ico` 文件通常包含多种尺寸（16×16、32×32、256×256 等）。PE 文件会把每种尺寸拆成单独的 `RT_ICON`（ID 3）条目，再用一个 `RT_GROUP_ICON`（ID 14）条目把它们"打包"引用。应用程序实际使用的是 `RT_GROUP_ICON`，加载器按需挑选尺寸。

## 资源表解析流程

从 [[07-详解PE文件(七)：数据目录]] 出发，完整的解析路径如下：

```text
DataDirectory[2].VirtualAddress
       │
       │  RVA → 文件偏移（用节表换算）
       ▼
根 IMAGE_RESOURCE_DIRECTORY
       │
       │  遍历 NumberOfNamedEntries + NumberOfIdEntries 个 ENTRY
       ▼
IMAGE_RESOURCE_DIRECTORY_ENTRY（第一层：类型）
       │ DataIsDirectory = 1
       │  OffsetToDirectory → 子目录偏移（相对资源节起点）
       ▼
IMAGE_RESOURCE_DIRECTORY（第二层：ID/名称）
       │ DataIsDirectory = 1
       │  OffsetToDirectory → 子目录偏移
       ▼
IMAGE_RESOURCE_DIRECTORY（第三层：语言）
       │ DataIsDirectory = 0
       │  OffsetToData → 叶节点偏移
       ▼
IMAGE_RESOURCE_DATA_ENTRY
       │
       │  OffsetToData（RVA）→ 文件偏移
       ▼
    真实资源数据（图标位图/字符串/对话框模板…）
```

> [!warning] 解析陷阱：偏移基址混淆
> 目录条目中的 `OffsetToDirectory` / `OffsetToData` **相对资源节起点**，而 `IMAGE_RESOURCE_DATA_ENTRY.OffsetToData` 是 **RVA**，两者语义不同。很多初学者在此踩坑：前者加资源节的文件基址，后者需通过节表做 RVA→文件偏移换算。混淆后读到的数据会完全错乱。

## 实战：遍历资源表的 C 代码

以下代码完整展示了打开 PE 文件、定位资源表根目录并递归遍历三层结构的过程：

> [!example] 完整遍历示例（C 语言）

```c
#include <windows.h>
#include <stdio.h>

// 常见资源类型名称
static const char* ResourceTypeNames[] = {
    NULL, "RT_CURSOR", "RT_BITMAP", "RT_ICON", "RT_MENU",
    "RT_DIALOG", "RT_STRING", "RT_FONTDIR", "RT_FONT",
    "RT_ACCELERATOR", "RT_RCDATA", "RT_MESSAGETABLE",
    "RT_GROUP_CURSOR", NULL, "RT_GROUP_ICON", NULL,
    "RT_VERSION", NULL, NULL, NULL,
    "RT_PLUGPLAY", "RT_VXD", "RT_ANICURSOR", "RT_ANIICON",
    "RT_HTML", "RT_MANIFEST"
};

// RVA转文件偏移
DWORD RvaToFileOffset(PIMAGE_NT_HEADERS ntHeaders, DWORD rva) {
    PIMAGE_SECTION_HEADER section = IMAGE_FIRST_SECTION(ntHeaders);
    for (int i = 0; i < ntHeaders->FileHeader.NumberOfSections; i++) {
        if (rva >= section[i].VirtualAddress &&
            rva < section[i].VirtualAddress + section[i].Misc.VirtualSize) {
            return rva - section[i].VirtualAddress + section[i].PointerToRawData;
        }
    }
    return 0;
}

// 获取资源类型名称
const char* GetResourceTypeName(DWORD type) {
    if (type < ARRAYSIZE(ResourceTypeNames) && ResourceTypeNames[type]) {
        return ResourceTypeNames[type];
    }
    return "Unknown";
}

// 递归遍历资源目录
void EnumerateResourceDirectory(LPBYTE baseAddress, PIMAGE_NT_HEADERS ntHeaders,
                               DWORD directoryRva, int level) {
    DWORD directoryOffset = RvaToFileOffset(ntHeaders, directoryRva);
    if (directoryOffset == 0) return;

    PIMAGE_RESOURCE_DIRECTORY resDir = (PIMAGE_RESOURCE_DIRECTORY)(baseAddress + directoryOffset);
    DWORD totalEntries = resDir->NumberOfNamedEntries + resDir->NumberOfIdEntries;

    // 遍历目录条目
    PIMAGE_RESOURCE_DIRECTORY_ENTRY resEntry =
        (PIMAGE_RESOURCE_DIRECTORY_ENTRY)(resDir + 1);

    for (DWORD i = 0; i < totalEntries; i++) {
        // 根据层级打印信息
        for (int j = 0; j < level; j++) printf("  ");

        if (resEntry[i].NameIsString) {
            // 处理命名资源
            DWORD nameOffset = RvaToFileOffset(ntHeaders, resEntry[i].NameOffset);
            PIMAGE_RESOURCE_DIR_STRING_U nameString =
                (PIMAGE_RESOURCE_DIR_STRING_U)(baseAddress + nameOffset);
            printf("Name: %.*S\n", nameString->Length, nameString->NameString);
        } else {
            // 处理ID资源
            if (level == 0) {
                // 第一层是资源类型
                printf("Type: %s (ID: %d)\n",
                       GetResourceTypeName(resEntry[i].Id), resEntry[i].Id);
            } else {
                printf("ID: %d\n", resEntry[i].Id);
            }
        }

        // 如果是目录，递归遍历
        if (resEntry[i].DataIsDirectory) {
            EnumerateResourceDirectory(baseAddress, ntHeaders,
                                     resEntry[i].OffsetToDirectory, level + 1);
        } else {
            // 如果是数据条目，显示资源信息
            DWORD dataOffset = RvaToFileOffset(ntHeaders, resEntry[i].OffsetToData);
            PIMAGE_RESOURCE_DATA_ENTRY dataEntry =
                (PIMAGE_RESOURCE_DATA_ENTRY)(baseAddress + dataOffset);

            for (int j = 0; j < level + 1; j++) printf("  ");
            printf("Data RVA: 0x%08X, Size: %d bytes\n",
                   dataEntry->OffsetToData, dataEntry->Size);
        }
    }
}

void PrintResourceTable(const char* filename) {
    HANDLE hFile = CreateFile(filename, GENERIC_READ, FILE_SHARE_READ,
                              NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);

    if (hFile == INVALID_HANDLE_VALUE) {
        printf("无法打开文件: %s\n", filename);
        return;
    }

    HANDLE hMapping = CreateFileMapping(hFile, NULL, PAGE_READONLY, 0, 0, NULL);
    if (!hMapping) {
        printf("创建文件映射失败\n");
        CloseHandle(hFile);
        return;
    }

    LPVOID lpBase = MapViewOfFile(hMapping, FILE_MAP_READ, 0, 0, 0);
    if (!lpBase) {
        printf("映射文件失败\n");
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取DOS头
    PIMAGE_DOS_HEADER dosHeader = (PIMAGE_DOS_HEADER)lpBase;

    // 验证DOS签名
    if (dosHeader->e_magic != IMAGE_DOS_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取NT头
    PIMAGE_NT_HEADERS ntHeaders = (PIMAGE_NT_HEADERS)((LPBYTE)lpBase + dosHeader->e_lfanew);

    // 验证PE签名
    if (ntHeaders->Signature != IMAGE_NT_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取资源表信息
    PIMAGE_DATA_DIRECTORY resourceDir =
        &ntHeaders->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_RESOURCE];

    if (resourceDir->VirtualAddress == 0) {
        printf("该文件没有资源表\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    printf("=== 资源表信息 ===\n");
    printf("资源表RVA: 0x%08X\n", resourceDir->VirtualAddress);
    printf("资源表大小: %d bytes\n", resourceDir->Size);

    // 遍历资源表
    EnumerateResourceDirectory((LPBYTE)lpBase, ntHeaders, resourceDir->VirtualAddress, 0);

    UnmapViewOfFile(lpBase);
    CloseHandle(hMapping);
    CloseHandle(hFile);
}
```

## 资源表的实际意义

资源表在 Windows 程序开发与逆向工程中有着多维度的价值：

| 应用场景 | 说明 |
|---|---|
| **界面元素存储** | 图标、位图、对话框等界面资源集中管理，与代码分离 |
| **多语言本地化** | 语言层（第三层）让同一资源有不同语言版本，切换 `LANGID` 即可 |
| **模块化维护** | 修改 UI 无需重新编译代码，只改资源节即可 |
| **运行时按需加载** | `LoadResource` / `FindResource` 系列 API 动态查找并加载 |
| **逆向工程** | 分析图标/清单/版本信息可快速判断程序身份与目标平台 |
| **资源替换/注入** | 工具（如 ResourceHacker）直接修改 `.rsrc` 节，可换图标、汉化界面 |

> [!warning] 逆向 / 安全提醒
> 恶意软件常利用资源表：
> - 把 shellcode 或加密 payload 塞进 `RT_RCDATA`（类型 10）条目，伪装成普通自定义数据。
> - 在 `RT_MANIFEST`（类型 24）中篡改权限级别（`requestedExecutionLevel`）触发 UAC 绕过。
> - 通过修改 `RT_VERSION`（类型 16）来仿冒合法软件的版本信息，欺骗安全产品。
> 分析可疑 PE 时，务必重点检查这三类资源的内容。

> [!summary] 小结
> 资源表是 PE 文件存储非代码数据的标准机制，三层树形结构（类型→ID→语言）设计兼顾了资源分类、实例管理和多语言支持。解析时从 [[07-详解PE文件(七)：数据目录]] 的第 3 项（索引 2）出发，先找根 `IMAGE_RESOURCE_DIRECTORY`，再逐层向下递归，直到 `IMAGE_RESOURCE_DATA_ENTRY` 得到真实数据的 RVA 和大小；注意目录内偏移与 RVA 的语义区别是最常见的解析陷阱。对于逆向与安全分析，资源节是快速了解程序身份的入口，也是 payload 隐藏的高频区域。相关篇目：[[06-详解PE文件(六)：可选头]] | [[07-详解PE文件(七)：数据目录]] | [[11-详解PE文件(十一)：异常表]]。
