# 详解PE文件(八)：导入表

> 来源：[CSDN 原文](https://blog.csdn.net/geesehoward20000/article/details/154742735)　｜　发布：2025-11-19　｜　合集《PE文件详解》第 8/26 篇

> [!tip] 一句话核心
> 导入表回答一个问题：**这个程序要从哪些 DLL、借哪些函数？** 它的核心是一个 `IMAGE_IMPORT_DESCRIPTOR` 数组（**每个被导入的 DLL 一项**），每项又拉出两条并行的"清单"：**INT**（导入名称表，记函数名）和 **IAT**（[[20-详解PE文件(二十)：导入地址表|导入地址表]]，加载后被填入真实函数地址）。

> [!info] 速查
> - **数据目录索引**：1（`IMAGE_DIRECTORY_ENTRY_IMPORT`，见 [[07-详解PE文件(七)：数据目录|数据目录]]）
> - **核心结构**：`IMAGE_IMPORT_DESCRIPTOR`（以全零项结尾）
> - **配套结构**：`IMAGE_THUNK_DATA`（INT/IAT 元素）、`IMAGE_IMPORT_BY_NAME`（按名导入）
> - **关键概念**：INT（名字清单，恒定）vs IAT（地址清单，加载时回填）
> - **对偶篇**：[[09-详解PE文件(九)：导出表|导出表]]（一方导出、一方导入）

导入表记录了程序运行时需要从外部动态链接库（DLL）中调用的函数信息，使程序能复用系统或他人 DLL 的功能，而无需把这些代码塞进自身。

## 导入表概述

当程序需要调用外部 DLL 中的函数时，这些函数的名称和所在 DLL 的信息就存储在导入表中。Windows 加载器在加载程序时会根据导入表加载相应的 DLL，并将函数的实际地址填入 [[20-详解PE文件(二十)：导入地址表|导入地址表（IAT）]]。

## 导入表的整体结构

导入表不是一张表，而是"描述符 + 两条并行清单 + 函数名"的网状结构：

```text
DataDirectory[1] ─► IMAGE_IMPORT_DESCRIPTOR[]   (每个 DLL 一项，全零项结尾)
   ┌────────────────────────────┐
   │ OriginalFirstThunk (INT) ──┼─► [thunk][thunk]…0 ─► IMAGE_IMPORT_BY_NAME{Hint,"MessageBoxA"}
   │ Name ──────────────────────┼─► "user32.dll"
   │ FirstThunk (IAT) ──────────┼─► [thunk][thunk]…0  (加载后被覆盖为真实地址)
   └────────────────────────────┘
   ┌────────────────────────────┐
   │ ...下一个 DLL (kernel32.dll)│
   └────────────────────────────┘
```

### 1. 导入描述符数组（IMAGE_IMPORT_DESCRIPTOR）

导入表的核心是一个 `IMAGE_IMPORT_DESCRIPTOR` 结构数组，每个结构描述一个被导入的 DLL。数组以一个全零的结构作为结束标志。

```c
typedef struct _IMAGE_IMPORT_DESCRIPTOR {
    union {
        DWORD   Characteristics;            // 0 for terminating null import descriptor
        DWORD   OriginalFirstThunk;         // RVA to original unbound IAT (PIMAGE_THUNK_DATA)
    } DUMMYUNIONNAME;
    DWORD   TimeDateStamp;                  // 0 if not bound,
                                            // -1 if bound, and real date\time stamp
                                            //     in IMAGE_DIRECTORY_ENTRY_BOUND_IMPORT (new BIND)
                                            // O.W. date/time stamp of DLL bound to (Old BIND)

    DWORD   ForwarderChain;                 // -1 if no forwarders
    DWORD   Name;                           // RVA to DLL name
    DWORD   FirstThunk;                     // RVA to IAT (if bound this IAT has actual addresses)
} IMAGE_IMPORT_DESCRIPTOR;
```

各字段说明：

| 字段 | 含义 |
|---|---|
| `OriginalFirstThunk` | 指向**导入名称表（INT）**的 RVA |
| `TimeDateStamp` | 时间戳，用于[[19-详解PE文件(十九)：绑定配置表\|绑定导入]] |
| `ForwarderChain` | 转发链，用于处理函数转发（`-1` 表示无） |
| `Name` | DLL 名称字符串的 RVA |
| `FirstThunk` | 指向**导入地址表（IAT）**的 RVA |

### 2. 导入名称表（Import Name Table, INT）

INT 是一个 `IMAGE_THUNK_DATA` 结构数组，每个元素对应一个导入函数：

```c
typedef struct _IMAGE_THUNK_DATA32 {
    union {
        DWORD ForwarderString;      // PBYTE
        DWORD Function;             // PDWORD
        DWORD Ordinal;
        DWORD AddressOfData;        // PIMAGE_IMPORT_BY_NAME
    } u1;
} IMAGE_THUNK_DATA32;
```

### 3. 导入地址表（Import Address Table, IAT）

IAT 与 INT **结构完全相同**，但在程序加载时，加载器会把每个槽位替换为对应函数的**实际地址**。详见 [[20-详解PE文件(二十)：导入地址表]]。

### 4. 导入名称结构（IMAGE_IMPORT_BY_NAME）

对于按名称导入的函数，INT 中的元素指向此结构：

```c
typedef struct _IMAGE_IMPORT_BY_NAME {
    WORD    Hint;
    CHAR   Name[1];
} IMAGE_IMPORT_BY_NAME, *PIMAGE_IMPORT_BY_NAME;
```

`Hint` 是一个"提示序号"，帮助加载器更快在 [[09-详解PE文件(九)：导出表|导出表]] 中定位函数；`Name` 是变长函数名字符串。

> [!important] INT 与 IAT：为什么要两份一样的表
> 这是导入机制最关键的设计：
>
> | | INT（OriginalFirstThunk） | IAT（FirstThunk） |
> |---|---|---|
> | 加载**前** | 指向函数名 | 指向函数名（与 INT 相同） |
> | 加载**后** | **保持不变**（仍指向名字） | **被覆盖为真实函数地址** |
>
> 加载器拿 INT 当"原始清单"逐个解析函数地址，写进 IAT。程序运行时调用 `call [IAT槽]` 就能跳到真实函数。保留 INT 是为了在地址被改写后，仍有一份"名字底稿"可供[[19-详解PE文件(十九)：绑定配置表|绑定校验]]等用途。

## 导入表工作原理

```text
① 链接器在 EXE 里建好导入表（DLL 名 + 函数名清单）
        │
② 加载器读取导入表，逐个 IMAGE_IMPORT_DESCRIPTOR
        │
③ 按 Name 加载对应 DLL 到进程地址空间
        │
④ 对 INT 中每个函数：在该 DLL 的[[09-详解PE文件(九)：导出表|导出表]]里查地址 → 写入 IAT
        │
⑤ 运行时 call [IAT] 直接跳到真实函数
```

## 导入表在 PE 文件中的位置

导入表的位置和大小存储在 [[07-详解PE文件(七)：数据目录|可选头的数据目录]]中，索引为 `IMAGE_DIRECTORY_ENTRY_IMPORT`（值为 1）：

```c
// 数据目录中的导入表项
DataDirectory[IMAGE_DIRECTORY_ENTRY_IMPORT]
```

## 实际示例

以下是一个遍历 PE 文件导入表的示例代码：

```c
#include <windows.h>
#include <stdio.h>

void PrintImportTable(const char* filename) {
    HANDLE hFile = CreateFile(filename, GENERIC_READ, FILE_SHARE_READ,
                              NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);

    if (hFile == INVALID_HANDLE_VALUE) {
        printf("无法打开文件: %s\n", filename);
        return;
    }

    HANDLE hMapping = CreateFileMapping(hFile, NULL, PAGE_READONLY, 0, 0, NULL);
    if (!hMapping) {
        printf("创建文件映射失败\n");
        CloseHandle(hFile);
        return;
    }

    LPVOID lpBase = MapViewOfFile(hMapping, FILE_MAP_READ, 0, 0, 0);
    if (!lpBase) {
        printf("映射文件失败\n");
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取DOS头
    IMAGE_DOS_HEADER* dosHeader = (IMAGE_DOS_HEADER*)lpBase;

    // 验证DOS签名
    if (dosHeader->e_magic != IMAGE_DOS_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取NT头
    IMAGE_NT_HEADERS* ntHeaders = (IMAGE_NT_HEADERS*)((BYTE*)lpBase + dosHeader->e_lfanew);

    // 验证PE签名
    if (ntHeaders->Signature != IMAGE_NT_SIGNATURE) {
        printf("不是有效的PE文件\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取导入表信息
    IMAGE_DATA_DIRECTORY* importDir = &ntHeaders->OptionalHeader.DataDirectory[IMAGE_DIRECTORY_ENTRY_IMPORT];
    if (importDir->VirtualAddress == 0) {
        printf("该文件没有导入表\n");
        UnmapViewOfFile(lpBase);
        CloseHandle(hMapping);
        CloseHandle(hFile);
        return;
    }

    // 获取导入描述符数组
    IMAGE_IMPORT_DESCRIPTOR* importDesc = (IMAGE_IMPORT_DESCRIPTOR*)((BYTE*)lpBase + importDir->VirtualAddress);

    printf("=== 导入表信息 ===\n");

    // 遍历导入描述符数组
    for (; importDesc->Name != 0; importDesc++) {
        // 获取DLL名称
        char* dllName = (char*)((BYTE*)lpBase + importDesc->Name);
        printf("\nDLL名称: %s\n", dllName);

        // 获取导入名称表
        IMAGE_THUNK_DATA32* thunk = (IMAGE_THUNK_DATA32*)((BYTE*)lpBase + importDesc->OriginalFirstThunk);

        // 遍历导入函数
        while (thunk->u1.AddressOfData != 0) {
            if (thunk->u1.Ordinal & IMAGE_ORDINAL_FLAG32) {
                // 按序号导入
                printf("  函数序号: %d\n", IMAGE_ORDINAL32(thunk->u1.Ordinal));
            } else {
                // 按名称导入
                IMAGE_IMPORT_BY_NAME* importByName = (IMAGE_IMPORT_BY_NAME*)((BYTE*)lpBase + thunk->u1.AddressOfData);
                printf("  函数名称: %s (Hint: %d)\n", importByName->Name, importByName->Hint);
            }
            thunk++;
        }
    }

    UnmapViewOfFile(lpBase);
    CloseHandle(hMapping);
    CloseHandle(hFile);
}
```

> [!note] 注意这里用 INT 而非 IAT 遍历
> 示例里遍历的是 `OriginalFirstThunk`（INT）。因为静态分析磁盘文件时，IAT 还没被加载器回填，用 INT 才能稳定拿到函数名。最高位是 `IMAGE_ORDINAL_FLAG32` 时表示"按序号导入"，否则按名称导入。

## 导入表的重要性

| 价值 | 说明 |
|---|---|
| **模块化设计** | 复用外部库功能，无需把代码全打进 EXE |
| **节省内存** | 多个程序共享同一 DLL |
| **便于更新** | 更新 DLL 即可影响所有使用者 |
| **逆向工程** | 看导入表即可快速判断程序"会调用哪些系统能力" |
| **安全分析** | 程序调用的关键 API（网络、进程、注册表等）都体现在导入表里 |

> [!summary] 小结
> 导入表以 `IMAGE_IMPORT_DESCRIPTOR` 数组组织每个依赖 DLL，通过 **INT（名字）+ IAT（地址）** 双表完成动态链接：加载器顺着 INT 在目标 DLL 的 [[09-详解PE文件(九)：导出表|导出表]]里查地址、回填 [[20-详解PE文件(二十)：导入地址表|IAT]]。它与导出表是一对"借/还"关系，是逆向分析中最先要看的结构之一；其变体还有 [[19-详解PE文件(十九)：绑定配置表|绑定导入]] 与 [[21-详解PE文件(二十一)：延迟导入表|延迟导入]]。
