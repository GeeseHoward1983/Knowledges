# OS启动（05）· 从实模式到保护模式到长模式

## 概述与定位

> [!abstract] TL;DR
> x86 CPU 上电后进入**实模式**（16 位、段:偏移寻址、约 1 MB 可用），bootloader 负责三步升级：① 开 A20 地址线；② 加载 GDT 并置 `CR0.PE=1` 进入**保护模式**（32 位、GDT 段描述符、Ring 0–3）；③ 建 64 位页表，依次置 `CR4.PAE=1` → `EFER.LME=1`（MSR `0xC0000080`）→ `CR0.PG=1`，CPU 随即自动置 `EFER.LMA=1` 进入**长模式**（64 位）。三步切换本质是对**几个控制寄存器比特位**的依序设置，顺序错则 CPU 触发 triple fault。

本篇是 CPU 模式切换的完整技术手册。上游（第 04 篇）GRUB 在实模式完成最后的磁盘读取与参数填充；下游（第 06 篇）`startup_64` 在长模式接管内核解压。本篇覆盖两者之间的寄存器级操作序列，配合 QEMU + gdb 可实机验证。

## 原理与机制

### x86 三大运行模式

x86 的"模式"（Mode）是 CPU 对地址宽度、内存保护、特权级等核心行为的整体设置。每次加电后 CPU 从**实模式**出发，软件必须主动驱动模式升级。

```mermaid
graph LR
    PWR["上电/复位<br/>RESET#"] --> REAL["实模式<br/>Real Mode<br/>16 位、段<<4+偏移、≈1MB"]
    REAL -->|"置 CR0.PE=1<br/>far jump 刷新 CS"| PROT["保护模式<br/>Protected Mode<br/>32 位、GDT、Ring 0-3"]
    PROT -->|"建页表<br/>CR4.PAE→EFER.LME→CR0.PG"| LONG["长模式<br/>Long Mode<br/>64 位、4 级页表、EFER.LMA=1"]
    LONG -.可退回.-> PROT
    style PWR fill:#555,color:#fff
    style REAL fill:#c0392b,color:#fff
    style PROT fill:#2471a3,color:#fff
    style LONG fill:#1e8449,color:#fff
```

> **兼容子模式（Compatibility Mode）**：长模式内可执行 32 位代码（CS 的 `L` 位 = 0），是 64 位操作系统运行 32 位应用的机制，本篇聚焦主线升级路径。

### 实模式（Real Mode）

| 属性 | 值 |
|---|---|
| 数据宽度 | 16 位（寄存器 AX/BX/CX/DX/SI/DI/SP/BP） |
| 地址计算 | 物理地址 = 段寄存器（CS/DS/SS/ES） `<< 4` + 16 位偏移 |
| 可寻址空间 | 约 1 MB（20 位地址线，`0x00000`–`0xFFFFF`） |
| 内存保护 | **无**，任意代码可读写任意物理地址 |
| 特权级 | **无**，等价于 Ring 0 |
| 上电状态 | CPU 复位后默认进入实模式 |

物理地址计算示例：CS = `0x07C0`，IP = `0x0000`，则 PC = `0x07C0 << 4 + 0x0000 = 0x07C00`，即 MBR 被加载到 `0x7C00` 的由来。

**地址回绕（Wraparound）**：实模式地址总线只有 20 位（A0–A19），访问 `0xFFFF:0x0010` 时计算结果为 `0x100000`，超出 20 位范围的高位被截断，回绕到 `0x00000`。这是 A20 地址线问题的根源。

### 保护模式（Protected Mode）

保护模式以**描述符**（Descriptor）取代段寄存器直接当地址的做法。段寄存器存放的是**段选择子**（Segment Selector），CPU 用它索引 **GDT（全局描述符表）** 中的描述符，再从描述符取出真实基址与界限：

```
线性地址 = 段描述符.基址（Base） + 有效地址（Offset）
```

**段描述符结构（8 字节，64 位）**：

```
 63      56 55 52 51  48 47  40 39      32
 ┌─────────┬────┬──────┬───────┬─────────┐
 │Base[31:24]│Flags│Limit│ Access│Base[23:16]│
 └─────────┴────┴──────┴───────┴─────────┘
 31                   16 15                 0
 ┌──────────────────────┬────────────────────┐
 │     Base[15:0]       │    Limit[15:0]     │
 └──────────────────────┴────────────────────┘
```

关键字段说明：

| 字段 | 位置 | 含义 |
|---|---|---|
| Base | bits 63:56 + 39:32 + 15:0 | 段基地址（32 位拼接） |
| Limit | bits 51:48 + 15:0 | 段界限（20 位，单位由 G 位决定） |
| DPL | Access[6:5] | 描述符特权级（0=最高/内核，3=最低/用户） |
| P | Access[7] | 段存在位（Present），0 则访问触发 #NP |
| S | Access[4] | 0=系统段（TSS/LDT），1=代码/数据段 |
| Type | Access[3:0] | 代码段（可执行/一致性）/数据段（可写/扩展方向） |
| G | Flags[3] | 粒度：0=界限单位字节，1=单位 4KB |
| D/B | Flags[2] | 默认操作数大小：32 位代码段（D=1）/32 位栈（B=1） |

**段选择子（Segment Selector，16 位）**：

```
 15                          3  2   1  0
 ┌──────────────────────────┬───┬────────┐
 │       Index（13 位）      │ TI│  RPL  │
 └──────────────────────────┴───┴────────┘
  TI：0=GDT，1=LDT     RPL：请求特权级
```

**特权级（Ring 0–3）**：Ring 0（内核），Ring 3（用户态），Ring 1/2 现代 OS 基本不用。DPL/RPL 的比较由 CPU 硬件执行，违反时触发 `#GP`（通用保护异常，向量 13）。

**进入保护模式的核心操作**：
- 加载 GDTR（`lgdt`）
- 置 `CR0.PE = 1`（bit 0）
- 立即执行 **far jump**（`ljmp`）刷新 CS，使新 GDT 描述符生效

### 长模式（Long Mode）

长模式是 64 位运行环境，由 AMD64 引入（Intel EM64T 兼容），通过 **EFER（Extended Feature Enable Register）** MSR 控制：

- MSR 地址：**`0xC0000080`**
- 关键位：`EFER.LME`（bit 8）= Long Mode Enable，写 1 请求进入
- 激活确认：`EFER.LMA`（bit 10）= Long Mode Active，CPU 在 `CR0.PG` 置 1 后自动设置

**分段在长模式中的退化**：

| 段寄存器 | 长模式行为 |
|---|---|
| CS | 基址忽略（强制 0）；`L` 位（bit 21）= 1 表示 64 位子模式 |
| DS/ES/SS | 基址、界限全部忽略 |
| FS/GS | **仍有效**，基址通过 MSR `0xC0000100`（FS.base）/ `0xC0000101`（GS.base）设置；用于 TLS 和每 CPU 数据 |

**长模式强制要求开分页**：必须先建好至少能覆盖内核代码的 64 位页表（PML4→PDPT→PD→PT，详见第 07 篇），再执行切换序列。

## 结构 / 汇编 / 流程详解

### A20 地址线

**历史背景**：8086 有 20 根地址线（A0–A19），`0xFFFF:0xFFFF` = `0x10FFEF` 会回绕至 `0x0FFEF`。PC/AT 用键盘控制器的第 2 位控制 A20，沿用至今成为历史包袱。

**若不开 A20**：访问 `0x100000` 以上（1 MB+）的内存地址时，A20 始终为 0，奇数 MB（`0x100000`–`0x1FFFFF`、`0x300000`–`0x3FFFFF` …）不可访问，保护模式内核崩溃。

**开启方式**（三种，任选其一）：

| 方式 | 机制 | 说明 |
|---|---|---|
| BIOS INT 15h | `AX=2401h; INT 15h` | 最简单，需在实模式调用 |
| 键盘控制器（8042） | 写 Port `0x64`（命令 `0xD1`）再写 Port `0x60`（`0xDF`） | 通用但慢，需等待 IBF |
| Fast A20（Port 0x92） | 写 Port `0x92` 的 bit 1 置 1 | 最快，现代主板支持 |

**验证**：置 A20 后写 `0x00100000`、读 `0x00000000`，若值不同则 A20 已开启（无回绕）。

### GDT 布局（引导阶段最小集）

引导代码进入保护模式前至少需要 3 个描述符：

```
GDT:
  [0x00] 空描述符（Null descriptor，必须全零）
  [0x08] 代码段描述符（Base=0, Limit=4GB, DPL=0, 32位）
  [0x10] 数据段描述符（Base=0, Limit=4GB, DPL=0, 32位可写）
```

GDTR（6 字节）：

```
 47                       16 15           0
 ┌──────────────────────────┬──────────────┐
 │      Base（32 位基址）    │  Limit-1    │
 └──────────────────────────┴──────────────┘
```

### 实模式 → 保护模式 → 长模式完整时序

以下伪汇编以 Intel 语法标注，演示三阶段完整切换流程：

```nasm
; ============================================================
; 阶段 0：实模式准备（16 位）
; ============================================================

; 1. 开 A20（Fast A20 方式）
    in   al, 0x92
    or   al, 0x02          ; bit 1 = A20 enable
    out  0x92, al

; 2. 加载 GDT
    lgdt [gdt_descriptor]  ; gdt_descriptor = { limit, base }

; 3. 关中断（切换过程中 IDT 尚未建立）
    cli

; 4. 置 CR0.PE = 1 进入保护模式
    mov  eax, cr0
    or   eax, 0x1          ; bit 0 = PE
    mov  cr0, eax

; 5. far jump 刷新 CS（使 GDT 中代码段描述符生效，冲刷流水线）
    jmp  0x08:pm_entry     ; 0x08 = GDT 代码段选择子（Index=1，TI=0，RPL=0）

; ============================================================
; 阶段 1：保护模式（32 位）
; ============================================================
pm_entry:
    ; 更新数据段寄存器
    mov  ax, 0x10          ; 数据段选择子（Index=2）
    mov  ds, ax
    mov  es, ax
    mov  ss, ax

    ; 建 64 位页表（示意：identity map 最低 2MB）
    ; ... 填充 PML4[0]→PDPT[0]→PD[0]（2MB 大页，PS=1）...
    ; CR3 ← PML4 物理地址（4KB 对齐）
    mov  eax, pml4_table
    mov  cr3, eax

    ; 置 CR4.PAE = 1（物理地址扩展，bit 5）
    mov  eax, cr4
    or   eax, 0x20
    mov  cr4, eax

    ; 置 EFER.LME = 1（通过 RDMSR/WRMSR 操作 MSR 0xC0000080）
    mov  ecx, 0xC0000080   ; EFER 的 MSR 地址
    rdmsr                  ; EDX:EAX ← EFER
    or   eax, 0x100        ; bit 8 = LME
    wrmsr                  ; EFER ← EDX:EAX

    ; 置 CR0.PG = 1（分页使能，bit 31），CPU 立即置 EFER.LMA=1
    mov  eax, cr0
    or   eax, 0x80000001   ; 同时保留 PE（bit 0）
    mov  cr0, eax

    ; far jump 进入 64 位代码段（刷新 CS；CS 选择子对应 L=1 描述符）
    jmp  0x18:lm_entry     ; 0x18 = 64 位代码段描述符（GDT 第 3 项）

; ============================================================
; 阶段 2：长模式（64 位）
; ============================================================
lm_entry:
    ; 至此 CPU 已处于 64 位长模式（EFER.LMA=1）
    ; 更新 64 位数据段（FS/GS 可用 WRFSBASE/WRGSBASE 或 MSR 单独设置 base）
    mov  ax, 0x20          ; 64 位数据段选择子
    mov  ds, ax
    mov  es, ax
    mov  ss, ax

    ; 建立 64 位栈，跳转到内核入口
    mov  rsp, kernel_stack_top
    jmp  kernel_entry      ; 如 startup_64（详见第 06 章）
```

> [!warning] 示例输出为示意
> 上述伪汇编仅展示关键寄存器操作顺序，实际引导代码（如 Linux `arch/x86/boot/compressed/head_64.S`）还需初始化 IDT 存根、处理 `boot_params`、重定位等步骤，不可直接作为生产代码使用。

### 关键寄存器位速查

| 寄存器/MSR | 位 | 名称 | 作用 |
|---|---|---|---|
| `CR0` | bit 0 | `PE` | Protected Mode Enable，置 1 进保护模式 |
| `CR0` | bit 31 | `PG` | Paging Enable，置 1 开分页 |
| `CR4` | bit 5 | `PAE` | Physical Address Extension，64 位页表前提 |
| `EFER`（MSR `0xC0000080`） | bit 8 | `LME` | Long Mode Enable，请求进入长模式 |
| `EFER`（MSR `0xC0000080`） | bit 10 | `LMA` | Long Mode Active，CPU 自动置 1 确认 |
| `CR3` | bits 51:12 | PML4 基址 | PML4 表物理地址（4 KB 对齐） |

### far jump 的必要性

每次写完 CR0.PE 或更换 CS 对应的描述符后，CPU **流水线**仍可能保留旧模式下预取的指令。`far jump`（`ljmp seg:offset`）强制以新的 CS 描述符刷新：
1. 将 CS 更新为新选择子，描述符缓存（隐藏部分）同步刷新；
2. 清空指令预取队列；
3. 对长模式：CS 描述符的 `L=1` 使 CPU 切换为 64 位解码模式。

遗漏 far jump 是初学者最常见的 triple fault 来源。

### 与内核启动的衔接

```
实模式 setup（arch/x86/boot/main.c）
  └─ go_to_protected_mode()
       ├─ enable_a20()          # 开 A20
       ├─ reset_coprocessor()
       ├─ protected_mode_jump() # lgdt + CR0.PE + far jmp
       └─→ startup_32（保护模式 32 位入口）
             └─ 建页表 + CR4.PAE + EFER.LME + CR0.PG + far jmp
                  └─→ startup_64（长模式 64 位入口，详见第 06 章）
                         └─→ start_kernel()
```

## 实战 / 观察

### QEMU + gdb 观察模式切换

**启动 QEMU（暂停等待 gdb）**：

```bash
qemu-system-x86_64 \
    -kernel bzImage \
    -append "console=ttyS0 nokaslr" \
    -nographic \
    -s -S          # -s 开 gdbserver :1234，-S 暂停等待连接
```

**连接 gdb 并设断点**：

```gdb
(gdb) target remote :1234
(gdb) set architecture i8086          # 初始是实模式
(gdb) info registers                  # 查看初始 CS:IP、CR0
(gdb) break *0x7c00                   # MBR 入口
(gdb) continue

# 到达 MBR 后，单步到 CR0.PE 被置位
(gdb) watch *(int*)0x...cr0           # 监视 CR0 变化（gdb 可监视寄存器）
(gdb) continue
```

**进保护模式后检查 CR0**：

```gdb
(gdb) set architecture i386:x86-64   # 切到 64 位解码
(gdb) info registers cr0 cr4 efer
```

**示例输出**（QEMU 内 `info registers` 节选，非本机实跑）：

```text
CR0=80050033  CR4=000006f0  EFER=d01
  CR0.PE=1  CR0.PG=1  CR0.WP=1
  CR4.PAE=1  CR4.PSE=1
  EFER.LME=1  EFER.LMA=1  EFER.SCE=1
```

> [!warning] 示例输出为示意
> 以上寄存器值来自典型 Linux 早期启动阶段，具体数值因内核版本和配置而异，以实际调试输出为准。

**QEMU Monitor 直接查看**（另一窗口）：

```bash
(qemu) info registers
# 或进入 monitor：Ctrl-A c
(qemu) x /4gx 0x7c00       # 查看 MBR 内存
(qemu) info mem             # 查看页表映射（长模式开启后）
```

**验证 EFER.LMA 被 CPU 自动置位**：

在 `CR0.PG = 1` 设置前后各读一次 MSR：

```gdb
(gdb) p/x $ecx = 0xC0000080
(gdb) p/x $eax             # RDMSR 后 EAX.bit10 = LMA
```

## 安全性与正确使用

### 模式与特权级是隔离基石

CPU 模式切换本身是内核权限的**不可逆上锁**：一旦进入长模式并建立 OS 页表，用户态代码（Ring 3）无法再访问 `CR0`/`CR4`/MSR（触发 `#GP` 异常，向量 13），更无法自行切换回实模式或修改 GDT/IDT。这是操作系统隔离用户进程、防止恶意代码破坏内核的基础。

若 GDT 中段描述符的 DPL 配置错误（如代码段 DPL=3），则用户态可绕过特权级检查直接执行内核代码——这是早期 DOS 保护模式 bug 的典型模式。现代内核强制 DPL=0（内核段）配合 Ring 3 用户段隔离，两者不可混用。

### 切换时序错误导致 Triple Fault 的排错

**Triple Fault（三重错误）**：CPU 依次触发异常 → 处理异常时再触发异常 → IDT/堆栈异常，最终 CPU 复位重启（QEMU 表现为无限重启）。

常见触发原因与排查：

| 错误 | 症状 | 排查方法 |
|---|---|---|
| 忘记 far jump（遗漏 `ljmp`） | 进保护模式后立即复位 | gdb 在 `mov cr0, eax` 后下一条指令处断点；检查 CS 是否已更新 |
| GDT 描述符全零或未加载 | `lgdt` 前就置 `CR0.PE` | `x /6bx gdt_addr` 检查 GDT 内存内容是否正确 |
| 未开 A20 就访问 1MB+ | 随机崩溃 | 进保护模式后写 `0x100000`，读 `0x000000`，验证值不同 |
| 进长模式前未建页表 | 长模式下第一条指令即 #PF | `cr3` 是否指向有效 PML4？`info mem` 查映射 |
| 切换顺序错误（如先 PG 后 LME） | CPU 拒绝（`#GP`）或静默崩溃 | 严格遵循：`CR4.PAE` → `EFER.LME` → `CR0.PG` |
| 栈指针未对齐 | 进 64 位后首个 `push` 触发 #GP | `RSP` 必须 16 字节对齐（ABI 要求） |

**排错黄金法则**：在每次寄存器写后、far jump 前用 `info registers` 确认当前 CR0/CR4/EFER，确保每一步符合预期再继续。

### 历史漏洞警示

- **实模式 SMRAM Overlay**：早期主板 SMM（系统管理模式）可能将某些实模式可访问地址映射到 SMRAM，形成特权提升路径。
- **A20 Line 竞争**：若 A20 开启不完整（键盘控制器方式下未等待 IBF 清空），切到保护模式后偶发地址别名，内存写入会污染低 1MB 数据。
- **Long Mode 规范地址（Canonical Address）**：64 位指针 bits 63:48 必须等于 bit47（符号扩展）——用户段 bit47=0 时高位全 0，内核段 bit47=1 时高位全 1，否则触发 `#GP`。内核布局在高规范地址（`0xFFFF800000000000` 起），用户在低规范地址，两者中间是不可访问的"空洞"。

## 小结

| 模式 | 关键开关 | 地址宽度 | 分段状态 | 分页 |
|---|---|---|---|---|
| 实模式 | 上电默认 | 20 位（段×16+偏移） | 段寄存器直接当地址 | 无 |
| 保护模式 | `CR0.PE=1` + far jump | 32 位线性地址 | GDT 段描述符全功能 | 可选 |
| 长模式 | `CR4.PAE=1` + `EFER.LME=1` + `CR0.PG=1` | 48 位虚拟地址（当前） | 分段基本退化（FS/GS 仍用） | **强制** |

切换序列是 bootloader 最精密的部分：A20 → GDTR → CR0.PE → far jump → 页表 → CR4.PAE → EFER.LME → CR0.PG → far jump → 长模式。任何一步乱序都会导致 triple fault。理解这个序列，就能在 QEMU + gdb 里逐步观测一台 x86 机器从 16 位蜕变为 64 位的全过程。
