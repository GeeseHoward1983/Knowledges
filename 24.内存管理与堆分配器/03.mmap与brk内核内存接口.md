# 内存与堆（03）· mmap与brk内核内存接口

## 概述与定位

> [!abstract] TL;DR
> 堆分配器向内核要内存只有两条路：`brk`/`sbrk` 推进**堆段的顶端边界（program break）**，让堆连续向上生长；或用 `mmap` 申请**匿名私有映射**，获得可独立释放的任意大小内存块。ptmalloc 的 `main_arena` 默认走 `brk` 扩堆，线程 arena 及单次请求 ≥ 128KB（`M_MMAP_THRESHOLD`）时走 `mmap`。理解这两个接口的机制，是读懂 `malloc`/`free` 与内核之间"批发合同"的关键。

堆分配器扮演**内存中间商**：向内核批发大块内存，再按需零售给应用。但分配器自身从内核申请内存，只有两种系统调用——`brk` 和 `mmap`。本篇聚焦这两个内核接口的语义、差异、以及分配器如何在两者之间做选择。与前篇[[02.进程地址空间与虚拟内存]]建立的地址空间模型直接衔接：堆段的 "top" 地址就是 program break，匿名 mmap 区域就是地址空间中 heap 和 stack 之间的"浮动映射区"。

---

## 原理与机制

### brk vs mmap 决策流

```mermaid
graph TD
    APP["应用调用 malloc(size)"] --> CHECK{"size ≥ M_MMAP_THRESHOLD<br/>（默认 128KB）？"}
    CHECK -->|是| MMAP_PATH["直接 mmap 匿名页<br/>置 IS_MMAPPED 标志"]
    CHECK -->|否| ARENA{"使用哪个 arena？"}
    ARENA -->|main_arena| BRK_PATH["brk/sbrk 推进<br/>program break"]
    ARENA -->|线程 arena| MMAP_ARENA["mmap 创建整块<br/>arena 堆区域"]
    BRK_PATH --> ALLOC["从 top chunk 切割分配"]
    MMAP_ARENA --> ALLOC
    MMAP_PATH --> DIRECT["直接返回 mmap 映射<br/>free 时 munmap"]
```

### 惰性提交与 overcommit

无论 `brk` 还是 `mmap`，内核在系统调用返回时**只建立虚拟内存映射（VMA），不立刻分配物理页**。这就是**惰性提交（lazy commit）**：

- 首次访问该地址 → 触发**缺页中断（page fault）**
- 内核在缺页处理中分配物理页，填入 TLB，返回用户态继续执行
- 此机制使 `mmap(1GB)` 瞬间完成，但物理内存只在真正使用时才消耗

内核通过 `vm.overcommit_memory` 控制是否允许过度提交：

| 取值 | 策略 |
|------|------|
| 0（默认） | 启发式：允许适度 overcommit，拒绝明显过量 |
| 1 | 始终允许，不检查 |
| 2 | 严格：总提交量不超过 `swap + RAM * overcommit_ratio` |

`mmap` 的匿名页默认在 `overcommit_memory=0/1` 下允许超额承诺，因此一个进程可以 `mmap` 远超物理内存的空间——只要实际访问量在物理内存范围内即可。

## 接口详解

### brk / sbrk

`brk`/`sbrk` 是最古老的内存扩展接口，操作**堆段的上边界（program break）**。

#### 系统调用签名

```c
#include <unistd.h>

/* 直接设置 program break 到地址 addr */
int brk(void *addr);

/* 相对移动 program break，增量为 increment 字节
 * 返回值：移动前的 program break 地址
 * sbrk(0) 返回当前 break（不移动） */
void *sbrk(intptr_t increment);
```

> `sbrk` 是 C 库封装，底层调用 `brk` 系统调用（Linux 只有 `brk` syscall，`sbrk` 是 libc 包装）。

#### 工作原理

进程地址空间中，堆从 BSS 段末尾（`end`）向高地址生长，当前堆顶就是 **program break**。`brk` 只需内核更新该进程的 VMA 边界：

```
低地址                                       高地址
┌───────┬───────┬─────────────────┬─────────────────────────
│ .text │ .data │ .bss  │  HEAP   │         ...
└───────┴───────┴─────────────────┴─────────────────────────
                         ↑ end    ↑ program break（可上移）
```

典型用法（ptmalloc 内部）：

```c
/* 获取当前 break */
void *old_brk = sbrk(0);

/* 上移 CHUNK_SIZE，扩展堆 */
if (sbrk(CHUNK_SIZE) == (void *)-1) {
    /* ENOMEM：系统内存不足 */
}
```

#### brk 的局限

- **只能连续扩展**：堆是一段连续虚拟内存，`brk` 只能上移或下移顶端
- **只能从顶端收缩**：中间释放的内存无法直接还给内核；只有当 top chunk（堆顶剩余空闲块）足够大时，ptmalloc 才会调用 `malloc_trim` 下移 break
- **单线程扩堆**：多线程竞争时 `main_arena` 扩堆需要加锁，性能瓶颈

---

### mmap / munmap

`mmap` 是通用映射接口，既可映射文件，也可申请**匿名私有页**（堆分配器常用方式）。

#### 匿名映射申请

```c
#include <sys/mman.h>

/* 申请匿名私有内存，等价于分配器的"大块内存" */
void *ptr = mmap(
    NULL,                           /* 让内核选择地址 */
    size,                           /* 字节数（按页对齐） */
    PROT_READ | PROT_WRITE,         /* 可读写 */
    MAP_PRIVATE | MAP_ANONYMOUS,    /* 私有匿名映射 */
    -1,                             /* fd = -1（匿名） */
    0                               /* offset = 0 */
);
if (ptr == MAP_FAILED) { /* ENOMEM 等 */ }

/* 归还映射（立刻有效，物理页回收） */
munmap(ptr, size);
```

**与 `brk` 对比的核心优势**：

| 特性 | brk | mmap 匿名 |
|------|-----|-----------|
| 位置 | 连续堆段顶端 | 地址空间任意位置 |
| 独立释放 | 只能收缩顶端 | 任意块随时 `munmap` |
| 适用场景 | 小/中等请求，频繁分配 | 大块请求，线程 arena |
| 多线程 | main_arena 需加锁 | 每个线程 arena 独立 |
| 内核开销 | 低（一次移指针） | 稍高（维护 VMA 树） |

---

### madvise：归还物理页但保留映射

当分配器持有大块内存暂时不用，希望把**物理内存**还给内核但**保留虚拟地址映射**时，使用 `madvise`：

```c
#include <sys/mman.h>

/* 告知内核：[addr, addr+len) 的物理页可以回收
 * 下次访问触发缺页重新分配物理页，数据变为零 */
madvise(addr, len, MADV_DONTNEED);

/* glibc 2.7+：页可回收，但下次访问前原数据可能仍在
 * 比 MADV_DONTNEED 更激进（内核按需懒回收） */
madvise(addr, len, MADV_FREE);
```

**区别**：
- `MADV_DONTNEED`：物理页立即标记可回收，再次访问获得全零页
- `MADV_FREE`（Linux 4.5+）：物理页在内存压力时才回收，访问前原内容可能仍在，性能更优

ptmalloc 在 `malloc_consolidate` 后对大型空闲 chunk 可能调用 `madvise(MADV_DONTNEED)` 释放物理内存，但 VMA 仍在，下次分配可直接复用虚拟地址。

---

### mmap 阈值（M_MMAP_THRESHOLD）

ptmalloc 对每次 `malloc` 请求都判断：是从堆（`brk` 区域）分配，还是直接 `mmap`？决定因素是 **`M_MMAP_THRESHOLD`**。

```c
/* glibc malloc/malloc.c 相关宏 */
#define DEFAULT_MMAP_THRESHOLD      (128 * 1024)      /* 128KB */
#if __WORDSIZE == 32
#  define DEFAULT_MMAP_THRESHOLD_MAX  (512 * 1024)                      /* 32位: 512KB */
#else
#  define DEFAULT_MMAP_THRESHOLD_MAX  (4 * 1024 * 1024 * sizeof(long))  /* 64位: 4*1MB*8 = 32MB */
#endif

/* 可通过 mallopt 调整 */
mallopt(M_MMAP_THRESHOLD, 256 * 1024);  /* 手动设为 256KB */
```

**动态调整（trim/mmap 联动）**：

- 默认情况下，`M_MMAP_THRESHOLD` **不是固定 128KB**，而是动态增长的
- 当一个大 mmap 块被 `free`（触发 `munmap`）时，ptmalloc 会将阈值上调至该块的大小（上限 `DEFAULT_MMAP_THRESHOLD_MAX`，约 32MB）
- 意图：避免对相同大小的请求反复 `mmap`/`munmap`，让它们进入堆的 fastbin/largebin 被复用
- 手动调用 `mallopt(M_MMAP_THRESHOLD, X)` 会**关闭动态调整**，固定为 X

```
请求大小 ≥ M_MMAP_THRESHOLD
    → mmap 直接分配
    → chunk->size 置 IS_MMAPPED（低位 0x2）
    → free 时判断 IS_MMAPPED，调用 munmap 直接归还内核
    → 不经过 bins，不合并，不进 tcache
```

---

### malloc_trim：收缩 brk 堆

`malloc_trim` 是分配器主动将**堆顶的空闲内存还给内核**的接口（降低 program break）：

```c
#include <malloc.h>
/* pad：保留堆顶 pad 字节不还（允许留一点余量避免频繁 brk）
 * 成功返回 1，无法收缩返回 0 */
int malloc_trim(size_t pad);
```

内部逻辑：若 `main_arena` 的 top chunk 大小超过 `M_TRIM_THRESHOLD`（默认 128KB），则调用 `sbrk(-n)` 下移 break，将 `n` 字节还给内核。

> **注意**：`malloc_trim` 只对 `main_arena` 的 `brk` 区域有效；线程 arena 用 `mmap` 建堆，空闲时通过 `munmap` 直接归还，不需要 trim。

## 实战：strace 看 brk/mmap 节奏

通过 `strace` 捕获分配器与内核的真实对话：

```bash
# 追踪 brk 和 mmap/munmap 系统调用
strace -e trace=brk,mmap,munmap ./a.out 2>&1 | head -60
```

典型输出：

```text
brk(NULL)                               = 0x5591234a5000   # 获取初始 break
brk(0x5591234c6000)                     = 0x5591234c6000   # 扩堆 ~132KB（首次）
mmap(NULL, 8192, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0) = 0x7f1234000000
mmap(NULL, 139264, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0) = 0x7f1233fde000
munmap(0x7f1233fde000, 139264)          = 0
brk(0x5591234e7000)                     = 0x5591234e7000   # 再次扩堆
```

> [!warning] 示例输出为示意
> 以上 strace 输出仅为说明性示意，真实地址与大小因程序、libc 版本、ASLR 而不同。

**解读节奏**：

1. 启动时 `brk(NULL)` → 获取初始 program break
2. 首次 `malloc` 触发 `brk(new_addr)` → 一次性预扩大段（通常扩 128KB 以上）；后续小分配在已扩区域切割，不再 syscall
3. `malloc(≥128KB)` 出现 `mmap(MAP_ANONYMOUS)`，`free` 后出现对应 `munmap`
4. 多线程程序可以观察到线程 arena 的 `mmap` 请求（通常 64MB 对齐的大块）

```bash
# 更细粒度：同时看调用栈
strace -e trace=brk,mmap,munmap -k ./a.out 2>&1 | grep -A4 mmap
```

## 安全性与正确使用

### 误区：free 之后内存立刻还给内核

这是最常见的认知误区。`free(ptr)` **不一定**触发系统调用：

- 若 chunk 大小 < `M_MMAP_THRESHOLD`：chunk 进入 tcache/fastbin/unsorted bin，**虚拟内存和物理内存都仍属进程**，RSS 不下降
- 只有 `IS_MMAPPED` 的块 `free` 时才立刻 `munmap`，还给内核
- `brk` 堆上的块只有当 top chunk 足够大时，经 `malloc_trim` 才会下移 break

**实际影响**：监控 `RSS`（驻留内存）不会在 `free` 后立刻下降，这是正常行为，不是泄漏。

### overcommit 与 OOM Killer

启用 overcommit 后：

- `mmap(1GB)` 成功不意味着有 1GB 可用物理内存
- 物理内存耗尽时，Linux OOM Killer 会按评分（`/proc/<pid>/oom_score`）杀进程
- 服务器程序应设置 `mallopt(M_MMAP_THRESHOLD, ...)` 合理阈值，避免大量碎片 mmap 触发 OOM

```c
/* 检查是否已分配物理内存（访问测试页） */
unsigned char vec;
mincore(ptr, page_size, &vec);
/* vec & 1 == 1：该页已在物理内存中 */
```

### mmap 块与堆块的区别

| 特性 | mmap 块（IS_MMAPPED） | 堆块（brk 区域） |
|------|----------------------|------------------|
| chunk->size 低位 | `IS_MMAPPED=0x2` 置位 | 仅 `PREV_INUSE` / `NON_MAIN_ARENA` |
| free 行为 | 直接 `munmap`，不进 bins | 进 tcache/fastbin/bins |
| 合并 | 不参与相邻合并 | 参与前/后向合并 |
| trim | 不需要 | 需 `malloc_trim` 收缩 break |
| 地址范围 | 地址空间任意位置 | 堆段连续区域 |

> 调试时，`pwndbg` 的 `heap` 命令只显示 `brk` 堆上的 chunk；mmap 块需要查 `/proc/<pid>/maps` 或 `vmmap`。

### 正确归还内存给内核

```c
/* 场景一：大块 mmap 内存 */
void *big = mmap(NULL, 4*1024*1024, PROT_READ|PROT_WRITE,
                 MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
/* ... 使用 ... */
munmap(big, 4*1024*1024);  /* 立刻归还内核，RSS 下降 */

/* 场景二：让堆顶空闲内存还内核 */
malloc_trim(0);  /* pad=0：尽量还 */

/* 场景三：保留映射但释放物理页（如大型缓冲区闲置期） */
madvise(cache_buf, cache_size, MADV_DONTNEED);
/* 再次访问时缺页，但虚拟地址仍有效 */
```

### 安全视角：mmap 匿名映射与堆块的攻击面差异

- mmap 块不在 ptmalloc 的 chunk 链表中，**不受 tcache key / safe-linking 保护**，但也不参与 bins 操作，堆元数据篡改不影响它
- mmap 匿名区域通常有 `PROT_READ|PROT_WRITE` 权限，若泄漏地址可成为 ROP/shellcode 跳板（NX 开启时除外）
- `madvise(MADV_FREE)` 在多线程下可导致 **use-after-free 竞态**：一个线程 advise 释放物理页，另一线程仍在读取，数据可能变零 —— 需严格同步

## 小结

| 接口 | 操作对象 | 适用场景 | 还给内核方式 |
|------|----------|----------|-------------|
| `brk`/`sbrk` | program break（堆顶） | 小/中请求，main_arena | `sbrk(-n)` / `malloc_trim` |
| `mmap` | 匿名私有 VMA | 大块（≥128KB），线程 arena | `munmap` |
| `madvise` | 已有映射的物理页 | 闲置缓冲区节省物理内存 | 物理页懒回收，VMA 保留 |

ptmalloc 的决策树：请求 ≥ `M_MMAP_THRESHOLD` → `mmap`；线程 arena → `mmap` 建堆；其余走 `brk`。理解这条决策链，就能看懂 `strace` 里分配器与内核的对话节奏，也能解释 `free` 后 RSS 为何不降。
