# 详解Mach-O(五)Mach-O LC_SYMTAB

> [!abstract] TL;DR
> **`LC_SYMTAB` 是定位"符号表（symbol table）+ 字符串表（string table）"的加载命令**，是符号解析、调试、`nm`/`dsymutil`/`dyld` 查名字的总入口。命令体 `symtab_command` 只有四个核心字段：`symoff`/`nsyms`（符号表文件偏移与条数）、`stroff`/`strsize`（字符串表文件偏移与字节大小）。
> 符号表是一串定长的 `nlist_64`（32 位为 `nlist`）记录。每条记录**不直接存名字**，而用 `n_strx` 索引到字符串表里的字符串——这种"定长表 + 变长字符串池"的分离设计贯穿整个 [[16.Mach-O __LINKEDIT]]。
> `nlist_64` 的灵魂是 1 字节的 `n_type`：它被位拆成 `N_STAB`(0xe0) / `N_PEXT`(0x10) / `N_TYPE`(0x0e) / `N_EXT`(0x01) 四段，其中 `N_TYPE` 又有 `N_UNDF`/`N_ABS`/`N_SECT`/`N_PBUD`/`N_INDR` 五种取值，配合 `n_sect`、`n_desc`、`n_value` 共同刻画一个符号"是什么、在哪、值多少、从哪个库来"。读懂 `LC_SYMTAB`，就读懂了 Mach-O 符号系统的地基。

## 概述与定位

符号（symbol）把"名字"与"地址/属性"关联起来：一个函数名、一个全局变量名，对应它在镜像中的位置或它是一处对外部库的引用。`LC_SYMTAB` 就是声明"这张关联表（符号表）和它配套的名字池（字符串表）在文件里的哪个偏移、有多大"的加载命令。

它指向的两块数据都物理位于 [[16.Mach-O __LINKEDIT]] 段内，由**静态链接器 `ld` 生成**，由 **`dyld`（动态链接绑定）、调试器（`lldb`）、符号工具（`nm`/`dsymutil`/`atos`）读取**。`LC_SYMTAB` 是几乎每个 Mach-O 文件都有的命令——目标文件（`MH_OBJECT`）、可执行文件、动态库都需要它。

需要分清两条命令的分工：

- **`LC_SYMTAB`**：描述"**全量、扁平**的符号表"——所有符号一字排开，不分组。
- **[[06.Mach-O LC_DYSYMTAB]]**：在同一张物理符号表之上**叠加分区视图**（本地符号区 / 外部已定义区 / 未定义区）并提供"间接符号表"（`__stubs`、`__la_symbol_ptr` 等的回填依据）。它本身**不复制符号**，只记录"本地区从第几条到第几条"等索引。

换句话说：`LC_SYMTAB` 提供原料（一维数组 + 字符串池），`LC_DYSYMTAB` 提供对这块原料的切片说明。二者协同，缺一不可。

## 核心原理与字段详解

### 1. 命令体 `symtab_command`

定义于 `<mach-o/loader.h>`，是个极简的定长结构（24 字节）：

```c
struct symtab_command {
    uint32_t cmd;      // LC_SYMTAB (0x2)
    uint32_t cmdsize;  // sizeof(struct symtab_command) == 24
    uint32_t symoff;   // 符号表在文件中的字节偏移（指向第一个 nlist_64）
    uint32_t nsyms;    // 符号条数：符号表共 nsyms 个 nlist_64
    uint32_t stroff;   // 字符串表在文件中的字节偏移
    uint32_t strsize;  // 字符串表的总字节大小
};
```

四个值的语义与算法：

- **`symoff`**：符号表起点的**文件偏移**（不是虚拟地址）。第 `i` 条记录位于 `symoff + i * sizeof(nlist_64)`（64 位下 `sizeof(nlist_64) == 16`，32 位下 `sizeof(nlist) == 12`）。
- **`nsyms`**：符号总数，因此符号表占 `nsyms * 16` 字节（64 位）。
- **`stroff`**：字符串表起点的**文件偏移**。读某符号名字时，用 `stroff + nlist.n_strx` 定位到以 `\0` 结尾的 C 字符串。
- **`strsize`**：字符串表字节数，常被 4/8 字节对齐填充。

> [!note] 偏移是"文件偏移"而非"虚拟地址"
> `symoff`/`stroff` 都相对文件起点（对 FAT 二进制是相对该 slice 起点）。它们落在 `__LINKEDIT` 的文件范围内：`__LINKEDIT` 的 `fileoff..fileoff+filesize` 应当覆盖符号表与字符串表。这也是 `strip` 能"砍掉"调试符号、缩小文件的物理基础——动的就是这两段加 `nsyms`/`strsize`。

### 2. 符号项 `nlist_64`（64 位）与 `nlist`（32 位）

符号表是 `nsyms` 个 `nlist_64` **连续紧排**。结构定义于 `<mach-o/nlist.h>`：

```c
// 64 位：每条 16 字节
struct nlist_64 {
    union {
        uint32_t n_strx;   // 符号名在字符串表中的字节偏移（0 = 空名 ""）
    } n_un;
    uint8_t  n_type;       // 类型字节：N_STAB | N_PEXT | N_TYPE | N_EXT 四段位域
    uint8_t  n_sect;       // 所在节序号（1..255），不在任何节为 NO_SECT(0)
    uint16_t n_desc;       // 附加描述：引用类型 / 弱引用弱定义 / Thumb / 库序号 等
    uint64_t n_value;      // 符号的值：已定义符号通常是其虚拟地址；详见各类型特例
};

// 32 位：每条 12 字节，仅 n_value 宽度不同
struct nlist {
    union {
        uint32_t n_strx;   // 32 位下历史上也可能是 char *n_name（链接前），见下注
    } n_un;
    uint8_t  n_type;
    uint8_t  n_sect;
    int16_t  n_desc;       // 历史上声明为有符号 short
    uint32_t n_value;      // 32 位地址/值
};
```

逐字段拆解：

- **`n_strx`（名字索引）**：核心设计点——**不内联名字**，只存"名字在字符串表里的字节偏移"。读名字 = `stroff + n_strx` 处的 C 串。约定 `n_strx == 0` 代表空名 `""`（因为字符串表第 0 字节恒为 `\0`），故任何非空名字的 `n_strx` 都不会是 0。
- **`n_type`（类型字节）**：1 字节被切成四段位域，是判断"这是不是调试符号、是不是外部符号、属于哪种类型"的总开关。**详见下一小节**。
- **`n_sect`（节序号）**：当 `N_TYPE == N_SECT` 时，给出符号所在节的**全局序号**。序号从 1 开始，跨段连续编号，按 `LC_SEGMENT_64` → `section_64` 出现顺序数（即第 1 节、第 2 节……）。不在任何节用 `NO_SECT(0)`。`#define NO_SECT 0`、`#define MAX_SECT 255`，故合法节号 1..255。注意：同一个序号在不同文件里可能指向不同节，序号无跨文件稳定性。
- **`n_desc`（附加描述）**：16 位，承载引用类型、弱符号标记、ARM Thumb 标记，以及（两级命名空间下）未定义符号来自哪个库的"库序号"。**详见后续小节**。
- **`n_value`（值）**：含义随类型而变——`N_SECT` 已定义符号一般是其**虚拟地址**；`N_UNDF` 未定义符号通常为 0（但 common 符号例外，存的是大小）；`N_INDR` 间接符号里存的是"目标符号名"在字符串表的偏移；stab 调试符号里存的是地址/偏移/时间戳等。

> [!note] 32 位 `n_un` 为何是 union
> 历史上 32 位 `nlist` 在链接器内存态会用 `char *n_name` 直接指向名字字符串；落到文件里则用 `n_strx`（偏移）。两者复用同一片空间，故声明成 `union`。64 位 `nlist_64` 文件态只用 `n_strx`，但为兼容沿用了 `n_un` 这层 union 包装。

### 3. `n_type` 的位分解（最关键）

`n_type` 这 1 字节按位被切成四个子字段，用四个掩码取值：

```c
#define N_STAB  0xe0   // 1110 0000：高 3 位——任一位为 1，则整条是 stab 调试符号
#define N_PEXT  0x10   // 0001 0000：私有外部符号（private extern）位
#define N_TYPE  0x0e   // 0000 1110：类型位（取值见下）
#define N_EXT   0x01   // 0000 0001：外部符号位
```

按位图理解这 8 个 bit：

```text
位:   7   6   5   4   3   2   1   0
     └──── N_STAB ────┘   │   └─N_TYPE─┘ │
       (0xe0, 3 bits)     │  (0x0e,3bit) └─ N_EXT (0x01)
                          └─ N_PEXT (0x10)
```

各段含义：

- **`N_STAB`（0xe0，高 3 位）**：**总开关**。只要这 3 位中任一位为 1，本条就是 **stab（调试）符号**，此时**整个 `n_type` 字节按 `<mach-o/stab.h>` 的 stab 值解读**，下面的 `N_TYPE`/`N_EXT` 划分不再适用。普通（非调试）符号的这 3 位全为 0。
- **`N_PEXT`（0x10，私有外部位）**：置位表示"私有外部符号"——作用域受限的全局符号。喂给静态链接器时，`ld` 会对带 `N_PEXT` 的符号**清掉 `N_EXT` 位**（除非 `ld -keep_private_externs`）。对应 C 的 `__private_extern__` / `__attribute__((visibility("hidden")))` 语义。
- **`N_TYPE`（0x0e，类型位）**：决定符号"是未定义、绝对、在某节、预绑定、还是间接"。**五种取值见下表**。
- **`N_EXT`（0x01，外部位）**：置位表示**外部符号**——要么定义在别处（待本文件引用），要么定义在本文件但允许被其他文件引用。`nm` 里大写字母（`T`/`D`/`U`…）即外部符号，小写（`t`/`d`…）即非外部（本地）符号。

**`N_TYPE` 的五种取值**（对 `n_type & 0x0e` 的结果）：

| 取值 | 值 | 含义 | 典型 `n_sect` / `n_value` |
|---|---|---|---|
| `N_UNDF` | `0x0` | **未定义**（undefined）：本文件引用、定义在别处（如外部库函数） | `n_sect = NO_SECT`；`n_value = 0`（common 符号例外，见下） |
| `N_ABS` | `0x2` | **绝对**（absolute）：值固定、不随重定位改变，不属于任何节 | `n_sect = NO_SECT`；`n_value` 为该绝对值 |
| `N_INDR` | `0xa` | **间接**（indirect）：本符号等同于另一个符号（别名） | `n_value` 是**另一符号名**在字符串表的偏移 |
| `N_PBUD` | `0xc` | **预绑定未定义**（prebound undefined）：未定义、但已在某 dylib 预绑定（旧 prebinding 机制） | `n_sect = NO_SECT` |
| `N_SECT` | `0xe` | **定义在某节**：本镜像内已定义的符号，落在 `n_sect` 指定的节里 | `n_sect = 1..255`；`n_value` 为其虚拟地址 |

> [!note] 两个高频特例
> **common 符号**：在 C 里"声明但未初始化"的全局变量（如顶层 `int g;`）。它必须是 `N_UNDF` 且置 `N_EXT`，而 `n_value` 此时**不是地址而是该数据的字节大小**。common 符号只出现在目标文件（`MH_OBJECT`）里，链接后会被分配进 `__common`/`__bss`。详见 [[29.Mach-O __common节]]、[[28.Mach-O __bss节]]。
> **间接符号 `N_INDR`**：用于"符号别名"。其 `n_value` 不是地址，而是**目标符号名在字符串表里的偏移**；当目标符号被定义时，二者一起获得相同的类型与值。`ld` 内部用形如 `n_type = N_INDR | N_EXT, n_sect = NO_SECT` 的模板构造它。

### 4. `n_desc` 的常见位

`n_desc` 是 16 位的"杂项描述位"。低 3 位是引用类型，其余是若干标志位；在**两级命名空间**镜像里，**高 8 位被借用来记录"库序号"**。

**(a) 低 3 位：`REFERENCE_TYPE`（引用类型，掩码 `0x7`）**

```c
#define REFERENCE_TYPE                          0x7
#define REFERENCE_FLAG_UNDEFINED_NON_LAZY         0   // 未定义、非延迟（数据引用）
#define REFERENCE_FLAG_UNDEFINED_LAZY             1   // 未定义、延迟（函数引用，走 stub）
#define REFERENCE_FLAG_DEFINED                    2   // 本模块已定义
#define REFERENCE_FLAG_PRIVATE_DEFINED            3   // 已定义、仅本共享库内可见
#define REFERENCE_FLAG_PRIVATE_UNDEFINED_NON_LAZY 4   // 私有未定义、非延迟
#define REFERENCE_FLAG_PRIVATE_UNDEFINED_LAZY     5   // 私有未定义、延迟
```

它告诉链接器某引用是"数据型（non-lazy，立即绑定）"还是"函数型（lazy，首次调用再绑定）"，与 [[30.Mach-O __la_symbol_ptr节]] / [[31.Mach-O __nl_symbol_ptr节]] 的 lazy/non-lazy 指针一一呼应。

**(b) 标志位（与库序号不重叠的中段位）**

```c
#define N_ARM_THUMB_DEF        0x0008   // 该定义是 ARM Thumb 模式函数（地址最低位语义）
#define REFERENCED_DYNAMICALLY 0x0010   // 被 dlsym/NSLookupSymbolInImage 等动态 API 引用，strip 不得删
#define N_NO_DEAD_STRIP        0x0020   // （目标文件中）禁止 ld 死代码剥离该符号
#define N_WEAK_REF             0x0040   // 弱引用：找不到定义时地址置 0，不报错
#define N_WEAK_DEF             0x0080   // 弱定义：若存在非弱定义则本定义被忽略（coalesced 段）
#define N_SYMBOL_RESOLVER      0x0100   // 该符号是 resolver（运行期决定实际实现）
#define N_ALT_ENTRY            0x0200   // 该符号是另一符号区域内的"备用入口"
```

逆向/链接时最常打交道的是 `N_WEAK_REF`（弱链接，对应 `LC_LOAD_WEAK_DYLIB` 与 `__attribute__((weak_import))`）、`N_WEAK_DEF`（C++ 模板/inline 的弱定义合并）、`N_ARM_THUMB_DEF`（ARM32 下函数是 Thumb 还是 ARM）、`REFERENCED_DYNAMICALLY`（保命位，`strip` 见到它会留手）。

> [!note] 0x20 的双重含义
> `N_NO_DEAD_STRIP`(0x0020) 仅在**可重定位目标文件**（`MH_OBJECT`）里对已定义符号有效；同一个 bit 在**已完成链接的镜像**里被复用为 `N_DESC_DISCARDED`（dyld 运行期临时使用）。二者语境不重叠——不要在最终镜像里设置这个位。

**(c) 高 8 位：库序号（`GET_LIBRARY_ORDINAL`）**

当 Mach 头带 `MH_TWOLEVEL`（两级命名空间，现代二进制默认）时，**未定义符号的 `n_desc` 高 8 位记录"它定义在哪个库"**，用宏存取：

```c
#define GET_LIBRARY_ORDINAL(n_desc)        (((n_desc) >> 8) & 0xff)
#define SET_LIBRARY_ORDINAL(n_desc, ordinal) \
        (n_desc) = (((n_desc) & 0x00ff) | (((ordinal) & 0xff) << 8))
```

库序号取值约定：

| 序号 | 常量 | 含义 |
|---|---|---|
| `0x00` | `SELF_LIBRARY_ORDINAL` | 当前镜像自身 |
| `0x01`–`0xfd` | （1..253，`MAX_LIBRARY_ORDINAL=0xfd`） | 按 `LC_LOAD_DYLIB`/`LC_LOAD_WEAK_DYLIB`/`LC_REEXPORT_DYLIB`/… 在头部出现的**顺序**编号，从 1 起 |
| `0xfe` | `DYNAMIC_LOOKUP_ORDINAL` | 运行期 flat 查找（`-undefined dynamic_lookup`） |
| `0xff` | `EXECUTABLE_ORDINAL` | 该符号来自主可执行程序（插件回引宿主时用） |

`ld` 在链接时用 `SET_LIBRARY_ORDINAL` 把"这个未定义符号绑到第几个 `LC_LOAD_DYLIB`"写进高 8 位；`dyld` 加载时据此**精确**到具体库去解析（这正是"两级命名空间"相对旧 flat 命名空间的优势：避免同名符号撞库）。`otool -Iv` 与 `nm -m` 的 `(from libSystem)` 字样即由此而来。flat 命名空间镜像下，高 8 位必须为 0。

### 5. 字符串表（string table）布局

字符串表是紧跟在符号表之后（位置由 `stroff`/`strsize` 指定）的一块**以 `\0` 分隔的连续字符池**：

- **首字节恒为 `\0`**：偏移 0 被保留给"空名"。所以非空名字的 `n_strx` 永远 > 0。
- **每个名字以 `\0` 结尾**：读名字就是从 `stroff + n_strx` 起读到下一个 `\0`。
- **可去重/共享**：多个符号若同名，链接器可让它们的 `n_strx` 指向同一段字节，省空间（典型如多个引用同一外部函数）。
- **常带对齐填充**：`strsize` 末尾可能补 `\0` 到 4/8 字节对齐。

直观布局（首字节 0 处为空，随后是各 C 串）：

```text
偏移:  0    1                       N1                          N2
      \0  '_','m','a','i','n','\0'  '_','p','r','i','n','t','f','\0'  ...
      ↑    ↑                        ↑
    空名  n_strx=1 指向 "_main"     n_strx=N1 指向 "_printf"
```

这种"定长记录数组（`nlist_64`）+ 变长字符串池（string table）"的二分结构，是 `__LINKEDIT` 内多张表（符号表、间接符号表、绑定/导出信息）共同遵循的范式：定长部分便于随机索引，变长部分集中存放、可去重。

### 6. 与 `LC_DYSYMTAB` / `__LINKEDIT` 的关系

- **同一张物理表，两套视图**：`LC_SYMTAB.symoff/nsyms` 圈定的这**一**份 `nlist_64` 数组，被 [[06.Mach-O LC_DYSYMTAB]] 进一步划成三段连续区间——本地符号（`ilocalsym/nlocalsym`）、外部已定义（`iextdefsym/nextdefsym`）、未定义（`iundefsym/nundefsym`）。`ld` 会**按这三类把符号排好序**写进表里，使每类是连续区间。`LC_DYSYMTAB` 还提供"间接符号表"（`indirectsymoff`），供 `__stubs`/`__la_symbol_ptr`/`__got` 回填——但它存的只是"指向 `LC_SYMTAB` 那张表的索引"，名字仍要回到本表 + 字符串表去查。
- **物理归宿都是 `__LINKEDIT`**：`symoff`/`stroff` 指向的字节落在 [[16.Mach-O __LINKEDIT]] 段范围内。`__LINKEDIT` 是"只读、按页映射、链接器/`dyld` 专用元数据区"，符号表、字符串表、间接符号表、`LC_DYLD_INFO_ONLY`/链式 fixups 的数据都挤在这里。`strip` 缩小文件、`codesign` 计算哈希，动的都是 `__LINKEDIT`。
- **命令体系中的位置**：`LC_SYMTAB`（`0x2`）属于 [[03.Mach-O加载命令]] 里的"符号与链接信息"类，几乎总与 `LC_DYSYMTAB`（`0xb`）成对出现。

### 7. stab 调试符号简介

当 `n_type & N_STAB`（即高 3 位非 0）时，本条不是普通符号，而是 **stab（symbol table，源自 a.out 时代的调试格式）**，整个 `n_type` 字节按 `<mach-o/stab.h>` 的常量解读。stab 记录把"源文件、函数、行号、局部变量、对象文件时间戳"等调试信息编码进符号表。常见 stab 类型：

| 常量 | 值 | 含义（注释格式 `name,,n_sect,desc,value`） |
|---|---|---|
| `N_GSYM` | `0x20` | 全局符号：`name,,NO_SECT,type,0` |
| `N_FNAME` | `0x22` | 过程名（f77）：`name,,NO_SECT,0,0` |
| `N_FUN` | `0x24` | 函数：`name,,n_sect,linenumber,address` |
| `N_STSYM` | `0x26` | 静态符号：`name,,n_sect,type,address` |
| `N_LCSYM` | `0x28` | `.lcomm` 符号：`name,,n_sect,type,address` |
| `N_BNSYM` | `0x2e` | 节内符号区起点：`0,,n_sect,0,address` |
| `N_AST` | `0x32` | AST 文件路径 |
| `N_OPT` | `0x3c` | 由 gcc 发出的编译选项标记 |
| `N_RSYM` | `0x40` | 寄存器变量：`name,,NO_SECT,type,register` |
| `N_SLINE` | `0x44` | 源代码行：`0,,n_sect,linenumber,address` |
| `N_ENSYM` | `0x4e` | 节内符号区终点：`0,,n_sect,0,address` |
| `N_SO` | `0x64` | 源文件名：`name,,n_sect,0,address` |
| `N_OSO` | `0x66` | 目标文件名：`name,,0,0,st_mtime`（值为文件时间戳） |
| `N_LSYM` | `0x80` | 局部符号：`name,,NO_SECT,type,offset` |
| `N_BINCL` | `0x82` | include 文件起点 |
| `N_SOL` | `0x84` | `#include` 的文件名 |
| `N_LBRAC` | `0xc0` | 左花括号（作用域起点） |
| `N_RBRAC` | `0xe0` | 右花括号（作用域终点） |
| `N_LENG` | `0xfe` | 第二条 stab 的长度 |

现代 macOS 用 **DWARF** 做主调试格式，但仍保留少量 stab（尤其是 `N_OSO`/`N_SO`/`N_FUN`）作为"调试映射（debug map）"：`dsymutil` 据此把每个 `.o` 里的 DWARF 收集成 `.dSYM`。`N_OSO` 的 `n_value` 存对象文件的修改时间戳，用于校验 `.o` 是否过期。`strip` 默认会去掉这些 stab（这就是 release 包看不到调试符号的原因）。

## 实操：用工具查看

> [!warning] 示例输出为示意
> 本机为 Windows 环境，以下 `nm`/`otool`/`dyld_info`/`symbols` 输出基于结构知识构造，字段对齐与数值以你机器上 Xcode 工具链实跑为准。

### 1. `otool -l` 看 `LC_SYMTAB` 命令体

```bash
otool -l /bin/ls | grep -A 4 LC_SYMTAB
```

```text
Load command 11
     cmd LC_SYMTAB
 cmdsize 24
  symoff 24576          ; 符号表文件偏移
   nsyms 124            ; 124 个 nlist_64
  stroff 28672          ; 字符串表文件偏移
 strsize 2080           ; 字符串表 2080 字节
```

四个值直接对应 `symtab_command` 的四字段；符号表占 `124 * 16 = 1984` 字节。

### 2. `nm -m` 看每个符号的"详细属性"

`-m`（macho）展示外部/未定义、所属节、弱属性、来源库——直接映射 `n_type`/`n_sect`/`n_desc`：

```bash
nm -m /bin/ls
```

```text
(undefined) external _printf (from libSystem)        ; N_UNDF|N_EXT，库序号→libSystem
(undefined) external _exit (from libSystem)
0000000100003a10 (__TEXT,__text) external _main      ; N_SECT|N_EXT，n_sect 指向 __text
0000000100008040 (__DATA,__data) non-external _g_buf ; N_SECT，无 N_EXT（本地）
(undefined) weak external _operator_new (from libc++); N_WEAK_REF
```

`(from libSystem)` 即 `n_desc` 高 8 位的库序号经 `GET_LIBRARY_ORDINAL` 解出后映射到对应 `LC_LOAD_DYLIB`。

### 3. `nm -ap` 看全部符号（含调试 stab）与原始顺序

`-a` 显示包括调试符号（stab）在内的全部条目，`-p` 不排序（按符号表物理顺序，即 `LC_DYSYMTAB` 分区顺序）：

```bash
nm -ap /path/to/MyApp.debug
```

```text
0000000100003a10 T _main
0000000000000000 - 00 0000    SO /Users/me/main.c     ; N_SO 源文件名
0000000000000000 - 01 0000   OSO main.o               ; N_OSO 目标文件+时间戳
0000000100003a10 - 00 0001   FUN _main                ; N_FUN 函数 stab
                 U _printf
```

带 `SO`/`OSO`/`FUN` 字样的即 stab（`N_STAB` 位置位），是 `dsymutil` 生成 `.dSYM` 的调试映射来源。

### 4. `dyld_info` / `symbols` 看链接器视角的符号

新版 Xcode 用 `dyld_info`（取代部分 `otool`）观察 `__LINKEDIT`：

```bash
dyld_info -symbolic_fixups /bin/ls     # 看符号绑定/fixup
dyld_info -imports /bin/ls             # 看未定义符号来自哪个库（含库序号）
xcrun symbols -arch arm64 /bin/ls      # 罗列符号、地址、节归属
```

```text
# dyld_info -imports（示意）
_printf          (from libSystem)      ; 对应 N_UNDF 符号 + 库序号
_exit            (from libSystem)

# symbols（示意）
0x100003a10  __TEXT __text  _main      [external]
0x100008040  __DATA __data  _g_buf     [local]
```

## 与相邻章节的关系

- [[06.Mach-O LC_DYSYMTAB]]：在本表（同一份 `nlist_64` 数组）之上做本地/外部/未定义分区，并提供间接符号表；二者总成对出现。
- [[16.Mach-O __LINKEDIT]]：`symoff`/`stroff` 指向的符号表与字符串表的物理归宿。
- [[03.Mach-O加载命令]]：`LC_SYMTAB`（`0x2`）在加载命令体系"符号与链接信息"类中的位置。
- [[07.Mach-O LC_LOAD_DYLIB]]：`n_desc` 高 8 位的"库序号"正是按这些 `LC_LOAD_DYLIB` 的出现顺序编号。
- [[30.Mach-O __la_symbol_ptr节]] / [[31.Mach-O __nl_symbol_ptr节]]：`REFERENCE_FLAG_*` 的 lazy/non-lazy 与这两节呼应。

## 小结

- `LC_SYMTAB` 用 `symoff/nsyms/stroff/strsize` 四个值定位"符号表 + 字符串表"，二者都在 `__LINKEDIT` 内。
- 符号表是 `nlist_64`（32 位为 `nlist`）数组；符号名通过 `n_strx` 间接索引到以 `\0` 分隔、首字节为空的字符串表，实现"定长表 + 字符串池"分离。
- `n_type` 是灵魂：高 3 位 `N_STAB` 标记调试符号；`N_PEXT` 私有外部；`N_TYPE`（`N_UNDF`/`N_ABS`/`N_SECT`/`N_PBUD`/`N_INDR`）定类型；`N_EXT` 定外部性。`n_sect`/`n_desc`/`n_value` 分别给出节归属、附加属性（弱符号、引用类型、库序号）与取值。
- `LC_SYMTAB` 提供扁平全量表，[[06.Mach-O LC_DYSYMTAB]] 在其上分区并做间接符号；它是 `nm`、`lldb`、`dsymutil`、`dyld` 进行符号解析的共同地基。

## FAQ

> [!question] `LC_SYMTAB` 和 `LC_DYSYMTAB` 到底什么关系？会有两份符号表吗？
> 不会。物理上只有 `LC_SYMTAB` 指向的**一份** `nlist_64` 数组。`LC_DYSYMTAB` 不复制符号，只在这份数组上记录"本地区/外部已定义区/未定义区各自从第几条起、共几条"以及"间接符号表"的位置。可以理解为：`LC_SYMTAB` 是数据，`LC_DYSYMTAB` 是对这块数据的切片索引。

> [!question] 为什么 `nm` 有些符号没有地址、显示 `U`？
> `U`（undefined）对应 `N_TYPE == N_UNDF` 且 `N_EXT` 置位的符号——它是对**外部库**的引用，本镜像里没有定义，地址要等 `dyld` 运行时绑定，故此刻无地址。它的 `n_desc` 高 8 位还记着"该去哪个库找"（库序号）。`nm -m` 会显示 `(from libSystem)` 之类。

> [!question] `strip` 之后符号去哪了？文件为什么变小？
> `strip` 主要删的是**调试 stab 符号**和**本地（非外部）符号**：它重写 `LC_SYMTAB`，减小 `nsyms` 并把对应名字从字符串表挪走、缩小 `strsize`，相应收缩 `__LINKEDIT`。但带 `REFERENCED_DYNAMICALLY`(0x10) 的符号 `strip` 不敢删（运行期 `dlsym` 还要用）；导出符号、重定位需要的未定义符号也会保留。这就是为什么 release 包仍能跑、但 `nm` 看不到内部函数名。

> [!question] `n_value` 一定是地址吗？
> 不一定，含义随类型变：`N_SECT` 已定义符号是虚拟地址；`N_UNDF` 普通未定义为 0，但 **common 符号**（`N_UNDF|N_EXT`，仅 `MH_OBJECT`）的 `n_value` 是数据**字节大小**；`N_INDR` 间接符号的 `n_value` 是**目标符号名在字符串表的偏移**；`N_ABS` 是绝对值；stab 里则是地址/行号偏移/时间戳。读 `n_value` 前必须先看 `n_type`。
