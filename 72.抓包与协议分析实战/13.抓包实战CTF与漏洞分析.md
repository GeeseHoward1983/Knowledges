# 抓包实战：CTF与漏洞分析

> [!abstract] TL;DR
> CTF 流量分析题的解题路径：载入 pcap → 协议概览（Protocol Hierarchy）→ 过滤关键流 → 数据提取 → 解码还原 flag。常见题型涵盖 HTTP 明文、TLS+密钥日志解密、DNS 隧道提取、WebSocket 隐写。漏洞分析场景中，抓包能还原漏洞触发的完整流量，如 Heartbleed 的异常 HeartbeatRequest 是经典案例。

## 概述与定位

### CTF 流量分析题型分类

CTF 中的 pcap 分析题（Forensics / Network 方向）通常分为以下类型：

| 题型 | 特征 | 典型工具 |
|---|---|---|
| HTTP 明文提取 | flag 在 HTTP body/header 中 | Wireshark 过滤 + Follow TCP Stream |
| TLS 加密流量 + Key Log | 提供 `sslkeylogfile`，需解密 | Wireshark 配置 TLS 密钥日志 |
| DNS 隧道 | flag 藏在 DNS 查询/响应的 TXT/QNAME 中 | tshark 提取 + Base64 解码 |
| WebSocket 隐写 | flag 在 WS 帧 payload 中 | Wireshark Follow WS Stream |
| 文件提取（HTTP/FTP/SMB） | pcap 中包含文件传输 | NetworkMiner / foremost / tshark |
| 自定义协议 | 需逆向协议格式 | Wireshark Protocol Hierarchy + Scapy 解析 |
| 图像/音频隐写（via 流量） | 文件含隐写 flag | 提取文件后用 steghide/zsteg |

### pcap vs pcapng 格式

| 特性 | pcap（旧） | pcapng（新，推荐） |
|---|---|---|
| 规范 | libpcap 私有 | RFC 草案（IETF） |
| 注释 | 不支持 | 支持（Interface/Packet/Section 注释） |
| 多接口 | 不支持 | 支持（多接口同时捕获） |
| 时间戳精度 | 微秒 | 纳秒（可选） |
| 工具支持 | 全部支持 | Wireshark 3.0+ / tshark 3.0+ / Scapy 2.4+ |

CTF 出题方偶尔在 pcapng 注释字段藏提示或 flag 的一部分：

```bash
# 查看 pcapng 文件的注释/元数据
capinfos -A challenge.pcapng

# 用 tshark 提取 pcapng 中的注释
tshark -r challenge.pcapng -z expert
```

### 大文件快速定位技巧

面对 GB 级 pcap 文件，直接用 Wireshark 载入会很慢：

```bash
# 1. 先用 capinfos 了解文件概况
capinfos large_capture.pcap

# 2. 按时间分割 pcap（每 5 分钟一个）
editcap -i 300 large_capture.pcap output_chunk.pcap

# 3. 按协议分割（只保留 HTTP 流量）
tcpdump -r large_capture.pcap -w http_only.pcap 'tcp port 80'

# 4. 快速统计协议分布（不打开 Wireshark）
tshark -r large_capture.pcap -q -z io,phs

# 5. 提取特定时间段
editcap -A "2024-01-01 10:00:00" -B "2024-01-01 11:00:00" \
  large_capture.pcap time_range.pcap
```

## 原理与机制

### CTF 流量题解题框架

```
Step 1: 概览阶段
  ├── capinfos 查看文件基本信息（包数/时间跨度/协议）
  ├── tshark -q -z io,phs 显示协议层次统计（Protocol Hierarchy）
  └── Wireshark Statistics → Conversations 查看通信方

Step 2: 定位阶段
  ├── 若发现 HTTP：过滤 http，看 Request/Response 包
  ├── 若发现 DNS：过滤 dns.qry.type == 16 (TXT) 或异常长 QNAME
  ├── 若发现 TLS：检查是否有 sslkeylogfile，配置 Wireshark 解密
  └── 若发现非标准端口：重点关注，可能是自定义协议

Step 3: 提取阶段
  ├── Wireshark: Follow TCP/UDP/HTTP/WebSocket Stream
  ├── tshark 批量提取特定字段
  ├── NetworkMiner 自动重组文件
  └── foremost / binwalk 从 pcap 二进制中提取文件

Step 4: 解码阶段
  ├── Base64 / Base32 / Hex 解码
  ├── ROT13 / XOR 等简单加密
  ├── Gzip/Deflate 解压
  └── 图像/音频 隐写工具
```

## 结构/算法/伪代码详解

### CTF 实战案例1：HTTP 明文提取

```bash
# 场景：flag 藏在 HTTP GET 请求的响应体中

# 1. 查看所有 HTTP 请求
tshark -r challenge.pcap -Y "http.request" \
  -T fields -e http.request.method -e http.request.uri \
  -e http.host 2>/dev/null

# 2. 查看 HTTP 响应内容
tshark -r challenge.pcap -Y "http.response" \
  -T fields -e http.response.code -e http.file_data 2>/dev/null | \
  grep -i "flag\|ctf\|{" 

# 3. 导出所有 HTTP 对象（Wireshark 菜单：File → Export Objects → HTTP）
# 命令行方式：
tshark -r challenge.pcap --export-objects http,/tmp/http_objects/

# 4. 在导出文件中搜索 flag
grep -r "flag{" /tmp/http_objects/ 2>/dev/null
strings /tmp/http_objects/* | grep -E "[A-Za-z0-9]+\{[A-Za-z0-9_]+\}"
```

### CTF 实战案例2：TLS 加密流量 + Key Log 解密

```bash
# 场景：提供了 .pcap 和 sslkeylogfile（或通过 Wireshark 选项导出）

# Wireshark 配置：
# Edit → Preferences → Protocols → TLS
# (Pre)-Master-Secret log filename: /path/to/sslkeylogfile

# 命令行用 tshark 解密
tshark -r encrypted.pcap \
  -o "tls.keylog_file:/path/to/sslkeylogfile" \
  -Y "http" \
  -T fields -e http.request.uri -e http.file_data 2>/dev/null

# 导出解密后的 HTTP 对象
tshark -r encrypted.pcap \
  -o "tls.keylog_file:/path/to/sslkeylogfile" \
  --export-objects http,/tmp/decrypted_objects/

# sslkeylogfile 格式（供参考）
# CLIENT_RANDOM <client_random_hex> <master_secret_hex>
# RSA <encrypted_premaster_hex> <premaster_secret_hex>
```

### CTF 实战案例3：DNS 隧道提取

```python
#!/usr/bin/env python3
"""
DNS 隧道数据提取脚本
场景：数据通过 DNS TXT 记录或 QNAME 的子域名传输
"""
import base64
from scapy.all import *

def extract_dns_tunnel(pcap_file, target_domain="tunnel.example.com"):
    pkts = rdpcap(pcap_file)
    extracted_data = []

    for pkt in pkts:
        if not pkt.haslayer(DNS):
            continue

        dns = pkt[DNS]

        # 方式1：从 QNAME 提取（数据编码在子域名中）
        if dns.qd:
            qname = dns.qd.qname.decode('utf-8', errors='ignore').rstrip('.')
            # 如果是目标域名的子域名
            if qname.endswith(target_domain):
                # 提取子域名部分（数据载体）
                subdomain = qname[:-len(target_domain)-1]
                # 去除分段点（tunnel 工具常将 Base32 数据分成多段）
                encoded = subdomain.replace('.', '')
                try:
                    data = base64.b32decode(encoded.upper() + '=' * (-len(encoded) % 8))
                    extracted_data.append(data)
                    print(f"[QNAME] 解码: {data[:50]}")
                except Exception:
                    # 可能是其他编码方式
                    print(f"[QNAME] 原始子域名: {subdomain}")

        # 方式2：从 TXT 记录响应提取
        if dns.an:
            rr = dns.an
            while rr and rr.type != 0:
                if rr.type == 16:  # TXT 记录
                    txt_data = rr.rdata
                    if isinstance(txt_data, list):
                        txt_data = b''.join(txt_data)
                    if isinstance(txt_data, bytes):
                        # 尝试 Base64 解码
                        try:
                            decoded = base64.b64decode(txt_data)
                            extracted_data.append(decoded)
                            print(f"[TXT] 解码: {decoded[:50]}")
                        except Exception:
                            print(f"[TXT] 原始: {txt_data[:50]}")
                rr = rr.payload if hasattr(rr, 'payload') else None

    # 合并所有提取的数据
    if extracted_data:
        full_data = b''.join(extracted_data)
        with open('/tmp/dns_tunnel_extracted.bin', 'wb') as f:
            f.write(full_data)
        print(f"\n[+] 提取 {len(full_data)} 字节，保存到 /tmp/dns_tunnel_extracted.bin")
        print(f"[+] 文件头: {full_data[:16].hex()}")

extract_dns_tunnel("challenge.pcap")
```

```bash
# tshark 方式提取 DNS 隧道数据（快速）
# 提取所有 TXT 记录内容
tshark -r challenge.pcap \
  -Y "dns.qry.type == 16 && dns.flags.response == 1" \
  -T fields -e dns.txt 2>/dev/null | \
  tr -d '"\n' | base64 -d > dns_tunnel_out.bin

# 提取 QNAME 的子域名部分
tshark -r challenge.pcap \
  -Y "dns.flags.response == 0" \
  -T fields -e dns.qry.name 2>/dev/null | \
  grep "\.tunnel\.example\.com" | \
  sed 's/\.tunnel\.example\.com//' | tr -d '.'
```

### CTF 实战案例4：WebSocket 隐写

```bash
# WebSocket 流量过滤
# Wireshark 过滤器：websocket 或 ws

# 命令行提取 WebSocket 数据帧
tshark -r challenge.pcap \
  -Y "websocket.payload" \
  -T fields -e websocket.payload 2>/dev/null

# WebSocket 帧解码（帧可能有掩码，Wireshark 自动解掩）
tshark -r challenge.pcap \
  -Y "websocket" \
  -T fields \
  -e websocket.payload \
  -e websocket.opcode 2>/dev/null | \
  while IFS=$'\t' read -r payload opcode; do
    # opcode 1=文本, 2=二进制
    echo "Opcode:${opcode} Data:${payload}" | \
      python3 -c "import sys,base64; line=sys.stdin.read(); \
      parts=line.split('Data:'); \
      data=bytes.fromhex(parts[1].strip()); print(data[:100])"
  done
```

### 漏洞分析案例：Heartbleed（CVE-2014-0160）流量特征

```bash
# Heartbleed 漏洞：OpenSSL TLS HeartbeatRequest 越界读
# 流量特征：
#   - TLS 记录类型 0x18 (24, Heartbeat)
#   - HeartbeatRequest: type=1, payload_length 远大于实际 payload
#   - HeartbeatResponse: 返回超出实际 payload 的内存数据

# Wireshark 过滤 Heartbeat 流量
# 过滤器：tls.record.content_type == 24

# tshark 提取 Heartbeat 记录
tshark -r heartbleed_sample.pcap \
  -Y "ssl.record.content_type == 24" \
  -T fields \
  -e ip.src -e ip.dst \
  -e ssl.record.length \
  -e frame.number 2>/dev/null

# Heartbleed 特征识别脚本
python3 << 'EOF'
from scapy.all import *

pkts = rdpcap("heartbleed_sample.pcap")
for pkt in pkts:
    if pkt.haslayer(Raw) and pkt.haslayer(TCP):
        payload = bytes(pkt[Raw])
        # TLS Record: ContentType=24 (Heartbeat), Version=TLS1.x
        if len(payload) >= 5 and payload[0] == 0x18 and payload[1] == 0x03:
            rec_len = int.from_bytes(payload[3:5], 'big')
            print(f"[Heartbeat] {pkt[IP].src} -> {pkt[IP].dst}")
            print(f"  TLS Record Length: {rec_len}")
            if len(payload) >= 8:
                hb_type = payload[5]   # 1=Request, 2=Response
                hb_payload_len = int.from_bytes(payload[6:8], 'big')
                actual_payload = payload[8:8+hb_payload_len] if len(payload) > 8 else b''
                print(f"  Heartbeat Type: {'Request' if hb_type==1 else 'Response'}")
                print(f"  Claimed Payload Length: {hb_payload_len}")
                print(f"  Actual Payload in Packet: {len(actual_payload)}")
                if hb_type == 1 and hb_payload_len > len(actual_payload):
                    print(f"  [!!!] 潜在 Heartbleed: 声明长度 {hb_payload_len} > 实际 {len(actual_payload)}")
                if hb_type == 2 and rec_len > hb_payload_len + 3:
                    print(f"  [!!!] 异常大的响应，可能泄露内存数据")
                    print(f"  泄露内存前 64 字节: {payload[8+hb_payload_len:8+hb_payload_len+64].hex()}")
EOF
```

### tshark 批量提取字段脚本

```bash
#!/usr/bin/env bash
# pcap_extract.sh — 通用字段批量提取脚本

PCAP="$1"
OUTPUT_DIR="${2:-/tmp/pcap_extract}"
mkdir -p "$OUTPUT_DIR"

echo "=== 分析文件: $PCAP ==="
echo ""

# 1. 文件基本信息
echo "--- 基本信息 ---"
capinfos -M "$PCAP" 2>/dev/null

# 2. 协议层次统计
echo ""
echo "--- 协议分布 ---"
tshark -r "$PCAP" -q -z io,phs 2>/dev/null

# 3. 前 20 个对话（按字节数排序）
echo ""
echo "--- Top 20 对话 (TCP) ---"
tshark -r "$PCAP" -q -z conv,tcp 2>/dev/null | \
  head -30

# 4. HTTP 请求统计
echo ""
echo "--- HTTP 请求 URI ---"
tshark -r "$PCAP" -Y "http.request" \
  -T fields -e http.host -e http.request.uri 2>/dev/null | \
  sort | uniq -c | sort -rn | head -20 > "$OUTPUT_DIR/http_uris.txt"
cat "$OUTPUT_DIR/http_uris.txt"

# 5. DNS 查询统计
echo ""
echo "--- DNS 查询域名 ---"
tshark -r "$PCAP" -Y "dns.flags.response == 0" \
  -T fields -e dns.qry.name 2>/dev/null | \
  sort | uniq -c | sort -rn | head -20 > "$OUTPUT_DIR/dns_queries.txt"
cat "$OUTPUT_DIR/dns_queries.txt"

# 6. TLS SNI 提取
echo ""
echo "--- TLS SNI ---"
tshark -r "$PCAP" \
  -Y "tls.handshake.type == 1" \
  -T fields -e tls.handshake.extensions_server_name 2>/dev/null | \
  sort -u > "$OUTPUT_DIR/tls_sni.txt"
cat "$OUTPUT_DIR/tls_sni.txt"

# 7. 导出 HTTP 对象
echo ""
echo "--- 导出 HTTP 对象到 $OUTPUT_DIR/http_objects/ ---"
mkdir -p "$OUTPUT_DIR/http_objects"
tshark -r "$PCAP" --export-objects "http,$OUTPUT_DIR/http_objects/" 2>/dev/null
ls -la "$OUTPUT_DIR/http_objects/" 2>/dev/null | head -20

echo ""
echo "=== 分析完成，结果保存到 $OUTPUT_DIR/ ==="
```

### dnscat2 DNS 隧道检测

```bash
# dnscat2 的流量特征：
# - 大量 CNAME 查询（dnscat2 默认用 CNAME）
# - 子域名格式：<session_id>.<seq>.<data>.dnscat.example.com

# 检测脚本
tshark -r challenge.pcap \
  -Y "dns.qry.type == 5" \  # CNAME 查询
  -T fields -e dns.qry.name 2>/dev/null | \
  awk -F. 'NF > 4 {print}' | head -20

# 提取 dnscat2 数据（需知道 C2 域名）
C2_DOMAIN="example.com"
tshark -r challenge.pcap \
  -Y "dns.flags.response == 0 && dns.qry.name contains \"${C2_DOMAIN}\"" \
  -T fields -e dns.qry.name 2>/dev/null | \
  sed "s/\\.${C2_DOMAIN}$//" | \  # 去掉 C2 域名
  awk -F. '{print $NF}' | \        # 取最后一段（数据部分）
  xxd -r -p                         # Hex 转二进制
```

### Wireshark Protocol Hierarchy 快速概览

```
Statistics → Protocol Hierarchy
显示所有协议及其占比，帮助快速确定分析重点

常见 CTF 场景识别：
- 80% TCP + 大量 HTTP → 关注 HTTP 内容
- 异常高的 DNS（>10%）→ 可能是 DNS 隧道
- 大量 ICMP → 可能是 ICMP 隧道（ping 数据载体）
- 非常规端口的 TCP → 可能是自定义协议或 C2
- TLS 但无 HTTP2/QUIC → 标准 HTTPS，需 Key Log 解密
```

> [!caution] 合规边界：CTF 技术的适用范围
> CTF 中学习的流量分析技术（DNS 隧道提取、Heartbleed 特征识别、SSL Pinning 绕过）都基于**授权环境**：
>
> **合法使用：**
> - 参加 CTF 比赛（Capture The Flag），分析赛方提供的 pcap 文件
> - 在自建靶机/测试网络中验证漏洞影响（如部署存在 Heartbleed 的旧版 OpenSSL 测试环境）
> - 安全课程学习中分析教学用 pcap 样本
> - 授权渗透测试中对目标网络捕获流量并分析
>
> **严禁以下行为：**
> - 在未获授权的生产网络中捕获他人流量
> - 利用 Heartbleed 等漏洞攻击真实在线服务（即使只是"测试"）
> - 将 CTF 样本中的攻击技术直接用于未授权系统
> - 将学习过程中获取的真实漏洞利用技术在合规披露前公开
>
> **负责任披露：** 若在安全研究中发现真实漏洞，应通过 CNVD（国家信息安全漏洞共享平台）、CVSS 或直接联系厂商安全团队进行报告，给予修复周期后再公开技术细节。

## 小结

CTF 流量分析的核心技能是**快速定位**（Protocol Hierarchy → 识别异常协议 → 过滤关键流 → 提取数据）和**解码能力**（Base64/Hex/自定义编码）。漏洞分析中的抓包则要求对协议正常行为有深入理解，才能识别异常（如 Heartbleed 的 `payload_length > actual_payload` 特征）。tshark 的批量提取能力配合 Python/bash 脚本，能有效处理大规模 pcap 文件。
