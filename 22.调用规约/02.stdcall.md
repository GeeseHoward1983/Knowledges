# `__stdcall` 详解（Standard Call / Win32 标准调用规约）

> 关键词：`__stdcall` ｜ **callee 清栈 `ret N`** ｜ 全栈传参 ｜ **Win32 API 标准** ｜ `WINAPI`/`CALLBACK`
> 上级：[[22.调用规约/00.总览|x86 三种调用规约总览]]

`stdcall` 是 **Win32 API 的标准调用规约**。你在头文件里见到的 `WINAPI`、`APIENTRY`、`CALLBACK`、`PASCAL` 宏，在 32 位下**展开后都是 `__stdcall`**。

与 cdecl 相比，它只改了一件事：**清栈责任从 caller 移交给 callee**。一字之差，派生出体积更小、但不支持可变参数的特性。

---

## 核心规则

| 项目 | 规定 |
|------|------|
| **参数传递** | 全部经**栈**传递，无寄存器参数（与 cdecl 相同） |
| **压栈顺序** | **从右往左**（与 cdecl 相同） |
| **栈清理** | **被调用者（callee）清** —— 函数内用 `ret N` 在返回的同时弹出参数 |
| **返回值** | 整型/指针 → `EAX`；64 位 → `EDX:EAX`；浮点 → `ST(0)` |
| **callee-saved** | `EBX`、`ESI`、`EDI`、`EBP`（同 cdecl） |
| **名称修饰（MSVC，C 链接）** | `_func@N`，`N` = 参数总字节数。`int add(int,int)` → `_add@8` |

---

## 汇编示例

C 源码：

```c
int __stdcall add(int a, int b) { return a + b; }
int r = add(1, 2);
```

调用方（caller）—— 注意**调用后没有 `add esp`**：

```asm
push 2            ; b
push 1            ; a
call _add@8
mov  [r], eax     ; ★ 直接取返回值，无需清栈（callee 已清）
```

被调用方（callee）：

```asm
_add@8:
    push ebp
    mov  ebp, esp
    mov  eax, [ebp+8]    ; a
    add  eax, [ebp+12]   ; b
    pop  ebp
    ret  8               ; ★ callee 清栈：返回并弹出 8 字节参数
```

> 指纹组合：**callee `ret N`（N>0）+ caller 调用后无 `add esp`**。`_add@8` 这种 `@N` 后缀也是一眼认出 stdcall。

---

## 为什么 Win32 API 选 stdcall

- **体积**：API 被成千上万处调用，清栈代码只在 API 内部**一处**，比 cdecl 在每个调用点重复 `add esp` 省下大量字节。
- **历史**：源自 Pascal/Win16 约定（`PASCAL` 宏），Win32 沿用为统一 ABI，让所有语言（C/C++/Delphi/VB）都能按同一契约调用系统函数。
- **明确性**：参数个数固定 → callee 能算准 `N`，契约清晰。

```c
// 这些宏在 32 位 Windows 下都是 __stdcall
#define WINAPI   __stdcall
#define APIENTRY __stdcall
#define CALLBACK __stdcall   // 窗口过程 WndProc、回调函数
```

---

## 不支持可变参数

callee 必须 `ret N`，而 `N` 要在编译期定死 → **参数个数不能变**。

- 因此 stdcall **不能用于可变参数函数**。
- MSVC 下若给 `...` 函数标 `__stdcall`，编译器**静默退化为 cdecl**（保证 `printf` 这类仍可用）。

---

## ⚠️ 规约不匹配 = 栈失衡

stdcall 最常见的坑出现在**跨语言/跨模块**：

- C# `[DllImport]` 默认按 `CallingConvention.Winapi`（即 stdcall），若目标 DLL 导出的是 cdecl 函数 → **两边都不清 / 都清**，`ESP` 漂移。
- 函数指针类型与实际函数规约不符（如把 cdecl 函数赋给 stdcall 函数指针）→ 调用后栈不平。

> 症状：单次调用看似正常，**多次调用后**在毫不相干的位置崩溃；Debug 版 MSVC 会报 *"Run-Time Check Failure #0 - The value of ESP was not properly saved across a function call"*。

---

## 逆向识别

- 函数以 `ret N`（N>0）收尾，且 `call` 前**全部参数压栈**（无 `ECX/EDX` 装参）→ **stdcall**。
- 调用点 `call` 之后**没有** `add esp`。
- 符号名形如 `_funcname@N`。

> 若 `call` 前还往 `ECX/EDX` 装了参数，则是 [[22.调用规约/03.fastcall.md|fastcall]]（或 `ECX=this` 的 thiscall）。
