# 详解ELF文件(三十一).debug_pubnames节

.debug_pubnames节是DWARF调试信息格式中的一个可选部分，用于存储全局可见的符号名称（如函数名、全局变量名等）与它们对应的调试信息条目（DIE）之间的映射关系。这个节的主要目的是提供一种快速查找全局符号的机制。

## 1. 基本概念和作用

.debug_pubnames节是一个"公共名称"查找表，它包含程序中所有全局可见的符号名称：

- 全局函数
- 全局变量
- 静态函数和变量（在某些实现中）
- 类、结构体等类型的公共成员

该节的主要作用是为调试器提供一种快速查找全局符号的机制，而不需要遍历整个 [[26.debug_info节|.debug_info]] 节（与 [[30.debug_aranges节|.debug_aranges]] 按地址查找正好互补——本节按名字查找）。

## 2. 完整数据结构

.debug_pubnames节由一系列"集合（set）"组成，每个集合对应一个编译单元，内含该 CU 中所有对外可见的符号名。

### 2.1 集合头部格式

```
字段名                    大小          说明
unit_length               4 字节        本集合的字节数（不含 unit_length 自身）
                                        64 位 DWARF：先写 0xffffffff 再写 8 字节
version                   2 字节        DWARF 版本号（通常为 2）
debug_info_offset         4/8 字节      指向 .debug_info 中对应 CU 的偏移
debug_info_length         4/8 字节      对应 CU 的大小（字节数），用于边界检查
```

### 2.2 名称条目格式

头部之后跟随若干名称条目（Name Entry）：

```
字段名                    大小          说明
die_offset                4/8 字节      该符号 DIE 在 .debug_info 中的偏移（相对于 CU 起始）
name                      变长字符串    null 结尾的符号名（函数名、变量名等）
```

- 每个集合以一个 `die_offset = 0` 的空条目结束（列表终止符）
- 名称条目在磁盘上**未排序**，调试器需自行索引

### 2.3 完整内存布局示例

```
.debug_pubnames节完整结构示例（2个CU）：

=== 集合 1（CU 位于 .debug_info 偏移 0x00000000）===
unit_length:         52
version:             2
debug_info_offset:   0x00000000
debug_info_length:   0x000001a0

  die_offset=0x50    name="main\0"
  die_offset=0x65    name="global_var\0"
  die_offset=0x00    (End of list)

=== 集合 2（CU 位于 .debug_info 偏移 0x000001a0）===
unit_length:         36
version:             2
debug_info_offset:   0x000001a0
debug_info_length:   0x000000e8

  die_offset=0x2c    name="helper_func\0"
  die_offset=0x00    (End of list)
```

### 2.4 结构图示

```mermaid
graph LR
  NAME["要查的符号名 main"] -->|查表| PUB[".debug_pubnames"]
  PUB -->|CU偏移 0x00 + DIE偏移 0x50| INFO[".debug_info 中的 DIE"]
  INFO -->|DW_AT_name = main| DETAIL["函数 main 的完整调试信息"]
```

## 3. 工作原理

1. 当调试器需要查找某个全局符号（如函数名）时，先查询 .debug_pubnames 节
2. 顺序扫描各集合的名称条目，查找匹配的符号名（字符串比较）
3. 找到后获得 `debug_info_offset`（CU 起始）和 `die_offset`（CU 内偏移）
4. 两者相加得到 .debug_info 中目标 DIE 的全局偏移
5. 用该偏移直接访问 .debug_info 中的详细调试信息

## 4. .debug_pubtypes 节

与 .debug_pubnames 并列存在的还有 .debug_pubtypes 节，两者格式完全相同，只是存储的内容不同：

| | .debug_pubnames | .debug_pubtypes |
|--|--|--|
| 存储内容 | 全局函数名、全局变量名 | 全局类型名（struct、class、typedef、enum 等） |
| 引用 DIE | DW_TAG_subprogram、DW_TAG_variable | DW_TAG_structure_type、DW_TAG_typedef 等 |
| 典型用途 | 按名查找函数入口点 | 调试器解析类型时快速定位类型定义 |

```text
# 示例输出（代表性，非本机实跑）
$ readelf --debug-dump=pubtypes program

Contents of the .debug_pubtypes section:

  Length:                   40
  Version:                   2
  Offset into .debug_info:   0x00000000
  Size of area in .debug_info: 0x000001a0

    Offset      Name
    0x0000002a  my_struct
    0x0000006b  Point
    (null)
```

## 5. GNU 扩展：.debug_gnu_pubnames / .debug_gnu_pubtypes

GCC 还有扩展版本的公共名称节，通过 `-ggnu-pubnames` 编译选项生成（`-gsplit-dwarf` 会隐式开启）：

```bash
gcc -g -ggnu-pubnames foo.c -o foo
```

GNU 扩展版本在每个条目中增加了一个**类型字节（linkage byte）**，用于描述符号的链接属性：

| 类型值 | 含义 |
|--------|------|
| `GDB_INDEX_SYMBOL_KIND_FUNCTION` | 函数 |
| `GDB_INDEX_SYMBOL_KIND_VARIABLE` | 变量 |
| `GDB_INDEX_SYMBOL_KIND_TYPE` | 类型 |
| `GDB_INDEX_SYMBOL_KIND_OTHER` | 其他 |

这个类型字节供链接器（gold、lld、mold）构建 .gdb_index 时使用，之后 .debug_gnu_pubnames 本身被丢弃。

## 6. DWARF 5：.debug_names 全面取代

### 6.1 设计背景

.debug_pubnames 和 .debug_pubtypes 存在若干根本性缺陷，DWARF 5 专门设计了 .debug_names 来全面替代：

**旧节的缺陷**：
- 仅包含"公共"符号（外部链接），静态函数、局部类型无法按名查找
- 未排序，只能线性扫描 O(N)
- 大型 C++ 项目中，C++ 模板展开、重载函数导致大量重名，无法高效区分
- 无法查询命名空间和类成员

### 6.2 .debug_names 格式概述

.debug_names 是一个带哈希表的名称索引，结构远比旧节复杂：

```
.debug_names 节结构（DWARF 5）：

[头部 Header]
  unit_length            4/8 字节
  version                2 字节（值 5）
  padding                2 字节
  comp_unit_count        4 字节   # 覆盖的 CU 数量
  local_type_unit_count  4 字节   # 本地类型单元数量
  foreign_type_unit_count 4 字节  # 外部类型单元数量
  bucket_count           4 字节   # 哈希桶数量
  name_count             4 字节   # 名称条目总数
  abbrev_table_size      4 字节   # 缩写表大小

[CU offset 列表]               # comp_unit_count 个 CU 的 .debug_info 偏移
[Local TU offset 列表]
[Foreign TU signature 列表]
[哈希桶数组 Bucket array]      # bucket_count 个桶，每桶存索引
[哈希值数组 Hash array]        # name_count 个哈希值
[字符串偏移数组]               # name_count 个 .debug_str_offsets 中的名称字符串偏移
[条目池偏移数组]               # name_count 个条目池中的偏移
[缩写表 Abbrev table]          # 描述 DW_IDX 属性的缩写
[条目池 Entry pool]            # 每个名称的实际 DW_IDX 属性列表
```

### 6.3 DW_IDX 属性详解

.debug_names 中每个名称条目通过 `DW_IDX_*` 属性描述该符号在哪个 CU/TU 中、DIE 偏移等信息：

| DW_IDX 属性 | 说明 |
|-------------|------|
| `DW_IDX_compile_unit` | 该条目所在 CU 在 CU 偏移列表中的索引 |
| `DW_IDX_type_unit` | 该条目所在 TU 的索引 |
| `DW_IDX_die_offset` | 目标 DIE 在 CU/TU 内的偏移 |
| `DW_IDX_parent` | 父条目的偏移（用于表达命名空间层次） |
| `DW_IDX_GNU_internal` | GNU 扩展：标记静态链接符号（值 0x2000） |
| `DW_IDX_GNU_main` | GNU 扩展：标记主函数 |
| `DW_IDX_GNU_language` | GNU 扩展：源语言编号 |
| `DW_IDX_GNU_linkage_name` | GNU 扩展：mangled 名称 |

### 6.4 哈希函数

.debug_names 使用 **DJB 哈希**（Daniel J. Bernstein hash）：

```c
// DJB hash（Fowler/Noll/Vo 变体）
uint32_t djb_hash(const char *name) {
    uint32_t h = 5381;
    while (*name)
        h = h * 33 + (unsigned char)*name++;
    return h;
}
```

调试器计算符号名的 DJB 哈希值后，直接定位到哈希桶，大幅减少比较次数，实现近似 O(1) 的名称查找。

### 6.5 生成 .debug_names

```bash
# GCC：DWARF5 模式自动生成（需 GCC >= 11）
gcc -gdwarf-5 foo.c -o foo

# Clang：显式生成 DWARF5 debug_names
clang -gdwarf-5 -gname-index-from-debug foo.c -o foo

# 链接器 lld 从已有 .debug_gnu_pubnames 构建 .debug_names
ld.lld --debug-names foo.o -o foo
```

## 7. GDB index：.gdb_index 节

.gdb_index 是 GDB 专有（非 DWARF 标准）的加速索引，与 .debug_names 并行存在：

### 7.1 生成方式

```bash
# 方式1：GDB 自动生成并保存
gdb -batch -ex "save gdb-index ." program

# 方式2：gold 链接器直接生成
gcc -g -Wl,--gdb-index foo.c -o foo

# 方式3：lld 链接器生成
clang -g -fuse-ld=lld -Wl,--gdb-index foo.c -o foo
```

### 7.2 与 .debug_names 的对比

| | .gdb_index | .debug_names |
|--|--|--|
| 标准 | GDB 专有 | DWARF 5 官方标准 |
| 格式 | GDB 内部格式（版本化） | DWARF 5 规范格式 |
| 哈希算法 | DJB | DJB（与 GDB 相同） |
| 覆盖范围 | 函数、变量、类型 | 所有命名 DIE（含静态） |
| 工具支持 | GDB 原生 | GDB 8.0+, LLDB, 新版调试器 |

## 8. 局限性和现状

.debug_pubnames节有一些重要局限，导致现代工具链使用减少：

1. **仅含公共符号**：不包括静态函数或私有变量，调试静态函数时需退化为遍历 .debug_info
2. **不被所有调试器使用**：内容不一致且有限
3. **C++ 名称修饰问题**：复杂 C++ 符号存储的可能是完全限定名，但 mangled 名与 demangled 名的映射问题复杂
4. **未排序**：磁盘上通常未排序，需调试器自行解析，大型项目中查找很慢

> 在 DWARF5 中，本节与 .debug_pubtypes 被更高效的 **.debug_names** 索引取代。许多编译器默认不再生成 .debug_pubnames。

## 9. 实战：查看各类名称索引节

### 9.1 查看 .debug_pubnames

```bash
readelf --debug-dump=pubnames program
objdump --dwarf=pubnames program
```

```text
# 示例输出（代表性，非本机实跑）
$ readelf --debug-dump=pubnames program

Contents of the .debug_pubnames section:

  Length:                   52
  Version:                   2
  Offset into .debug_info:   0x00000000
  Size of area in .debug_info: 0x000001a0

    Offset      Name
    0x00000050  main
    0x00000065  global_var
    (null)
```

### 9.2 查看 .debug_names（DWARF5）

```bash
llvm-dwarfdump --debug-names program
readelf --debug-dump=names program    # GNU binutils 2.38+ 支持
```

```text
# 示例输出（代表性，非本机实跑）
$ llvm-dwarfdump --debug-names a.out
.debug_names contents:
  Name Index @ 0x0 {
    Header {
      Version: 5
      Bucket Count: 7
      Name Count: 5
    }
    Buckets [
      0: 1
      1: 0
      ...
    ]
    Name Table {
      0: "main" @ .debug_str[0x1b]
      1: "argc" @ .debug_str[0x20]
      ...
    }
    Entries {
      *0x28 { DW_IDX_compile_unit: 0, DW_IDX_die_offset: 0x50 }
    }
  }
```

### 9.3 检查节是否存在

```bash
readelf -S program | grep -E 'pubnames|pubtypes|gdb_index|debug_names'
```

尽管使用在减少，了解 .debug_pubnames 节的工作原理对于深入理解 DWARF 调试信息格式和调试器工作原理仍然很有价值。
