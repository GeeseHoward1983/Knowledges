# 详解ELF文件(四十七).eh_frame_hdr节

.eh_frame_hdr节是ELF（Executable and Linkable Format）文件中的一个重要节区，全称是"Exception Handling Frame Header"（异常处理帧头）。它作为 [[46.eh_frame节|.eh_frame]] 节的辅助节区，用于加速异常处理和栈回溯过程。

## 1. 基本概念和作用

.eh_frame_hdr节的主要作用是提供 .eh_frame 节的索引信息，以加速查找过程：

- 为 .eh_frame 节提供快速查找索引
- 加速异常处理和栈回溯过程
- 提供二分搜索表以提高运行时效率（O(log n) 查找，避免线性扫描）
- 包含指向 .eh_frame 节的指针（用于 fallback 访问）

它由 PT_GNU_EH_FRAME 程序段指向（见 [[03.程序头表]]），运行时展开器据此入口工作。

### 1.1 为什么需要 .eh_frame_hdr

.eh_frame 节本身是顺序存储的 CIE/FDE 链表，若想确定某 PC 地址属于哪个 FDE，最坏情况需要线性扫描所有记录，时间复杂度 O(n)。对于含有大量函数的共享库，这一开销不可忽视。.eh_frame_hdr 提供按 PC 排序的二分查找表，将查找降至 O(log n)。

由 GNU ld 的 `--eh-frame-hdr` 选项（或 gold 的对应选项）在链接时生成，llvm-lld 也支持此选项。

## 2. 数据结构和特征

.eh_frame_hdr节具有以下特征：

- 节类型：SHT_PROGBITS
- 节标志：SHF_ALLOC（可分配到内存中）
- 包含版本信息、编码格式、指针和可选的二分搜索表

### 2.1 完整头部结构

```c
/* .eh_frame_hdr 完整结构（伪代码） */
struct eh_frame_hdr {
    uint8_t  version;           // 版本号，固定为 1
    uint8_t  eh_frame_ptr_enc;  // eh_frame 指针编码（DW_EH_PE_*）
    uint8_t  fde_count_enc;     // FDE 计数编码（DW_EH_PE_omit 表示无搜索表）
    uint8_t  table_enc;         // 搜索表项编码（DW_EH_PE_omit 表示无搜索表）
    encoded  eh_frame_ptr;      // 指向 .eh_frame 节起始的指针
    /* 以下仅当 fde_count_enc != DW_EH_PE_omit 时存在 */
    encoded  fde_count;         // 搜索表中的条目数（= .eh_frame 中 FDE 总数）
    /* 以下为二分搜索表，fde_count 个条目，每条目：*/
    struct {
        encoded initial_loc;    // FDE 的 PC_begin（函数起始地址），已排序
        encoded fde_addr;       // 该 FDE 在 .eh_frame 中的地址
    } sorted_table[fde_count];
};
```

### 2.2 字段详解

| 字段 | 大小 | 值示例 | 说明 |
|------|------|--------|------|
| `version` | 1 字节 | `0x01` | 固定为 1，其它值保留 |
| `eh_frame_ptr_enc` | 1 字节 | `0x1b` | DW_EH_PE_pcrel\|DW_EH_PE_sdata4，4字节相对偏移 |
| `fde_count_enc` | 1 字节 | `0x03` 或 `0xff` | 搜索表 FDE 数量的编码；`0xff`(DW_EH_PE_omit) 表示无表 |
| `table_enc` | 1 字节 | `0x3b` | 搜索表条目编码；`0xff` 表示无表 |
| `eh_frame_ptr` | 编码 | pcrel+sdata4 值 | 使用 eh_frame_ptr_enc 编码的 .eh_frame 起始地址 |
| `fde_count` | 编码 | `0x06` | FDE 总数 |
| `sorted_table[]` | N×2×编码 | 见下方示例 | 按 initial_loc 升序的 (PC_begin, FDE_addr) 对 |

## 3. DW_EH_PE_* 编码在 .eh_frame_hdr 中的应用

.eh_frame_hdr 使用 DW_EH_PE_* 编码所有指针和偏移，详见 [[46.eh_frame节]] 第 6 节完整表格。此处列举 .eh_frame_hdr 最常见的编码：

| 编码值 | 名称 | 含义 | .eh_frame_hdr 中的用途 |
|--------|------|------|----------------------|
| `0x00` | DW_EH_PE_absptr | 绝对指针（平台指针宽度） | 无 PIC 的静态链接 |
| `0x03` | DW_EH_PE_udata4 | 4 字节无符号 | fde_count（计数不需要相对） |
| `0x0b` | DW_EH_PE_sdata4 | 4 字节有符号 | 小偏移量 |
| `0x1b` | DW_EH_PE_pcrel\|DW_EH_PE_sdata4 | PC 相对 4 字节有符号 | eh_frame_ptr（最常见） |
| `0x3b` | DW_EH_PE_datarel\|DW_EH_PE_sdata4 | 相对 .eh_frame_hdr 起始 4 字节有符号 | table_enc（**典型值**，搜索表条目） |
| `0xff` | DW_EH_PE_omit | 省略该字段 | fde_count_enc/table_enc（无搜索表时） |

> **重要**：搜索表的标准编码是 `DW_EH_PE_datarel | DW_EH_PE_sdata4`（值 `0x3b`），即每个条目是相对于 `.eh_frame_hdr` 节起始地址的 4 字节有符号偏移。GCC 的展开库（libgcc）目前只支持这一种表编码。

## 4. 工作原理与二分搜索表

### 4.1 搜索流程

.eh_frame_hdr 的核心是一张按 `initial_loc` 升序排序的二分搜索表，避免线性扫描 .eh_frame：

```mermaid
graph LR
  PC["异常发生地址 PC"] -->|二分查找| TBL[".eh_frame_hdr 搜索表\n(按 initial_loc 升序)"]
  TBL -->|定位| FDE[".eh_frame 中对应 FDE"]
  FDE --> UNWIND["执行该帧的展开规则"]
```

**搜索算法**：
1. 读取 `fde_count` 条目
2. 对 sorted_table 做标准二分查找，找最大 `initial_loc <= PC` 的条目
3. 取该条目的 `fde_addr`，得到 .eh_frame 中 FDE 的地址
4. 解析该 FDE，验证 `PC_begin <= PC < PC_begin + PC_range`

### 4.2 搜索表示例

```text
# 示例输出（代表性，非本机实跑）
sorted_table[6 entries] (encoding: DW_EH_PE_datarel|DW_EH_PE_sdata4):
  [0]  initial_loc=0x4006b0  fde_addr=0x400648
  [1]  initial_loc=0x4006d8  fde_addr=0x400678
  [2]  initial_loc=0x4006f0  fde_addr=0x4006a8
  [3]  initial_loc=0x400720  fde_addr=0x4006d8
  [4]  initial_loc=0x400780  fde_addr=0x400708
  [5]  initial_loc=0x4007c0  fde_addr=0x400738
```

表中 `initial_loc` 即各函数入口地址（与 FDE 中的 PC_begin 对应），`fde_addr` 为 .eh_frame 节中对应 FDE 记录的地址。

### 4.3 无搜索表的退化情形

当 `fde_count_enc == DW_EH_PE_omit` 时，.eh_frame_hdr 不含搜索表，展开器回退到线性扫描 .eh_frame（使用 `eh_frame_ptr` 找到 .eh_frame 入口）。这在小型程序或某些嵌入式场景下出现。

## 5. PT_GNU_EH_FRAME 程序头

.eh_frame_hdr 节被 `PT_GNU_EH_FRAME`（类型值 `0x6474e550`）程序头指向，这是动态链接器和展开库定位 .eh_frame_hdr 的标准方式。

```bash
# 示例输出（代表性，非本机实跑）
$ readelf -l a.out | grep -A4 GNU_EH_FRAME
  GNU_EH_FRAME   0x000598 0x00400598 0x00400598 0x00004c 0x00004c R   0x4
```

字段含义：
- `p_offset`：.eh_frame_hdr 在文件中的偏移
- `p_vaddr`：运行时虚拟地址
- `p_filesz = p_memsz`：节的大小
- `p_flags = R`：只读（无执行权限）
- `p_align = 4`：4 字节对齐

## 6. 运行时注册机制

### 6.1 dl_iterate_phdr

动态链接器通过 `dl_iterate_phdr()` 枚举所有已加载模块的程序头，展开库（libgcc_s、libunwind）利用此接口找到每个 DSO 的 PT_GNU_EH_FRAME 段，进而访问各模块的 .eh_frame_hdr：

```c
#include <link.h>

// 展开库内部逻辑（伪代码）
static int callback(struct dl_phdr_info *info, size_t size, void *data) {
    for (int i = 0; i < info->dlpi_phnum; i++) {
        if (info->dlpi_phdr[i].p_type == PT_GNU_EH_FRAME) {
            // 找到此 DSO 的 .eh_frame_hdr
            uintptr_t hdr_addr = info->dlpi_addr + info->dlpi_phdr[i].p_vaddr;
            // 在 hdr_addr 处读取 eh_frame_hdr 结构，注册 FDE 搜索表
        }
    }
    return 0;
}
dl_iterate_phdr(callback, NULL);
```

### 6.2 __register_frame 与 __deregister_frame

对于动态加载（dlopen）的共享库，展开库自动通过 PT_GNU_EH_FRAME 注册。若需手动注册自定义生成的 CFI 数据，可调用：

```c
void __register_frame(const void *begin);      // 注册单个 FDE
void __deregister_frame(const void *begin);    // 注销单个 FDE
void __register_frame_info(const void *begin, void *ob); // 注册整个 .eh_frame
```

这些函数主要用于 JIT 编译器（如 LLVM MCJIT）动态生成代码时注册展开信息。

## 7. 实战：查看 .eh_frame_hdr

### 7.1 查看节与程序头

```bash
readelf -S a.out | grep eh_frame_hdr              # 查看节属性
readelf -l a.out | grep GNU_EH_FRAME              # 查看对应程序头
objdump -s -j .eh_frame_hdr a.out                 # 十六进制原始内容
readelf --debug-dump=frames-interp a.out           # 配合查看解释后的帧
readelf -wF a.out                                  # 显示 .eh_frame_hdr 搜索表
```

### 7.2 示例输出解读

## 8. 注意事项

- **可选性**：当 table_enc 为 DW_EH_PE_omit 时，表示没有二分搜索表，展开器回退到线性扫描 .eh_frame
- **编码复杂性**：不同编译器/平台可能用不同编码，libgcc 只支持 `DW_EH_PE_datarel|DW_EH_PE_sdata4` 搜索表
- **共享库**：每个共享库有自己的 .eh_frame_hdr，动态链接器通过 `dl_iterate_phdr` 逐一注册
- **静态链接**：静态链接的可执行文件也有 .eh_frame_hdr，由链接器合并所有目标文件的 CFI 记录

.eh_frame_hdr节是现代ELF程序中重要的性能优化机制，它通过提供 .eh_frame 节的索引信息，显著提高了异常处理和栈回溯的效率，对 C++ 异常密集型应用尤为重要。
