# 异常向量实战（裸机中断处理）

[[21.Asm/29 异常中断处理对比.md|29 异常 / 中断处理对比]] 讲的是**机制对比**，本页是它的**实战姊妹篇**：在**裸机（无操作系统）** 环境下，如何真正写出"设置向量表 → 保存现场 → 分发 → 处理 → 返回"的中断处理代码。以**定时器中断**（裸机要驯服的第一个中断）为主线，给出 ARM64 / RISC-V / LoongArch 可落地的骨架。

> 说明：以下为示意骨架（GAS 语法），省略了链接脚本、栈初始化、缓存/MMU 配置等样板；CSR 编号以各架构手册为准。目标是讲清**结构与关键寄存器**，而非可直接烧录的完整固件。

## 裸机中断处理五步骤（通用心智模型）

1. **设向量表基址**：把异常入口地址写进架构规定的寄存器（ARM `VBAR_EL1`、RISC-V `mtvec`、LoongArch `EENTRY`）。
2. **保存现场**：进入处理程序后，手动把会被破坏的寄存器压栈（RISC 硬件只存返回地址+原因，现场全靠软件）。
3. **读因分发**：读原因寄存器（`ESR`/`mcause`/`ESTAT`）判断是哪类异常/中断，跳到对应处理。
4. **处理 + 应答**：干活，并向中断源/控制器**应答清除**（否则会反复触发）。
5. **恢复现场 + 返回**：弹回寄存器，用专用返回指令（`eret`/`mret`/`ertn`）原子地恢复 PC 与特权级。

## ARM64 裸机实战

### 设置向量表（VBAR_EL1）

```asm
    adr     x0, vector_table
    msr     VBAR_EL1, x0       // 向量基址，需 2KB 对齐
    isb
```

### 向量表布局（16 入口 × 128 字节）

```asm
.align 11                       // 2^11 = 2KB 对齐
vector_table:
    .align 7                    // 每入口 128B（2^7）
    b   sync_sp0                // 当前 EL + SP0：同步
    .align 7
    b   irq_sp0                 //              IRQ
    .align 7
    b   fiq_sp0                 //              FIQ
    .align 7
    b   serr_sp0               //              SError
    .align 7
    b   sync_spx               // 当前 EL + SPx：同步
    .align 7
el1_irq:                        //              IRQ ← 内核态中断常走这里
    bl  save_ctx
    bl  irq_handler
    bl  restore_ctx
    eret                        // 据 ELR_EL1 + SPSR_EL1 返回
    // …余下入口（低 EL AArch64 / AArch32）省略
```

### 保存/恢复现场

```asm
save_ctx:                       // 把 x0–x29 压栈（x30=LR 单独处理）
    stp x0,  x1,  [sp, #-16]!
    stp x2,  x3,  [sp, #-16]!
    // … 直到 x28, x29
    ret
restore_ctx:
    // … 逆序 ldp 弹出
    ldp x0,  x1,  [sp], #16
    ret
```

### 定时器中断（Generic Timer + 开中断）

```asm
    mrs x0, CNTFRQ_EL0          // 定时器频率（Hz）
    mov x1, #100
    udiv x0, x0, x1            // 10ms 后触发
    msr CNTP_TVAL_EL0, x0      // 设倒计时值
    mov x0, #1
    msr CNTP_CTL_EL0, x0       // bit0=ENABLE，开启物理定时器
    msr DAIFClr, #2            // 清 I 位，开 IRQ（DAIF: D/A/I/F）
    // irq_handler 内：重写 CNTP_TVAL_EL0 续期，并经 GIC 完成 EOI 应答
```

> ARM 进入异常自动把返回地址存入 `ELR_EL1`、状态存入 `SPSR_EL1`，但**通用寄存器要自己存**；外部中断（IRQ/FIQ）经 **GIC** 分发并需 EOI 应答。

## RISC-V 裸机实战（M 模式）

```asm
    # 1) 设 trap 入口（Direct 模式：所有 trap 都到 trap_vector）
    la      t0, trap_vector
    csrw    mtvec, t0           # mtvec 低 2 位=00 即 Direct

    # 2) 设定时器：CLINT 的 mtimecmp = mtime + 间隔
    li      t0, CLINT_MTIME
    ld      t1, 0(t0)
    li      t2, 1000000
    add     t1, t1, t2
    li      t0, CLINT_MTIMECMP
    sd      t1, 0(t0)

    # 3) 使能中断：mie.MTIE(bit7) + mstatus.MIE(bit3)
    li      t0, (1 << 7)
    csrs    mie, t0
    li      t0, (1 << 3)
    csrs    mstatus, t0
    ...

.align 2                        # mtvec 要求 4 字节对齐
trap_vector:
    csrrw   sp, mscratch, sp    # 经典技巧：与 mscratch 交换，切到中断栈
    addi    sp, sp, -256
    sd      ra, 0(sp)           # 保存现场（示意，实际要存所有用到的寄存器）
    sd      t0, 8(sp)
    ...
    csrr    t0, mcause
    bltz    t0, .irq            # 最高位=1（负）→ 中断
    j       .exc                # 否则异常
.irq:
    # 定时器中断：重设 mtimecmp 续期（否则一直挂起）
    li      t0, CLINT_MTIMECMP
    ld      t1, 0(t0)
    li      t2, 1000000
    add     t1, t1, t2
    sd      t1, 0(t0)
    # …处理 tick…
.done:
    ld      t0, 8(sp)           # 恢复现场
    ld      ra, 0(sp)
    addi    sp, sp, 256
    csrrw   sp, mscratch, sp    # 换回原栈
    mret                        # 据 mepc + mstatus.MPP 返回
```

> RISC-V 定时器中断**没有专门的清除位**——靠**重写 `mtimecmp`**（推后下次比较时刻）来"应答"，否则中断会持续挂起。`mscratch` 交换栈是裸机/内核 trap 入口的标准手法。

## LoongArch 裸机定时器（已核实 CSR）

LoongArch 有架构内建的**恒定频率定时器**，裸机设置四步：

```asm
    # 1) 设异常入口 EENTRY(0xc)
    la.local $t0, trap_entry
    csrwr    $t0, 0xc

    # 2) 配置定时器 TCFG(0x41)：低2位为 EN/PERIOD，高位为定时值
    li.d     $t0, (1000000 << 2) | 0x1 | 0x2   # 值<<2 | EN(bit0) | PERIOD(bit1)
    csrwr    $t0, 0x41

    # 3) 使能定时器中断线：ECFG(0x4) 的 LIE 中 TI 位 = bit 11
    li.d     $t0, (1 << 11)
    csrwr    $t0, 0x4

    # 4) 开全局中断：CRMD(0x0) 的 IE = bit 2
    csrrd    $t0, 0x0
    ori      $t0, $t0, 0x4
    csrwr    $t0, 0x0
    ...

trap_entry:
    csrwr    $t0, 0x30          # 用 SAVE0(0x30) 暂存 t0，腾出工作寄存器
    csrrd    $t0, 0x5           # 读 ESTAT
    andi     $t1, $t0, ...      # 检查 IS 域 bit11（定时器中断 INT_TI）
    # …处理 tick…
    li.d     $t1, 0x1
    csrwr    $t1, 0x44          # 写 TICLR(0x44) 清定时器中断
    csrrd    $t0, 0x30          # 恢复 t0
    ertn                        # 原子恢复 PC←ERA、CRMD←PRMD
```

> 核实要点：定时器 CSR 为 `TCFG=0x41`/`TVAL=0x42`/`TICLR=0x44`，中断使能在 `ECFG=0x4` 的 LIE 字段、定时器中断状态在 `ESTAT=0x5` 的第 11 位；处理末尾**必须写 `TICLR` 清中断**。`SAVE0–15`（0x30 起）是供异常处理腾寄存器用的暂存 CSR。

## x86 / MIPS 要点

- **x86**：裸机要建 **IDT**（256 个门描述符）并 `lidt` 加载；外部中断历史上经 **8259 PIC**、现代经 **APIC**；定时器可选 PIT(8254)/APIC Timer/HPET。还牵涉实模式→保护模式→长模式切换，是五家中裸机启动最繁琐的。
- **MIPS**：异常向量多为**固定地址**（通用异常 `0x80000180`），或经 `EBase` 重定位；置 `Status.IE` 开中断、看 `Cause.IP` 判中断源；定时器用 **CP0 `Count`/`Compare`**（`Count` 自增，等于 `Compare` 时触发，写 `Compare` 清中断）；`eret` 返回。注意延迟槽下 `Cause.BD` 的处理。

## 实战要点

1. **现场保存范围**：至少保存处理程序会破坏的 caller-saved 寄存器；若中断里调用 C 函数，按 [[21.Asm/23 调用约定对比.md|调用约定]] 它会自行保存 callee-saved，但参数/临时寄存器要你存。
2. **应答方式各异**：RISC-V 定时器靠**重写 `mtimecmp`**、LoongArch 靠**写 `TICLR`**、MIPS 靠**写 `Compare`**、ARM 经 **GIC EOI**——漏了就会反复进中断。
3. **嵌套与可重入**：默认进入异常会**关中断**（RISC-V `mstatus.MIE`→0、ARM `DAIF` 置位），要支持嵌套须在保存好现场后手动再开。
4. **定时器是第一课**：它是验证"向量表设对了、中断能进能出、能应答清除"的最小闭环——跑通周期 tick，裸机中断框架就立住了。

## 总结

- 五步心智模型（设入口→存现场→读因分发→处理应答→恢复返回）对五架构通用，差异在**寄存器名**与**应答方式**。
- 返回指令与入口寄存器要记牢：ARM `VBAR`/`eret`、RISC-V `mtvec`/`mret`、LoongArch `EENTRY`/`ertn`、MIPS 固定向量/`eret`。
- LoongArch 裸机定时器：`TCFG` 配置 → `ECFG.LIE` 使能 → `CRMD.IE` 全局开 → 处理末写 `TICLR` 清除。
