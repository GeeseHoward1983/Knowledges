# 虚拟化扩展对比

硬件虚拟化扩展让一台机器高效跑多个虚拟机。本页对比五大架构的虚拟化方案——它们要解决同样三个问题：**特权指令陷入、两阶段地址翻译、中断虚拟化**。承接 [[21.Asm/29 异常中断处理对比.md|29 异常中断]] 与 [[21.Asm/38 MMU与页表设置实战.md|38 MMU / 页表]]。

## 虚拟化要解决的三件事

1. **特权指令陷入**：Guest 执行敏感指令（改页表、关中断…）须**陷入（trap）** 到 hypervisor 模拟，而非真改硬件。
2. **两阶段地址翻译**：Guest 以为自己有连续物理内存（GPA），实际还要再翻译一层到真实物理地址（HPA）。
3. **中断虚拟化**：把物理中断路由给正确的 VM，并能注入虚拟中断。

## 五架构虚拟化扩展对照

| 架构 | 扩展 | hypervisor 态 | 二级翻译 | Guest 状态载体 |
|------|------|--------------|---------|---------------|
| [[21.Asm/15 x86(64).md\|x86]] | **VT-x（VMX）** | VMX root | **EPT** | VMCS |
| [[21.Asm/11 ARM.md\|ARM]] | Virtualization | **EL2**（+VHE） | **Stage-2**（VTTBR_EL2） | 系统寄存器 |
| [[21.Asm/14 RISC-V.md\|RISC-V]] | **H 扩展** | HS 模式 | **G-stage**（hgatp） | VS-level CSR |
| [[21.Asm/13 LoongArch64.md\|LoongArch]] | **LVZ** | Host 模式 | GTLB / 二级 | **GCSR（Guest CSR）** |
| [[21.Asm/12 MIPS.md\|MIPS]] | VZ ASE | Root 模式 | — | Guest CP0 |

## 逐架构要点

### x86 VT-x（VMX）

- **两种模式**：VMX **root**（hypervisor）与 **non-root**（guest）。`VMLAUNCH`/`VMRESUME` 进入 guest，敏感事件触发 **`VMEXIT`** 回 hypervisor。
- **VMCS（虚拟机控制结构）**：保存 guest/host 完整状态与控制位，决定哪些事件导致退出。
- **EPT（扩展页表）**：GPA→HPA 的硬件二级翻译；**VPID** 给每个 vCPU 打标签，避免切换时全 flush TLB。

### ARM（EL2 + Stage-2）

- **EL2** 是专门的 hypervisor 异常级（高于内核 EL1，见 [[21.Asm/29 异常中断处理对比.md|异常级]]）。
- **两阶段翻译**：Stage-1（GVA→GPA，guest 自管）+ **Stage-2**（GPA→HPA，hypervisor 经 `VTTBR_EL2`/`VTCR_EL2` 管）。`HCR_EL2` 配置哪些操作陷入 EL2。
- **VHE（Armv8.1）**：让宿主 OS 直接运行在 EL2，KVM 等受益；中断经 **GIC 虚拟化**（虚拟 CPU 接口）注入。

### RISC-V H 扩展

- **新增模式**：**HS**（hypervisor-extended supervisor，跑 hypervisor）、**VS**（虚拟化 supervisor，guest 内核）、**VU**（guest 用户）。
- **两阶段**：VS-stage（GVA→GPA）+ **G-stage**（GPA→HPA，经 `hgatp`）。提供影子 **VS-level CSR**（`vsatp`/`vsstatus`…）让 guest 透明运行。
- **专用指令**：`hlv`/`hsv`（hypervisor 按 guest 视角访存）、`hfence.gvma`/`hfence.vvma`（两阶段 TLB 维护）。

### LoongArch LVZ（已核实）

- **LVZ（Loongson VirtualiZation）**：实现时处理器有**两套 CSR——Host 一套、Guest 一套**，即 **GCSR** 机制，是 guest 透明运行的基础。
- 涉及特权指令、CSR、异常/中断、内存管理的成套虚拟化支持；TLB 为软件管理（类 MIPS），含 **GTLB**（Guest TLB）与 **GINTC**（Guest 中断控制器）。

### MIPS VZ

- **VZ ASE**：Root/Guest 模式，**Guest 有自己的 CP0**，Root 模式控制 guest 行为；软件管理 TLB 下的两阶段翻译较复杂。

## 两阶段地址翻译（核心机制）

虚拟化最关键的硬件是**嵌套/两阶段页表**：

```
Guest 虚拟地址 (GVA)
      │  ← Stage-1 / VS-stage：guest 自己的页表（guest 管）
      ▼
Guest 物理地址 (GPA)   ← guest 以为这就是物理内存
      │  ← Stage-2 / G-stage / EPT：hypervisor 的页表（host 管）
      ▼
Host 物理地址 (HPA)    ← 真实内存
```

> 没有硬件二级翻译时，hypervisor 要维护"影子页表"（shadow page table）软件合并两级，开销巨大。**EPT / Stage-2 / G-stage / GTLB** 把第二级交给硬件，是现代虚拟化性能的关键。代价是 TLB 缺失要 walk 两套页表（嵌套 walk）。

## 关键设计对比

| 维度 | 说明 |
|------|------|
| hypervisor 隔离 | ARM 用独立**异常级 EL2**、RISC-V 用独立**模式 HS/VS**、x86 用 **root/non-root**——都把 hypervisor 与 guest 内核硬隔离 |
| Guest 状态 | x86 集中存 **VMCS**（一块结构）；ARM/RISC-V/LoongArch 用**影子寄存器组**（EL2 系统寄存器 / VS-CSR / GCSR）让 guest 直接读写而透明陷入 |
| 二级翻译 | 一致采用嵌套页表（EPT/Stage-2/G-stage/GTLB），消除影子页表开销 |
| 退出开销 | `VMEXIT`/陷入 EL2/陷入 HS 都有固定成本，减少退出次数是优化重点（半虚拟化、设备直通） |

## 总结

- 三大任务：特权指令陷入、两阶段地址翻译、中断虚拟化——五架构方案神似、命名各异。
- hypervisor 隔离：x86 root/non-root、ARM EL2、RISC-V HS/VS、LoongArch Host/Guest、MIPS Root/Guest。
- 二级翻译是性能核心：x86 **EPT**、ARM **Stage-2**、RISC-V **G-stage**、**LoongArch GTLB（GCSR 双 CSR）**——都把 GPA→HPA 交给硬件，告别影子页表。
