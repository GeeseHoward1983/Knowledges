# 各架构性能特性对比

本页横向梳理五大架构在性能上的特性差异。**核心认知先行：实际性能主要由「微架构 + 工艺 + 设计投入」决定，而非 ISA 本身**——但 ISA 会通过若干设计点影响实现难度与性能上限。下文据此把性能因素拆成 **ISA 级**（随指令集而定）与 **微架构级**（与 ISA 大体正交）两层。

## 认知框架：ISA ≠ 性能

- **同一 ISA 可以有天差地别的实现**：ARM 既有 Apple M 系列这样的高性能乱序大核，也有 Cortex-M0 这样的顺序小核；x86 既有 Zen/Core 大核，也有早期顺序执行的 Atom。性能差异主要来自微架构，而非「ARM 还是 x86」。
- **「RISC 比 CISC 快」已是过时论断**：现代 x86 在前端把 CISC 指令译码成内部 **µops（微操作）**，乱序后端本质是「RISC 式」执行；而 RISC 阵营也不断加入复杂特性。CISC/RISC 的边界早已模糊。
- ISA 真正的性能影响在于：**代码密度、寻址模式、寄存器数量、标志位依赖、译码复杂度、是否暴露流水线细节**这几处——下面逐一展开。

## ISA 级性能因素

### 1. 代码密度（影响取指带宽与 I-cache）

- **x86**：变长编码（1–15 字节），常用指令短，**代码密度高**，同样逻辑占用更少字节，利于 I-cache 命中。
- **定长 RISC**（ARM64 / MIPS / RISC-V / LoongArch）：32 位定长，单条偏大；但各自有压缩编码缩小差距——ARM **Thumb-2**、RISC-V **C 扩展**（16 位）、MIPS16e。RISC-V 开 C 扩展后代码密度可与 x86 接近甚至更优。

### 2. 寻址模式与 load-store

- **x86（CISC）**：算术指令可直接带内存操作数（`add (%rsi), %eax`），单指令做「访存 + 运算」，代码更密、指令数更少。
- **RISC（其余四家）**：**load-store 架构**，访存只能 `load`/`store`，运算只在寄存器间。指令规整、定长、副作用少，**利于流水线与乱序调度**。代价是同样逻辑需更多条指令，但每条更简单。

### 3. 寄存器数量（影响寄存器压力 / spill）

| 架构 | 通用寄存器数 |
|------|------------|
| x86-64 | 16 |
| ARM64 / RISC-V / LoongArch / MIPS | 32 |

寄存器越多，编译器越少把变量「溢出（spill）」到栈，**减少访存**。乱序核的寄存器重命名能缓解架构寄存器偏少的压力（x86-64 物理寄存器远多于 16），但架构寄存器多仍对编译器友好——这也是 x86-64 相比 32 位 x86 仅 8 个寄存器时的一大改进。

### 4. 条件标志依赖（纯 RISC 的微妙优势）

- **x86 / ARM(AArch32)**：算术逻辑指令**隐式更新标志位**（CF/ZF/SF/OF 或 NZCV），标志寄存器成为额外的数据依赖，乱序实现必须对标志做重命名，增加复杂度。
- **MIPS / RISC-V / LoongArch**：**无整数标志位**，分支直接比较寄存器（RISC-V `blt`/`bge` 直接比两个寄存器），依赖链清晰、利于调度。详见 [[21.Asm/01 汇编指令集对比.md|对比总览]] 的标志位段。

### 5. 译码复杂度（定长 vs 变长）

- **定长 32 位**：指令边界天然对齐，**译码简单、易并行多发射**——多个译码器可同时开工。
- **x86 变长**：需先确定每条指令边界才能译码，前端复杂；现代实现用 **µop cache（Intel DSB / AMD op cache）** 缓存已译码的微操作，绕开重复译码瓶颈，热循环几乎不受变长译码拖累。

### 6. 分支延迟槽（MIPS 的历史包袱）

- **MIPS** 把早期五级流水线的实现细节——「跳转后一条指令照常执行」的**延迟槽**——硬塞进了 ISA。在浅流水线时代它能免费利用一个槽位；但到**深流水线 / 超标量**时代，一个延迟槽既填不满流水线气泡，又**复杂化乱序实现**，反成包袱。
- 这是「ISA 不该暴露微架构细节」的反面教材。**ARM / RISC-V / LoongArch 都不采用延迟槽**，正是吸取了这一教训。

### 7. 宏融合 / 微操作融合

- **x86**：前端把 `cmp + jcc` 等常见配对**宏融合（macro-op fusion）** 成单个 µop 执行，等效提升发射宽度。
- **RISC-V**：鼓励实现去**融合**常见指令对（如 `auipc+addi` 取地址、`slli+add` 等），用「指令多但可融合」换取编码简单——把复杂度从 ISA 移到微架构。

## 微架构级特性（与 ISA 大体正交）

下列技术任何 ISA 都能采用，是高/低性能实现的真正分野：

| 特性 | 低功耗 / 嵌入式实现 | 高性能实现 |
|------|--------------------|-----------|
| **执行顺序** | 顺序（in-order） | **乱序（OoO）**：重命名 + ROB + 保留站挖掘 ILP |
| **流水线深度** | 浅（经典 MIPS 五级） | 深（15–20+ 级），频率高但误预测代价大 |
| **超标量宽度** | 单发射 | 多发射（大核常 4–8 宽） |
| **分支预测** | 静态 / 简单 | TAGE / 感知机等，命中率 >95% |
| **缓存层次** | L1（甚至无 L2） | L1/L2/L3 + 预取器 |

> 关键点：**这五项几乎与「选哪个 ISA」无关**。一颗 RISC-V 顺序 MCU 与一颗 RISC-V 乱序大核，性能差几个数量级，差距全在微架构。

## 实践要点与误区

1. **别用 ISA 给芯片性能下结论**：决定一颗芯片快慢的是微架构、制程、缓存与功耗预算，ISA 影响有限。
2. **代码密度仍然重要**：在 I-cache 受限或取指带宽紧张时，x86 的高密度、RISC-V+C 的压缩编码能转化为实打实的性能。
3. **延迟槽是真包袱**：逆向 / 移植 MIPS 代码时务必处理延迟槽语义（见 [[21.Asm/33 逆向反汇编速查.md|逆向反汇编速查]]），它也是 MIPS 难做高性能乱序核的原因之一。
4. **内存模型影响并发性能**：弱序架构（ARM/RISC-V/LoongArch/MIPS）能更激进地重排访存以提速，但要求正确的屏障；x86 强序省心却限制了某些重排优化。详见 [[21.Asm/28 原子操作与内存模型.md|原子操作与内存模型]]。
