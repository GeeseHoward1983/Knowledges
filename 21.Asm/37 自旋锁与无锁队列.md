# 自旋锁与无锁队列多架构实现

[[21.Asm/28 原子操作与内存模型.md|28 原子操作与内存模型]] 讲了原语与内存序，本页是它的**实战篇**：用各架构的原子指令真正写出**自旋锁**与**无锁队列**，并暴露弱序架构上最常见的并发 bug。核心一句话：**锁要 acquire、解锁要 release**，弱序架构上漏了就出隐患。

> 说明：示意代码，省略了完整错误处理。x86 用 AT&T 语法。锁变量约定：`0`=未锁、`1`=已锁。

## 自旋锁：四架构对照

最简自旋锁＝原子地把锁从 0 改 1（拿锁），解锁写回 0。关键在**内存序**：

### x86-64（TSO，acquire/release 几乎免费）

```asm
spin_lock:                      # 锁地址在 %rdi
    mov     $1, %eax
.retry:
    xchg    %eax, (%rdi)        # 原子交换，xchg 隐含 lock（全屏障=acquire）
    test    %eax, %eax
    jz      .done               # 旧值=0 → 拿到锁
.spin:
    pause                       # 自旋提示：降功耗、缓解缓存争用
    cmpl    $0, (%rdi)          # TTAS：先只读自旋，等它变 0
    jne     .spin
    jmp     .retry
.done:
    ret
spin_unlock:
    movl    $0, (%rdi)          # TSO 下普通 store 即具 release 语义
    ret
```

> x86 **TSO** 强序：`xchg` 自带 `lock`（全屏障）作 acquire，解锁用普通 `mov` 即可（store 不会前移，天然 release）——这是强序"掩盖"屏障的典型（见 [[21.Asm/28 原子操作与内存模型.md|内存模型]]）。

### ARM64（LSE CAS 或 LL/SC，须显式 acquire/release）

```asm
// LSE 原子（Armv8.1+）：CAS-acquire 拿锁、store-release 解锁
spin_lock:                      // 锁地址 x0
.retry:
    mov     w1, #0              // 期望值=0
    mov     w2, #1              // 新值=1
    casa    w1, w2, [x0]       // CAS-acquire：[x0]==0 则置1；w1=旧值
    cbnz    w1, .retry          // 旧值非0 → 重试
    ret
spin_unlock:
    stlr    wzr, [x0]          // store-release 解锁
    ret

// 经典 LL/SC 版（Armv8.0）：
spin_lock_llsc:
.retry:
    ldaxr   w1, [x0]           // load-acquire-exclusive
    cbnz    w1, .retry
    mov     w2, #1
    stxr    w3, w2, [x0]       // store-exclusive
    cbnz    w3, .retry          // sc 失败重试
    ret
```

### RISC-V（AMO 带 .aq/.rl 标志）

```asm
spin_lock:                      # 锁地址 a0
    li      t0, 1
.retry:
    amoswap.w.aq t1, t0, (a0)   # 原子交换 + acquire
    bnez    t1, .retry          # 旧值非0 → 重试
    ret
spin_unlock:
    amoswap.w.rl x0, x0, (a0)   # 原子写0 + release（或 fence rw,w; sw）
    ret
```

### LoongArch（ll/sc + dbar，或带屏障原子）

```asm
# 老核（3A5000）：ll.w/sc.w + dbar 屏障
spin_lock:                      # 锁地址 a0
.retry:
    ll.w    $t1, $a0, 0         # load-linked
    bnez    $t1, .retry          # 已锁 → 重试
    li.w    $t0, 1
    sc.w    $t0, $a0, 0          # store-conditional
    beqz    $t0, .retry          # sc 失败 → 重试
    dbar    0                    # acquire 屏障
    jr      $ra
spin_unlock:
    dbar    0                    # release 屏障
    st.w    $zero, $a0, 0        # 写0解锁
    jr      $ra
# 简化：amswap_db.w $t1, $t0, $a0  （一条带 DBAR 的原子交换）
# v1.1 核（3A6000）：amcas_db.w（CAS）、llacq.w/screl.w（专用 acquire/release）、dbar 0x700（轻量 hint）
```

> 核实要点：LoongArch 的 `_db` 后缀原子（如 `amswap_db.w`）**自带 DBAR 屏障**；**v1.1** 新增 `llacq`/`screl`（专用 acquire/release）、`amcas`（CAS）与有意义的 `dbar` hint（`0x700` 比 `dbar 0` 更轻），老核所有 hint 都当 `dbar 0`。

## 优化：TTAS、pause、ticket lock

- **TTAS（test-test-and-set）**：拿不到锁时**只读自旋**（普通 load 等它变 0），变 0 才再试原子写——避免每次自旋都写缓存行、引发一致性风暴。
- **降争用提示**：x86 `pause`、ARM `wfe`/`yield`、RISC-V `pause`(Zihintpause)、LoongArch 等待——自旋时让出，降功耗与总线压力。
- **ticket lock（公平）**：用 `fetch-and-add` 取递增"票号"，按号服务，保证 **FIFO 公平**，避免简单 TAS 锁的饥饿。x86 `lock xadd`、ARM `ldadd`(LSE)、RISC-V `amoadd`、LoongArch `amadd_db.w` 取票。

## 无锁队列

### SPSC 环形缓冲（最简，只需 acquire/release）

单生产者单消费者环形队列**无需 CAS**——生产者只写 `tail`、消费者只写 `head`：

- 生产者：写数据 → **store-release** 更新 `tail`（保证数据先于 tail 可见）。
- 消费者：**load-acquire** 读 `tail` → 读数据（保证读到 tail 后才读数据）。

> 一对 acquire/release 就够，是弱序架构上最划算的无锁结构；x86 上甚至普通 load/store 即可。

### MPMC 与 Michael-Scott 队列（CAS + ABA）

多生产者多消费者无锁队列（如 Michael-Scott 链表队列）靠 **CAS 推进 head/tail 指针**，但会遇到 **ABA 问题**：

- **ABA**：线程读到指针 A，CAS 前它经历 A→B→A，CAS 误以为"没变"而成功，破坏结构。
- **解法**：① **带版本号的指针**（双字 CAS：x86 `cmpxchg16b`、ARM `casp`）；② **LL/SC 天然免疫**（`sc` 检测的是"这块有没有被写过"，而非"值变没变"——RISC-V/ARM/LoongArch 的 LL/SC 因此不受 ABA 困扰）；③ hazard pointer / RCU 管理回收。

## 关键陷阱

1. **弱序漏 acquire/release = 间歇 bug**：x86 上 `unlock` 用普通 `mov` 没事（TSO），但 ARM/RISC-V/LoongArch **必须** `stlr`/`.rl`/`dbar`，否则临界区的写可能重排到解锁之后 → 数据竞争。这是从 x86 移植到弱序架构最常见的并发 bug（见 [[21.Asm/28 原子操作与内存模型.md|内存模型]]）。
2. **false sharing**：锁变量与被保护数据落在同一缓存行 → 自旋写锁不断使数据缓存行失效。解法：**缓存行对齐（通常 64 字节）** 隔离热点变量。
3. **LL/SC 虚假失败与活锁**：`sc` 可能因无关事件失败；LL/SC 循环体要**短小**，否则可能反复失败甚至活锁。
4. **公平性**：朴素 TAS 锁可能饿死某些线程，高竞争场景用 ticket lock 或 MCS 锁。

## 总结

- 自旋锁四架构：x86 靠 `xchg`+TSO（解锁普通 mov）；ARM 用 `casa`/`stlr` 或 `ldaxr`/`stxr`；RISC-V 用 `amoswap.w.aq/.rl`；LoongArch 用 `ll/sc`+`dbar` 或 `amswap_db.w`，v1.1 有 `llacq`/`screl`/`amcas`。
- **锁 acquire、解锁 release** 是铁律——弱序架构漏了就埋雷。
- 无锁：SPSC 环形缓冲只需 acquire/release；MPMC 需 CAS 并处理 ABA（版本号 / LL-SC 免疫）；当心 false sharing。
