# 逆向 / 反汇编速查

本页汇总把二进制还原成可读汇编、再读懂它的常用工具与套路：反汇编工具、AT&T/Intel 语法、各架构**函数序言/尾声**识别、调用约定还原、常见编译器代码模式（PLT/GOT、跳转表、栈保护）、以及跨架构调试。配套见 [[21.Asm/01 汇编指令集对比.md|五架构对比总览]] 与 [[21.Asm/23 调用约定对比.md|调用约定对比]]。

## 工具速查

| 工具 | 用途 | 备注 |
|------|------|------|
| `file` / `readelf -h` | 识别架构、位数、字节序、是否 PIE/静态 | 逆向第一步先看清目标 |
| `strings` | 抽取可打印字符串 | 快速找提示串、URL、格式串 |
| `nm` / `objdump -t` | 列符号表 | `-D` 看动态符号 |
| `ldd` / `readelf -d` | 看依赖的动态库 | `-d` 看 `NEEDED` 项 |
| **`objdump -d`** | 静态反汇编 | binutils 自带，最通用 |
| **`gdb`** | 动态调试、运行时反汇编 | `gdb-multiarch` 支持跨架构 |
| `radare2` / `rizin` | 交互式逆向框架 | `r2 -A` 自动分析 |
| **Ghidra** | 反汇编 + **反编译**（免费） | NSA 出品，多架构，出伪 C |
| IDA Pro / Hex-Rays | 业界标杆反汇编 + 反编译 | 商业 |
| Binary Ninja | 现代化逆向平台 | 商业，API 友好 |
| Capstone / Keystone | 多架构反汇编 / 汇编**库** | 写脚本/工具时调用 |
| QEMU user-mode | 跑异架构用户态程序 | 配 `gdb` 远程调试外架构 |

## objdump 常用法

```bash
objdump -d a.out                 # 反汇编可执行节（.text 等）
objdump -d -M intel a.out        # x86 用 Intel 语法（默认 AT&T）
objdump -D a.out                 # 反汇编所有节（含数据，慎读）
objdump -dr obj.o                # 带重定位项（读 .o 时定位外部调用）
objdump -S a.out                 # 源码与汇编交错（需 -g 调试信息）
objdump -j .text -d a.out        # 只反汇编指定节
objdump --start-address=0x1149 --stop-address=0x1180 -d a.out
objdump -R a.out                 # 动态重定位（看 GOT/PLT 条目）
objdump -f a.out                 # 文件头：架构 + 入口地址
```

> `objdump` 自动按目标文件头选择架构反汇编器，所以同一个 `objdump`（若按多架构 binutils 构建）能直接读 ARM/MIPS/RISC-V/LoongArch 的 ELF；发行版常单独提供 `aarch64-linux-gnu-objdump` 等交叉版本。

## x86 语法：AT&T vs Intel

读 x86 反汇编要先认清两套语法（同一条指令、两种写法）：

| 方面 | AT&T（GAS / objdump 默认） | Intel（NASM / `-M intel`） |
|------|---------------------------|---------------------------|
| 操作数顺序 | `op 源, 目的` | `op 目的, 源` |
| 寄存器 | `%rax` | `rax` |
| 立即数 | `$0x10` | `0x10` |
| 内存寻址 | `disp(base,index,scale)` 如 `8(%rbp)` | `[base+index*scale+disp]` 如 `[rbp+8]` |
| 间接跳转 | `jmp *%rax` | `jmp rax` |
| 大小后缀 | 助记符带 `b/w/l/q`（`movq`） | 由操作数推断，必要时 `qword ptr` |

> 一眼区分：看到 `%`、`$` 和「源在前」就是 AT&T；看到 `[...]` 和「目的在前」就是 Intel。其余 RISC 架构（ARM/MIPS/RISC-V/LoongArch）统一是「目的在前」的单一语法。

## 函数序言 / 尾声识别（逆向核心技能）

认出 **prologue（序言）** 与 **epilogue（尾声）** 就能切分函数、定位栈帧、还原局部变量布局。各架构有固定套路：

### x86-64（System V）

```asm
push   %rbp                # 保存调用者帧指针
mov    %rsp, %rbp          # 建立本帧（-fomit-frame-pointer 时可能没有）
sub    $0x20, %rsp         # 为局部变量分配栈
...
leave                      # = mov %rbp,%rsp ; pop %rbp
ret
```

> 叶函数常省去帧指针并直接用 **128 字节 red zone**（不调 `%rsp`）；此时序言可能只剩几条 `mov`。

### ARM64（AAPCS64）

```asm
stp    x29, x30, [sp, #-0x20]!   // 同时压 FP(x29)/LR(x30) 并下移 sp（预索引）
mov    x29, sp                   // 建立帧指针
...
ldp    x29, x30, [sp], #0x20     // 恢复 FP/LR 并上移 sp（后索引）
ret                              // 返回到 x30(LR)
```

> 看到成对的 `stp x29,x30` / `ldp x29,x30` 基本就是 ARM64 函数边界；`BL` 不自动压 LR，故非叶函数必须在序言里保存 x30。

### RISC-V

```asm
addi   sp, sp, -32
sd     ra, 24(sp)          # 保存返回地址
sd     s0, 16(sp)          # 保存帧指针
addi   s0, sp, 32
...
ld     ra, 24(sp)
ld     s0, 16(sp)
addi   sp, sp, 32
ret                        # = jalr x0, 0(ra)
```

### LoongArch

```asm
addi.d $sp, $sp, -32
st.d   $ra, $sp, 24        # 保存返回地址
st.d   $fp, $sp, 16        # 保存帧指针（$fp=$r22）
...
ld.d   $ra, $sp, 24
ld.d   $fp, $sp, 16
addi.d $sp, $sp, 32
jr     $ra                 # = jirl $zero, $ra, 0
```

### MIPS（O32）

```asm
addiu  $sp, $sp, -32
sw     $ra, 28($sp)        # 保存返回地址
sw     $fp, 24($sp)        # 保存帧指针
...
lw     $ra, 28($sp)
lw     $fp, 24($sp)
jr     $ra
nop                        # ← 分支延迟槽，跳转后这条照常执行
```

> **MIPS 特征**：`jr $ra` 后紧跟一条延迟槽指令（常被填成有用指令或 `nop`）。读 MIPS 反汇编务必记得「跳转的后一条先执行」，否则会误判控制流（见 [[21.Asm/23 调用约定对比.md|调用约定对比]] 的延迟槽说明）。

## 从汇编还原调用约定

定位参数/返回值寄存器，是还原函数签名的关键。各架构「前几个整数参数 + 返回值」速记（完整版见 [[21.Asm/23 调用约定对比.md|调用约定对比]]）：

| 架构 | 整数参数（前几个） | 返回值 |
|------|------------------|--------|
| x86-64 SysV | `rdi, rsi, rdx, rcx, r8, r9` | `rax` |
| x86-64 Windows | `rcx, rdx, r8, r9` | `rax` |
| ARM64 | `x0–x7` | `x0` |
| RISC-V | `a0–a7` | `a0` |
| LoongArch | `a0–a7`（`r4–r11`） | `a0` |
| MIPS O32 | `a0–a3`（仅 4 个） | `v0` |

> 见到函数开头从这些寄存器取值、结尾往返回寄存器写值，即可逆推参数个数与返回路径。x86-64 两套 ABI 参数寄存器不同，逆向 Windows 程序别套用 Linux 习惯。

## 常见编译器代码模式

- **PLT / GOT（动态链接调用）**：调用外部函数表现为 `call <printf@plt>`；PLT 桩跳转经 GOT 间接寻址，首次调用经动态链接器惰性解析。`objdump -R` / `readelf -r` 可看 GOT 重定位。
- **跳转表（switch）**：稠密 `switch` 常编成索引间接跳转，x86 形如 `jmp *0x4010(,%rax,8)`——从地址表按索引取目标；识别它能快速还原多分支结构。
- **栈金丝雀（stack canary）**：x86-64 序言 `mov %fs:0x28, %rax` 从 TLS 取金丝雀存栈，返回前比对，不符则跳 `__stack_chk_fail`；ARM64 经 `TPIDR_EL0` 取值，套路类似。
- **PIC / PIE 取地址**：x86-64 用 RIP 相对 `lea sym(%rip), %rax`；取全局符号经 GOT：`mov sym@GOTPCREL(%rip), %rax`。RISC-V/LoongArch 用 `auipc`+偏移 / `pcalau12i` 等 PC 相对两步定位。
- **字符串引用**：`lea 0x...(%rip), %rsi` 指向 `.rodata`，多数反汇编器会自动把目标字符串注释在旁，是定位关键逻辑的抓手。

## GDB 动态分析速查

```text
gdb ./a.out
set disassembly-flavor intel   # x86 切 Intel 语法
disassemble main               # 反汇编函数（disas 简写）
disassemble /r main            # 附带原始字节
x/20i $pc                      # 查看 PC 处 20 条指令
break *0x401149                # 在地址处下断
info registers                 # 看寄存器（i r）
stepi / nexti                  # 单步一条指令（si / ni）
x/s 0x402004                   # 把地址当字符串看
info symbol 0x401149           # 地址 → 符号
layout asm                     # TUI 汇编视图（layout regs 看寄存器）
```

> 配合 `strace ./a.out`（跟踪系统调用）、`ltrace ./a.out`（跟踪库调用）做行为分析，比纯静态读更快定位关键路径。

## 跨架构反汇编与调试

```bash
# 在 x86 主机上跑/调异架构二进制（需 qemu-user）：
qemu-aarch64 ./arm_prog
qemu-riscv64 -g 1234 ./rv_prog &     # 启动 gdbstub，监听 1234
gdb-multiarch ./rv_prog
  (gdb) set arch riscv:rv64
  (gdb) target remote :1234           # 远程连上 QEMU，断点/单步外架构
```

- **Capstone**：多架构反汇编库（x86/ARM/MIPS/RISC-V/PPC/…），Python `pip install capstone` 即可写自定义反汇编脚本；其姊妹 **Keystone** 负责反向的多架构汇编。
- **Ghidra / radare2**：跨架构、带反编译（Ghidra 免费出伪 C），处理陌生架构时比单纯 `objdump` 高效得多。
