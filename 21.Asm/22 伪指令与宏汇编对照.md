# 伪指令与宏汇编对照

本页梳理「**伪指令 / 汇编器指示符 / 宏**」三层概念的区别，横向对照五大架构的常见伪指令，并解释**为什么 RISC 伪指令丰富、CISC 几乎不需要**——这与代码密度、定长 vs 变长编码一脉相承（见 [[21.Asm/30 各架构性能特性对比.md|性能特性对比]]）。

## 先分清三个概念

| 概念 | 英文 | 是否生成机器码 | 例子 |
|------|------|--------------|------|
| **伪指令** | pseudo-instruction | 是，展开为 1 条或多条真实指令 | RISC-V `li`/`mv`/`ret`、MIPS `move`、LoongArch `la.local` |
| **汇编器指示符** | directive | 否，控制汇编过程 | `.text`/`.global`/`.align`/`.word` |
| **宏** | macro | 是，展开为用户定义的指令序列 | GAS `.macro`、MASM/NASM 宏 |

- **伪指令**长得像指令，但 CPU 并不认识它，是汇编器替你翻译成真实指令的「便利助记符」。
- **指示符**（GAS 中以 `.` 开头）不产生指令，只告诉汇编器「往哪个段放、如何对齐、放什么数据」。
- **宏**是你自己定义的"指令模板"，调用时按参数展开。

## 五架构常见伪指令对照

| 意图 | RISC-V | MIPS | LoongArch | ARM64 | x86 |
|------|--------|------|-----------|-------|-----|
| 寄存器搬移 | `mv rd, rs` | `move rd, rs` | `move rd, rj` | `mov`（真实指令） | `mov`（真实指令） |
| 加载立即数 | `li rd, imm` | `li rd, imm` | `li.w`/`li.d rd, imm` | `mov`/`ldr =imm` | `mov`（真实指令） |
| 加载符号地址 | `la rd, sym` | `la rd, sym` | `la.local`/`la.global` | `ldr xN, =sym` / `adrp` | `lea`（真实指令） |
| 空操作 | `nop` | `nop` | `nop` | `nop`（真实指令） | `nop`（真实指令） |
| 无条件跳转 | `j off` | `b off` | `b off`（真实指令） | `b`（真实指令） | `jmp`（真实指令） |
| 函数返回 | `ret` | `jr $ra`（真实指令） | `ret` | `ret`（真实指令） | `ret`（真实指令） |
| 取反/求负 | `not`/`neg` | `not`/`neg` | —（用 `nor`/`sub`） | —（`mvn`/`neg` 真实） | `not`/`neg`（真实） |

> 一眼看出规律：**RISC-V / MIPS / LoongArch 的搬移、加载、返回大量靠伪指令**；x86 / ARM64 这些都是真实指令或直接 `mov`/`lea`。

### 典型展开（汇编器实际翻译）

```asm
# —— RISC-V ——
nop            →  addi x0, x0, 0
mv   a0, a1    →  addi a0, a1, 0
neg  a0, a1    →  sub  a0, x0, a1
not  a0, a1    →  xori a0, a1, -1
seqz a0, a1    →  sltiu a0, a1, 1
ret            →  jalr x0, 0(ra)
li   a0, 0x12345  →  lui a0, 0x12 ; addi a0, a0, 0x345   （视立即数可能多条）
la   a0, sym   →  auipc a0, %pcrel_hi(sym) ; addi a0, a0, %pcrel_lo(sym)
bgt  a0, a1, L →  blt  a1, a0, L            （交换操作数实现"大于"）
beqz a0, L     →  beq  a0, x0, L
```

```asm
# —— MIPS（$at=$1 是汇编器保留的临时寄存器，用于展开伪指令）——
move $a0, $a1  →  or    $a0, $a1, $zero      （或 addu）
nop            →  sll   $zero, $zero, 0      （编码恰为全 0）
li   $a0, big  →  lui   $a0, hi ; ori $a0, $a0, lo
bgt  $a0,$a1,L →  slt   $at, $a1, $a0 ; bne $at, $zero, L
```

```asm
# —— LoongArch ——
move $a0, $a1  →  or     $a0, $a1, $zero
nop            →  andi   $zero, $zero, 0
ret            →  jirl   $zero, $ra, 0
li.d $a0, imm  →  lu12i.w + ori + lu32i.d + lu52i.d  （按位段拼，最多四条）
la.local $a0,s →  pcalau12i $a0, %pc_hi20(s) ; addi.d $a0, $a0, %pc_lo12(s)
bgt  $a0,$a1,L →  blt    $a1, $a0, L          （与 RISC-V 同理，交换操作数）
```

```asm
# —— ARM64：传统"伪指令"少，但 ldr =立即数/符号 是经典一例 ——
ldr  x0, =0x123456789   →  汇编器把常量放入"文字池(literal pool)"，
                            再用 PC 相对 ldr 从池中加载
mov  x0, #0xFFFF0000     →  汇编器自动选 movz/movn/movk 序列
```

> **为什么 `bgt`/`ble` 常是伪指令**：RISC-V 基础分支只有 `beq/bne/blt/bge/bltu/bgeu` 六种，LoongArch 类似。「大于」「小于等于」通过**交换两个操作数**复用 `blt`/`bge` 实现，于是 `bgt`/`ble` 做成伪指令——这点在 [[21.Asm/13 LoongArch64.md|LoongArch]]、[[21.Asm/14 RISC-V.md|RISC-V]] 详解里也有提及。

## GAS 汇编器指示符速查（跨架构通用）

因五架构示例都用 GNU as，这些指示符通用：

| 类别 | 指示符 |
|------|--------|
| 段 | `.text` `.data` `.bss` `.rodata` `.section <名>` |
| 符号 | `.global`/`.globl` `.local` `.set`/`.equ` `.type` `.size` |
| 对齐 | `.align N` `.p2align N`（按 2^N） `.balign N`（按字节） |
| 数据 | `.byte`(1B) `.short`/`.hword`(2B) `.long`/`.int`(4B) `.quad`(8B) |
| 字符串 | `.ascii`（不含\0） `.asciz`/`.string`（含\0） |
| 填充 | `.space N` / `.skip N` / `.zero N` |
| 宏/重复 | `.macro`/`.endm` `.rept`/`.endr` `.irp` |
| 条件 | `.if` `.else` `.endif` |
| 包含 | `.include "f"` `.incbin "f"` |

> ⚠️ **`.word` 大小陷阱**：GAS 的 `.word` 是 **target-dependent**——在 **x86/x86-64 上是 2 字节**，在 **ARM/MIPS 等多数 RISC 上是 4 字节**。跨架构移植数据定义时，**优先用无歧义的 `.long`(4B) / `.quad`(8B)**，别赌 `.word` 的宽度。

## GAS 宏示例

```asm
# 定义一个"成对压栈"宏（ARM64），\参数 是宏形参
.macro push_pair r1, r2
    stp \r1, \r2, [sp, #-16]!
.endm

.macro pop_pair r1, r2
    ldp \r1, \r2, [sp], #16
.endm

# 使用：
    push_pair x19, x20      // 展开为 stp x19, x20, [sp, #-16]!
    pop_pair  x19, x20
```

> x86 世界的宏系统更为强大：**MASM**（Microsoft Macro Assembler）、**NASM** 提供条件汇编、`%rep` 重复、局部标号、`%macro` 变参等，历史上承担了 RISC 用伪指令解决的那部分"便利性"。

## 为什么 RISC 伪指令多、CISC 少？

1. **定长编码装不下大立即数/远地址**：RISC 指令固定 32 位，无法在一条里塞进 32/64 位常量或远跳转目标，必须拆成 `lui+addi`（RISC-V）、`lu12i.w+ori…`（LoongArch）等多条；`li`/`la` 伪指令把这种"拆装"复杂度对程序员隐藏起来。
2. **正交精简，常用操作没专门指令**：`mv`、`neg`、`not`、`nop`、`ret` 在 RISC 里都不是独立指令，而是用现有指令 + 约定寄存器（如 `x0`/`$zero`/`$ra`）组合，再用伪指令给个好记的名字。
3. **分支种类有限**：只提供等于/小于若干基础分支，`bgt`/`ble`/`beqz` 等靠交换操作数或与零比较的伪指令补全。
4. **CISC 反过来**：x86 变长编码可直接 `mov rax, 0x123456789`，`mov`/`lea` 万能，指令集本身丰富，几乎不需要指令级伪指令——复杂度转移到了**汇编器宏系统**与指示符上。

> 这正是 [[21.Asm/30 各架构性能特性对比.md|性能特性对比]] 中"代码密度 / 定长 vs 变长译码"的另一面：RISC 把复杂度交给**汇编器（编译期）**，CISC 把复杂度交给**译码器（运行期）**。

## 总结

- **伪指令 ≠ 真实指令**：它是汇编器的语法糖，最终展开为机器码；读反汇编时看到的是展开后的真实指令（见 [[21.Asm/33 逆向反汇编速查.md|逆向反汇编速查]]）。
- **指示符**控制汇编过程、不生成指令；**宏**是用户自定义的指令模板。
- RISC（RISC-V/MIPS/LoongArch）伪指令丰富，是定长编码 + 正交精简的必然结果；x86/ARM64 更多用真实指令与宏。
- 跨架构写数据时当心 `.word` 的宽度差异，用 `.long`/`.quad` 更稳。
