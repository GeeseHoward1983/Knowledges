# 异常 / 中断处理对比

本页横向对比五大架构的**异常与中断**机制——这是写操作系统内核、裸机固件、驱动时绕不开的特权级底层。重点看各家如何「进入异常（保存什么、跳到哪）→ 分发原因 → 返回」，以及 CISC（硬件包办）与 RISC（软件可控）的设计分野。

## 先分清：异常 vs 中断 vs 陷阱

| 术语 | 来源 | 同步性 | 例子 |
|------|------|--------|------|
| **异常**（exception / fault） | 指令执行内部触发 | **同步**（与指令绑定） | 除零、缺页、非法指令、地址非对齐 |
| **中断**（interrupt） | 外部设备 | **异步**（随时可来） | 定时器、键盘、网卡、核间中断 IPI |
| **陷阱**（trap / syscall） | 指令有意触发 | 同步 | 系统调用、断点 |

> 多数架构把三者统称为 **trap**，用同一套「保存现场→跳转处理→返回」框架，仅靠**原因寄存器**区分。下文用「异常」泛指这套机制。

## 五架构机制对照

| 维度 | x86-64 | ARM64 | RISC-V | LoongArch | MIPS |
|------|--------|-------|--------|-----------|------|
| 特权级 | Ring 0–3 | EL0–EL3 | M / S / U（可选 H） | PLV0–PLV3 | User/Sup/Kernel |
| 向量表机制 | **IDT**（256 门） | **VBAR_ELn**（16 入口） | `mtvec`/`stvec` | `EENTRY` | `EBase`/固定址 |
| 返回地址 | 压栈（RIP） | `ELR_ELn` | `mepc`/`sepc` | `ERA` | `EPC` |
| 原因 | 向量号 + 错误码 | `ESR_ELn`（EC 字段） | `mcause`/`scause` | `ESTAT`（Ecode） | `Cause`（ExcCode） |
| 故障地址 | `CR2`（缺页） | `FAR_ELn` | `mtval`/`stval` | `BADV` | `BadVAddr` |
| 状态保存 | RFLAGS 压栈 | `SPSR_ELn` | `mstatus`（MPP/MPIE） | `PRMD`（PPLV/PIE） | `Status`（EXL） |
| **返回指令** | `iret`/`sysret` | `eret` | `mret`/`sret` | `ertn` | `eret` |
| 系统调用 | `syscall` | `svc #0` | `ecall` | `syscall` | `syscall` |
| 中断控制器 | APIC / x2APIC | GIC | PLIC + CLINT | 扩展 I/O 中断 | 内置 + 外部 |

## 逐架构要点

### x86-64：IDT + 硬件自动压栈

- **IDT（中断描述符表）**：最多 256 个门描述符，`IDTR` 指向。向量 **0–31 为 CPU 预留异常**（#DE 除零=0、#UD 非法指令=6、#GP 一般保护=13、#PF 缺页=14…），**32–255** 为外部/软中断（`int n`）。
- **三类异常**：**Fault**（故障，可恢复，返回到出错指令重试，如缺页）、**Trap**（陷阱，返回到下一条，如断点）、**Abort**（中止，不可恢复）。
- 进入异常时**硬件自动压栈** SS、RSP、RFLAGS、CS、RIP（部分异常再压 error code）；缺页地址放 `CR2`。返回用 `iret`。
- **快速系统调用**：`syscall`/`sysret`（配合 MSR：LSTAR 存入口、STAR/SFMASK），绕开 IDT 开销。外部中断由 **APIC**（Local APIC + IO-APIC）管理。

### ARM64：按「类型×来源」分 16 个向量入口

- **异常级别 EL0–EL3**：EL0 用户、EL1 内核、EL2 hypervisor、EL3 安全监控（TrustZone）。
- **向量表**由 `VBAR_ELn` 指向，含 **16 个入口 = 4 类 × 4 来源**：
  - 4 类：**Synchronous、IRQ、FIQ、SError**；
  - 4 来源：当前 EL 用 SP_EL0 / 当前 EL 用 SP_ELx / 低 EL（AArch64）/ 低 EL（AArch32）。
  - 每入口 **128 字节**（可内联 32 条指令）。
- 关键寄存器：`ELR_ELn`（返回地址）、`SPSR_ELn`（保存的 PSTATE）、`ESR_ELn`（异常综合症，EC 字段编码原因）、`FAR_ELn`（故障地址）。
- 触发：`svc`→EL1、`hvc`→EL2、`smc`→EL3；返回用 **`eret`**（据 ELR+SPSR 恢复）。中断经 **GIC**（Generic Interrupt Controller）分发。

```asm
// ARM64 向量表布局：VBAR 要求 2KB(2^11) 对齐，每入口 128B(2^7)
.align 11
vectors:
    .align 7
    b   sync_curr_sp0      // +0x000 同步异常
    .align 7
    b   irq_curr_sp0       // +0x080 IRQ
    .align 7
    b   fiq_curr_sp0       // +0x100 FIQ
    .align 7
    b   serror_curr_sp0    // +0x180 SError
    // …余下 12 个入口同理（当前 EL SPx、低 EL AArch64/32）
```

### RISC-V：极简 CSR 驱动 + 中断委托

- **特权级 M/S/U**（可选 H/虚拟化）：M 必备（最高），S 跑 OS，U 用户态。
- **CSR 一族**：`mtvec`/`stvec`（向量基址，MODE 位选 **Direct**=所有 trap 到 BASE 或 **Vectored**=中断到 BASE+4×cause）、`mepc`/`sepc`（返回 PC）、`mcause`/`scause`（**最高位=1 表中断、=0 表异常**，低位为编码）、`mstatus`、`mtval`（故障地址/非法指令）、`mie`/`mip`（中断使能/挂起）、`mscratch`（暂存内核栈指针）。
- **中断委托** `medeleg`/`mideleg`：把指定异常/中断**直接下放给 S 模式**处理，免去每次都陷入 M 模式的开销——RISC-V 特有的灵活点。
- 触发：`ecall`（进更高特权级做系统调用）、`ebreak`；返回 **`mret`/`sret`**。中断控制器：**CLINT**（核内：软件 + 定时器中断）+ **PLIC**（平台级外部中断），新标准为 AIA。

```asm
# RISC-V trap 设置与分发骨架（M 模式，Direct）
    la      t0, trap_handler
    csrw    mtvec, t0           # 所有 trap 跳到 trap_handler
    ...
trap_handler:
    csrr    t0, mcause
    bltz    t0, handle_irq      # 最高位=1（负数）→ 中断
    # 否则为异常：csrr mepc/mtval 后按 mcause 低位分发
    ...
    mret                        # 据 mepc + mstatus 返回
```

### LoongArch：CSR 风格 + TLB 重填独立入口

- **特权级 PLV0–PLV3**（**PLV0 最高/内核，PLV3 最低/用户**，注意与某些资料方向相反，已核实）。
- **CSR 一族**（已对照官方/内核核实）：`CRMD`（当前模式：PLV 特权级、IE 中断使能）、`PRMD`（异常前模式：PPLV/PIE）、`EENTRY`（异常入口基址）、`ERA`（返回地址）、`ESTAT`（异常状态：Ecode 异常编码 + IS 中断状态域）、`BADV`（故障虚地址）、`ECFG`（异常配置/中断使能）、`SAVE0–15`（暂存）。
- **TLB 重填异常有独立入口 `TLBRENTRY`**（及独立的 TLBRBADV/TLBRERA/TLBRSAVE 等寄存器），机器错误异常另有 `MERRENTRY`——专用快路径，软件 TLB 管理更高效。
- 常见异常：**INT**（中断）、**ADEF**（取指地址错）、**ALE**（地址非对齐）、**SYS**（系统调用）、**BRK**（断点）、**INE**（指令不存在）等。
- 触发：`syscall`（系统调用异常）、`break`；返回 **`ertn`**——**原子地**把 PC 从 `ERA` 恢复、把 `PRMD` 的 PPLV/PIE 写回 `CRMD` 的 PLV/IE。

```asm
# LoongArch trap 骨架：CSR 编号 EENTRY=0xc, ESTAT=0x5, ERA=0x6
    la.local $t0, trap_entry
    csrwr    $t0, 0xc           # 写 EENTRY（异常入口）
    ...
trap_entry:
    csrrd    $t0, 0x5           # 读 ESTAT 判断 Ecode / IS 中断域
    ...                          # 按原因分发处理
    ertn                        # 原子恢复 PC←ERA, CRMD←PRMD
```

### MIPS：经典 CP0 + 延迟槽的 BD 位

- **特权级** User/Supervisor/Kernel（由 `Status.KSU` 控制）。
- 异常经**协处理器 0（CP0）** 管理：`EPC`（异常 PC）、`Cause`（原因，`ExcCode` 字段 + **`BD` 位**）、`Status`（`IE` 全局中断、`EXL` 异常级、`IM` 中断屏蔽）、`BadVAddr`（故障地址）、`EBase`（可重定位向量基址）。
- 异常向量经典为**固定地址**（通用异常 `0x80000180`、TLB 重填 `0x80000000`、中断 `0x80000200`），现代用 `EBase` 相对。返回用 **`eret`**；触发 `syscall`/`break`。**软件管理 TLB**（缺失即异常，软件填表）。
- **延迟槽的代价**：若异常发生在**分支延迟槽**中，`EPC` 指向**分支指令本身**（而非延迟槽指令），同时 `Cause.BD=1`，处理程序须特殊判断才能正确重启——这是分支延迟槽（见 [[21.Asm/23 调用约定对比.md|调用约定对比]]）渗入异常机制的额外复杂度。

## 关键设计差异

1. **硬件做多少**：x86 进入异常时**硬件自动压栈**丰富上下文（SS/RSP/RFLAGS/CS/RIP[+错误码]），CISC「硬件包办」；RISC（RISC-V/LoongArch/MIPS）只把返回地址、原因写进专用寄存器，**现场保存全靠软件**——精简、可控、便于定制。
2. **向量表结构**：x86 是 256 项按向量号索引的描述符表；ARM64 按「**异常类型 × 来源**」分 16 个 128 字节内联入口；RISC-V/LoongArch/MIPS 多为**单一入口**，软件读原因寄存器再分发（RISC-V 另支持向量化模式）。
3. **特权与委托**：ARM64 的 EL0–3 干净分离用户/内核/hypervisor/安全；RISC-V 用 `medeleg`/`mideleg` 把 trap **直接委托**给 S 模式，避免无谓陷入 M 模式。
4. **TLB 缺失谁来填**：x86/ARM 由**硬件** walk 页表重填 TLB；MIPS 用**软件**管理 TLB；LoongArch 折中——为 TLB 重填设**独立异常入口** `TLBRENTRY`，软件可控又走专用快路径。
5. **延迟槽再添乱**：MIPS 的 `Cause.BD` 是延迟槽渗入异常机制的典型负担，也是 ARM/RISC-V/LoongArch 弃用延迟槽的又一理由（参见 [[21.Asm/30 各架构性能特性对比.md|性能特性对比]]）。

## 中断控制器一览

| 架构 | 核内本地中断 | 外部/平台中断 |
|------|-------------|--------------|
| x86-64 | Local APIC（含定时器、IPI） | IO-APIC / MSI |
| ARM64 | （GIC 统一管理） | **GIC**（v2/v3/v4，含 ITS 处理 MSI） |
| RISC-V | **CLINT**（软件中断、定时器） | **PLIC**（外部中断）；新标准 AIA |
| LoongArch | 核内中断（软件/定时器/硬件） | 扩展 I/O 中断控制器 |
| MIPS | CP0 内置中断（`Cause.IP`） | 外部中断控制器 |

## 总结

- 五架构都遵循「**保存返回地址 + 原因 → 跳向量入口 → 软件分发 → 专用指令返回**」框架，差异在**硬件替你做多少**、**向量表怎么组织**、**特权级如何分层与委托**。
- 记返回指令最实用：x86 `iret`、ARM64/MIPS `eret`、RISC-V `mret`/`sret`、LoongArch `ertn`；系统调用对应 `syscall`/`svc`/`ecall`（见 [[21.Asm/32 HelloWorld示例.md|HelloWorld 示例]]）。
- RISC（尤其 RISC-V/LoongArch）走**极简 CSR 驱动 + 软件保存现场**路线，灵活可控；x86 走**硬件包办**路线，省心但定制空间小——这是 CISC/RISC 哲学在系统层的延续。
