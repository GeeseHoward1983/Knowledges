# 调试与性能剖析

本页对比五大架构的**硬件调试**（断点、观察点、单步）与**性能剖析**（PMU 性能计数器、指令 trace）支持——这是调试器、profiler、动态分析工具的底层依托。承接 [[21.Asm/30 各架构性能特性对比.md|30 性能特性]] 与 [[21.Asm/33 逆向反汇编速查.md|33 逆向速查]]。

## 软件断点 vs 硬件断点

| | 软件断点 | 硬件断点 |
|--|---------|---------|
| 原理 | 把目标指令**改写成陷阱指令** | 专用寄存器存地址，命中即陷入 |
| 数量 | 无限 | 有限（通常 2–8 个） |
| 限制 | 不能用于 ROM/只读；改代码 | 不改代码，可用于只读区、**数据观察点** |
| 指令 | `INT3`/`BRK`/`ebreak`/`break` | 调试寄存器 |

**软件断点陷阱指令**：x86 **`INT3`（单字节 `0xCC`，便于原地替换）**、ARM `BRK #imm`、RISC-V `ebreak`、LoongArch `break`、MIPS `break`。调试器把原指令首字节换成陷阱、命中后再换回（见 [[21.Asm/33 逆向反汇编速查.md|逆向速查]]）。

## 硬件断点 / 观察点寄存器对照

| 架构 | 断点（执行） | 观察点（数据读/写） | 状态/控制 |
|------|-------------|---------------------|----------|
| x86 | `DR0–DR3`（地址） | 同 `DR0–DR3`（`DR7` 选读/写/执行） | `DR6`(状态)/`DR7`(控制)，共 4 个 |
| ARM64 | `DBGBVR<n>`/`DBGBCR<n>` | `DBGWVR<n>`/`DBGWCR<n>` | 数量实现定义（常 6 断点+4 观察点） |
| RISC-V | trigger 模块 `tdata1/2`、`tselect` | 同 trigger（type 选） | 数量实现定义 |
| LoongArch | 取指观察点 `FWPC`/`FWPnCFG` | 访存观察点 `MWPC`/`MWPnCFG` | `MWPS`/`FWPS` 状态 |
| MIPS | EJTAG | `WatchLo`/`WatchHi` | CP0 |

> 核实要点：**LoongArch 调试相关 CSR 是 `DBG`（调试寄存器）、`DERA`（调试异常返回地址）、`DSAVE`（调试数据暂存）**——注意是 `DBG` 而非 RISC-V 的 `DCSR`；观察点分**访存（`MWPC`/`MWPnCFG`）** 与**取指（`FWPC`/`FWPnCFG`）** 两组。数据观察点（watchpoint）能在"某变量被写"时中断，是调试内存损坏的利器。

## 单步执行

| 架构 | 单步机制 |
|------|---------|
| x86 | `EFLAGS.TF`（Trap Flag）=1，每条指令后触发 #DB |
| ARM64 | `MDSCR_EL1.SS`（software step）+ `PSTATE.SS` |
| RISC-V | trigger 的 icount，或调试模式单步位 |
| LoongArch | 调试模式相关控制位 |
| MIPS | EJTAG 单步 |

> 单步是调试器 `stepi`（见 [[21.Asm/33 逆向反汇编速查.md|逆向速查]] 的 GDB 命令）的硬件基础：执行一条即陷回调试器。

## 性能监控单元（PMU）

PMU 用一组**性能计数器**统计微架构事件（周期、指令、cache 缺失、分支误预测…），是 profiler（`perf`、VTune）的核心：

| 架构 | 计数器 | 事件配置 | 周期/指令计数 |
|------|--------|---------|--------------|
| x86 | `PMC`（`rdpmc` 读） | `IA32_PERFEVTSEL` | `rdtsc`（时间戳）/ 固定计数器 |
| ARM64 | `PMEVCNTR<n>` | `PMEVTYPER<n>` + `PMCR_EL0` | `PMCCNTR_EL0`（周期） |
| RISC-V | `hpmcounter`/`mhpmcounter` | `mhpmevent<n>` | `cycle` / `instret` |
| LoongArch | **`PMCNT`** | **`PMCFG`** | （PMCFG 选事件） |
| MIPS | CP0 `PerfCnt` | CP0 `PerfCtl` | `Count` |

> 核实要点：**LoongArch 性能监控用 `PMCFG`（配置，选事件/使能）+ `PMCNT`（计数值）** 成对寄存器（手册 7.8 节）。典型事件：时钟周期、退休指令数、L1/L2 cache 缺失、TLB 缺失、分支误预测——这些直接对应 [[21.Asm/30 各架构性能特性对比.md|性能特性]] 里讨论的微架构瓶颈。

## 指令 Trace（高级剖析）

- **ARM CoreSight / ETM**：硬件指令/数据流追踪，重建完整执行轨迹。
- **Intel PT（Processor Trace）**：低开销记录控制流，事后重建每条分支，用于精确剖析与调试难复现 bug。
- RISC-V 有 **N-Trace / E-Trace** 规范；LoongArch 等也在完善 trace 能力。
- Trace 比采样式 PMU 更精确（不漏事件），但数据量大、需专用解码。

## 总结

- **软件断点**改指令为陷阱（`INT3`/`BRK`/`ebreak`/`break`），无限但不能用于只读区；**硬件断点/观察点**用专用寄存器，有限但能监视数据写、用于 ROM。
- 硬件调试寄存器：x86 `DR0–7`、ARM `DBGBVR/DBGWVR`、RISC-V trigger、**LoongArch `FWPC`/`MWPC` + `DBG`/`DERA`/`DSAVE`**。
- 性能剖析靠 PMU：x86 `PMC`、ARM `PMEVCNTR`、RISC-V `hpmcounter`、**LoongArch `PMCFG`/`PMCNT`**；更精确的全量追踪用 Intel PT / ARM ETM。
