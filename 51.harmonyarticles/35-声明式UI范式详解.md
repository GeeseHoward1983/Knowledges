## 🎯 什么是声明式UI?

**声明式UI**: 描述"UI应该是什么样子"，而不是"如何一步步构建UI"

```typescript
// ❌ 命令式UI（传统Android）
TextView textView = new TextView(context);
textView.setText("Hello");
textView.setTextColor(Color.RED);
textView.setTextSize(20);
layout.addView(textView);

// ✅ 声明式UI（ArkUI）
Text('Hello')
  .fontColor(Color.Red)
  .fontSize(20)
```

**核心理念**: **UI = f(State)**
- UI是状态的函数
- 状态变化 → UI自动更新
- 开发者只需关心数据，不需手动操作DOM

## 一、声明式 vs 命令式对比

### 1.1 命令式UI（传统方式）

**Android示例**:
```java
// ✅ 可运行代码
// 创建列表
ListView listView = new ListView(context);

// 创建Adapter
ArrayAdapter adapter = new ArrayAdapter(context, R.layout.item, dataList);
listView.setAdapter(adapter);

// 数据更新时，手动刷新
dataList.add("新数据");
adapter.notifyDataSetChanged();

// 修改样式
listView.setBackgroundColor(Color.WHITE);
listView.setPadding(16, 16, 16, 16);
```

**问题**:
- 🔴 代码冗长，可读性差
- 🔴 需要手动管理UI状态
- 🔴 容易出现状态不一致
- 🔴 难以维护和测试

---

### 1.2 声明式UI（现代方式）

**ArkUI示例**:
```typescript
// ✅ 可运行代码
@Component
struct UserList {
  @State dataList: string[] = ['Alice', 'Bob', 'Charlie']

  build() {
    List() {
      ForEach(this.dataList, (item: string) => {
        ListItem() {
          Text(item)
        }
      })
    }
    .backgroundColor(Color.White)
    .padding(16)
  }

  addUser() {
    this.dataList.push('新用户')  // ✅ 数据变化，UI自动更新
  }
}
```

**优势**:
- ✅ 代码简洁，可读性强
- ✅ 自动管理UI状态
- ✅ 数据驱动，状态一致
- ✅ 易于维护和测试

### 2.2 单向数据流

```typescript
// ✅ 可运行代码

         ↓

         ↓
```

## 三、@Component装饰器原理

### 3.1 @Component的作用

```typescript
// ✅ 可运行代码
@Component  // 声明这是一个UI组件
struct MyButton {
  @Prop text: string  // 接收外部传入的属性

  build() {
    // 必须实现build()方法
    Button(this.text)
  }
}

// 使用
MyButton({ text: '点击我' })
```

**@Component做了什么**:
1. **注册组件**: 将组件注册到ArkUI框架
2. **生命周期管理**: 自动管理aboutToAppear、aboutToDisappear等
3. **状态监听**: 自动监听@State/@Prop变化
4. **优化渲染**: 启用虚拟DOM和Diff算法

---

### 3.2 组件生命周期

```typescript
// ✅ 可运行代码
@Component
struct LifecycleDemo {
  @State message: string = 'Hello'

  // 1. 组件即将出现
  aboutToAppear() {
    console.log('组件创建')
    // 初始化数据、订阅事件
  }

  // 2. 组件即将消失
  aboutToDisappear() {
    console.log('组件销毁')
    // 清理资源、取消订阅
  }

  // 3. 页面显示
  onPageShow() {
    console.log('页面显示')
  }

  // 4. 页面隐藏
  onPageHide() {
    console.log('页面隐藏')
  }

  build() {
    Text(this.message)
  }
}
```

**生命周期流程**:
```typescript
// ✅ 可运行代码
创建 → aboutToAppear → build → 显示
                                 ↓
                              onPageShow
                                 ↓
                              运行中
                                 ↓
                              onPageHide
                                 ↓
                         aboutToDisappear → 销毁
```

## 四、@Builder装饰器原理

### 4.1 @Builder的作用

**抽取可复用的UI片段**:

```typescript
// ✅ 可运行代码
@Component
struct BuilderDemo {
  @State isVip: boolean = true

  // ✅ 使用@Builder抽取公共UI
  @Builder
  UserCard(name: string, avatar: string) {
    Row() {
      Image(avatar)
        .width(50)
        .height(50)
        .borderRadius(25)

      Column() {
        Text(name)
          .fontSize(16)
          .fontWeight(FontWeight.Bold)

        if (this.isVip) {
          Text('VIP会员')
            .fontSize(12)
            .fontColor(Color.Gold)
        }
      }
      .alignItems(HorizontalAlign.Start)
      .margin({ left: 10 })
    }
    .padding(10)
  }

  build() {
    Column() {
      this.UserCard('张三', '/images/avatar1.png')
      this.UserCard('李四', '/images/avatar2.png')
      this.UserCard('王五', '/images/avatar3.png')
    }
  }
}
```

## 五、虚拟DOM与Diff算法

### 5.1 虚拟DOM原理

**虚拟DOM**: UI的JavaScript对象表示

```typescript
// ✅ 可运行代码
// 真实UI
Text('Hello')
  .fontSize(16)
  .fontColor(Color.Red)

// 对应的虚拟DOM（简化）
{
  type: 'Text',
  props: {
    content: 'Hello',
    fontSize: 16,
    fontColor: Color.Red
  }
}
```

---

### 5.2 Diff算法

**更新流程**:
```typescript
// ✅ 可运行代码
旧虚拟DOM         新虚拟DOM
    ↓                 ↓
    └─────> Diff算法 <─┘
                ↓
           最小变更集
                ↓
           更新真实UI
```

**示例**:
```typescript
// ✅ 可运行代码
@Component
struct TodoList {
  @State todos: string[] = ['任务1', '任务2', '任务3']

  build() {
    List() {
      ForEach(this.todos, (todo: string, index: number) => {
        ListItem() {
          Text(todo)
        }
      }, (todo: string, index: number) => index.toString())  // key函数
    }
  }

  addTodo() {
    // 添加新任务
    this.todos.push('任务4')

    // Diff算法:
    // 1. 对比旧虚拟DOM和新虚拟DOM
    // 2. 发现只增加了一个ListItem
    // 3. 只渲染新增的ListItem，不重新渲染整个列表
  }
}
```

**key的重要性**:
```typescript
// ❌ 没有key（低效）
ForEach(this.todos, (todo: string) => {
  ListItem() {
    Text(todo)
  }
})
// 数据变化时，无法高效复用组件

// ✅ 有key（高效）
ForEach(this.todos, (todo: string, index: number) => {
  ListItem() {
    Text(todo)
  }
}, (todo: string, index: number) => todo.id)
// 根据唯一ID复用组件
```

## 六、状态驱动视图更新

### 6.1 响应式原理

```typescript
// ✅ 可运行代码
@Component
struct ReactiveDemo {
  @State user: User = { name: '张三', age: 25 }

  build() {
    Column() {
      // UI依赖state
      Text(`姓名: ${this.user.name}`)
      Text(`年龄: ${this.user.age}`)

      Button('修改')
        .onClick(() => {
          // 修改state → 自动触发UI更新
          this.user = { name: '李四', age: 30 }

          // 内部原理:
          // 1. @State装饰器拦截赋值操作
          // 2. 标记组件为"脏"（dirty）
          // 3. 触发重渲染
          // 4. Diff算法对比
          // 5. 更新变化的部分
        })
    }
  }
}
```

---

### 6.2 深层对象更新

```typescript
// ✅ 可运行代码
@Observed
class User {
  name: string = ''
  age: number = 0
}

@Component
struct DeepUpdate {
  @State user: User = new User()

  build() {
    Column() {
      Text(`${this.user.name}, ${this.user.age}岁`)

      Button('修改属性')
        .onClick(() => {
          // ❌ 错误：直接修改属性不会触发更新
          // this.user.age = 30

          // ✅ 方法1：重新赋值整个对象
          this.user = { ...this.user, age: 30 }

          // ✅ 方法2：使用@Observed + @ObjectLink
          // 见下一章"状态管理"
        })
    }
  }
}
```

## 七、性能优化机制

### 7.1 懒加载（LazyForEach）

```typescript
// ✅ 可运行代码
class MyDataSource implements IDataSource {
  private list: string[] = []

  constructor(list: string[]) {
    this.list = list
  }

  totalCount(): number {
    return this.list.length
  }

  getData(index: number): string {
    return this.list[index]
  }

  registerDataChangeListener(listener: DataChangeListener): void {}
  unregisterDataChangeListener(listener: DataChangeListener): void {}
}

@Component
struct LazyList {
  private data: MyDataSource = new MyDataSource(
    Array.from({ length: 10000 }, (_, i) => `Item ${i}`)
  )

  build() {
    List() {
      // ✅ 懒加载：只渲染可见区域
      LazyForEach(this.data, (item: string, index: number) => {
        ListItem() {
          Text(item)
            .height(50)
        }
      }, (item: string, index: number) => index.toString())
    }
  }
}
```

**性能对比**:
- `ForEach`: 10000项 → 渲染10000个组件 → 卡顿
- `LazyForEach`: 10000项 → 只渲染可见的20项 → 流畅

---

### 7.2 避免过度渲染

```typescript
// ✅ 可运行代码
@Component
struct Parent {
  @State parentState: number = 0

  build() {
    Column() {
      Text(`父组件: ${this.parentState}`)

      // ❌ 错误：父组件状态变化，子组件也重渲染
      Child1()

      // ✅ 正确：传递状态，只在状态变化时重渲染
      Child2({ count: this.parentState })

      Button('更新父组件')
        .onClick(() => {
          this.parentState++
        })
    }
  }
}

@Component
struct Child1 {
  build() {
    Text('子组件1')
      .onAppear(() => {
        console.log('Child1重渲染')  // 每次都会执行
      })
  }
}

@Component
struct Child2 {
  @Prop count: number

  build() {
    Text(`子组件2: ${this.count}`)
      .onAppear(() => {
        console.log('Child2重渲染')  // 只在count变化时执行
      })
  }
}
```

## 📌 本章总结

### 核心要点

1. **声明式UI**: UI = f(State)，数据驱动视图
2. **@Component**: 声明组件，自动管理生命周期
3. **@Builder**: 抽取可复用UI片段
4. **虚拟DOM**: 提升渲染性能，最小化DOM操作
5. **响应式**: 状态变化自动触发UI更新
6. **性能优化**: LazyForEach、key、避免过度渲染

### 设计哲学

- **数据驱动**: 关注数据，UI自动更新
- **组件化**: 可复用、可组合、可测试
- **单向数据流**: 状态 → UI，逻辑清晰
- **性能优先**: 虚拟DOM、Diff算法、懒加载
