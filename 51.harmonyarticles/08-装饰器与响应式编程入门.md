## 引言：为什么需要装饰器？

如果你写过Vue或React,一定遇到过这样的痛点：

```typescript
// ✅ 可运行代码
// 传统方式：手动管理状态更新
class Counter {
  count: number = 0

  increment() {
    this.count++
    // 😓 需要手动触发UI更新
    this.updateUI()
  }

  updateUI() {
    // 找到DOM元素,手动更新...
  }
}
```

**问题**:
- ❌ 状态变化与UI更新分离,容易遗漏
- ❌ 样板代码多,影响开发效率
- ❌ 难以追踪数据流向

**ArkTS的解决方案 - 装饰器**:

```typescript
// ✅ 可运行代码
@Component
struct Counter {
  @State count: number = 0  // ✅ 自动追踪变化

  build() {
    Column() {
      Text(`${this.count}`)  // ✅ 自动更新UI
      Button('加1')
        .onClick(() => this.count++)  // ✅ 直接修改
    }
  }
}
```

**装饰器带来的变化**:
- ✅ **自动追踪**: 修改`count`自动触发UI刷新
- ✅ **代码简洁**: 无需手动调用更新函数
- ✅ **类型安全**: 编译时检查,避免运行时错误

## 1. 装饰器基础：语法与原理

### 装饰器编译时转换原理

```mermaid
sequenceDiagram
    participant Dev as 开发者代码
    participant Compiler as ArkTS编译器
    participant Runtime as 运行时代码

    Dev->>Compiler: @State count: number = 0
    Note over Compiler: 编译时转换

    Compiler->>Compiler: 生成getter/setter
    Compiler->>Compiler: 注入依赖追踪代码
    Compiler->>Compiler: 生成更新通知逻辑

    Compiler->>Runtime: 转换后的代码:<br/>private __count: number<br/>get count()<br/>set count(value)

    Note over Runtime: 运行时行为
    Runtime->>Runtime: count++ 触发setter
    Runtime->>Runtime: 记录依赖关系
    Runtime->>Runtime: 通知UI更新

    style Compiler fill:#4dabf7,stroke:#1971c2,color:#fff
    style Runtime fill:#51cf66,stroke:#2f9e44,color:#fff
```

### 1.1 什么是装饰器？

装饰器是一种**特殊的声明**,附加在类、方法、属性上,**在编译时修改其行为**。

**类比理解**:
> 装饰器就像给房子安装"智能家居系统" - 原本需要手动开关灯,装上智能系统后,灯会根据人进入房间自动开启。

### 1.2 装饰器的基本语法

```typescript
// ✅ 可运行代码
// 1. 类装饰器
@Component  // 标记这是一个UI组件
struct MyComponent {
  build() { /* ... */ }
}

// 2. 属性装饰器
@State count: number = 0       // 状态变量
@Prop title: string            // 父组件传递的属性

// 3. 方法装饰器
@Concurrent  // 标记可并发执行的函数
async function heavyTask() { /* ... */ }

// 4. 结构体装饰器
@Observed  // 标记可观察的类
class Person {
  name: string = ''
}
```

### 1.3 装饰器的编译时转换

**源代码**:
```typescript
// ✅ 可运行代码
@Component
struct Counter {
  @State count: number = 0

  build() {
    Text(`${this.count}`)
  }
}
```

**编译后（简化）**:
```typescript
// ✅ 可运行代码
class Counter {
  private __count: number = 0
  private __updateFlag: boolean = false

  // Getter添加依赖收集
  get count(): number {
    registerDependency(this, 'count')  // 🔍 追踪访问
    return this.__count
  }

  // Setter添加变更通知
  set count(value: number) {
    if (this.__count !== value) {
      this.__count = value
      this.__updateFlag = true
      scheduleUpdate(this)  // 🔔 触发更新
    }
  }

  build() {
    return Text(`${this.count}`)  // 触发getter
  }
}
```

**核心机制**:
1. **依赖收集**: `getter`记录哪些组件访问了这个状态
2. **变更通知**: `setter`触发时,通知所有依赖组件更新
3. **脏检查优化**: 只有值真正改变才触发更新

## 2. 状态装饰器家族

### 2.1 @State：组件内部状态

**用途**: 管理组件自己的可变状态

```typescript
// ✅ 可运行代码
@Component
struct TodoList {
  @State tasks: string[] = ['学习ArkTS', '写代码']

  build() {
    Column() {
      ForEach(this.tasks, (task: string) => {
        Text(task)
      })

      Button('添加任务')
        .onClick(() => {
          // ✅ 数组变化会触发UI更新
          this.tasks.push('新任务')
        })
    }
  }
}
```

**特性**:
- ✅ **私有性**: 只能在当前组件内修改
- ✅ **响应式**: 修改后自动触发`build()`重新执行
- ⚠️ **浅层监听**: 对于对象/数组,只监听引用变化

**深层对象更新问题**:
```typescript
@State user: { name: string } = { name: '张三' }

// ❌ 不会触发更新（引用未变）
this.user.name = '李四'

// ✅ 正确方式1：替换整个对象
this.user = { name: '李四' }

// ✅ 正确方式2：使用@Observed（后续讲解）
```

### 2.2 @Prop：单向数据流

**用途**: 接收父组件传递的只读属性

```typescript
// ✅ 可运行代码
// 父组件
@Component
struct Parent {
  @State count: number = 0

  build() {
    Column() {
      Child({ count: this.count })  // 传递状态
      Button('父组件+1')
        .onClick(() => this.count++)
    }
  }
}

// 子组件
@Component
struct Child {
  @Prop count: number  // 接收父组件数据

  build() {
    Text(`子组件显示: ${this.count}`)
      .onClick(() => {
        // ❌ 编译错误：不能修改@Prop
        // this.count++
      })
  }
}
```

**工作流程**:
1. 父组件的`@State`变化
2. 自动传递给子组件的`@Prop`
3. 子组件UI重新渲染

**单向数据流的好处**:
- ✅ **数据流向清晰**: 只能父→子,不会反向污染
- ✅ **调试友好**: 状态变化路径可追踪
- ✅ **性能优化**: 只有必要时才触发子组件更新

### 2.3 @Link：双向绑定

**用途**: 父子组件共享可变状态

```typescript
// ✅ 可运行代码
// 父组件
@Component
struct Parent {
  @State count: number = 0

  build() {
    Column() {
      Child({ count: $count })  // 使用$传递引用
      Text(`父组件: ${this.count}`)
    }
  }
}

// 子组件
@Component
struct Child {
  @Link count: number  // 双向绑定

  build() {
    Button(`子组件+1 (当前${this.count})`)
      .onClick(() => {
        this.count++  // ✅ 修改会同步到父组件
      })
  }
}
```

**关键点**:
- 传递时使用`$`符号: `Child({ count: $count })`
- 父子组件共享同一份数据
- 任意一方修改都会同步

**使用场景**:
- 表单输入框双向绑定
- 多个组件需要同步修改同一状态
- 子组件需要"向上"通知父组件

### 2.4 装饰器对比表

| 装饰器 | 可修改性 | 数据流向 | 使用场景 |
|--------|----------|----------|----------|
| `@State` | ✅ 可修改 | 组件内部 | 组件自身状态 |
| `@Prop` | ❌ 只读 | 父→子 | 展示型组件 |
| `@Link` | ✅ 可修改 | 父⇄子 | 需要同步的状态 |
| `@Provide` | ✅ 可修改 | 祖先→后代 | 跨层级传递 |
| `@Consume` | ✅ 可修改 | 接收@Provide | 深层组件访问 |

## 3. 响应式编程思想

### 3.1 什么是响应式编程？

**传统命令式编程**:
```typescript
// ✅ 可运行代码
let a = 1
let b = 2
let c = a + b  // c = 3

a = 10
console.log(c)  // ❌ 仍然是3,需要手动重新计算
```

**响应式编程**:
```typescript
// ✅ 可运行代码
@Component
struct Calculator {
  @State a: number = 1
  @State b: number = 2

  // c会"响应" a和b的变化
  get c(): number {
    return this.a + this.b
  }

  build() {
    Column() {
      Text(`${this.c}`)  // 自动更新
      Button('a+1').onClick(() => this.a++)
    }
  }
}
```

**核心思想**:
> **数据变化自动驱动视图更新**, 开发者只需声明"数据与UI的关系",无需手动管理更新逻辑。

### 3.2 依赖追踪原理

**响应式系统的三个核心部分**:

```typescript
// ✅ 可运行代码
// 1. 依赖收集器
class Dep {
  subscribers: Set<Component> = new Set()

  depend(component: Component) {
    this.subscribers.add(component)  // 记录依赖
  }

  notify() {
    this.subscribers.forEach(comp => comp.update())  // 通知更新
  }
}

// 2. 响应式对象
function reactive(obj: any) {
  const dep = new Dep()

  return new Proxy(obj, {
    get(target, key) {
      dep.depend(currentComponent)  // 🔍 收集依赖
      return target[key]
    },
    set(target, key, value) {
      target[key] = value
      dep.notify()  // 🔔 触发更新
      return true
    }
  })
}

// 3. 组件更新调度器
function scheduleUpdate(component: Component) {
  // 批量更新,避免重复渲染
  nextTick(() => component.build())
}
```

**实际运行流程**:

```typescript
// ✅ 可运行代码
@Component
struct App {
  @State count: number = 0  // 创建响应式Proxy

  build() {
    // 1. 执行build时,访问this.count
    // 2. 触发Proxy的get,记录"App依赖count"
    Text(`${this.count}`)

    Button('加1')
      .onClick(() => {
        // 3. 修改count
        this.count++
        // 4. 触发Proxy的set
        // 5. 找到所有依赖count的组件(App)
        // 6. 调度App.build()重新执行
      })
  }
}
```

### 3.3 批量更新与性能优化

**问题**: 如果短时间内多次修改状态,会触发多次渲染吗？

```typescript
// ✅ 可运行代码
@State count: number = 0

this.count++  // 触发更新？
this.count++  // 又触发更新？
this.count++  // 再触发更新？
```

**ArkTS的优化策略**:

```typescript
// ✅ 可运行代码
class UpdateScheduler {
  private pendingUpdates: Set<Component> = new Set()
  private isScheduled: boolean = false

  scheduleUpdate(component: Component) {
    this.pendingUpdates.add(component)  // 收集待更新组件

    if (!this.isScheduled) {
      this.isScheduled = true
      // 使用微任务队列,在同步代码执行完后统一更新
      queueMicrotask(() => {
        this.flush()
      })
    }
  }

  flush() {
    this.pendingUpdates.forEach(comp => comp.update())
    this.pendingUpdates.clear()
    this.isScheduled = false
  }
}
```

**效果**:
```typescript
// ✅ 可运行代码
this.count++  // 标记需要更新
this.count++  // 复用标记
this.count++  // 复用标记
// 同步代码执行完毕后,只触发一次build()
```

## 4. 高级装饰器

### 4.1 @Observed与@ObjectLink

**问题**: `@State`只监听对象引用,不监听内部属性变化

```typescript
@State user: User = new User()

// ❌ 不会触发更新
this.user.name = '新名字'
```

**解决方案**: 使用`@Observed`标记类

```typescript
// ✅ 可运行代码
// 1. 标记类为可观察
@Observed
class User {
  name: string = '张三'
  age: number = 18
}

@Component
struct Parent {
  @State user: User = new User()

  build() {
    Column() {
      // 2. 使用@ObjectLink传递
      Child({ user: this.user })
    }
  }
}

@Component
struct Child {
  @ObjectLink user: User  // 深度监听

  build() {
    Column() {
      Text(this.user.name)
      Button('改名')
        .onClick(() => {
          // ✅ 现在可以触发更新
          this.user.name = '李四'
        })
    }
  }
}
```

**工作原理**:
- `@Observed`将类的所有属性转为响应式
- `@ObjectLink`建立深度依赖追踪
- 任何属性变化都会触发UI更新

### 4.2 @Provide与@Consume

**用途**: 跨层级传递数据,避免"属性透传地狱"

**传统方式的痛点**:
```typescript
// ✅ 可运行代码
// 😓 需要一层层传递
Parent({ theme: this.theme })
  -> Child({ theme: this.theme })
    -> GrandChild({ theme: this.theme })
      -> DeepChild({ theme: this.theme })
```

**使用@Provide/@Consume**:
```typescript
// ✅ 可运行代码
// 祖先组件
@Component
struct Parent {
  @Provide theme: string = 'dark'  // 提供数据

  build() {
    Child()  // 不需要传递
  }
}

// 中间组件（无需处理theme）
@Component
struct Child {
  build() {
    GrandChild()
  }
}

// 深层组件
@Component
struct GrandChild {
  @Consume theme: string  // 直接消费数据

  build() {
    Text('当前主题: ' + this.theme)
  }
}
```

**特性**:
- ✅ 跳过中间组件,直接传递
- ✅ 双向绑定,深层组件可修改
- ✅ 自动追踪依赖

### 4.3 @Concurrent：并发编程

**用途**: 标记可在TaskPool中并发执行的函数

```typescript
// ✅ 可运行代码
// 普通函数（只能主线程执行）
function heavyTask(data: number[]): number {
  return data.reduce((a, b) => a + b, 0)
}

// 并发函数（可在工作线程执行）
@Concurrent
function concurrentTask(data: number[]): number {
  return data.reduce((a, b) => a + b, 0)
}

// 使用
import taskpool from '@ohos.taskpool'

async function processData() {
  const data = Array.from({ length: 1000000 }, (_, i) => i)

  // ✅ 在后台线程执行,不阻塞UI
  const result = await taskpool.execute(concurrentTask, data)
  console.log(result)
}
```

**限制**:
- ❌ 不能访问UI相关API
- ❌ 不能捕获外部变量（闭包）
- ✅ 可以传递基础类型和Sendable对象

## 5. 实战案例：待办事项应用

### 5.1 需求分析

**功能**:
- 添加/删除任务
- 标记任务完成
- 统计未完成任务数量
- 支持优先级排序

### 5.2 数据模型

```typescript
// ✅ 可运行代码
@Observed
class Task {
  id: number
  title: string
  completed: boolean
  priority: number  // 1-3

  constructor(title: string, priority: number = 2) {
    this.id = Date.now()
    this.title = title
    this.completed = false
    this.priority = priority
  }
}

@Observed
class TodoStore {
  tasks: Task[] = []

  // 添加任务
  addTask(title: string, priority: number = 2) {
    this.tasks.push(new Task(title, priority))
  }

  // 删除任务
  removeTask(id: number) {
    const index = this.tasks.findIndex(t => t.id === id)
    if (index > -1) {
      this.tasks.splice(index, 1)
    }
  }

  // 切换完成状态
  toggleTask(id: number) {
    const task = this.tasks.find(t => t.id === id)
    if (task) {
      task.completed = !task.completed
    }
  }

  // 未完成任务数
  get pendingCount(): number {
    return this.tasks.filter(t => !t.completed).length
  }

  // 按优先级排序
  get sortedTasks(): Task[] {
    return [...this.tasks].sort((a, b) => a.priority - b.priority)
  }
}
```

### 5.3 主界面组件

```typescript
// ✅ 可运行代码
@Component
struct TodoApp {
  @State store: TodoStore = new TodoStore()
  @State newTaskTitle: string = ''
  @State newTaskPriority: number = 2

  build() {
    Column({ space: 16 }) {
      // 标题栏
      Text('待办事项')
        .fontSize(24)
        .fontWeight(FontWeight.Bold)

      // 统计
      Text(`未完成: ${this.store.pendingCount} / ${this.store.tasks.length}`)
        .fontSize(14)
        .fontColor('#666')

      // 添加任务输入框
      Row({ space: 8 }) {
        TextInput({ placeholder: '新任务标题' })
          .layoutWeight(1)
          .onChange(value => this.newTaskTitle = value)

        // 优先级选择
        Select([
          { value: '低', label: '低优先级' },
          { value: '中', label: '中优先级' },
          { value: '高', label: '高优先级' }
        ])
          .selected(1)
          .onSelect(index => this.newTaskPriority = index + 1)

        Button('添加')
          .onClick(() => {
            if (this.newTaskTitle.trim()) {
              this.store.addTask(this.newTaskTitle, this.newTaskPriority)
              this.newTaskTitle = ''
            }
          })
      }

      // 任务列表
      List({ space: 8 }) {
        ForEach(this.store.sortedTasks, (task: Task) => {
          ListItem() {
            TaskItem({ task: task, store: this.store })
          }
        }, (task: Task) => task.id.toString())
      }
      .layoutWeight(1)
    }
    .padding(16)
    .width('100%')
    .height('100%')
  }
}
```

### 5.4 任务项组件

```typescript
// ✅ 可运行代码
@Component
struct TaskItem {
  @ObjectLink task: Task  // 深度监听Task对象
  @Link store: TodoStore

  build() {
    Row({ space: 12 }) {
      // 完成状态复选框
      Checkbox()
        .select(this.task.completed)
        .onChange(checked => {
          this.store.toggleTask(this.task.id)
        })

      // 任务标题
      Text(this.task.title)
        .fontSize(16)
        .decoration({
          type: this.task.completed ? TextDecorationType.LineThrough : TextDecorationType.None
        })
        .fontColor(this.task.completed ? '#999' : '#333')
        .layoutWeight(1)

      // 优先级标签
      Text(this.getPriorityText())
        .fontSize(12)
        .fontColor('#fff')
        .padding({ left: 8, right: 8, top: 4, bottom: 4 })
        .borderRadius(4)
        .backgroundColor(this.getPriorityColor())

      // 删除按钮
      Button('删除')
        .fontSize(14)
        .type(ButtonType.Normal)
        .backgroundColor('#ff4d4f')
        .onClick(() => {
          this.store.removeTask(this.task.id)
        })
    }
    .width('100%')
    .padding(12)
    .backgroundColor('#f5f5f5')
    .borderRadius(8)
  }

  getPriorityText(): string {
    return ['高', '中', '低'][this.task.priority - 1]
  }

  getPriorityColor(): string {
    return ['#ff4d4f', '#faad14', '#52c41a'][this.task.priority - 1]
  }
}
```

## 6. 最佳实践

### 6.1 选择合适的装饰器

```typescript
// ✅ 可运行代码
// ✅ 组件私有状态用@State
@State counter: number = 0

// ✅ 父组件传递只读数据用@Prop
@Prop title: string

// ✅ 父子共享可变数据用@Link
@Link selectedIndex: number

// ✅ 跨层级传递用@Provide/@Consume
@Provide theme: string
@Consume theme: string

// ✅ 嵌套对象用@Observed/@ObjectLink
@Observed class User {}
@ObjectLink user: User
```

### 6.2 避免过度使用@State

**❌ 错误示例**:
```typescript
// ✅ 可运行代码
@State temp1: string = ''  // 临时变量不需要响应式
@State temp2: number = 0
@State cacheData: any = null  // 缓存数据不需要响应式
```

**✅ 正确方式**:
```typescript
// ✅ 可运行代码
private temp1: string = ''  // 普通属性
private temp2: number = 0
private cacheData: any = null

@State uiData: Data = new Data()  // 只有影响UI的数据才用@State
```

### 6.3 性能优化技巧

**1. 使用不可变更新**

```typescript
// ❌ 慢：直接修改数组
this.tasks[0].title = '新标题'  // 需要深度对比

// ✅ 快：替换整个数组
this.tasks = this.tasks.map(t =>
  t.id === targetId ? { ...t, title: '新标题' } : t
)
```

**2. 拆分大组件**

```typescript
// ❌ 一个大组件，任何状态变化都重新渲染全部
@Component
struct BigComponent {
  @State data1: Data1
  @State data2: Data2
  @State data3: Data3

  build() {
    Column() {
      // 大量UI代码
    }
  }
}

// ✅ 拆分成小组件，精确控制更新范围
@Component
struct SmallComponent1 {
  @Prop data1: Data1  // 只依赖data1
  build() { /* ... */ }
}
```

**3. 使用计算属性代替方法**

```typescript
// ❌ 每次build都调用方法
Text(this.getDisplayText())

// ✅ 使用getter，自动缓存
get displayText(): string {
  return this.tasks.filter(t => !t.completed).length.toString()
}
Text(this.displayText)
```

## 7. 常见问题

### Q1: @State修改对象属性不更新？

**问题**:
```typescript
@State user: User = { name: '张三' }
this.user.name = '李四'  // ❌ UI不更新
```

**解决方案**:
```typescript
// ✅ 可运行代码
// 方案1：替换整个对象
this.user = { ...this.user, name: '李四' }

// 方案2：使用@Observed/@ObjectLink
@Observed class User { name: string }
@ObjectLink user: User
```

### Q2: @Link传递时报错？

**问题**:
```typescript
Child({ data: this.data })  // ❌ 类型不匹配
```

**解决**:
```typescript
// ✅ 可运行代码
Child({ data: $data })  // ✅ 使用$符号传递引用
```

### Q3: 多个状态同时变化，会渲染几次？

**答案**: 只渲染1次

ArkTS会**批量更新**，在同步代码执行完后统一渲染。
