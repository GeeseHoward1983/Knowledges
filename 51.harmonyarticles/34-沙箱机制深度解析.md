## 🎯 什么是沙箱机制?

**沙箱（Sandbox）** 是鸿蒙的核心安全机制，为每个应用提供**隔离的文件存储空间**：

```typescript
// ✅ 可运行代码
应用A沙箱                应用B沙箱
┌───────────┐          ┌───────────┐
│ /data/    │          │ /data/    │
│ /cache/   │  ❌隔离  │ /cache/   │
│ /files/   │          │ /files/   │
└───────────┘          └───────────┘
     ↑                       ↑
   只能访问              只能访问
   自己的目录            自己的目录
```

**核心价值**:
- 🔒 **数据隔离**: 应用无法访问其他应用数据
- 🛡️ **安全防护**: 防止恶意应用窃取用户数据
- 📁 **规范管理**: 统一的文件组织结构
- 🚫 **权限控制**: 分级访问控制

### 1.2 沙箱隔离原理

**隔离机制**:
1. **命名空间隔离**: 每个应用看到的文件系统视图不同
2. **路径重映射**: 应用内的`/data/`实际指向`/data/app/el2/bundle/<bundleName>/`
3. **权限检查**: 内核级别阻止跨沙箱访问

**示例**:
```typescript
// ✅ 可运行代码
// 应用A中
const path = '/data/storage/el2/base/files/data.txt'

// 实际物理路径
// /data/app/el2/bundle/com.example.appA/files/data.txt

// 应用B无法访问应用A的路径
// 即使知道物理路径，内核也会拒绝访问
```

### 2.2 四个隔离级别

| 级别 | 名称 | 加密 | 可用时机 | 典型用途 |
|------|------|------|----------|----------|
| **EL1** | 公共数据区 | ❌ 不加密 | 始终可用 | 公开数据、缓存 |
| **EL2** | 普通数据区 | ✅ 加密 | 设备解锁后 | 应用私有数据 |
| **EL3** | 敏感数据区 | ✅ 强加密 | 首次解锁后 | 密码、token |
| **EL4** | 极敏感数据区 | ✅ 最强加密 | 首次使用时 | 金融数据、指纹 |

---

### 2.2 EL1: 公共数据区

**特点**:
- 不加密
- 设备启动后即可访问
- 用于公开数据

**路径**:
```typescript
// ✅ 可运行代码
/data/storage/el1/
├── base/                  # 基础目录
│   ├── cache/            # 缓存（可被系统清理）
│   └── temp/             # 临时文件
└── bundle/               # 应用包相关
```

**使用场景**:
```typescript
// ✅ 可运行代码
import fs from '@ohos.file.fs'

// EL1缓存目录
const cacheDir = getContext().cacheDir  // /data/storage/el1/base/cache/

// 存储可公开的缓存数据
const imagePath = `${cacheDir}/avatar.png`
```

---

### 2.3 EL2: 普通数据区

**特点**:
- 加密存储
- 设备解锁后可访问
- **最常用**的数据存储区

**路径**:
```typescript
// ✅ 可运行代码
/data/storage/el2/
├── base/
│   ├── files/            # 应用文件
│   ├── cache/            # 加密缓存
│   ├── temp/             # 加密临时文件
│   └── preferences/      # 首选项数据
├── database/             # 数据库
└── distributedfiles/     # 分布式文件
```

**使用场景**:
```typescript
// ✅ 可运行代码

// EL2文件目录
const filesDir = getContext().filesDir  // /data/storage/el2/base/files/

// 存储应用数据

const file = fs.openSync(dataPath, fs.OpenMode.CREATE | fs.OpenMode.READ_WRITE)
fs.writeSync(file.fd, JSON.stringify({ name: '张三', age: 25 }))
fs.closeSync(file)
```

**特点**:

## 四、ArkTS层文件操作

### 4.1 基础文件操作

```typescript
// ✅ 可运行代码
import fs from '@ohos.file.fs'

// ==================== 写入文件 ====================
function writeFile(content: string) {
  const filesDir = getContext().filesDir
  const filePath = `${filesDir}/data.txt`

  try {
    // 打开文件（不存在则创建）
    const file = fs.openSync(filePath, fs.OpenMode.CREATE | fs.OpenMode.READ_WRITE)

    // 写入数据
    fs.writeSync(file.fd, content)

    // 关闭文件
    fs.closeSync(file)

    console.log('写入成功')
  } catch (err) {
    console.error('写入失败:', err.message)
  }
}

// ==================== 读取文件 ====================
function readFile(): string {
  const filesDir = getContext().filesDir
  const filePath = `${filesDir}/data.txt`

  try {
    // 打开文件
    const file = fs.openSync(filePath, fs.OpenMode.READ_ONLY)

    // 获取文件大小
    const stat = fs.statSync(filePath)
    const bufferSize = stat.size

    // 读取数据
    const buffer = new ArrayBuffer(bufferSize)
    fs.readSync(file.fd, buffer)

    // 关闭文件
    fs.closeSync(file)

    // 转换为字符串
    const decoder = util.TextDecoder.create('utf-8')
    return decoder.decodeWithStream(new Uint8Array(buffer))
  } catch (err) {
    console.error('读取失败:', err.message)
    return ''
  }
}

// ==================== 删除文件 ====================
function deleteFile() {
  const filesDir = getContext().filesDir
  const filePath = `${filesDir}/data.txt`

  try {
    fs.unlinkSync(filePath)
    console.log('删除成功')
  } catch (err) {
    console.error('删除失败:', err.message)
  }
}

// ==================== 检查文件是否存在 ====================
function fileExists(fileName: string): boolean {
  const filesDir = getContext().filesDir
  const filePath = `${filesDir}/${fileName}`

  try {
    fs.accessSync(filePath)
    return true
  } catch (err) {
    return false
  }
}
```

## 六、权限模型

### 6.1 权限分类

**系统权限**:
- `ohos.permission.INTERNET`: 网络访问
- `ohos.permission.LOCATION`: 位置信息
- `ohos.permission.CAMERA`: 摄像头
- `ohos.permission.MICROPHONE`: 麦克风
- `ohos.permission.READ_MEDIA`: 读取媒体文件
- `ohos.permission.WRITE_MEDIA`: 写入媒体文件

**权限等级**:
- **normal**: 普通权限，安装时自动授予
- **system_basic**: 系统基础权限，需用户授权
- **system_core**: 系统核心权限，仅系统应用

## 八、安全最佳实践

### 8.1 敏感数据加密

```typescript
// ✅ 可运行代码
import cryptoFramework from '@ohos.security.cryptoFramework'

// AES加密
async function encryptData(plainText: string, key: string): Promise<string> {
  const symKeyGenerator = cryptoFramework.createSymKeyGenerator('AES256')
  const symKey = await symKeyGenerator.convertKey({ data: stringToUint8Array(key) })

  const cipher = cryptoFramework.createCipher('AES256|ECB|PKCS7')
  await cipher.init(cryptoFramework.CryptoMode.ENCRYPT_MODE, symKey, null)

  const encrypted = await cipher.doFinal({ data: stringToUint8Array(plainText) })
  return uint8ArrayToHex(encrypted.data)
}
```

### 8.2 安全检查清单

**文件安全**:
- ✅ 敏感数据使用EL3/EL4
- ✅ 不要在EL1存储密码、token
- ✅ 删除文件时覆盖写入
- ✅ 验证文件路径，防止路径穿越

**权限安全**:
- ✅ 最小权限原则
- ✅ 运行时请求权限
- ✅ 权限被拒绝时有降级方案
